## 2. doc_id：全局顺序编号

- 格式：`D%04d`（`D0001` 起），计数器存 SQLite 元表 `id_counters(name TEXT PRIMARY KEY, value INTEGER NOT NULL)`，在扫描事务内自增；单写锁 + 事务保证唯一。
- **doc_id 永不复用**。规则表（衔接 03 §6.1 变更四情形）：

| 扫描情形 | 判定 | doc_id 处置 |
|---|---|---|
| 新增 | path 无匹配、sha256 无匹配 | 分配新号 |
| 修改 | path 匹配、sha256 变化 | **保留** doc_id，重解析 |
| 移动 | sha256 匹配、path 不同（原 path 已消失） | **保留** doc_id，仅改 path（验收 §10.2-5 零重抽取由此 + 缓存命中保证） |
| 重复 | sha256 匹配、原 path 仍存在 | 分配新号，`status='duplicate'`，**不入队、不填 FTS** |
| 删除 | path 消失且无移动匹配 | `status='deleted'`（墓碑；M5 图节点软删衔接） |

- `files.status` 枚举（M2 定义，DDL 为 TEXT 应用层校验）：`{new, active, needs_confirm, duplicate, deleted}`。流水线成功后 `new→active`；分类不确定 → `needs_confirm`（§7）。

## 3. 扫描规则（`kb index scan`）

- **白名单扩展名**（大小写不敏感）：`.pdf .html .htm .md .docx .txt`；其余文件不扫描（不做"全扫后由解析器拒绝"）。
- **忽略规则**：隐藏文件/目录（`.` 开头）；遵循各 corpus 根的 `.gitignore`（pathspec）；`summaries/` 目录下的 `.md` **不入语料库**，仅作 manifest 绑定源（§5）——避免摘要与原文双重计算。
- **符号链接**：不跟随（`os.walk(followlinks=False)`）。
- **corpus 范围**：M2 只扫 `corpus_roots` 的 references/research/design；`inbox` M7 才扫；`external` 仅经 `kb index add` 登记（§12）。
- 变更检测按 03 §6.1 四情形 + §2 duplicate 规则；幂等要求不变（03 §9：重复执行不产生重复入库/抽取）。

## 4. 解析：覆盖率口径与 OCR

- **文本覆盖率口径**（03 §4 P1 阈值的分母，设计原缺）：
  `coverage = 提取的非空白字符数 / (页数 × parse.page_char_norm)`，`page_char_norm` 默认 **1500**（经验值，进 config 可调）。coverage ≥ `pdf_fast_min_coverage`(0.85) 判快路径达标；扫描版 PDF 字符≈0，自然落入 `no_text`。
- **三级判定在 M2 塌缩为两级**（实施修订，回写 03 §4 P1 的三级流程）：M2 不落地 Docling 降级路径、不建 `pdf_layout.py`；实现为「快路径（有文本层）／无文本层 `no_text`」两出口，coverage < 0.85 仅记 warning（`structure` 仍按标题数判 tree/flat）。Docling 降级随 M3 视需要再评估。OCR 默认关闭（§1）。

## 6. 分块与 FTS（M2 落地）

- **算法（结构感知）**：章节为原子单位；`len(section.text) ≤ parse.chunk_size`(2048) 则一章一块；超长章节按段落边界（优先双换行）递归切分，相邻块重叠 `chunk_overlap`(200) 字符；不切小章节合并（M3 视检索质量再优化）。
- `chunk_id = "<doc_id>#c%03d"`（文档内顺序号）。
- **幂等**：重解析时按 `doc_id` 物理删除旧 chunks 重写（05 §2.2 既有原则：索引可由原文重建）。
- **FTS 填充时点定为 M2**：`stage_chunk` 写完 chunks 即写入 `fts_chunks`。三处旧表述（03 §4"分块在 P5 前执行"、05 §10.3 把 FTS 归 M3、data-model"M2+ 解析后填入"）以本条为准，已同步。
- M2 即具备 SQL 级关键词检索能力，但 `kb search` CLI 仍 M3 落地。

## 7. 降级分类（M2，决策 1）

### 7.1 算法（关键词粗排）

```
输入：首章标题 + 正文前 4000 字符（无 embedding）
词表：classify.topic_keywords = {topic: [关键词…]}（config，默认 {}）
计分：标题命中 × 3 + 正文命中 × 1（大小写不敏感）
判定：top1 ≥ classify.min_keyword_score(2) 且 top1 ≥ top2 × classify.top_ratio(1.5)
      → 采用 top1；否则 topic=NULL 且 files.status='needs_confirm'
```

### 7.2 主题清单

- `topics` 表（§8）由 `kb init` 从 `config.core_topics` 播种；之后**以表为准**，人工维护；`doc_count` 由流水线维护。
- `needs_confirm` 文档进 `kb status` 待确认清单；人工改判（`kb config` 之外提供 M2 最小入口：直接改 `files.topic` 的维护命令不在 M2 范围，用 SQL/`kb config` 均不可——**M2 提供 `kb index set-topic <doc_id> <topic>`** 作为改判入口，即时生效）。
- M2 无质心，防震荡条款（质心冻结、90 天窗）整体推迟 M3；M2 改判即时生效即可。

### 7.3 doc_type 规则（03 §4 规则清单的展开）

按优先级：① manifest 绑定命中 → `paper`；② 文件名匹配 arXiv ID 正则（`\d{4}\.\d{4,5}`）→ `paper`；③ corpus=design 或路径含 `design/` → `design`；④ 扩展名 `.pdf` → `paper`（默认假设）；⑤ 其余 → `other`。`llm` extra 可用时 ⑤ 走 LLM 兜底，否则保持 `other`。

### 7.4 LLM 缺省降级

未安装 `llm` extra 或未配 API key 时：分类仍走 §7.1 纯规则；doc_type 无 LLM 兜底；`llm_arbitrate` 不调用。**解析/分块/FTS 全流程不依赖 LLM**，M2 主干可离线运行（NFR-1）。

### 7.5 M3 衔接

embedding 质心分类按 05 §4.2 原伪代码恢复（`gap_threshold`/`confirm_threshold` 启用）；M2 累积的人工改判结果作为初始质心语料与评估集。

## 9. LLM client（决策 3，M2 落地 `llm/litellm_client.py`）

接口按 05 §3.4（`LLM.complete(messages, json_mode=False, max_tokens=1024) -> str`，返回前记 `llm_usage`）。**两级重试语义**：

- **第一级 · 调用内指数退避**：可重试错误（网络异常 / 5xx / 429 / 超时）按 `delay = base × factor^(n-1)` 退避，封顶 `max_delay`；最多 `llm.retry.max_attempts=4` 轮（默认 delay 序列 1s→2s→4s——4 轮尝试只睡 3 次，末轮耗尽即止）。4xx 鉴权/参数类错误**不可重试**，直接转第二级。
- **第二级 · fallback 切换**：主 provider 第一级耗尽后，切 `llm.fallback` 链下一项重新走第一级；最多切换 `llm.fallback_max_switches=1` 次（一主一备）。
- **两级全败** → 抛 `RetryableError` 交 runner 退避（30s→1m→5m，M1 已落地）。
- **不做限流**（决策 3 明确）；M3+ 视多 provider 混用情况再评估。
- 记账：`purpose` 枚举沿用 M1 落库的 `classify|summarize|extract|arbitrate|embed`；`cost` 列 M2 记 NULL（价格表来源未定，M4 评估）。**M3 起枚举扩 `query_expand|rerank`（11 §7），并移除 litellm_client 对未知 purpose 的静默回退。**

config 扩展（已回写 05 §2.5，全部可 `kb config set` 修改）：

```yaml
llm:
  retry: { max_attempts: 4, base_delay_seconds: 1, backoff_factor: 2, max_delay_seconds: 30 }
  fallback_max_switches: 1
```

## 10. Runner 串行模型（决策 6）

- `kb index run`：**前台同步、串行**、取全局写锁（`--wait` 可选）；循环 `next_task → mark_running → 分发 STAGES → mark_done/mark_failed` 直至无可执行任务后退出。非常驻（02 D11）。
- **认领安全性**：M1 的 `next_task`（SELECT）与 `mark_running`（UPDATE）为两步操作，在"单写锁 + 串行 runner"前提下天然互斥——该前提是本设计的一部分，多 runner 并发属 M2 之后的事。
- **任务粒度**：一文一任务（`kind='parse'`），任务内顺序执行 `stage_parse → stage_chunk(§6) → stage_classify(§7)`；阶段幂等（doc_id/chunk_id 键 upsert）。
- `StageResult` dataclass：`{status: Literal["ok","skip"], detail: str, metrics: dict}`；失败走异常（`RetryableError`/`TerminalError`，M1 已落地）。
- **Ctrl-C**：捕获 `KeyboardInterrupt`，当前任务 `mark_failed(retryable)` 重置为立即可执行的 `pending`，退出码 130；重启 `kb index run` 续跑。
- `kb index reindex --full`：清空 `fts_chunks` 并把全部非 duplicate/deleted 文档重新入队；`--no-cache` 额外清 `cache/extracted/`。

## 11. `kb init`（M2 落地，行为定义）

幂等；**不覆盖任何既有文件**（已存在则跳过并提示相对默认值的 diff）：

1. `DataPaths.ensure_dirs()` 建目录树；
2. `config.yaml` 不存在 → 写入默认值（含 §9 新参数）；已存在则跳过并打印 diff（相对默认值）；`--force` 为显式重写入口（覆盖既有 config，仍不覆盖 sources.yaml 之外的注释模板）；
3. `sources.yaml` 不存在 → 写注释模板（P2 收集来源占位）；
4. 初始化 registry（DDL + `SCHEMA_VERSION=2`）并从 `config.core_topics` 播种 `topics` 表（§7.2）；
5. 环境校验：Python ≥ 3.11；数据目录所在盘剩余 ≥ 2GB；Tesseract 缺失仅警告（OCR 默认关闭，§1）；
6. **不下载模型**（bge-m3 下载引导随 M3，05 §11.6）；
7. 输出下一步指引（编辑 `config.yaml` → `kb index scan` → `kb index run`）。

## 12. `kb index add` 与命令路径归一

- `kb index add <path>`：**登记不拷贝**——库外文件以 `corpus='external'` 入库（path 为绝对路径），入队完整流水线；path 已存在则报错退出码 1。
- 命令路径**以 05 §1 为唯一口径**：`kb index scan / run / reindex / add`。04 §2.1 命令树中的顶层 `kb scan` / `kb reindex` / `kb add` 已回写修订（P3-4 的 `kb search query` 命名仍按原决议 M3 一并处理）。
