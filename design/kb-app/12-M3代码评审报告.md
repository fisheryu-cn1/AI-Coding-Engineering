## P1 — 必须修复（检索正确性 / 设计承诺失效）

1. **图路退化触发条件错误（已实机复现）**：`hybrid.py:196-203` 把"查询无主题词命中"当作退化条件——**任何纯关键词查询**都会把全库最新 20 篇的 section 以 w=0.5 注入 RRF，正是 11 §2.1（二轮 #1）要防的"新鲜但无关淹没融合"。设计要求：无主题命中 → 图路**空列表**；退化仅在 topic 稀疏（topic=NULL 占比高）时发生且按 corpus/doc_type 分组。复现：3 文件库（graphrag/cooking/hiking 各一）执行 `kb search "graphrag"`，结果 #2/#3 为无关的 cooking/hiking（纯图路新鲜度贡献 0.008 分），并打印误导性提示"主题未确认占比高"。修复方向：`else` 分支返回空列表；新增 topic 稀疏度判定（如 NULL 占比 > 50%）才走退化，且按 corpus/doc_type 分组。
2. **`--topic T` 后置过滤致 T 内召回静默损失**：`hybrid.py:325-343` FTS 全库执行 → 聚合截 40 条 → Python 侧才过滤 T——T 外文档占据 top chunk 时 T 内相关结果被截断丢弃。设计要求"FTS 仅在 T 的文档集内执行"（前置过滤）。修复方向：T 文档集约束下推 SQL（`doc_id IN (...)` 进 FTS 查询）。
3. **`graph` 模式忽略 `--topic`**：`hybrid.py:317-323` 提前 return，topic 过滤块不可达。11 §2.6："graph + T = 限定 T"。
4. **skip-as-done 丢伪 chunk**：`runner.py:165-171` 不看 `StageResult.status` 一律标 done；`stages.py:490-491` LLM 缺席返回 skip。链路：reindex/重解析时 `stage_chunk` 整删该 doc 全部 chunk（`registry.py:784-787` 含伪 chunk）→ 若此刻 LLM 不可用，classify 不入队 summarize（入队点控制）→ **此前生成的全部伪 chunk 静默消失、无任务残留、无任何提示**。修复方向：skip 区分"永久跳过"与"条件不满足"，LLM 缺席的 skip 应保活伪 chunk（stage_chunk 排除 `$summary`）或留 pending 任务。
5. **curated 非 stale 文档的伪 chunk 从未创建**：伪 chunk 唯一插入点是 `stage_summarize`，而它只为入队文档运行——纯策展库（未经 stale）的策展摘要**完全进不了 FTS**，11 §3.4"每文档一条"未兑现，05 §2.6"策展摘要作高信号检索层"的建库收益在纯策展场景不成立。修复方向：manifest 绑定（scan）时对 curated 非 stale 文档从策展文件构建伪 chunk。
6. **再策展后无清理重建**：`_stamp_manifest`（`index.py:411-423`）只更新三个字段，不删 `auto_summaries/<doc_id>.md`、不按 curated 文本重建伪 chunk——再策展后 FTS 里仍是旧 auto 文本，临时文件永久滞留（11 §3.1 四轮 (b) 的闭环缺尾）。

## P2 — 功能缺口 / 明显 bug

1. `related` 缺 FTS 共词扩展与 curated 一句话索引信号（`search.py:198-209` 仅同 topic 列表）；且 `list_files` 无 status 过滤，**deleted/duplicate 文档会被推荐**；topic=NULL 时退化"全库前 100 条"与设计不符。
2. FTS MATCH 词元引号未消毒（`hybrid.py:94`）：含奇数个 `"` 的查询直接 `OperationalError` traceback。
3. norm 碰撞提示未实现：`topics_cmd`（`search.py:251-265`）docstring 自称有碰撞提示但无代码；`kb status` 同样没有（现默认 core_topics 就含 ContextEngineering/context-engineering 碰撞对）。
4. LLM 提取的主题词不进图路（`hybrid.py:84-86` 扩展词只进 FTS），在线档图路只吃原始 query。
5. embedding 档警告仅 `search_cmd` 接线（`search.py:47-54`），status/show/read/related/compare/topics 均不触发；且未真实探测依赖存在性。
6. stale curated 清单两个提示出口均未实现：`kb status` 无此节；`reports/run_*.md` 根本没落盘（`_print_run_report` 只打印控制台）。
7. reindex --full 对 sha 未变的 auto 文档无缓存短路，全量重生摘要（11 §3.2"sha 未变则保留"的贯彻缺口；LLM 成本）。
8. 入队无去重：重复 classify/reindex 可堆积同 doc 多个 summarize 任务（幂等写入兜底但浪费 LLM 调用）。

## P3 — 轻偏差 / 打磨项

1. 重排输入为命中 snippet[:80] 而非设计的 L1 摘要/title+text[:200]（`hybrid.py:365`）。
2. 图路"标题命中者优先"仅单文档内生效，跨文档不优先（`hybrid.py:210`）。
3. graph 模式不打印退化提示（`graph_degraded` 无消费者）。
4. `$summary` 命中未按"文档级命中/标注摘要"渲染，原样打印在章节列（`search.py:77`）。
5. `assemble_context` 无 L1/L2/L3 分层装配，整份摘要 all-or-nothing（`assembler.py:104-109`）。
6. `topic_panorama` topic 精确匹配不过 norm()；先 limit 后滤 status 致少返回。
7. `_enrich` 的 `topic_filter` 死参数（三处调用恒 None）。
8. `search --limit` 硬编码 10，未消费 `retrieve.default_limit` 配置。
9. `_summary_input` 首节可击穿 12k 预算（`stages.py:570`）。
10. milestone-log 失真：测试数 200→实为 203、test_hybrid 7 项→实为 8 项；"topic 稀疏退化""curated 跳过/幂等""非 none 警告"三处 [x] 无测试佐证。

1. **必须先修**：P1-1/2/3（检索正确性，P1-1 已实机复现）、P1-4/5/6（伪 chunk 生命周期闭环）。

4. 修复完成 + DoD 全绿后 M3 关闭，随即进入 M4 收窄版——**M4 完成即 MVP 达成**。
