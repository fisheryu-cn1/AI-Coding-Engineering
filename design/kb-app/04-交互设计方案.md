# GraphIt-KB 交互设计方案

> 版本：v0.1（草案）
> 日期：2026-08-11
> 关联文档：《01-功能需求文档》《03-技术概要设计》（工具与命令的语义以概要设计为准，本文定义交互形态）

---

## 1. 交互总览

三种界面，共用同一检索与存储层：

| 界面 | 面向 | 场景 |
|---|---|---|
| CLI（`kb`） | 研究者 | 日常全部操作：建库、检索、查阅、审核、维护 |
| MCP 服务 | AI Agent | 检索、上下文组装、下钻取原文 |
| Web UI | 研究者 | 图谱可视化、关联阅读、比较分析、Inbox 审核 |

设计原则：

1. **渐进展开**：任何界面先给摘要级信息，原文与细节须显式下钻（少即是多）。
2. **全程可溯源**：每条展示信息带锚点，一键/一跳到原文位置。
3. **人在回路**：自动化的产出（分类、收集）都可审核、可改判，改判回流改进系统。
4. **终端优先**：核心工作流不依赖浏览器；Web UI 只做终端不擅长的事（图可视化、并排比较）。

## 2. CLI 交互设计

### 2.1 命令树

```
kb init                      初始化数据目录、生成配置（模型下载引导随 M3）
kb index scan                扫描资料目录，报告变更（增/改/移/删）
kb index run                 执行待处理任务（增量处理）
kb index reindex --full [--no-cache]  全量重建
kb index add <path>          手动纳入库外文件
```

> **命令路径归一（M2 起）**：索引类命令统一挂在 `kb index` 下，以 05 §1 为唯一口径；本文早先版本的顶层 `kb scan` / `kb reindex` / `kb add` 写法废止（09 §12）。

kb search "<query>" [--mode hybrid|vector|graph|topic-global] [--topic T] [--limit N]
kb show <doc>                文档元数据 + 章节树 + 文档摘要
kb read <doc> "<section>"    输出章节原文
kb related <doc|entity> [--hops N]
kb compare "<concept>" [--docs a,b,c]

kb topics                    主题清单与规模
kb inbox list|accept|reject  待审核收集
kb collect run               执行一次收集
kb report monthly            生成月度报告
kb config show|get|set       查看/修改配置（阈值、评分模块绑定等）
kb viz                       启动 Web UI
kb serve mcp                 启动 MCP stdio 服务
kb status                    库状态总览
kb maintenance              存储维护（LanceDB 清理/compaction）
```

> **M3 无向量口径（11 §2.5/§6.1）**：mode 名统一为 `topic-global`（原文 `topic` 已更正）；`related` 的实体/`--hops` 遍历与 `compare "<concept>"` 按概念收集观点为 M5/P1 目标态——M3 的 `related` 为同主题+共词文档级推荐、`compare` 仅支持 `--docs` 指定文档的摘要对比；`vector` mode 在无向量档显式报错。检索六命令 M3 起均为顶层命令（M2 的 `kb search` 占位子组移除）。

`kb config` 子命令（详见 03 §8.2.3）：

```
kb config show                                列出全部配置（含当前生效的评分模块与阈值）
kb config get <key>                           读单个键，如 scoring.thresholds.accept
kb config set <key> <value>                   写单个键（如 0.70、true、"default"）
kb config diff                                与默认配置对比（高亮用户修改项）
```

**`kb search "context rot" --limit 5`** —— 表格化命中，锚点可复制：

```

交互细节：

- 所有列表输出用 Rich 表格；章节树用树形组件；长输出自动分页。
- 检索无结果时给出建议：换模式（`--mode vector`）、放宽主题、或提示库中相近主题。
- 写操作（`accept`、`reindex --full`）执行前打印影响范围并要求确认（`--yes` 跳过）。

## 3. Web UI 设计（`kb viz` 启动）

单页应用，左侧导航四个页面 + 顶部全局搜索框。

### 3.1 检索页（首页）

- 搜索框 + 模式切换（混合/向量/图/主题全局）+ 主题过滤器（多选 chip）。
- 结果卡片：标题、章节路径、摘要两行、得分条、主题标签；点击卡片 → 文档页定位到该章节；卡片上"原文"按钮打开本地文件。
- 侧栏：命中实体的词云，点击实体追加为过滤条件（"在结果中收窄"）。

### 3.2 文档页

三栏布局：

```
┌────────────┬──────────────────────┬────────────────┐
│ 章节树     │ 内容区               │ 关联侧栏       │
│ （可折叠， │ 默认显示章节摘要；   │ · 关联资料     │
│ 当前节高亮)│ 点"展开原文"加载文本 │   (关联原因)   │
│            │ 页码锚点             │ · 提及实体     │
│            │                      │ · 版本/引用    │
└────────────┴──────────────────────┴────────────────┘
```

### 3.3 图谱页

- 渲染：AntV G6（v5）。节点四类（文档●/章节◾/实体◆/主题■），按主题着色；边带类型标签（悬停显示）；下钻/折叠、框选、路径高亮走 G6 内置 behavior，路径由后端 LadybugDB（Cypher SHORTEST PATH）计算，前端只渲染高亮。
- 交互：
  - 双击主题节点 → 展开其文档；双击文档 → 展开章节与实体（下钻）；右键 → 收起。
  - 点击节点 → 右侧信息面板（摘要 + "在文档页打开" + "以此为起点检索"）。
  - 框选两个节点 → "查找路径"，高亮最短关联路径并列出边的证据章节。
  - 顶部筛选器：按主题/实体类型/时间范围过滤；跳数滑块（1–3 跳）。
- 规模保护：默认只渲染选中主题的 2 跳子图，不加载全图。

### 3.4 Inbox 页

- 列表：标题、来源、初评得分（条形 + 数字）、**评分模块徽章**（如 `[default]` / `[ontology-keywords]`）、建议主题、抓取日期；按得分排序。
- 三档视觉分层：accept 区（白底）/ watchlist 区（折叠，淡灰底）/ reject 区（不显示，仅 collect_log）。
- 行内操作：接受（可改主题后入库）/ 拒绝 / 查看摘要与原文快照 / **查看评分明细**（弹窗：`sim_topic_hint`、`cross_topic_bonus`、`no_abstract` 等 `scoring_notes`）。
- 顶部展示本次收集运行报告摘要（新增 N、去重 M、watchlist K、淘汰 M），链接到完整报告；报告含每篇的评分模块与版本号。
- 阈值提示条：当前 `accept_threshold` / `reject_threshold` 数值 + 链接到 03 §8.2.1 与 `kb config set` 用法。

### 3.5 状态页

库规模统计、索引时间线、失败任务列表（可重试）、LLM token 月度消耗图。

### 3.6 设置页（P1；MVP 只读展示）

- **MVP**：只读展示当前配置（与 `kb config show` 等价），底部给出 `~/.graphit-kb/config.yaml` 路径与 `kb config set` 用法示例。不做可视化编辑器（避免 YAML 边界条件在前端复刻）。
- **P1**：可视化编辑评分阈值（带滑块）、主题绑定（每个主题一个下拉：选 `default` / 已注册模块）；变更写 config.yaml + config_audit 审计表。模块安装入口（从 `scoring_modules/` 目录扫描 + 启用/禁用）。

## 4. MCP 交互设计（Agent 视角）

### 4.1 典型时序：方案编写

```
Agent                         MCP 服务
  │── kb_assemble_context( ──▶│  混合检索 → 组装（§5.2 模板）
  │    task, budget=8000)     │
  │◀── 结构化上下文块 ────────│  含摘要、锚点、"可下钻条目"
  │  （写方案，需要某节原文）  │
  │── kb_read( ──────▶│
  │    doc, "§4.1")           │
  │◀── 章节原文 ──────────────│
  │── kb_related(entity) ────▶│
  │◀── 关联资料（关联原因）───│
```

### 4.2 典型时序：资料调研

`kb_topics` → `kb_search(mode=topic-global)`（主题全景）→ `kb_compare(concept)`（观点对比）→ `kb_show` + `kb_read`（精读）。

### 4.3 输出格式约定

- 所有工具返回 JSON（机器友好）；`kb_assemble_context` 返回的 `context_block` 字段为 Markdown 字符串，可直接嵌入提示词。
- 错误返回结构化 `{error, suggestion}`，如 `{"error": "doc_id not found", "suggestion": "call kb_search to resolve title to doc_id"}`，方便 Agent 自愈。
- 写工具（`kb_ingest`/`kb_reindex`）默认不出现，启动加 `--enable-write-tools` 才暴露。

## 5. 关键用户旅程

### J1 新增一批论文（对应 S1）

拖入目录 → `kb scan`（显示 6 新增）→ `kb index run`（进度条，逐文件：解析→分类→摘要→索引）→ `kb show <doc>` 抽查摘要质量 → 发现一篇分类错误，`kb show` 中改判 → 归属即时生效，主题质心不实时漂移，于下次批量重建时统一重算（防震荡，见 03 文档 §4 P2）。

### J2 主题研究（对应 S2）

`kb topics` 选定主题 → Web 图谱页展开主题节点浏览结构 → 发现两个实体意外相连 → "查找路径"看到证据链 → 文档页关联侧栏做关联阅读 → `kb compare` 收集分歧观点 → 在 `research/` 撰写新报告（由 Agent 经 MCP 辅助，见 J3）。

### J3 Agent 辅助写方案（对应 S3）

用户在 Agent 客户端布置任务 → Agent 走 §4.1 时序 → 产出的方案草稿中每个引用带来源锚点 → 用户抽查锚点，跳原文核对。

### J4 月度自动扩充（对应 S5）

openclaw 月初触发 `kb collect run && kb report monthly` → 用户打开 Web Inbox 页：17 篇候选，按初评得分排序 → 接受 5 篇（1 篇改判主题）、拒绝 12 篇 → 接受的自动进入流水线 → 阅读月度报告中的"图谱缺口分析"，决定下月跟踪方向。

### J5 目录重组（对应 S4）

用户将 `references/PetriNets/` 并入 `references/theory/` → `kb scan` 报告"6 移动、0 修改" → `kb index run` 秒级完成（仅更新路径，零重抽取）→ 检索验证无失效锚点。

### J6 调阈值/换评分模块（对应 FR-6.6）

`kb status` 发现 ontology 主题新候选常被误拒 → 用户打开 Inbox 看到 watchlist 折叠区有几篇本体相关 → 决定把 `accept_threshold` 从 0.70 调到 0.65 → `kb config set scoring.thresholds.accept 0.65` → 写审计表 → 下次 `kb collect run` 即生效 → watchlist 区自动重排，部分被接受。P1 时可在 Web 设置页滑块调整 + 选择主题绑定不同模块。

## 6. 反馈与改判回流

| 反馈动作 | 入口 | 系统响应 |
|---|---|---|
| 改判主题分类 | CLI `kb show` / Web 文档页 | 更新 `files.topic` 与 ABOUT_TOPIC 边并记录审计；主题质心不实时重算，下次批量重建时统一更新 |
| 摘要重写 | Web 文档页"重新生成" | 重跑 P3（可换模型），保留旧版本于历史 |
| 实体合并/拆分 | Web 图谱页信息面板 | 写 `SAME_AS` 边或撤销；后续抽取遵循改判 |
| Inbox 拒绝 | Inbox 页 | 记录拒绝特征，同来源同主题初评降权 |

所有改判写入 SQLite 审计表，保证"机器自动化 + 人类最终裁决"的边界清晰。Web UI 的全部写操作（含上表四项）不直接写图库/向量库，统一落 SQLite 意图/任务表，由任务执行器异步生效，页面轮询任务状态呈现结果（锁约定见 03 文档 §6.4）。
