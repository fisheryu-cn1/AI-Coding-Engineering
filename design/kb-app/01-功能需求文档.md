> 关联文档：《02-技术选型方案》《03-技术概要设计》《04-交互设计方案》

## 1. 背景与目标

### 1.1 现状

本项目已积累一个以个人研究为目的的资料库：

- `references/`：约 190 MB，69 篇 PDF（AIOS、CodeGraph、ContextEngineering、KnowledgeEngineering、ontology、PetriNets 六大主题）、网页存档、架构图集；其中约 59 篇 PDF 无任何文本提取版本。
- `references/<topic>/summaries/`：约 104 篇已生成的高质量论文摘要（固定五段结构 + 一句话索引 + §锚点），各主题另有 `INDEX.md`；这是一套**可复用的策展摘要资产**（构建与命名规范见 05 §2.6）。
- `research/`：43 篇 Markdown 研究报告，按 7 个主题子目录组织，命名风格不统一。
- 索引体系：三层 README 索引 + 月度文献扫描 + manifest/SHA-256 台账，全部由人工维护的 Markdown 表格构成，无机器可读元数据（无 frontmatter、无标签系统）。

### 1.2 问题

1. PDF 资料大多为纯二进制，无法全文检索，定位内容依赖人工记忆和文件名。
2. 索引靠人工表格，随资料增长维护成本线性上升，且无法表达资料之间的语义关联。
3. 向 AI Agent 提供研究上下文时，需人工翻找、复制、拼接，无法精准定位和定量供给。
4. 资料扩充依赖人工检索下载，周期性的文献跟踪没有自动化。

### 1.3 目标

构建一个**纯本地运行**的知识库应用 GraphIt-KB，具备：

1. 对全部资料自动完成分类、索引、章节级结构化与多粒度摘要，支持检索、原文查阅、关联阅读与比较分析。
2. 为全部资料构建知识图谱索引，关联关系清晰、按主题可快速定位、支持可视化。
3. 作为本地 MCP 服务被 AI Agent 调用，为知识检索与方案编写提供精准的上下文定位与提示词组装。
4. 资料内容或目录结构变化时，支持增量更新与全量重建两种索引维护方式。
5. 知识管理与图谱链接的颗粒度达到**章节级**，而非仅到文档级。
6. 支持定期自动扩充收集、内容整理与分析，可由 openclaw 定时任务或人工指令触发。
7. 本身作为"Agent 配套知识管理与上下文管理"的一次实验载体。

### 1.4 设计依据

本需求吸收 `design/` 目录已有六份设计文档的共识（混合检索、Schema 先验、结构感知分块、哈希指纹增量、少即是多），并规避其中识别出的过度工程风险。溯源见《02-技术选型方案》各决策条目。

## 2. 术语

| 术语 | 定义 |
|---|---|
| 资料条目（Document） | 一篇 PDF、一个网页存档、一篇 Markdown 报告等最小收藏单位 |
| 章节（Section） | 资料条目内按标题层级划分的结构单元，带 `section_path` |
| Chunk | 章节内按长度限制切分的检索单元 |
| 实体（Entity） | 从资料中抽取的概念、方法、工具、数据集、人物、机构等 |
| 主题（Topic） | 资料归属的研究主题域，与目录体系对齐 |
| 指纹 | 文件内容的 SHA-256（或版本号），用于变更检测与去重 |
| Inbox | 自动收集的新资料的待审核暂存区 |
| 锚点 | 指向原文具体位置的引用（文件路径 + 章节路径 + 页码范围） |

## 3. 范围

### 3.1 范围内

- 本地资料库的接入、处理、索引、检索、可视化。
- 本地 MCP 服务（stdio 为主，供 Kimi Code / Claude Code 等 Agent 调用）。
- 基于 arXiv 与指定网页来源的自动扩充收集。
- openclaw 定时任务与人工触发两种调度方式。

### 3.2 范围外

- 云端同步、多用户协作、权限体系。
- 对原文资料的改写、翻译、批注（原文只读，产物单独存储）。
- 通用网页爬虫（仅白名单来源的定向收集）。
- 代码仓库级 AST/调用图分析（本系统处理的是文献资料，不是代码；依据 `design/Claude-Code-context-management.md` 的实证，刻意不引入 AST 路线）。

## 4. 用户与使用场景

### 4.1 用户角色

- **研究者（人）**：唯一的真人用户。查阅、比较、主题探索、审核自动收集结果。
- **AI Agent（机器）**：经 MCP 服务检索知识、获取组装好的上下文块，辅助研究与方案编写。

### 4.2 核心场景

- S1：新增一批论文 PDF，系统自动完成解析、分类、摘要、建索引，研究者可立即检索。
- S2：围绕某研究主题（如"上下文工程"），快速列出相关资料、理论、观点、参考方案，并进行关联阅读与观点比较。
- S3：Agent 接到方案编写任务，经 MCP 获取按 token 预算组装好的上下文（含溯源锚点），需要时下钻读取章节原文。
- S4：移动/重命名/删除部分资料后，一键增量更新全部索引；或定期全量重建校验。
- S5：每月由 openclaw 定时任务触发，自动检索 arXiv 新论文，去重、初评后放入 Inbox 并生成文献扫描报告，研究者审核后正式入库。
- S6：通过图谱可视化发现主题间的意外关联，辅助研究方向判断。

## 5. 功能需求

### FR-1 资料接入与智能处理

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-1.1 | 支持 PDF、HTML、Markdown、DOCX、TXT 五种格式的全文解析，输出纯文本与结构信息 | P0 |
| FR-1.2 | 自动分类：a) 主题域分类，对齐现有目录体系（AIOS / CodeGraph / ContextEngineering / KnowledgeEngineering / ontology / PetriNets / architecture / sdd / theory / industry 等，可扩展）；b) 文档类型识别（论文 / 研究报告 / 笔记 / 网页 / 图表集 / 设计方案） | P0 |
| FR-1.3 | 章节级结构化：还原标题层级树，每个章节记录 `section_path`、层级、页码范围（PDF） | P0 |
| FR-1.4 | 多粒度摘要：章节级摘要（1-3 句）与文档级摘要（含研究问题、方法、结论、与 GraphIt 的相关性） | P0 |
| FR-1.5 | 元数据自动登记：arXiv ID（含版本）、作者、发表日期、页数、SHA-256、来源路径；沿用 `references/arxiv_2026-07_manifest.md` 的字段规范 | P0 |
| FR-1.6 | 原文查阅：任何检索/图谱结果可一键跳转原文（打开文件并定位到章节/页码） | P0 |
| FR-1.7 | 解析产物（提取文本、章节树）持久化缓存，避免重复解析 | P0 |
| FR-1.8 | 复用预生成论文摘要（curated summary）：识别 `references/<topic>/summaries/` 中的策展摘要，命中即作为文档级摘要来源（跳过 LLM 生成）；摘要须遵循统一构建规范（固定五段结构 + 头部字段）与命名规范（`NN[-letter]-中文短标题.md`，序号与源 PDF 一致、不带版本号），格式与质量约束见 05 §2.6 | P0 |

### FR-2 知识图谱与关联分析

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-2.1 | 基于预定义 Schema（Schema 先验）从资料中抽取实体与关系，构建知识图谱；实体类型至少覆盖：概念、方法/技术、工具/系统、数据集/基准、人物、机构 | P1 |
| FR-2.2 | 实体消歧与融合：同名异义按类型区分，异名同义经相似度初筛 + 确认后合并 | P1 |
| FR-2.3 | 主题索引：任一主题可列出其下全部资料、核心实体、关键观点 | P0 |
| FR-2.4 | 关联阅读：给定一篇资料，返回关联资料列表（共享实体、同主题、引用/版本关系），并标注关联原因 | P1 |
| FR-2.5 | 比较分析支持：给定一个概念或问题，从多篇资料中并排取出相关章节段落与观点摘要，供对比阅读 | P1 |
| FR-2.6 | 图谱可视化：本地 Web 界面，支持按主题着色、节点下钻（文档→章节→实体）、路径查看 | P1 |
| FR-2.7 | 成本控制：实体关系抽取仅针对**核心域主题内的**论文/设计方案与被单独标记的文档执行（默认核心域清单与再评估机制见《03-技术概要设计》§4 P4；遵循"只结构化 15–25% 核心实体"原则，溯源 `design/Wiki与图数据库混合架构策略笔记.md` §3.2），其余资料仅做向量与全文索引 | P1 |

### FR-3 LLM 检索与 MCP 服务

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-3.1 | 混合检索：向量检索 + 图遍历 + 全文关键词三路，可配置检索模式（向量优先 / 图优先 / 混合 / 主题全局）。MVP 阶段"图"路为主题/章节结构导航（基于结构图谱），P1 实体图谱建成后升级为实体子图遍历。**MVP 检索为无向量变体（FTS + 结构导航两路 + LLM 重排），向量路为 P1 目标态（11 §2）；离线档（无 LLM）跨语言召回依赖 `search.synonyms` 静态表兜底，未配时显著受限（11 §2.3）** | P0 |
| FR-3.2 | 上下文组装：按 token 预算（默认 8k，可配）输出结构化上下文块，含分层摘要与溯源锚点，可直接作为提示词组成部分 | P0 |
| FR-3.3 | 渐进展开：先返回 L1/L2 级紧凑摘要（每条 50–100 token），Agent 可按需下钻取章节原文（溯源 `README.md` API 卡片分层供给策略） | P0 |
| FR-3.4 | 本地 MCP 服务：stdio 传输为主，暴露检索、查阅、关联、组装等工具（工具清单见《03-技术概要设计》§7） | P0 |
| FR-3.5 | 全部返回内容携带来源锚点（文档 ID + 章节路径 + 页码），保证可追溯 | P0 |

### FR-4 索引更新

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | 变更检测：基于文件指纹（SHA-256）与 mtime 检测新增、修改、删除、移动（重命名）四种变更 | P0 |
| FR-4.2 | 增量更新：仅对变更文件重新执行处理流水线，同步更新图索引、向量索引与元数据注册库 | P0 |
| FR-4.3 | 全量重建：清空索引后重建；可选择复用解析缓存（仅重建索引）或不复用（彻底重跑） | P0 |
| FR-4.4 | 删除与移动处理：采用墓碑（`valid_to`）软删除，保留历史可追溯；移动不触发重抽取，仅更新路径 | P1 |
| FR-4.5 | 触发方式：手动 CLI 命令 + 目录监听（可选）+ 定时任务 | P0 |
| FR-4.6 | 存储维护：`kb maintenance` 定期清理 LanceDB 过期版本与碎片（compaction），报告三存储体积 | P1 |

### FR-5 章节级颗粒度

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-5.1a | 结构图谱：图谱节点覆盖文档与章节两个层级（Document/Section/Topic，零 LLM，随解析索引流水线自然产出）。**MVP 形态裁决（11 §0 决策 3 / §9）：MVP 交付"结构关系导航"——Topic→Document→Section 可遍历、可下钻、章节级定位，以 SQLite（topics/files/fts_chunks）承载；LadybugDB 节点图存储为 M5 目标态** | P0 |
| FR-5.1b | 实体图谱：实体挂载到章节（MENTIONS 边指向 Section） | P1 |
| FR-5.2 | 摘要、实体归属、分类标签均可定位到章节 | P0 |
| FR-5.3 | 检索与 MCP 返回的最小定位单位为章节，而非文档 | P0 |

### FR-6 自动扩充与定期整理

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-6.1 | 来源管理：配置文件定义 arXiv 检索式（关键词 / 分类号 / 作者跟踪）与网页白名单 | P2 |
| FR-6.2 | 自动收集：按调度抓取新资料，经去重（arXiv ID 去版本号 + SHA-256 + 拒绝名单）、相关性初评（§8.2.1 公式 + 阈值三档处置：accept/watchlist/reject）后放入 Inbox，不直接入库 | P2 |
| FR-6.3 | 人在回路：研究者审核 Inbox（接受 / 拒绝 / 改分类），接受后才进入正式处理流水线 | P2 |
| FR-6.4 | 定期整理报告：周期性产出文献扫描报告（沿用 `arxiv_2026-07_literature_scan.md` 的格式：分级表 + 阅读路线）、图谱缺口分析（哪些主题覆盖薄弱） | P2 |
| FR-6.5 | 调度：支持 openclaw 定时任务触发与人工 CLI 触发，两者走同一入口，任务幂等 | P2 |
| FR-6.6 | 评分模块可插拔与可配置：MVP 阶段内置 `default` 模块 + 阈值可配；P1 阶段允许按主题绑定不同评分模块（插件式接入），未来可扩展不同研究主题的算法；配置入口支持 config.yaml 文件 + `kb config` CLI 子命令 | P2 |
| FR-6.7 | 评分结果可追溯：Inbox 每条记录携带 `scoring_module` + `scoring_version` + `scoring_notes`；运行报告含每篇的评分明细；阈值变更写 `config_audit` 审计表 | P2 |

## 6. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | 纯本地运行：除可选的 LLM API 外，全部组件（图库、向量库、Embedding）本地化；除用户自有的 openclaw 网关与可选 Web UI 外，KB 组件本身无独立常驻服务进程 |
| NFR-2 | 隐私：默认使用本地 Embedding 模型；调用外部 LLM API 时仅发送必要文本片段，密钥经环境变量注入 |
| NFR-3 | 原文不可变：系统永不修改 `references/`、`research/` 原始文件，全部产物存于独立数据目录 |
| NFR-4 | 性能：增量更新单篇 PDF（30 页内）端到端处理 < 2 分钟（不含 LLM 摘要）；检索响应 < 3 秒；MCP 上下文组装 < 10 秒 |
| NFR-5 | 可移植：数据目录整体可拷贝迁移；索引可由原文 + 缓存完全重建 |
| NFR-6 | 成本可控：结构化解析零 LLM 调用；LLM 仅用于摘要、分类仲裁、实体抽取，且可切换本地模型；首次全量建库的 LLM 成本量级估算见《03-技术概要设计》§10.2 |
| NFR-7 | 可观测：每次流水线执行有任务日志与统计（处理文件数、token 消耗、失败项） |
| NFR-8 | 扩展性：评分模块、解析器、检索器等可扩展点均以"接口 + 注册表"模式接入；新增模块不需修改主代码；失败模块降级回内置默认，不阻塞流水线 |

## 7. 验收标准

1. 对当前资料库执行全量建库后：≥95% 的 PDF 成功解析并产生章节树与摘要；全部资料有主题分类与元数据记录。
2. 任意一篇资料，可通过一个命令列出其章节树、各章摘要与关联资料。
3. 以"上下文 rot""代码图谱"等主题词检索，返回章节级命中且每条带原文锚点，锚点可实际打开对应位置。
4. Agent 经 MCP 调用上下文组装工具，返回 ≤ 预算 token 的结构化上下文块，且每条信息可溯源。
5. 移动一个目录后执行增量更新，索引中路径正确更新且不发生重复抽取；删除文件后检索不再命中（墓碑生效）。
6. 图谱可视化中可从一个主题节点下钻到资料、章节、实体，并查看两节点间的关联路径。
7. 自动收集任务运行后，Inbox 中出现去重后的候选资料与一份文献扫描报告；审核接受后自动进入处理流水线。

## 8. 分期路线

| 阶段 | 内容 | 对应需求 |
|---|---|---|
| MVP | 解析接入、章节树、指纹元数据、**结构图谱（Document/Section/Topic，零 LLM）**、全文+结构导航检索（**无向量 MVP 变体**，向量三路为 P1 目标态，见 11 §2）、CLI、增量/全量更新、基础 MCP（检索 + 章节读取 + 上下文组装） | FR-1、FR-3.1–3.5、FR-4、FR-5.1a/5.2/5.3 |
| P1 | 实体关系抽取、实体图谱构建与消歧、关联阅读、比较分析、Web 可视化、完整 MCP 工具集 | FR-2、FR-5.1b、FR-3 完整 |
| P2 | 来源管理、自动收集、Inbox 审核流、定期报告、openclaw 调度接入 | FR-6 |

分期原则：先验证"索引与检索"这一地基（MVP 即可解决当前最痛的 PDF 不可检索问题），再上图谱，最后做自动扩充。避免一次性铺开（溯源 `design/Wiki与图数据库混合架构策略笔记.md》"过度工程"陷阱）。
