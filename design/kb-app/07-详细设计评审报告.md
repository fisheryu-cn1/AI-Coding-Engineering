## 2. 严重问题（实现级错误，必须先改）

### S1. LanceDB 写入语义错误（05 §2.3）

`add(..., mode="overwrite")` 在 LanceDB 中是**整表覆盖**，不是按 `chunk_id` 去重 upsert。按现写法，每批写入会清空其他文档的向量，同时破坏 §4.5 声称的"幂等 upsert"。

**建议**：改用 `merge_insert("chunk_id").when_matched_update_all().when_not_matched_insert_all()`，或先 `delete("chunk_id IN (...)")` 再 append。

### S2. FTS5 插入不幂等（05 §4.5）

FTS5 虚拟表无 upsert 语义，`fts.insert(chunks)` 在任务重放（§7.2 崩溃恢复）时产生重复行，与 §10.1"幂等重放（同 doc 跑两次结果一致）"的测试目标直接冲突。

**建议**：插入前先 `DELETE FROM fts_chunks WHERE chunk_id = ?`（或按 doc_id 整批删除重插）。

### S3. 图 Schema DDL 与设计要点/伪代码三处自相矛盾（05 §2.2）

1. 设计要点写"软删除：节点带 `valid_from/valid_to`"（03 §3.2 亦为"所有节点"），但 DDL 仅 `Document` 有这两列，`Section/Chunk/Entity/Topic` 均缺。删除文档时其 Section/Chunk 无法置墓碑，"查询一律加 `WHERE valid_to IS NULL`"对 Section 不可执行。
2. §4.3 伪代码 `upsert_nodes("Section", [{..., model, generated_at}])`，但 `Section` 表无 `model/generated_at` 列（03 §4 P3 明确要求摘要携带这两个元数据，供换模型后局部重生成）。
3. 注释称"ABOUT_TOPIC 为 rel group：Document 与 Section 均可指向 Topic"，实际 DDL 拆为 `ABOUT_TOPIC` + `SECTION_ABOUT_TOPIC` 两张表——拆分本身利于 Neo4j 移植（方向正确），但注释陈旧需更新。

**建议**：为 `Section` 补齐 `valid_from/valid_to/model/generated_at`；或显式裁决"软删除只到 Document 级、Section 级联过滤"，并统一改写设计要点与查询口径。

### S4. 文档级摘要没有存储位置（05 §4.3）

`doc.summary = 四段式(...)` 之后落库位置未定义：`files` 表无 `summary` 列，`Document` 节点无 `summary` 属性（03 §3.1 同样没有）。而 `kb_get_document`、`kb show`、上下文组装均依赖文档级摘要；curated summary 有 `summary_path` 兜底，auto 生成的没有。

**建议**：`Document` 节点增加 `summary` 属性（连同 `summary_model/generated_at`），或 `files` 表加列，二选一并写进 DDL。

### S5. Inbox accept 锁约定与 03 冲突（05 §7.1）

05 §7.1 将 `accept` 列入取写锁命令；03 §6.4 明确"Inbox accept 只写 SQLite + 入队任务，**不取图库写锁**，实际索引由随后的 `index run` 完成"——该折衷是刻意的（Web Inbox 高频审核不应与只读 MCP/Web 进程互斥）。05 头部虽声明"冲突处以本文为准"，但此处改动理由不成立。

**建议**：维持 03 口径，`accept` 不取写锁；如需改判，应显式记录裁决理由。

### S6. 分类阈值公式逻辑错误 + 阈值未入配置（05 §4.2、§2.5）

- `top1.sim > max(top2.sim, classify_gap_threshold)` 把"绝对阈值"与"top1−top2 差距"混为一谈：top1=0.91、top2=0.90 时差距仅 0.01（明显应仲裁），却会因 0.91 > 0.90 直接定类。03 §4 P2 原意是"top1 − top2 > 阈值时直接定类"，应为差值比较。
- `classify_gap_threshold` 与人工确认阈值 `0.7` 均未出现在 §2.5 config.yaml 中（03 也未给默认值）。

**建议**：公式改为 `top1.sim - top2.sim > gap_threshold`；config.yaml 增加 `classify:` 段（`gap_threshold`、`confirm_threshold` 及默认值）。

### S7. 写锁文件无 stale 回收（05 §7.1）

O_EXCL 锁文件在持锁进程崩溃后永久残留，此后所有写命令永远报 `LOCK_HELD`。锁文件内虽写有 PID，但伪代码无"PID 存活检测 / 锁超时回收"逻辑；且 `os.read(p)` 签名有误（需先 `os.open` 取 fd）。

**建议**：获取锁失败时读取 PID 并检测进程存活，死锁文件自动回收；或按锁文件 mtime 超时回收。

### S8. 图库二级索引可行性存疑（05 §2.2）

`CREATE INDEX idx_section_doc ON Section(doc_id)` 等三条：Kùzu 系（含 LadybugDB）历史上不支持节点属性二级索引（仅主键索引），且 `CREATE INDEX` 语法与 §3.1"只用标准 Cypher 子集、不依赖后端特有扩展"的承诺冲突。

**建议**：核实 LadybugDB 当前版本能力；若不支持，热路径查询改走主键或关系 traversal 表达，并删除该三条 DDL。

## 4. 合理性问题（较小，建议修正）

- **runner 无真实退避**（05 §4.0）：声称"退避重试"实则立即重置 `pending`，`tasks` 表缺 `run_after` 字段，LLM 限流场景会打满重试。
- **锚点格式未分类型**（05 §3.5）：`file://<path>#page=3` 对 PDF 可用，对 HTML/MD 无页码语义，建议按 doc_type 定义锚点格式。
- **MECW 计数黑盒**（05 §5.2）：token 计数用哪个 tokenizer、与目标模型不一致时的安全余量未说明，"实际 ~6200"如何量出不可复现。
- **Embedding 接口混入 LLM 类**（05 §3.4）：本地 bge-m3 推理塞进 `LLM.embed`，与 `embedding.backend` 配置分层不一致，建议 Embedding 独立接口。
- **Inbox accept 与 NFR-3 的字面张力**（03 §8.3 遗留）：accept 把文件移入 `references/`，与"永不修改 references/"需在文档中明确表述为"只新增、不改已有文件"。
