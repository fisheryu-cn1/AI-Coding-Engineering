## P2 — 正确性/质量问题（可随 M2 早期顺带处理）

1. **`kb config diff` 把真实的 `None` 值渲染成 `<missing>`**（`cli/config.py:192-197`）。`diff_defaults` 用字符串 `"<missing>"` 做哨兵，而 `_render` 又把 `None` 也显示为 `<missing>`——例如用户修改默认值为 `None` 的 `llm.api_base` 后，diff 的"默认值"列显示 `<missing>`，语义错误。

2. **`config_audit` 用 `repr()` 编码非标量**（`registry.py:363-368`）。dict/list 审计值存成 Python repr，不可机器解析；建议改 `json.dumps(ensure_ascii=False)`。

3. **只读命令有写副作用**：`resolve_data_dir`（`cli/_common.py:22-32`）在任何命令（含 `config get`、`status`、`--help` 之外的只读操作）下都会 `mkdir` 数据目录。另外 `_common.py` 的 `DataDirOpt` 定义后无人使用（main.py 各自声明），属死代码。

4. **任务队列三处小问题**：
   - `next_task` docstring 称"created_at 单调（ULID 前缀）"——`created_at` 是秒精度 ISO 字符串，同秒可并列，注释与实现不符（`task.py:221-222`）；
   - `mark_done`/`mark_failed` 不校验当前状态为 `running`，可把任意状态任务直接终态化（`task.py:256-303`）；
   - `count_tasks`/`list_tasks` 只读查询也走 `BEGIN IMMEDIATE` 写事务（`task.py:330-360`），无碍正确性但增加不必要的写锁占用。
   - 另注：默认 `max_attempts=3` 时退避只走到 30s/60s，**5m 档永远不可达**；若设计意图是"第三次重试等 5 分钟"，需把 `max_attempts` 默认调为 4 或调整计数时点。建议与设计作者确认口径。

5. **写锁的 mtime 回收存在理论竞态**（`lock.py`）：PID 存活但 mtime 超时被判死锁回收后，原持有进程恢复时 `release_write_lock` 会无条件 unlink，可能删掉新持有者的锁文件。单用户本地场景概率极低，但建议在 `release_write_lock` 中比对锁文件内容 PID 后再删，或在 docstring 中明确记录该已知限制。此外 `_is_alive` 为 POSIX-only（`os.kill`），pyproject 未声明平台限制。

6. **mypy 未配且不过**：dev 依赖声明了 mypy 但无 `[tool.mypy]` 配置，实测 10 个 error——`registry.py` 的 `own/conn` 模式无法通过类型窄化（6 处 union-attr/arg-type），另缺 `types-PyYAML` stub。要么补配置 + stub 并修窄化，要么从 dev 依赖移除，避免"装了不用"。

7. **`ruff format --check` 有 8 个文件不合格式**（lint 本身全过）。pyproject 未声明 format 门禁，但既然用 ruff，建议跑一次 `ruff format` 并在 milestone 验收中加入 `--check`。

8. **测试小瑕疵**：`test_stale_pid_is_reclaimed` 硬编码 PID `99999999` 假设其不存在（`test_lock.py:67`），理论上可遇 PID 撞车导致偶发失败；可用 `os.fork`+回收或 `/proc` 探测构造确定死 PID。
