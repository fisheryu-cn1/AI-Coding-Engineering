# GraphIt-KB 论文摘要构建与命名规范

> 版本：v1.0
> 日期：2026-08-13
> 适用范围：`references/<topic>/summaries/` 下所有论文摘要（`.md`）的**构建、命名、质量**约定
> 关联文档：01-功能需求文档（FR-1.8）、05-详细设计方案（§2.6 为本文档的设计内浓缩版，以本文档为准）
> 读者：生成/审核摘要的 Agent 与研究者

---

## 1. 目的与定位

`summaries/` 中的摘要是 GraphIt-KB 的**高信号检索层**：被检索引擎直接消费（`一句话索引` 作 L1、`适用场景+主要观点` 作 L2、`达到的效果` 表作 compare/topic-global），并作为文档级摘要的**高质量替代**（命中即跳过 LLM 生成）。因此摘要必须：

1. **结构一致**——可被机器稳定解析；
2. **字段齐全**——可与 `arxiv_2026-07_manifest.md` 台账交叉校验；
3. **质量达标**——可直接嵌入 Agent 上下文而不需二次改写；
4. **命名规范**——文件名本身携带检索信号（绑定源 PDF + 中文主词 + 稳定锚点）。

> 原则：摘要是**入口而非替代**。全文 + 向量索引始终保留，摘要只负责"让 Agent 快速判断相关性"，原文细节靠锚点下钻。

---

## 2. 适用范围

- **必读**：所有写入 `references/<topic>/summaries/` 的论文摘要。
- **不适用**：`research/`、`design/` 下的研究报告与设计文档（其摘要由 KB 流水线自动生成，或另行约定）。
- 每主题一个 `INDEX.md`，其格式一并约定（见 §9）。

---

## 3. 文件命名规范

### 3.1 模式

```
<NN>[-<letter>]-<中文短标题>.md
```

| 段 | 规则 |
|---|---|
| `<NN>` | 2 位补零序号（>99 自然扩 3 位）；**必须与源 PDF 的 `NN-` 前缀严格一致**（summary→PDF 绑定键） |
| `[-<letter>]` | 可选字母后缀（a/b/c），当同一 `NN` 号对应多篇（如 `05a`/`05b`）时使用，与源 PDF 的 letter 后缀一致 |
| `<中文短标题>` | 8–20 字中文主词，概括论文核心；多词用 `-` 或 `_` 分隔 |

### 3.2 约束（检索相关性）

1. **序号即绑定**：`NN[-letter]` 前缀与源 PDF 一致 → 一键定位原文，且是主题内阅读顺序（对应 `INDEX.md` 的"推荐先读"）。
2. **中文短标题是检索信号**：文件名进入 `kb_search` 的 FTS5 trigram + 向量检索字段；中文主词比 `01-Agent-Harness-Evolution.pdf` 这类英文/PascalCase 名更利于中文召回。
3. **不带版本号**：`_vN` 属于源 PDF 文件名、不属于摘要名——摘要名保持稳定，检索结果锚点不随版本漂移（版本变更由头部 `source_pdf` 字段 + sha256 绑定 + `stale` 标记处理）。
4. **不含非法/歧义字符**：禁 `/` `\` `:` `*` `?` `"` `<` `>` `|` 及空格。
5. **主题内唯一**：同一主题目录内 `NN[-letter]` 不重复。

### 3.3 正例 / 反例

- ✅ `10-Agent_Harness演化与质量回归.md`（NN 与 PDF 一致、中文主词、无版本号）
- ✅ `05a-LLM作为数据库管理员.md`（letter 后缀与 PDF `05a-` 一致）
- ❌ `10-Ben_Sghaier-Agent_Harness_Evolution_v2.md`（带版本号 → 版本漂移破坏锚点）
- ❌ `Agent Harness 演化.md`（无序号 → 无法绑定源 PDF、无阅读顺序）
- ❌ `10-Agent Harness 演化.md`（含空格 → 解析歧义）

## 4. 头部元数据规范

### 4.1 规范格式（YAML frontmatter，新文采用）

新生成的摘要一律用 **YAML frontmatter** 承载头部元数据，正文为五段 Markdown：

```markdown
---
title: "Don't Blame the Large Language Model: How Agent Harness Evolution Shapes Coding Agent Quality"
source_pdf: "10-Ben_Sghaier-Agent_Harness_Evolution_v2.pdf"
arxiv_id: "2607.03691"
arxiv_version: "v2"
authors:
  - "Oussama Ben Sghaier"
  - "Hao Li"
  - "Bram Adams"
  - "Ahmed E. Hassan"
year: 2026
venue: "ACM TOSEM"
type: "Agent 设计参考 + 内容索引"
generated_at: "2026-08-12"
summary_version: "1.0"
---

# 论文摘要：Agent Harness Evolution（harness 演化对 Agent 质量的影响）

## 1. 适用场景
…
```

### 4.2 字段表

| 字段 | 必填 | 说明 | 示例 |
|---|---|---|---|
| `title` | ✅ | 原论文英文标题 | Don't Blame the LLM: … |
| `source_pdf` | ✅ | **绑定键**：完整 PDF 文件名，含 `_vN` | `10-Ben_Sghaier-Agent_Harness_Evolution_v2.pdf` |
| `arxiv_id` | ✅ | 去版本号的 arXiv ID（去重主键） | `2607.03691` |
| `arxiv_version` | ✅ | 版本（与 manifest `version` 一致） | `v2` |
| `authors` | ✅ | 作者列表（YAML 数组） | 见上 |
| `year` | ✅ | 出版年份 | `2026` |
| `venue` | ✅ | 出版（期刊/会议；未发表填 arXiv） | `ACM TOSEM` |
| `type` | ✅ | 摘要类型（受控词表，见 §4.3） | `Agent 设计参考 + 内容索引` |
| `generated_at` | ✅ | 生成日期（ISO） | `2026-08-12` |
| `summary_version` | 建议 | 摘要自身版本，重生成时递增，便于追踪 | `1.0` |

### 4.3 受控词表（`type`）

`type` 采用「用途 + 粒度」两段式，从下列词表组合（用 ` + ` 连接）：

- **用途**：`内容索引`（可检索的内容摘要）/ `设计参考`（支撑 GraphIt-KB 设计决策）/ `评测对照`（可作评测基线）/ `业界观察`（趋势/观点）
- **粒度**：默认不写粒度；若为"全文精读"级可标 `精读`。

示例：`Agent 设计参考 + 内容索引`、`内容索引`、`评测对照 + 内容索引`。

### 4.4 与 manifest 台账对齐

头部字段必须与 `references/arxiv_2026-07_manifest.md` 台账对应列一致（`arxiv_id`↔`arXiv ID`、`arxiv_version`↔`Version`、`authors`↔`Authors`、`year`↔`Published`、`source_pdf`↔`Local PDF`），使 KB 可交叉校验"摘要 ↔ 台账 ↔ 源文件"三者一致。不一致时 `kb index` 报 `SUMMARY_MANIFEST_MISMATCH`。

### 4.5 存量 blockquote 格式兼容

早期 ~104 篇摘要用 blockquote 头部（`> **字段**：值`）。解析器按已知字段名宽容匹配；新文不再使用此格式。字段映射：

| blockquote 字段 | frontmatter 字段 |
|---|---|
| 原论文标题 | `title` |
| 完整 PDF 文件名 | `source_pdf` |
| arXiv（括号内 `arXiv:XXXX.XXXXXvN`） | `arxiv_id` + `arxiv_version` |
| 作者 / 年份 / 出版 | `authors` / `year` / `venue` |
| 摘要类型 | `type` |
| 生成日期 | `generated_at` |

## 5. 五段结构规范

正文固定五段，顺序与标题名**不可变**（解析器按 `## N.` 标题定位）。

### 5.1 `## 1. 适用场景`

- 写**可操作的"何时读这篇"**（≥1 条），每条是"当你要做 X 时读这篇"，而非内容复述。
- 反例："本文研究了 harness 演化"（内容复述）；正例："评估模型升级 vs harness 升级哪个更影响 Agent 质量时"（可操作）。
- 段尾可加一条锚点行（`> 锚点：…`）指向对应小节。

### 5.2 `## 2. 主要观点与方案`

- 结构化呈现核心观点/方法，按论文自身的逻辑（研究问题→方法→发现→机制）分小节。
- **每条必须带论文原生 §锚点**（见 §6）。
- 只写"结论 + 支撑"，不堆砌过程性细节。

### 5.3 `## 3. 达到的效果`

- 固定三列表格：`度量 | 结果（数值） | 锚点`。
- **数值必须来自原文**，不得外推或四舍五入到失真的程度；无法量化的观点放 §2，不放 §3。
- 关键对比（vs 基线）单列成行。

### 5.4 `## 4. 参考项目 / 资源`

- 表格：`类别 | 链接 / 说明`。
- 论文类必填 **arXiv 链接**；代码、数据集、基线系统、关联方法按实填写。

### 5.5 `## 5. 一句话索引（给 Agent 用）`

- **~100–200 token**，独立可读（脱离全文也能判断相关性）。
- 必须含：**结论 + 关键证据/数字**（如"35 release × 50 task，无显著提升 + token/tool call 翻倍"）。
- 用 blockquote（`> …`）包裹。

---

## 6. 锚点规范

- 锚点精确到论文**原生 §**（如 `§4 RQ0 Findings`、`§6 Discussion`），与论文自身的章节编号一致。
- 多锚点用 `; ` 分隔，格式：`Abstract; §1 Introduction; §4 RQ0`。
- **禁止**"见原文""相关章节"这类无定位表述。
- 锚点与 KB 自身解析的 `section_path` 是**双轨**：摘要锚点指论文原生 §，KB 下钻走自身 `section_path`，二者经**章节标题匹配**对齐（arXiv 论文 §标题通常一致）；对齐失败时锚点降级为"文档级可下钻提示"。

---

## 7. 质量红线（审核时必须逐条勾选）

| # | 红线 |
|---|---|
| 1 | 一句话索引独立可读，含结论 + 关键数字 |
| 2 | 锚点精确到 §，无"见原文" |
| 3 | "达到的效果"数值来自原文，不外推 |
| 4 | 头部字段与 manifest 台账一致（尤其 `arxiv_id`/`version`/`source_pdf`） |
| 5 | 文件名符合 §3（序号与 PDF 一致、中文主词、无版本号、无空格） |
| 6 | 五段结构齐全且顺序正确 |
| 7 | 一句话索引 token 数落在 100–200 区间 |

---

## 8. 生成与维护流程

1. **生成**：Agent 依据 PDF 全文 + manifest 台账生成摘要，按本规范套用 frontmatter + 五段结构。
2. **审核**：研究者按 §7 红线逐条勾选；不达标的退回重生成。
3. **入库**：写入 `references/<topic>/summaries/<NN>[-letter]-<中文短标题>.md`；更新该主题 `INDEX.md`（§9）。
4. **版本变更**：源 PDF 升级（v1→v2）时——
   - 更新 `source_pdf`、`arxiv_version`（`arxiv_id` 不变）；
   - 重生成受版本影响的 §3 效果表（数字可能变化）；
   - `summary_version` 递增；
   - 其余段落仅在必要时更新。
   - KB 侧由 sha256 指纹检测到 PDF 变更后将摘要标 `stale`，直到上述更新完成（详见 05 §2.6）。

---

## 9. `INDEX.md` 规范

每主题一个 `INDEX.md`，结构固定：

```markdown
# <主题> 主题论文摘要索引

> 主题：<一句话定位>
> 文件数：N
> 生成日期：YYYY-MM-DD

## 论文列表

| # | 摘要文件 | 原论文标题 | 一句话定位 |
|---|---|---|---|

## 推荐先读

- <场景>：NN → NN → NN

## 与 GraphIt-KB 的相关性

- <1–3 条>
```

约束：`论文列表` 的 `#` 列与摘要文件名的 `NN[-letter]` 前缀一致；新增/删除摘要后同步更新 `文件数`。

## 11. 校验清单（给生成器/审核器）

- [ ] 文件名：`NN[-letter]-中文短标题.md`，`NN` 与源 PDF 一致，无 `_vN`、无空格
- [ ] frontmatter：`title/source_pdf/arxiv_id/arxiv_version/authors/year/venue/type/generated_at` 全填，且与 manifest 对齐
- [ ] 五段：`## 1 适用场景` → `## 2 主要观点` → `## 3 达到的效果` → `## 4 参考资源` → `## 5 一句话索引`，顺序固定
- [ ] 锚点：精确到 §，无"见原文"
- [ ] 效果表：三列 `度量|结果|锚点`，数值来自原文
- [ ] 一句话索引：100–200 token，独立可读，含结论+数字
- [ ] arXiv 链接：论文类必填
- [ ] 更新对应主题 `INDEX.md`
