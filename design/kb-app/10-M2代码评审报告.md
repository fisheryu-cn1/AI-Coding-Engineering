## P0 — 阻塞性缺陷（均已实机复现）

### P0-1 移动文件在同轮 scan 中被删除检测墓碑化

`cli/index.py:184-186`（Pass 2）先取 `registered` 全表快照，Pass 3 的 `apply_moved`（`core/files.py:181-205`）已把 path 改为新路径，但 Pass 4 `detect_deleted`（`index.py:255-258` + `files.py:114-124`）仍用**旧快照**比对——旧 path 不在盘上 → 同一 doc_id 随即被 `apply_deleted` 覆盖为 `status='deleted'`。

实机复现（references/a.txt → research/a.txt）：

```
scan1:  [('D0001', '.../references/a.txt', 'new', '0bdc6b')]
移动后: [('D0001', '', 'deleted', '')]
再扫:   [('D0001', '', 'deleted', ''), ('D0002', '.../research/a.txt', 'new', '0bdc6b')]
```

后果：09 §2"移动保留 doc_id、零重抽取"端到端完全失效——doc_id 被墓碑化后，sha256 被清空导致下轮 scan 对新路径重新分配新号（D0002）并重新入队解析。既有单测只覆盖 `decide_action` 纯函数，无 scan 级移动用例，故门禁未捕获。修复方向：删除检测改用事务内现读（或 Pass 3 后刷新快照），并补 scan 级移动/删除 e2e 用例。

### P0-2 同轮删除两个文件即 UNIQUE 约束崩溃

`apply_deleted`（`core/files.py:208-219`）把墓碑行的 `path` 清空为 `""`，而 `files.path` 是 `NOT NULL UNIQUE`——同轮 scan 删除两个文件时第二行写入即 `IntegrityError: UNIQUE constraint failed: files.path`，退出码 1、事务回滚（已复现）。且清空 path/sha256 抹掉了 M5 软删衔接所需的行识别信息，与 09 §2"仅置 `status='deleted'` 墓碑"的要求相比属画蛇添足。修复方向：墓碑保留原 path/sha256（或 path 置 NULL 需先改 DDL；注意保留 path 后需防止下轮 scan 将其当"新增"重收——删除检测与新增判定要互斥已墓碑的 path）。

## P3 — 质量与文档项

1. Ctrl-C 重排队走 30s 标准退避，非 09 §10"立即可执行的 pending"（`runner.py:12` 自述；语义偏差小）。
2. `kb init` 对已存在 config 只打印"[跳过]"、无 diff 提示（09 §11 要求"跳过并提示 diff"）；新增 `--force` 为设计外未登记入口，与"不覆盖任何既有文件"字面冲突。
3. `files.pages`/`files.title` 全库无写入点（解析出了 page_count 却不落库，FR-1.5 的 pages 列成死列）；cache payload 不写 `page_count/header_count/coverage` 三键，缓存命中后 metrics 恒 None（`stages.py:108-110`）。
4. manifest 搜索沿每个文件的**所有祖先目录**找 `summaries/`（`index.py:343-352`），越出"各 corpus 下"的设计范围，可能绑定 corpus 外摘要。
5. `llm.fallback`（list）与 `classify.topic_keywords`（dict）经 `kb config set` 只能写入字符串（`_coerce_scalar` 对容器直通），09 §9"全部参数可修改"对这两个键实际不可用。
6. runner 把非 parse 任务直接标 done（`runner.py:108-121`）——会把 M3+ 入队的 summarize/extract 任务静默吞掉；建议改为跳过且不转移状态。
7. 09 §1 的 docling→python-docx 依赖变更只登记在 milestone-log，09/05 §1 未回写，设计文档与 pyproject 不一致（M1 fastmcp 教训的同类问题）。
8. **连接泄漏**：`stages.py` 全文 10+ 处 `ctx.registry.connect()` 内联调用且从不关闭（:63/:70/:82/:92/:120/:149/:207/:273/:323/:337）；其中 `stages.py:92` 还是一行"no-op for now"的死调用——开了连接什么都不做。进程级 CLI 下危害有限，但应改为 `with registry.read_only() as conn:` 或复用单连接。
9. CLI 启动时 litellm 尝试拉取远端 cost map 超时警告（实机复现日志可见），离线环境下每次命令都有噪音；建议初始化时禁远程拉取（`LITELLM_LOCAL_MODEL_COST_MAP` 或等价配置）。
10. 09 §9 文本自相矛盾："4 轮退避、序列 1s→2s→4s→8s"——4 次尝试只睡 3 次（1/2/4s），8s 不可达；设计文本应改为"1s→2s→4s"。
