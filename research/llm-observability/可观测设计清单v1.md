# 可观测设计清单 v1（D3-S1 定稿）

> 日期：2026-08-17（P1 产出）
> 话题标签：[D3]（[D2+D3]：第 5 节质量面实体承接中间产物规范）
> 依据：`materials/llm系统可观测性调研.md`（OTel GenAI/OpenInference 规范、8 平台、judge 信度实证）、pi/DSH 框架机制（本地）、kb-app 案例的"登记≠执行"教训
> 用法：**构建前**过一遍第 1–5 节检查表（观测点预埋在边界，避免"事后补观测"）；第 6 节为场景一实施记录的登记模板。

---

## 1. 五层观测点检查表（预埋位置）

| 层 | 观测对象 | 标准承载 | 预埋位置 | ✓ |
|---|---|---|---|---|
| L1 agent 循环 | 计划/推理步骤、轮次、子 agent 委派 | OTel `invoke_agent` 父 span；OpenInference `AGENT` | agent 循环入口（SDK 包装层） | ☐ |
| L2 provider 边界 | 模型名、token、finish reason、延迟 | `chat` span + `gen_ai.*`；指标 `gen_ai.client.operation.duration` / `token.usage` | provider SDK 包装/网关（LiteLLM 式） | ☐ |
| L3 工具边界 | 工具名、参数、结果、异常（含 MCP） | `execute_tool` span（GenAI 仓库含 MCP 约定） | 工具注册/分发层 | ☐ |
| L4 会话/轨迹 | 多轮结构、用户/成本归因 | session/user 实体（Langfuse 式） | 会话管理器 | ☐ |
| L5 中间产物 | 送入上下文的文档/检索结果/工件 | OpenInference `Retriever`/document 属性；Weave objects 版本化 | 上下文组装点 | ☐ |

原则：观测点埋在**边界**（SDK/工具分发/组装点），不散落业务代码——自动 instrumentation 即此做法（33+ 框架支持）。

## 2. 日志契约决策卡（核心设计决策）

两端之间显式选择，并可分层组合：

| 端点 | 特征 | 适用 |
|---|---|---|
| **全量落盘**（DSH："model-visible means logged"） | 复现/调试/评估依赖真实上下文；本地存储+治理 | 实验、研究、评测集生产 |
| **元数据默认 + opt-in 内容**（OTel 默认） | 内容捕获是主要开销与风险源；默认只发元数据 | 生产导出、跨环境传输 |

**推荐组合（分层可见性）**：本地全量落盘 → 导出边界脱敏 → 访问分级。证据：HarnessFix 证明"轨迹可落盘可结构化"直接产生迭代价值（回归验证的修复，+6.3%–18.4%）；OTel 的敏感数据指南 + Collector redaction processor 提供标准治理抓手。

## 3. 采样与开销

- ☐ 尾部采样：失败/超时/高成本轨迹全量保留，正常轨迹低比例采样（头部/尾部采样直接迁移）；
- ☐ 选择性 judge：在线信号 + 语义接地指标先筛，再对可疑段做 LLM 评估（failure-aware 实证：大量 token 浪费在早预警之后——观测应能触发提前干预）；
- ☐ 观测自身开销登记：采集/judge 成本进入运行报告（"观测的观测"）。

## 4. 隐私与数据治理

三段管道（缺一不可）：☐ 应用内（导出前 wrapper 字段级 mask，OpenInference 要求）→ ☐ Collector（集中 redaction processor）→ ☐ 存储（加密 + 访问控制 + 保留期）。本地全量契约的前提是本地存储有访问治理。

## 5. 质量面实体（运行面之外的本方向增量）

运行面（延迟/token/成本/异常）复用三支柱，**不重建**；质量面按下表新增第一类实体：

| 实体 | 承载 | 说明 |
|---|---|---|
| 评分（scores） | 独立实体（numeric/boolean/categorical，Langfuse 式）或 OpenInference `EVALUATOR` span | 任务成功率、幻觉率、评分 |
| 在线质量代理 | 接管率/修正率/追问率（自研口径） | fail-plausible 只能靠用户侧信号暴露（8 周生产纵向研究）；区分"接管=质量差"与"接管=谨慎"需结合上下文 |
| 门禁语义 | promptfoo 式 CI 阈值阻断 | harness/prompt 变更触发（通用 CI 检不出） |

**judge 信度协议**（门禁可信的前提）：rubric 化 + 交换平均 + 多 judge 共识 + 人工对齐抽样 + judge 版本固化（换 judge 模型=换尺子，纳入回归门禁）。

## 6. 场景一实施记录模板

```
实施对象 / 日期
观测点落地：L1..L5 各一行（位置 + span 命名 + 采样策略）
日志契约选择：本地__ / 导出__ / 治理__
质量实体：scores__ / 在线代理__ / 门禁__
首次数据：轨迹数 / 评分条数 / 发现的问题
成本：采集与 judge 开销占比
```
