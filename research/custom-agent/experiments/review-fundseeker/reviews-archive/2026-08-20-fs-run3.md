### [P1] src/fundseeker/similarity/persistence.py::save_cluster_run / save_attribution — 写路径 delete-then-insert 在多写者下未隔离
- 类型：实现偏离（F1 修补 cron 重入后，本段持久层缺口仍存在；与 §7.2 "避免并发"的隐含单写者假设不符）
- 溯源：`src/fundseeker/similarity/persistence.py:39-119`（save_cluster_run），`src/fundseeker/similarity/persistence.py:178-217`（save_attribution）；`src/fundseeker/models/tables.py:583-595, 711-715`（UNIQUE 约束）
- 证据：
  - `save_cluster_run` 在 `with Session() as session:` 中先 `select` prior_runs，再逐条 `session.delete(run)`，然后 add 新 run；新 run 的 UNIQUE 键 `(report_date, algorithm, k, product_type_filter, created_at)` 含 `created_at`，故两个写者大概率都能插入成功但产生两套同语义 run
  - `save_attribution` delete filter 缺 `benchmark_code is None` 路径处理（仅在表达式中三元化），高并发下可能退化为 over-fetch delete；UNIQUE `(product_id, cluster_run_id, start_date, end_date, benchmark_type)` 在 `cluster_run_id` 相同时，两个写者互相覆盖
- 维度：RR-6（写路径并发）；RR-5（幂等性：同一逻辑 run 跑两次产生重复记录而非一处真相）
- 建议：将 key 升级为含 `created_at` 或 `pipeline_run_id` 的版本键；在 `save_cluster_run` / `save_attribution` 入口持有 `pg_advisory_xact_lock`；或迁移至"append-only + 当前指针"模式
