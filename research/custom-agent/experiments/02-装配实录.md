关键发现——**错误排除（false acquittal）**：R-3（RELATES_TO MERGE 不含 kind）与 R-4（sync 无条件写 valid_to）在意见卡"未发现问题的检查项"中被**主动排除**且理由有误（把 MERGE 行为当作与测试一致——而测试本身断言的就是缺陷行为）。这解释了启发式 82% 与语义 18% 的巨大差距：**关键词命中大量来自排除性表述**。教训双条：①评分器需区分"命中于意见"与"命中于排除"；②RR-4 的检查方法必须机械化（枚举 valid_to/MERGE 的全部写入点逐点核对，而非依赖阅读判断）。

评分器两处修正（v0→v1）：中文短语不可作关键词（整句成单 token 永不命中）；跨锚点案例须过滤（F/N 系列在 f62f287 已修复，计入分母是误罚）。

### 8.5 配对方法讨论备忘（2026-08-19，研究者两轮提问）

**问题**：自动配对能否引入大模型语义判定？如何解决长列表下判断标准漂移？产出端能否用格式约束降低匹配难度？

**结论（三层结构 + 两个前提）**：

1. **大模型语义配对可行，但定位为第二层而非替代**——机械配对（确定性、可复算）保持为引用数字的口径层；大模型处理其留下的人工核验清单（灰区意见），输出配对建议 + 一句话理由；人工终审确认，确认结果回流为裁判校准数据。
2. **长列表漂移的解法是按文件（→函数）分段，而非按条目数切段**：文件是两次评审天然共享的对齐键，分段后组内条目 1–5 条、判断稳定，且任务恰好收窄到机械最薄弱处（同文件多缺陷的语义区分——§8.1 错配问题的根源）。边角：跨文件宽意见需归属策略（主文件组 + 全局去重）；无文件意见单独成段。
3. **产出端格式约束三条（按杠杆排序）**：①溯源行必须列出缺陷涉及的**全部**对象文件（直接修复 §8.2 发现的 R-4/F-1 型签名盲区——意见溯源不列案例文件）；②标题约定"文件::函数前缀 + 缺陷一句话"（机械匹配获得强信号）；③排序规范化在**解析端**做（意见卡保持级别排序供人读，评分器解析后按文件→函数→行号重排）——生产端不加负担。
4. **风险结构**：pass^k 只在同 skill 版本内计算 ⇒ 同版本即同格式契约 ⇒ 格式化匹配恰好用在最需要稳定性的场景；大模型裁判的模型与提示词版本须冻结登记（分段解决判断质量，不解决版本漂移）；裁判上线前须用 run7×run8 人工配对真值校准（"机械 vs 大模型 vs 人工"三方对照本身是 notes/07 实验族的新样例）。

**落地序列**（并入批次 3 或紧随其后的独立小实验）：模板 v5 契约升级（①②）→ 评分器文件分组模式 → 组内大模型判定（理由输出）→ 人工终审 + 真值校准。
