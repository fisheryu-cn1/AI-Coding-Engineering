| 人工语义审计（宽松，部分命中计 0.5） | **2/11 ≈ 18%**（+R-2 web 半面、R-10 coalesce 半面） | |
| 未命中 | R-3、R-4、R-5、R-7(CLI 面)、R-8、R-12、R-13 | 2 条前端类（R-5/R-13）+ 2 条**错误排除** + 3 条未显式表达 |

关键发现——**错误排除（false acquittal）**：R-3（RELATES_TO MERGE 不含 kind）与 R-4（sync 无条件写 valid_to）在意见卡"未发现问题的检查项"中被**主动排除**且理由有误（把 MERGE 行为当作与测试一致——而测试本身断言的就是缺陷行为）。这解释了启发式 82% 与语义 18% 的巨大差距：**关键词命中大量来自排除性表述**。教训双条：①评分器需区分"命中于意见"与"命中于排除"；②RR-4 的检查方法必须机械化（枚举 valid_to/MERGE 的全部写入点逐点核对，而非依赖阅读判断）。

评分器两处修正（v0→v1）：中文短语不可作关键词（整句成单 token 永不命中）；跨锚点案例须过滤（F/N 系列在 f62f287 已修复，计入分母是误罚）。

## 2.4 第 3 场迭代输入（错误分析 → skill 修订）

1. **RR-4 机械化**：检查方法改为程序式——grep 全部 `valid_to` 写入点与全部 `MERGE` 模式，逐点核对四项（属性保留/读过滤/合并键/复活），把核对清单写进意见卡（使"未发现"可验证）；
2. **前端维度补充**：R-5/R-13 类检查项（HTML 声明的交互是否实现、图表库配置完整性）进入 checklist（当前八维度偏后端）；
3. **"未发现"表述约束**：须列出实际核对过的写入点/查询点清单，而非概括性结论（R9 登记真实性在 skill 内的自应用）；
4. run2/run3 同锚点复跑 → pass^k；意见卡头补登记 session id（观测关联，本轮遗漏）。
