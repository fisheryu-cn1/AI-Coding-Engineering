## 2. 关键决策与卡点

1. **skill 即规范执行者**：评审维度 checklist 直接嵌入 R8/R9/R11/R13 与 kb-app 评审惯例（幂等/并发/防御性）——画像附加问的设计落地，"评审 agent = 中间产物规范的执行者"首次实例化。
2. **守卫扩展的诚实降级**：pi 扩展事件负载字段名按调研材料推断（toolCall/name/arguments 多候选），未找到阻止 API 时**告警而非静默**——v0 风险登记进工作区 README，首次运行校准（R11 精神：登记真实性）。
3. **评估集锚点选择**：案例锚定"修复提交的父状态"（缺陷尚在）；`git 历史`可重现。**舍弃记录**（evals/README）：M2–M4 及其修复被压缩进单个提交 `e7c9aa9`，10/12 号报告的缺陷状态在历史中不存在——**教训：里程碑提交应保留缺陷→修复的中间态（或 squash 前导出快照），否则回溯式评估语料不可重建**；非代码类（R-6）、未修复类（R-9/O 系）、不可从代码观察类（N-2）共舍弃若干。
4. **评分器 v0 定位**：关键词启发式（严格口径=全部关键词命中；溯源文件命中=半命中信号）——语义召回留待 judge（按可观测清单 §5 信度协议）。
5. **流程 v1 使用发现**：②能力清单与③组件选配在轻场景下界限模糊（能力即组件映射表）——v2 可合并为一步并保留"知识三段登记"子检查。
6. **变更登记（2026-08-17 修订，R9 自应用）**：初版 SKILL.md 的维度 checklist 以"规则来源"列引用项目内部路径（R8/R9/R11/R13、kb-app 评审惯例），导致 skill 与本项目强关联、脱离项目后规则不可访问、不具分发完整性。**修订**：按 Agent Skills 规范把规则内容摘录为自包含文档 `assets/review-rules.md`（RR-1~RR-7，含检查方法与反例信号，文件头仅保留一行来源追溯）、意见卡模板外移 `assets/opinion-card-template.md`；SKILL.md 改为相对引用（RR 编号 + assets 路径），并把仓库特定表述泛化（"任意仓库的 AGENTS.md/README"）。**教训**：面向分发的 skill 中，项目内知识必须摘录进 assets 而非引用路径——"引用完整性"应作为 skill 编写的默认红线（已体现为组件目录 F-通用档位的隐含要求，v2 补为显式判据）。
