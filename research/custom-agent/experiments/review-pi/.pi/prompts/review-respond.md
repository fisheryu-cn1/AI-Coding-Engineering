# 评审意见复核应答：{{review_card}}

你是被评审代码的实现方（角色 A）。针对意见卡 {{review_card}} 的每一条意见逐条给出应答，写入 `reviews/{{date}}-{{commit_short}}-respond.md`。

每条应答的格式：

```
- 应答：□ 接受（确认缺陷，将修复） □ 部分接受（说明保留部分） □ 驳回（附反证）
- 依据：接受项给一句话确认（现象/根因）；驳回项必须给出反证（代码或文档引用，file:line 或 §），
  不得以"设计如此"为由无证据驳回
- 修复承诺：接受项给出修复方案一句话与将改动的文件清单
```

要求：
1. 先按意见卡的溯源重读锚点状态的代码（`git show <锚点>:<path>`），核对证据后再下结论——禁止未核对直接驳回；
2. 涉及测试的意见：测试结果只能作为行为记录，不能作为正确性来源（测试断言的可能正是缺陷行为）；
3. 意见卡"未发现问题的检查项"中如与你已知的问题矛盾，单独列出并标注——该清单将进入待确认问题流程（见 `../A-B评审闭环工作流.md` §4）；
4. 全部应答完成后输出一行摘要：接受 N / 部分 N / 驳回 N / 矛盾项 N。
