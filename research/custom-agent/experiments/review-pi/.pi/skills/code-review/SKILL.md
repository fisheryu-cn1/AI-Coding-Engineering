# 代码评审 SOP（code-review）

## 适用范围

- 评审对象：任意仓库的 git diff（PR 或 commit）或指定文件快照。
- 输出：写入 `reviews/<日期>-<目标>.md` 的意见卡（唯一允许的写位置），格式见 `assets/opinion-card-template.md`。
- 不做：自动修复代码、阻塞合并（人工裁决）；不修改被评审代码。

## 评审流程（五步）

1. **读取变更**：`git show <commit>` / `git diff <base>..<head>` 获取 diff；先建立变更地图（文件 × 改动类型：新增/修改/删除/移动）。
2. **收集上下文**：读被评审仓库的 AGENTS.md/README 与相关设计/规范文档（如该仓库有此惯例）；读被改文件的完整上下文（不只看 diff hunk）；判断该变更属于哪个功能域/契约域。
3. **逐维度检查**（下表）；涉及 RR 规则的先读 `assets/review-rules.md` 对应条目的"检查方法"再查代码；每发现一个问题，立即记录 file:line 与证据片段。
4. **生成意见卡**：按 `assets/opinion-card-template.md` 输出到 `reviews/`；每条意见必须含【溯源】【证据】【维度/规则】【建议】【分级】。
5. **自检**：过一遍红线清单后再写文件。

## 评审维度 checklist

| 维度 | 检查问 | 依据 |
|---|---|---|
| 正确性 | 变更是否引入行为错误（边界条件、None/空集、异常路径）？ | 通用 |
| 状态生命周期 | 软删除/墓碑：属性保留？读路径过滤？合并键完整？不可复活？ | RR-4 |
| 契约一致性 | 实现与设计文档的 DDL/接口签名/错误结构是否同形？错误结构字段完整？ | RR-1 |
| 变更登记 | 实现是否塌缩/偏离了设计而未登记？依赖变更是否回写？ | RR-2 |
| 登记真实性 | 测试/DoD 声称的通过是否真实（同形断言、执行证据、环境口径）？ | RR-3 / RR-1 |
| 幂等与重放 | 重跑/重放路径是否幂等（先删后插/完整键 merge/队列去重）？ | RR-5 |
| 并发与锁 | 写路径持锁是否正确且异常路径释放；读路径无需锁的依据？ | RR-6 |
| 防御性 | 外部输入（LLM 输出/文件名/用户参数/网络响应）有上界、消毒、兜底三件套？ | RR-7 |

> RR-1～RR-7 的规则内容、检查方法与反例信号见 **`assets/review-rules.md`**（随 skill 分发的独立规则文档，摘录自真实多轮评审实践，版本见其文件头）。

## 红线（违反任一条的意见卡无效）

1. 每条意见必须带 file:line 或文档 § 溯源——**禁止无证据泛泛而谈**；
2. 证据片段必须来自实际读取的代码/文档，不得凭变更主题推测；
3. 分级只依据"错误成本 × 确定性"（口径见 `assets/opinion-card-template.md` 分级表）；
4. 只写 `reviews/` 目录；不执行任何修改被评审代码的操作；
5. "未发现问题的检查项"必须如实列出（这是召回复核的依据，也是诚实性要求）。

## 分发说明

本 skill 自包含：SKILL.md（本文件）+ `assets/review-rules.md`（规则集）+ `assets/opinion-card-template.md`（模板）。规则集与模板可独立演进（递增版本号登记在各自文件头），脱离来源项目可正常使用。
