# 评审规则摘录（review-rules）

> 版本：v2（2026-08-17 第 3 场修订：RR-4 检查方法机械化、新增 RR-8 前端与交互一致性）
> 来源说明：本文件规则摘录自一个本地知识库项目（GraphIt-KB）的多轮设计/代码评审与产物规范实践（原文见该项目 `design/kb-app/experiments/02-中间产物模板集v0.md` 的 R8/R9/R11/R13 及评审报告惯例）。**摘录内容自足，本 skill 分发不依赖对来源项目的访问**；来源仅作追溯。
> **规则分层与适配提示**：本规则集为三层复合——框架层（SOP/红线/分级，任何项目可用）、领域先验层（RR-4 适用于任何含软删除的系统、RR-7 适用于任何消费 LLM/外部输入的系统、RR-5/6 适用于任何有状态流水线）、项目实例层（来源项目技术栈特有条目）。**应用于其他项目时**：保留框架层、按域选用先验层子集，并建议从**目标项目自身的缺陷史**（评审报告/issue/修复提交）挖掘增补项目实例层规则，同时更新本来源说明。
> 用法：SKILL.md 的维度 checklist 以 RR 编号引用本文件；逐条检查时按下述"检查方法"执行。

---

## RR-1 契约形状同断言（防弱断言）

- **规则**：接口/工具/错误结构的每一个契约面（字段、错误码、结构形状）在消费方测试中必须有**同形断言**——只断言状态码而不断言结构形状的测试视为弱断言。
- **检查方法**：找到被改契约的调用方测试；确认断言覆盖完整结构（如错误对象的三键 `{code, message, suggestion}` 逐一断言，而非只断 code）。
- **反例信号**：`assert resp["code"] == X` 之后直接结束；契约新增字段而测试未更新。

## RR-2 变更登记（防静默偏离）

- **规则**：实现若塌缩、简化或偏离了设计文档（含"设计写了但实现没做"），必须回写上游文档并登记；依赖版本变更同理。
- **检查方法**：对照 diff 涉及模块的设计文档章节；发现行为与文档不一致时，检查是否有变更登记/回写记录。
- **反例信号**：设计说三级判定、代码只有两级且无注释；依赖升级未在锁定文件与文档同步体现。

## RR-3 登记真实性（防虚报）

- **规则**：任何"已完成/已通过"的登记（DoD、里程碑日志、验收清单）必须附带**执行证据**（测试输出、截图、日志）与**环境口径**（语言/库/OS 版本）；未执行不得标记通过。
- **检查方法**：抽查登记项对应的证据产物是否存在、时间戳是否合理；测试数与登记数是否对得上。
- **反例信号**："全部通过"但 CI 无对应运行记录；登记的测试数与实际收集到的测试数不符。

## RR-4 状态生命周期（软删除/墓碑系统四查）——**检查程序机械化（v2）**

- **规则**：凡含软删除/墓碑/valid_to 机制的系统，四项必查：
  1. **属性保留**：置墓碑时不得把节点的其他属性清空/覆盖丢失；
  2. **读路径过滤**：全部读路径（列表/检索/图遍历/聚合/侧栏/API/CLI）都必须过滤墓碑；
  3. **合并键完整**：MERGE/UPSERT 的键必须含全部区分性维度（如边类型 kind），否则异构记录互相覆盖；
  4. **不可复活**：墓碑状态不可被后续写入（重放/重建/再同步）意外复活或标记被覆写。
- **检查程序（必须按序执行并留痕，概括性结论无效）**：
  1. **枚举写入点**：检索变更涉及模块中对软删除标记字段（valid_to / deleted / is_deleted 等）的**每一处写入**，抄录清单（文件:行 + 写入的值来源）；
  2. **枚举合并点**：检索全部 MERGE/UPSERT 语句，**抄录完整键清单**——逐条判断键是否含全部区分维度（对照该实体/边的 schema 定义）；
  3. **枚举读路径**：检索消费该标记的全部查询（MATCH/WHERE/SELECT/过滤函数），列出哪些带过滤、哪些不带；
  4. **逐点四问**：对上述三个清单逐点回答规则四项；任一点不确定即降级为意见（"未能排除"）而非"未发现"；
  5. **清单入卡**：三个清单与逐点结论写入意见卡"未发现问题的检查项"——没有清单的"未发现"视为未检查。
- **反例信号**：`row.get(k, "")` 类"缺失补默认值 + 整行 SET"组合；MERGE 模式省略区分键；同步任务无条件写标记字段；"与测试一致"但测试本身断言的是缺陷行为（**测试不能作为正确性来源，只能作为行为记录**）。

## RR-5 幂等与重放（评审惯例）

- **规则**：任务重放/重复执行必须幂等：写入采用"先删后插"或带完整键的 merge；队列去重；同输入重复运行结果一致。
- **检查方法**：对 diff 中新增的写路径，追问"同一任务跑两次会怎样"；检查删除范围是否精确到键。
- **反例信号**：追加式写入无唯一键；重跑导致重复记录或约束冲突。

## RR-6 并发与锁（评审惯例）

- **规则**：写路径明确持锁范围与释放路径（含异常路径回收、stale 锁检测）；读路径确认无需锁的依据；单写者假设要显式声明。
- **检查方法**：找到锁的获取/释放对；异常路径是否泄漏；新读路径是否绕过单写者约定。
- **反例信号**：锁获取后早退 return 无释放；进程崩溃后锁残留无兜底。

## RR-7 外部输入防御性（评审惯例）

- **规则**：外部输入（LLM 输出、文件名、用户参数、网络响应）必须有**上界**（长度/数量预算）、**消毒**（引号/注入/非法字符）、**兜底**（解析失败降级路径）三件套。
- **检查方法**：找 diff 中新增的外部输入消费点，逐点核对三件套；LLM 输出是否清洗控制标记、是否有 max_tokens 预算考量。
- **反例信号**：外部字符串直接拼进查询/命令；LLM 返回直接入库无长度限制；超长输入导致静默空响应。

## RR-8 前端与交互一致性（v2 新增）

- **规则**：UI 声明与实现一致——HTML/模板/文档宣称的交互行为（拖拽、框选、缩放、高亮）必须有对应事件绑定与处理器；可视化库初始化的必需配置（布局、容器尺寸、数据映射）完整；静态资源引用（脚本/样式/数据路径）可达。
- **检查方法（机械化）**：
  1. 对每个 UI 声明点（注释/文档/头注自称的交互），检索对应事件监听器/处理器是否存在；
  2. 对每个可视化初始化（如 `new Graph({...})`），对照库的必需配置项核对是否缺失；
  3. 对 HTML 中每个 `src`/`href` 引用，核对该文件在变更树中存在；
  4. 声明-实现对照清单写入意见卡"未发现"节。
- **反例信号**：头注自称支持 drag/zoom 但无 pointer/wheel 事件绑定；`new Graph` 未配置 layout 导致渲染异常；`<script src>` 引用不存在的文件（页面静默失败）。
