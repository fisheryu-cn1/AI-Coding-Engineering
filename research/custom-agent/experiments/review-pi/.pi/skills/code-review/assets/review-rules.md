# 评审规则摘录（review-rules）

> 版本：v2026-08-17 摘录
> 来源说明：本文件规则摘录自一个本地知识库项目（GraphIt-KB）的多轮设计/代码评审与产物规范实践（原文见该项目 `design/kb-app/experiments/02-中间产物模板集v0.md` 的 R8/R9/R11/R13 及评审报告惯例）。**摘录内容自足，本 skill 分发不依赖对来源项目的访问**；来源仅作追溯。
> 用法：SKILL.md 的维度 checklist 以 RR 编号引用本文件；逐条检查时按下述"检查方法"执行。

---

## RR-1 契约形状同断言（防弱断言）

- **规则**：接口/工具/错误结构的每一个契约面（字段、错误码、结构形状）在消费方测试中必须有**同形断言**——只断言状态码而不断言结构形状的测试视为弱断言。
- **检查方法**：找到被改契约的调用方测试；确认断言覆盖完整结构（如错误对象的三键 `{code, message, suggestion}` 逐一断言，而非只断 code）。
- **反例信号**：`assert resp["code"] == X` 之后直接结束；契约新增字段而测试未更新。

## RR-2 变更登记（防静默偏离）

- **规则**：实现若塌缩、简化或偏离了设计文档（含"设计写了但实现没做"），必须回写上游文档并登记；依赖版本变更同理。
- **检查方法**：对照 diff 涉及模块的设计文档章节；发现行为与文档不一致时，检查是否有变更登记/回写记录。
- **反例信号**：设计说三级判定、代码只有两级且无注释；依赖升级未在锁定文件与文档同步体现。

## RR-3 登记真实性（防虚报）

- **规则**：任何"已完成/已通过"的登记（DoD、里程碑日志、验收清单）必须附带**执行证据**（测试输出、截图、日志）与**环境口径**（语言/库/OS 版本）；未执行不得标记通过。
- **检查方法**：抽查登记项对应的证据产物是否存在、时间戳是否合理；测试数与登记数是否对得上。
- **反例信号**："全部通过"但 CI 无对应运行记录；登记的测试数与实际收集到的测试数不符。

## RR-4 状态生命周期（软删除/墓碑系统四查）

- **规则**：凡含软删除/墓碑/valid_to 机制的系统，四项必查：
  1. **属性保留**：置墓碑时不得把节点的其他属性清空/覆盖丢失；
  2. **读路径过滤**：全部读路径（列表/检索/图遍历/聚合/侧栏）都必须过滤墓碑；
  3. **合并键完整**：MERGE/UPSERT 的键必须含区分性维度（如边类型 kind），否则异构记录互相覆盖；
  4. **不可复活**：墓碑状态不可被后续写入意外复活（重放/去重路径尤其注意）。
- **检查方法**：grep 墓碑/valid_to 的写入点与全部读取点，逐点核对四项。
- **反例信号**：`SET n += {}` 式全覆盖写；MERGE 模式省略区分键；重放任务按旧快照重建。

## RR-5 幂等与重放（评审惯例）

- **规则**：任务重放/重复执行必须幂等：写入采用"先删后插"或带完整键的 merge；队列去重；同输入重复运行结果一致。
- **检查方法**：对 diff 中新增的写路径，追问"同一任务跑两次会怎样"；检查删除范围是否精确到键。
- **反例信号**：追加式写入无唯一键；重跑导致重复记录或约束冲突。

## RR-6 并发与锁（评审惯例）

- **规则**：写路径明确持锁范围与释放路径（含异常路径回收、stale 锁检测）；读路径确认无需锁的依据；单写者假设要显式声明。
- **检查方法**：找到锁的获取/释放对；异常路径是否泄漏；新读路径是否绕过单写者约定。
- **反例信号**：锁获取后早退 return 无释放；进程崩溃后锁残留无兜底。

## RR-7 外部输入防御性（评审惯例）

- **规则**：外部输入（LLM 输出、文件名、用户参数、网络响应）必须有**上界**（长度/数量预算）、**消毒**（引号/注入/非法字符）、**兜底**（解析失败降级路径）三件套。
- **检查方法**：找 diff 中新增的外部输入消费点，逐点核对三件套；LLM 输出是否清洗控制标记、是否有 max_tokens 预算考量。
- **反例信号**：外部字符串直接拼进查询/命令；LLM 返回直接入库无长度限制；超长输入导致静默空响应。
