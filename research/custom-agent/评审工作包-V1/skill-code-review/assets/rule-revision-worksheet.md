# 规则修订工作单（新案例 → 规则变更的受控流程）

> 版本：v1（skill v5 新增；修订史见 `../CHANGELOG.md`）
> 目的：把"从案例学习"变成受控流程——在**拟合**（案例触发的规则改进真实提升召回）与**过拟合**（规则只记住来源项目的具体写法，迁移到其他项目即失效或误报）之间取得平衡。每条规则修订（新增/修改/拆分/收窄）须填写一份本工作单。
> 适用触发：评估未命中分析 / 潜在新发现回流 / 确认误报后的原因分析 / 人工复核发现规则缺口。
> 衔接：未复现期望缺陷但发现同类问题时，先走"待确认问题"人工归类流程（P2 阶段评审决策清单 B1，四种情况归类）；归为"本轮漏检（评审能力缺口）"或"误检且归因规则过宽"的才进入本工作单，其余情况各有去处——防止用规则修订掩盖标注或流程问题。

## 1. 工作单字段（复制填写）

```markdown
# 规则修订工作单：<一句话标题>
- 日期 / 提出人（agent 或人工）
- 触发案例：<案例号或新发现编号、锚点、缺陷一句话>
- 触发类型：□ 评估未命中 □ 新发现回流 □ 确认误报 □ 人工复核缺口
- 根因归类（单选）：
  - □ R1 规则缺失（无规则覆盖该缺陷形态）
  - □ R2 规则存在但检查方法不可操作（未能引导发现）
  - □ R3 前置谓词误排除（适用场景被"适用性判定"排除）
  - □ R4 规则过宽（把合理代码判为缺陷——误报路径）
  - □ R5 非规则问题（模型能力/上下文/流程——不修规则，转出记录）
- 拟订修订：<新增/修改/拆分/收窄哪条规则；修订条文草案>
- 泛化检验（全部通过才可合入）：
  - Q1 抽象层归位：条文属于 □ 框架层（任何代码评审可用）□ 领域先验层（写明领域条件，如"含软删除的系统"）□ 项目实例层（仅来源项目）。**项目实例层不入随 skill 分发的规则集**，登记到目标项目自身资产。
  - Q2 表述检验：条文是否不含来源项目专有名词（文件名/模块名/特定库名）？含 → 改写为抽象形态，或降入实例层。
  - Q3 双向反例检验：
    - Q3a 过宽：能否构造"符合条文但并非缺陷"的合理代码场景？能 → 条文过宽，收窄表述或补前置谓词后重过。
    - Q3b 过窄：触发缺陷的等价形态（换写法/换模块/换技术栈）是否仍符合条文？否 → 条文过窄，抽象化后重过。
- 留出保护：修订依据是否来自留出项目（当前为 fundseeker）？**是 → 禁止合入**（其 P3 冷启动完成前），登记待办。
- 溯源标注：□ 先验 □ 案例渗入（案例号：__）——回流案例触发的必须标案例渗入。
- 验证要求：① 触发锚点复测命中（回归）；② 至少一个其他锚点复测无误报（泛化抽样）；pass^k 只在同规则版本内计算。
- 变更登记：CHANGELOG 记一行；review-rules.md 版本号递增。
```

## 2. 使用要点

- **一份修订一份单**：耦合的多条修订可合并为一份单，但每条修订条文单独过 Q1–Q3。
- **R5 转出**：非规则问题不修改规则集——记录到轨迹报告，防止"用规则修补模型能力问题"造成规则膨胀。
- **回流案例双登记**：新发现回流评估集（cases.jsonl）与规则修订是两个动作、各自登记——评估集的 expected_finding 按人工复核口径撰写；工作单的溯源标注写案例渗入。
- **误报路径**（R4）：误报确认后先做误报原因分析（B1 流程要求），归因到规则过宽才走 Q3a 收窄——防止规则把来源项目的写法习惯当成普适要求。

## 3. 过拟合三形态与检验的对应关系

| 过拟合形态 | 表现 | 检验 |
|---|---|---|
| 规则绑死来源项目 | 迁移到新项目即失效 | Q1 归层 + Q2 表述 |
| 规则只认触发案例的字面形态 | 同类缺陷换写法就漏检 | Q3b 过窄检验 |
| 规则把来源项目习惯当普适要求 | 新项目上产生误报 | Q3a 过宽检验 + R4 误报路径 |

留出验证（P3 fundseeker 冷启动）是本机制的整体校验：分发规则集在留出项目上的成绩即泛化成绩，其与来源项目成绩的差距 = 过拟合残余的度量。

## 4. 迭代停止条件（2026-08-20 补，B3 模板待补项落地）

何时从『机制验证』转入『迁移验证』（在全新项目上冷启动检验）——出现以下任一信号即停止在当前语料上的规则微迭代：

1. 修订开始针对单一案例的具体形态而非缺陷类别（起草条文时频繁出现语料专有名词的冲动）；
2. 复测通过率不再随修订显著提升（边际收益枯竭）；
3. 修订理由变为『再补一条更全』而非『某类漏检的机制性根因』；
4. 投入即将超过一次迁移验证（新项目冷启动一轮）的预期成本。

**样例（第 12 场，研究者裁定）**：源项目上连续第二轮修订（拟议的工作单 02）被叫停——规则细节已不具通用性、反复迭代偏离研究主目标。工作单的留出保护挡住了新语料泄漏，但没挡住源语料上的无限局部优化；违反停止条件的代价＝迭代消耗研究资源＋规则过拟合加深。
