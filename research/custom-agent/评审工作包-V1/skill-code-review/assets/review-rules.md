# 评审规则集（review-rules）

> 版本：v5（修订史见 `../CHANGELOG.md`）
> 来源说明：规则摘录自一个本地知识库项目（GraphIt-KB）的多轮设计/代码评审与产物规范实践。**内容自足，本 skill 分发不依赖对来源项目的访问**；来源仅作追溯。
> **清单完备性声明（元审查约定）**：机械化检查清单须注明枚举依据与版本，清单"未覆盖什么"显式声明——机械化把主观性移到清单编制层，清单自身的完备性是已知残余风险。
> **立项纪律（v5 新增，与 SKILL.md 红线第 6 条同文）**：检查清单中出现"缺/冲突/违规"判断的条目必须立项为意见（级别按错误成本定，可低不可无）或写明豁免理由——禁止降格为"标注即可"、以"同源/同因"并入其他意见、或以"取决于框架"搁置存疑项。
> **溯源标注（用于拟合/泛化区分）**：每条规则标注来源类型——`先验`（提炼自评审实践/通用工程知识）或 `案例渗入`（由评估案例的失败触发增补，标注案例号）。留出验证时据此区分两类规则的成绩。

---

## 使用第一步：适用性判定（前置谓词）

对每个评审范围先过此表，确认启用的规则子集（未满足谓词的规则不出现在意见与"未发现"清单中）：

| 规则 | 适用前置谓词 |
|---|---|
| RR-1 / RR-2 / RR-3 / RR-5 | 恒适用（过程级） |
| RR-7b / RR-7c | 消费外部系统输入 / 接受用户或运维输入（多数系统恒适用） |
| RR-8 | 变更涉及 UI / 前端资源 / 对外接口声明 |
| **RR-4** | 系统含软删除、墓碑或有效期标记（valid_to / deleted / is_deleted / TTL…） |
| **RR-6** | 存在共享可变状态或跨进程资源（写锁 / 队列 / 缓存 / 后台任务） |
| **RR-7a** | 消费 LLM 输出（生成 / 抽取 / 判断） |

## 通用层（恒适用或近恒适用）

### RR-1 契约形状同断言（防弱断言）｜溯源：先验
- **规则**：接口/工具/错误结构的每一个契约面在消费方测试中有**同形断言**——只断状态码不断结构形状的测试视为弱断言。
- **检查方法**：找被改契约的调用方测试，确认断言覆盖完整结构（如错误三键逐一断言）。
- **反例信号**：`assert resp["code"] == X` 即止；契约新增字段而测试未更新。

### RR-2 变更登记（防静默偏离）｜溯源：先验
- **规则**：实现塌缩/简化/偏离设计（含"设计有代码无"）必须回写上游并登记；依赖版本变更同理。
- **检查方法**：对照 diff 涉及模块的设计文档章节；不一致处查变更登记/回写记录。
- **反例信号**：设计三级判定、代码两级且无注释；依赖升级未同步锁定文件与文档。

### RR-3 登记真实性（防虚报）｜溯源：先验
- **规则**：任何"已完成/已通过"登记须附执行证据与环境口径；未执行不得标记通过。**测试结果只能作为行为记录，不能作为正确性来源**。
- **检查方法**：抽查登记项的证据产物、时间戳、测试数对账。
- **反例信号**："全部通过"无 CI 对应；登记测试数与实际不符。

### RR-5 幂等与重放｜溯源：先验
- **规则**：任务重放/重复执行幂等：先删后插或完整键 merge；队列去重；同输入重跑结果一致。
- **检查方法**：对新增写路径追问"同一任务跑两次会怎样"；删除范围是否精确到键。
- **反例信号**：追加式写入无唯一键；重跑重复记录或约束冲突。

### RR-7b 外部系统输入防御｜溯源：先验
- **规则**：外部系统（已经过测试的 API/库/平台）输入按**契约校验**——契约明确的边界不必过度设防，但须警惕**版本漂移**（同接口跨版本行为差异、平台语义差异）。
- **检查方法**：找外部输入消费点，核对契约校验存在性；外部依赖的版本语义差异（平台/次版本）是否有显式处理或 skipif 标记。
- **反例信号**：依赖平台特定语义无平台守卫；测试隐含特定版本行为未标记。

### RR-7c 用户输入防御｜溯源：先验（本项目 run 意见强化）+ 案例渗入（NF-5 硬上界，v5）
- **规则**：用户/运维人工输入**不可前置限制、边界不可控**——必须三件套齐备：上界（长度/数量）、消毒（注入/非法字符）、兜底（失败降级）。**数值型查询参数（limit/hops/页码/超时等）必须有显式硬上限**（代码内可见的钳制或校验，不接受"框架默认会处理"的假设）；对框架默认行为不确定时**须实读核实，不得以"取决于框架"搁置**。
- **检查方法**：找用户输入消费点（CLI 参数/配置/请求参数），逐点核对三件套与硬上限；数值参数逐个找钳制代码，找不到即立项。
- **反例信号**：用户可控列表直拼查询无上限；请求参数无硬顶；`?limit=` 无上限且以"框架会处理"为由跳过。

### RR-8 前端与交互一致性（双向）｜溯源：先验 + 案例渗入（17/R-5 事件绑定、17/R-12 反向依赖 v3、17/R-13 layout v3 与必立项纪律 v5）
- **规则**：UI 声明与实现一致，检查**双向**——正向（引用有效：每个 src/href 可达）；反向（依赖完备：页面 JS 调用的每个外部定义，其定义文件被该页面引入）；交互声明有实现；可视化必需配置完整。**声明-实现对照的不符项必立项**：与 DoD/设计条目直接关联的缺失（如必需配置未配置）不得以"标注即可"降格，至少以最低缺陷级立项（触发：run9 把 layout 缺失降为"标注即可"致 17/R-13 漏检）。
- **检查方法（机械化）**：①UI 声明点→事件监听/处理器存在性；②可视化初始化→必需配置清单（**G6 v5 `new Graph`：container/data/node/edge/behaviors/layout**；依据 G6 v5 文档，未覆盖：plugins/theme）；③正向引用可达；④反向：grep 页面 JS 顶层调用的外部定义符→定位定义文件→对照 script 引用清单；⑤对照清单（含双向结果）入卡。
- **反例信号**：宣称 drag/zoom 无事件绑定；`new Graph` 缺 layout；script 指向不存在文件；页面调用他文件定义函数而未引入（ReferenceError 静默失效）；对照不符项被记为"标注即可"。

## 域条件层（按前置谓词启用）

### RR-4 状态生命周期四查｜溯源：先验（产物规范 R13）+ 案例渗入（17/R-1~R-4，v2 机械化触发；17/R-2 独立立项纪律，v5）
- **规则**（启用条件：系统含软删除/墓碑/有效期标记）：①属性保留（置墓碑不清空其他属性）；②读路径过滤（全部读路径过滤墓碑——列表/检索/图遍历/聚合/侧栏/API/CLI）；③合并键完整（MERGE/UPSERT 键含全部区分维度）；④不可复活（重放/重建/再同步不意外复活）。
- **检查程序（五步机械化，概括性结论无效）**：枚举标记字段写入点（文件:行+值来源）→ 抄录全部 MERGE/UPSERT 完整键清单 → 枚举消费该标记的全部查询 → 逐点四问（不确定即降级为"未能排除"意见）→ 三清单与逐点结论入卡。
- **独立立项纪律（v5）**：②读路径过滤缺失须**单独成意见**，不得以与写路径意见"同源/同因"为由合并——判"同源"须引用设计文档条目（§ 级）佐证，否则不得合并（触发：run9 把读路径缺失并入写路径意见致 17/R-2 漏检）。
- **反例信号**：`row.get(k, "")` 缺失补默认值+整行 SET；MERGE 省略区分键；同步任务无条件写标记字段；"与测试一致"（测试可能断言的就是缺陷行为）；"与写路径问题同源故不另立项"。

### RR-6 并发与锁｜溯源：先验（评审惯例）
- **规则**（启用条件：共享可变状态/跨进程资源）：写路径明确持锁范围与释放（含异常路径回收、stale 锁检测及**跨平台语义**）；读路径确认无需锁依据；单写者假设显式声明。
- **检查方法**：锁获取/释放对；异常路径泄漏；新读路径绕过单写者约定；平台差异（PID/文件锁语义）显式处理或 skipif。
- **反例信号**：早退 return 无释放；崩溃锁残留无兜底；POSIX-only 语义无平台声明与测试标记。

### RR-7a LLM 输出防御｜溯源：先验 + 案例渗入（17/F-1~F-3，v3 兜底完备性触发）
- **规则**（启用条件：消费 LLM 输出）：LLM 输出**可能幻觉、格式漂移、推理标记污染**——防御以后处理为主：schema 校验、清洗（控制标记/围栏）、输入与输出双预算（输出预算须考虑推理模型 think 开销）；LLM 客户端调用参数**完备性**（凭证透传、超时、重试与兜底降级路径）；可选依赖 try/except 兜底覆盖全部缺失可能。
- **检查方法**：找 LLM 输出消费点核对后处理三件；核对调用参数清单（api_key 透传/max_tokens/timeout）；启动入口可选依赖捕获完备性。
- **反例信号**：凭证读取未透传；无总输入预算致超长空响应；max_tokens 默认值被 think 吃光；except ImportError 只包部分可选依赖。
