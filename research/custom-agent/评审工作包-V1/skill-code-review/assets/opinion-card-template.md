# 评审意见卡模板（v5）

> 用法：复制本模板到 `reviews/<日期>-<目标>.md` 后填写；字段缺失的意见卡视为无效（红线见 SKILL.md）。修订史见 `../CHANGELOG.md`。
> **格式契约声明**：本模板同时是评审产物的**格式契约文档**——评估工具 `scripts/score_review.py`（v2：`score` 子命令评召回、`pair`/`groups` 子命令做跨 run 配对与分组核验）的输入契约以本模板的机器可读字段为准：①`### [P0-3]` 标题；②`- 类型/溯源/维度` 单行字段；③**标题以对象前缀开头**（`文件::函数 — 缺陷一句话`，如 `web/api.py::_aggregate_entities — limit 参数无上限`）；④**溯源行须列出该缺陷涉及的全部对象文件**（不止主文件——多处文件的缺陷漏列会直接造成配对与评分漏配，第 8 场 R-4/F-1 盲区的根因）、单行含至少一个 `路径:行号`（"溯源 + 证据"合并式为 run7 已登记偏差，解析器容错但不得作为新产出格式）。模板字段变更须与工具解析同步（CHANGELOG 双端各记一行）。历史项目的非契约格式产出物应经适配器转换后进入评分，而非修改工具解析；评分器兼容无前缀/单文件的旧格式。

```markdown
# 评审意见卡：<目标（commit/PR 标识）>
- 日期：YYYY-MM-DD / 评审者：<agent 名与版本 + 模型标识（provider/model）>
- 基线：<被评审代码状态的 commit hash（评审输入锚点）>
- 变更地图：<文件数 × 类型分布（新增/修改/删除/移动），一句话>
- 启用规则：<按 review-rules 适用性判定启用的规则编号列表；未启用规则及原因一行>

## 意见（按级别排序）

### [P0|P1|P2|P3] <对象前缀> — <缺陷一句话>
- 类型：<范围缺口（需求未列入设计）| 设计错误（已列入但设计错）| 实现偏离（设计对实现走样）| 测试缺陷 | 其他>
- 溯源：<该缺陷涉及的全部对象文件 file:line（不止主文件），或设计/规范文档 §x>
- 证据：<实际读取到的代码片段或事实，≤3 行>
- 维度：<命中的评审维度名／规则编号（RR-x）>
- 建议：<可操作的修正方向，一句话>

（重复"意见"块直至穷尽发现）

## 未发现问题的检查项
<逐规则列出"已检查且未发现问题"的结论——**须附核对清单**（RR-4 三清单、RR-8 声明-实现对照表等，见各规则的检查程序），供人工复核聚焦，也是诚实性要求>

## 问题类型汇总
<范围缺口 N / 设计错误 N / 实现偏离 N / 测试缺陷 N / 其他 N——供迭代决策路由>

## 评审元信息
- 检查文件数：N / 耗时：X / 置信度：高|中|低（低须说明信息缺口）
- 会话标识：session id（供轨迹追溯）
- 规则集版本：assets/review-rules.md v<版本号>
```

## 分级口径（与 SKILL.md 红线一致）

| 级别 | 判据（错误成本 × 确定性） |
|---|---|
| P0 | 不可逆影响 / 数据损坏 / 安全；或确定性极高的行为错误 |
| P1 | 行为错误（错误结果、状态不一致），可修复 |
| P2 | 防御缺失、契约不完整（弱断言、缺兜底），当前未必然出错 |
| P3 | 风格、口径、文档同步类 |

## 问题类型口径（v2）

> 判定程序与已核定样例见同目录 `issue-type-guide.md`（先判测试缺陷，再查设计文档条目三分支；设计参照缺位标"其他"）。

| 类型 | 判据 | 典型修复路由 |
|---|---|---|
| 范围缺口 | 对应需求/约束未出现在设计文档（写代码前就没列入） | 细化设计文档 + 上下游覆盖检查（FR↔场景、NFR↔验收矩阵） |
| 设计错误 | 设计已列入但方案本身错 | 参考设计样例供给（针对基模能力弱点） |
| 实现偏离 | 设计正确、实现走样（含"设计有代码无"） | 登记/回写机制 |
| 测试缺陷 | 测试本身的缺陷（弱断言/平台未标记/覆盖虚报） | 测试修补 + 断言同形 |
