# 专用 Agent 装配流程方法 v2（checklist 化）

> 日期：2026-08-18（P2 第 6 场产出；由 v1 经场景一六场实践修订而来，v1 保留于 `装配流程v1.md` 作历史参照）
> 话题标签：[D1]（步骤 4/6 含 [D1+D2]，步骤 5/7 含 [D1+D3]）
> 修订依据：装配实录第 1–6 场的全部使用发现（每条 checklist 项后括注来源场号）
> 定位（承 notes/04）：本流程是"具象化填充方法"的骨架——把抽象模板与场景上下文结合形成具象成果物；**记录填充过程与记录装配清单同等重要**。

---

## 流程总览

```
①场景画像 → ②组件选配（含能力/知识登记，v1 的②③合并） → ③上下文与提示组装
      → ④评估集与门禁（观测预埋） → ⑤清洁运行 → ⑥验证与评分 → ⑦迭代闭环
```

## ① 场景画像

- [ ] 用《场景画像问卷》九问 + 附加问作答，产出画像卡（范式走查结论、护栏清单、风险 ≤3 条）（v1①）
- [ ] 评估语料自举检查：目标场景是否有可挖掘的缺陷史（评审报告/issue/修复提交）？（第 1 场：无则先建采集计划）

## ② 组件选配（能力-组件-知识三合一登记）

- [ ] 从组件目录选件；每件登记四契约字段 + 复用档位 + **迁移参照**（DSH 等价形态与接入成本——P3 迁移矩阵数据）（v1③）
- [ ] 知识三段登记：每项能力的知识来源（内蕴 / 外部知识 / 供给方式）——外部知识无供给方式的回到画像补问（v1②，[D1+D2]）
- [ ] F-绑定组件安排实测校准计划（第 2 场：文档调研→实测校准是必经步）
- [ ] 可分发组件检查引用完整性：项目内知识必须摘录进 assets，不得引用项目路径（第 1 场修订）

## ③ 上下文与提示组装

- [ ] 每次 LLM 调用的上下文构成 + token 预算 + 溯源锚点格式；产物用模板集模板（v1④）
- [ ] 规则/知识类资产先做**适用性判定**（前置谓词表）——只装启用的子集（第 5 场 v4）
- [ ] 迭代型资产建立 CHANGELOG，产物头只留当前版本号（第 5 场）
- [ ] **格式契约前置**：产出物的格式约定（模板 + 机器可读字段规范）作为必供内容随组装下发，使下游工具（评分/一致性分析）的输入契约在生产端即被满足（notes/06）

## ④ 评估集与门禁（观测预埋）[D1+D3]

- [ ] 评估集：标注来源（缺陷史挖掘）+ 指标口径（pass@1/pass^k/召回三口径：启发式上界/语义严格/宽松）+ **锚点登记**（每案例的验证 run 归属）（第 2–4 场）
- [ ] 门禁：schema 校验 + 红线 + 变更触发回归（v1⑤）
- [ ] 观测：优先复用宿主能力（pi 会话 JSONL 即 L1–L5），轨迹报告按可观测清单 §6 模板产出（第 2 场）
- [ ] 运行规程三前提：**清洁工作区**（隔离既有意见卡与评估材料）/ **同 skill 版本** / **锚点对应**（第 5–6 场）
- [ ] 防泄漏双禁：禁读评审锚点之后的提交；禁读评估材料目录（第 2、6 场）

## ⑤ 清洁运行

- [ ] 环境检查：项目信任（`-a` 或 trust.json）、模型/版本登记、会话 id 入卡（第 2 场）
- [ ] 按评分目的决定 run 数：基线 1 次；pass^k ≥2 次（同版本同锚点）（第 3/6 场）

## ⑥ 验证与评分

- [ ] 启发式评分（上界）→ 语义人工核定（严格/宽松）→ 三口径并报，**标注口径**（第 2 场）
- [ ] 一致性分析：意见配对用**稳定标识**（规则编号 + 关联文件），不用标题词/级别（第 6 场：签名 v1 伪影教训——溯源字段须机器可解析单行格式）
- [ ] **历史资产走适配器**：存量项目格式不同的产出物经适配层转换为契约格式进入评分，核心工具不写多格式宽容解析；适配器须登记未解析条目（不静默丢弃）（notes/06）
- [ ] "潜在新发现"复核通道：未入案例的意见人工判定真假；经代码级核证的真发现可回流标注集（第 6 场：12 真/0 误报）
- [ ] DoD 核对：执行证据 + 环境口径（模板集 R11）

## ⑦ 迭代闭环（错误分析 → 资产修订 → 复测验证）

- [ ] 错误分析区分两类：**错误排除**（被判"未发现"但实有——须机械化检查程序修复）与**盲区**（无规则覆盖——增补规则）（第 3 场）
- [ ] 新增规则登记**溯源**（先验 vs 案例渗入）入 CHANGELOG（第 5 场 v4）
- [ ] 规则修订后同锚点复测；跨版本结果不混算 pass^k（第 3 场）
- [ ] 问题类型分布（范围缺口/设计错误/实现偏离/测试缺陷）作为迭代决策路由：缺口多→设计过程；错误多→样例库；偏离多→流程纪律（第 5–6 场，[D1+D3]）
