# 决策自动化、异构多模型协作与缓存友好设计（P3 前置思考，2026-08-20）

> 背景（自足）：研究者在前两项改进（人工决策双场景规范、框架记忆渗漏防护，见 `08-人工决策双场景与记忆渗漏防护设计.md`）基础上提出四个递进的考虑：①人工审核的质量本身也可能不稳定或有遗漏，是否需要对人工反馈做评估；②人工决策环节是否可以换成"另一个模型构建的独立智能体"来提供自动化选项——尤其全量评审用便宜模型、决策阶段用更强更贵模型的成本分层；③如果不同工作阶段用不同模型的智能体，全局记忆如何设计——既让各阶段拿到必要背景，又不因信息渗漏破坏处理独立性；④如何让每次大模型调用更有效利用模型服务的 KV 缓存（键值缓存：服务端对相同前缀的请求复用已算结果，降低时延与费用）来提速降本。本笔记给出四项设计。

## 1. 人工反馈质量的评估环节

**问题**：人工是当前流程的终审，但人工同样会不稳定（同一材料两次判断不同）与遗漏（该核的没核、结论与依据不自洽）。终审无校核 = 质量单点。

**设计：双层互核 + 形式自检**（沿用第 11 场已实际运行过的"代理独立复核 + 研究者终审"结构，反向补全）：

1. **预判比对**：人工处理前，裁判智能体（见 §2）先独立给出参考结论与理由；人工结论回填后自动比对——**分歧项不判定谁对，只标记为"需二次审视"**（人工仍可能对，分歧本身就是反馈质量的观测数据）。统计口径：一致率、分歧类型分布（事实性/口径性/粗心性）。
2. **形式自检（代理自动执行，成本近零）**：①清单条目无遗漏（逐条有结论）；②结论字段齐备且"依据"栏引用的行号/命令确能支撑"结论"栏（抽核式一致性检查）；③处置动作是否真的被执行（回填核对）。
3. **指标化（进方向三的研究过程观测）**：处理时距、未处理率、依据引用有效率、与预判一致率、后续改判率。人工环节从"不可观测的黑箱终审"变为有质量指标的流程环节。

**边界**：评估目的是改进与观测，不是惩罚性考核；分歧标记默认不公开到结论引用层。

## 2. 决策自动化：独立裁判智能体与成本分层模型配置

**裁判智能体**（对 `08` §1.1 场景 A/B 的三个人工介入点提供自动化选项）：

- 独立性三原则：**换模型**（不得与被裁决产物的生产者同模型——防自证偏置）；**冻结提示词**（裁判提示词版本化登记，变更走日志——防裁判漂移，`02-装配实录.md` §8.5 已确立）；**视野对等**（可见双方材料的相同内容，不可见双方的置信度与既往裁决——防锚定）。
- 输出协议：结论 + 一句话理由 + 置信度（高/中/低）。**人工保留终审权**：默认采纳高置信结论并抽检，低置信全部人工——随校准数据积累逐步放宽（与 §8.5 三层结构的第二层一致，从"配对"推广到全部决策点）。

**成本分层的阶段-模型配置**（notes/07 已确立 pi 可按角色路由模型——平台优势的直接延伸）：

| 阶段 | 模型档位 | 理由 | 依据/风险 |
|---|---|---|---|
| 全量评审（批量过代码） | 便宜模型 | 工作量大、召回导向；对照实验显示裸模型也能产出 30 条意见但命中浅——便宜模型做初筛候选 | 漏检风险由下一层兜底 |
| 应答（A 复核） | 中档 | 需读代码核对证据，创造性低 | — |
| 复审 + 裁决 | 强模型 | 需根因级判断（对照分析 2-3：症状级任务裁判一致率高、根因级是混淆高发区——恰恰要用强模型并保留人工） | 成本占比小（调用次数少） |

**验证实验（P3 候选）**：同一评估集上跑两种配置——"强模型全流程" vs "便宜初筛 + 强模型裁决"——比较总成本、最终命中与误报。这是继"带/不带规则包"之后的第二个边际贡献实验（模型档位 × 阶段路由的性价比前沿）。

## 3. 异构多模型的全局记忆设计：阶段化信息配额

**核心矛盾**：各阶段智能体需要背景（项目情况、上游产物），但独立性要求某些信息对其不可见（评审者不可见旧评审与答案；裁判不可见双方置信度）。

**设计原则：以文档传递代替共享会话记忆（message-passing over shared memory）**——这恰与文献互证（MetaGPT 的结构化文档交接优于自由对话，见 `../../P2成果与论文观点对照分析.md` §1）：

1. **全局记忆 = 版本化工件集，不是会话历史**。两类共享物：①**项目卡片**（每项目一份、各阶段共见的稳定背景：被评审仓库说明、设计文档入口、任务定义、隔离纪律）；②**阶段工件**（意见卡/应答卡/复审卡/决策卡，命名与目录已约定）。任何阶段智能体都是**新会话**启动，上下文 = 提示模板 + 项目卡片 + 按配额可见的工件——不存在跨阶段共享的会话记忆，渗漏面从设计上收窄（notes/08 评估的高危通道全部不会激活）。
2. **阶段-信息配额表**（need-to-know 矩阵，随闭环工作流维护）：

| 阶段 | 必须有 | 可见前序工件 | 禁止 |
|---|---|---|---|
| 评审 | 项目卡片、被评审代码与设计文档 | 无 | 一切旧评审产物、评估材料、研究上下文 |
| A 应答 | 同上 | 意见卡 | 应答后他人对它的评论 |
| B 复审 | 同上 | 意见卡、应答卡、修复 diff | 既往复审 |
| 裁判 | 任务定义 | 双方材料（对等） | 双方置信度、既往裁决、研究上下文 |

3. **实现**：notes/08 §2.3 的 eval-hygiene 扩展从"评估专用"推广为**按阶段配置的白名单守卫**——每阶段启动时声明自己的角色，读保护按配额表生效；工件传递由编排脚本（或人）按表投递。**模型异构性因此无耦合**：上下文经文档传递，各阶段换模型不影响他阶段（无 KV/会话连续性依赖）。
4. 与 DSH 等价：其上下文/记忆组件的"可见性配置"对应形态随 P3 组件登记。

## 4. KV 缓存友好设计

**机制要点**（供应商通用规律）：KV 缓存按**前缀精确匹配**命中——请求开头越长的相同部分，命中越多、越省；会话式智能体的追加式上下文天然部分命中；**跨模型/跨供应商不共享**；温度等采样参数一般不影响前缀缓存，但提示词一个字符不同即从差异点失效。

**设计四条**：

1. **稳定前缀原则**：提示与注入内容按"稳定→易变"排序——系统提示与规则集（跨 run 不变）在前，项目卡片（跨阶段不变）次之，任务参数（锚点、日期、具体指令）置末。当前形态检查：pi 的系统提示含技能元数据（稳定 ✓）；评审提示模板中锚点等参数恰在末段 ✓；`-nc` 移除 research/AGENTS.md 后，评估运行的前缀比 P2 时期更稳定（该文件在研究推进中频繁变更，此前每次改动都在破坏全体系 run 的缓存前缀——**渗漏封堵与缓存友好同向**）。
2. **同锚点批量场景最受益**：同锚点多 run（pass^k 一致性测量）的前缀几乎全同，连续执行可显著命中——批跑脚本按"同锚点聚簇"排序执行（而非按案例交错）。
3. **跨阶段靠文档不靠缓存**：§3 的文档传递设计使跨阶段调用无需共享前缀——异构模型（各自缓存独立）不损失什么；阶段内保持同模型连续调用。
4. **度量与诚实登记**：供应商用量回报中的缓存命中 token 数纳入成本观测（`llm-observability/三对象指标卡v1.md` 待补"缓存命中率"一行）；**对照比较必须标注冷/热缓存状态**——回溯提示：P2 的成本方差 1.7 倍（run2 vs run3）可能部分是缓存冷热差异的混杂，此后成本对比补此口径。
