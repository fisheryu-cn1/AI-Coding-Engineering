# 方向一专题 07：案例项目的 A-B 交叉评审工作流（过程事实与定位修正）

> 日期：2026-08-18

> 状态：事实记录 + 定位修正（研究者口述确认，2026-08-18）
> 关联：notes/06（格式契约）、`review-pi/evals/`（评估语料）、kb-app 事实提取稿"评审三层结构"

## 1. 原始事实（研究者确认，2026-08-18）

三个案例项目（kb-app、Vision-Sudoku、fundseeker）的实际开发工作流**一致采用模型交叉评审环**：

```
模型 A 写代码/方案 → 模型 B 评审 → 模型 A 对评审意见复核（确认/驳回）→ 修改
      → 模型 B 复审修改结果 → （循环至通过）
```

即项目中的评审报告链（docs/ 的 CR/R/N 系列条目）都是这个环的产物：B 发现、A 复核确认、修复、B 复审关闭——kb-app 事实提取稿识别的"评审三层结构（评审→修复记录→独立复核）"与 17 号报告的"复核推翻评审"正是该环的文档痕迹。

## 2. 对研究的四点定位修正

### 2.1 评估语料质量升级（[D1]）

16 案例的期望意见全部经过**双重确认**（B 发现 + A 复核 + 修复提交验证）——不是单方评审的产出。ground truth 可靠性高于此前认知，支持门 2 B3 议题（新发现回流标注集）朝正向决策。

### 2.2 review-pi 的定位明确化：产品化的"B 角色"（[D1]）

评审 agent 不是新建角色，而是把案例项目中已存在的"模型 B 评审员"**资产化**（SOP + 规则集 + 评估集 + 门禁）。由此，本研究核心价值主张的实验形态变得精确：

> **技能装备的 B 角色（skill + 规则 + 评估集）vs 裸模型 B 角色（通用交叉评审）**——同一位置上的知识资产增益测量。

可选对照设计：同模型同锚点，带 skill 与不带 skill（裸 prompt 评审）各跑一轮，差值即 skill 的边际贡献。这是比"跨模型并集"更本质的实验（回应上一轮讨论：并集买到覆盖，资产买到可复用的可靠）。

### 2.3 完整工作环是场景深化的天然路线（[D1]）

当前 review-pi 只覆盖环的第一段（B 首评）。环的剩余段——**A 复核意见（确认/驳回/澄清）、修复、B 复审修复（回归门禁）**——既是三个项目的既有习惯（对齐即采纳），也是评审 agent 走向实用的完整闭环。门 2 A1"深化"选项由此获得具体内容：从单点评审扩展为环内多角色协作（评审 agent 出意见卡 → 编码 agent 复核应答 → 修复 → 复审）。

### 2.4 方向三的真实过程素材（[D1+D3]）

三个独立项目**自发收敛**到同一 A-B 交叉环——这是 RQ-B（过程观测）难得的现实基线：人机协作模式已在实践中成形（未被显式规范/度量），方向三的工作从"观测假设"变为"显式化并度量既有实践"。同时该环本身就是一个"独立验证器"的实现（较同模型自审更独立，回应 MAST FC3）——级联交叉复核不是理论建议，而是既成事实。
