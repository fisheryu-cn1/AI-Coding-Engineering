# AGENTS.md — Agent 构建方法研究项目

本文件是 research 目录下**对话式研究项目**的工作约定。本项目通过多轮对话整理思路、收集资料、逐步形成两个实验探索方向的研究成果。后续会话开始时先读本文件，再读相关方向的 `notes/00` 文档恢复上下文。

## 1. 项目概览

三个关联的研究方向：

| 方向 | 目录 | 一句话定位 |
|---|---|---|
| 方向一：定制化专用 Agent 构建方法 | `research/custom-agent/` | 工程方法：基于 pi / DSH 框架，面向特定场景快速组装专用 agent（组件模型 + 场景分析 + 工作流程） |
| 方向二：Agent 软件设计方法论 | `research/agent-software-design/` | 设计原理：从软件工程基本原理重走"需求 → 需求描述 → 架构设计"，研究 LLM 与传统组件的系统构成方式、中间产物规范 |
| 方向三：LLM 系统可观测性与过程观测 | `research/llm-observability/` | 度量方法：LLM 核心软件的可观测性（运行情况 + 任务质量）与 AI 辅助开发过程的观测（人 / AI 工具 / 人-AI 协同），及数据驱动的迭代决策 |

方向间的关系：方向二产出的设计原理与产物规范是方向一的理论基础；方向一的实验是方向二规范的检验场；方向三为两者提供观测与评估基础设施——LLM 系统的可观测设计（承接方向二的中间产物规范）与开发过程的量化（承接方向一的团队工程管理面）。**讨论中话题跳跃是预期行为**，按第 4 节的分类规则归档即可，不要强行要求单话题对话。

## 3. 目录与文件约定

每个方向目录下固定三层：

```
<direction>/
├── README.md        # 方向索引：目录组织、文档清单、进度 checklist（状态变化时同步更新）
├── notes/           # 思路与讨论沉淀（见第 4 节命名规范）
├── materials/       # 资料归档与摘要
└── experiments/     # 实验设计、执行记录、结果
```

## 4. 讨论内容分类与管理规则

这是本项目的核心约定。每轮对话产出的内容按以下规则处理：

### 4.1 话题分类标签

每条讨论内容归属以下四类之一：

- `[D1]` 仅方向一（custom-agent）
- `[D2]` 仅方向二（agent-software-design）
- `[D3]` 仅方向三（llm-observability）
- `[D1+D2]` / `[D1+D3]` / `[D2+D3]`（及三向）跨方向（典型如：组件模型、架构描述规范、评估口径——这类内容**记录在主要归属方向的笔记中，并在另一方向的笔记里加一行交叉引用**）
- `[META]` 研究方法本身（流程调整、分类规则修订等，记录在本文件的修订或 `notes/meta-*.md`）

### 4.2 笔记命名与状态

- `notes/00-方向界定与研究问题.md`：方向的基线文档，开放问题用 `❓` 标记；讨论中**达成共识的问题，把 ❓ 替换为结论并注明日期**。
- `notes/NN-<主题>.md`：专题讨论纪要，NN 递增。每篇开头标注：日期、话题标签（4.1）、状态（讨论中 / 已有结论 / 已冻结）。
- 讨论中产生的**决策**必须显式记录为"决策：……（日期，理由）"，避免后续会话重复讨论已定事项。
- 草案状态用文档头部 `> 状态：` 行维护，不另建版本文件。

### 4.3 每轮对话结束时的归档动作

1. 将本轮讨论内容按 4.1 分类，更新对应方向的笔记（新专题则新建文件）；
2. 新收集的资料登记到 `materials/README.md`；
3. 若进度状态变化，更新方向 `README.md` 的 checklist；
4. 若出现需要长期跟踪的开放问题，确保它在 `notes/00` 的开放问题清单中；
5. 跨方向内容按 `[D1+D2]` 规则双向链接；
6. 涉及新增/调整目录结构时，同步更新 `research/README.md` 总索引；
7. 时间序列文档（日志/实录/台账）按 §4.5 追加；多处登记按 §4.5-3 同批核对。
8. 本轮若产生需人工核定、裁决或决策的事项，在**当前研究步骤的人工待办清单**（命名 `人工待办事项清单-<研究步骤>-v<版本号>.md`，如 `人工待办事项清单-P2深化-v1.md`，规则见该文件头）末尾追加一节：逐项写明涉及文件的完整路径与对该文件的具体工作、处理建议；若已登记的人工待办有处理结果，先按结果执行处置，并把结论同步到工作推进日志、装配实录与相应 README（清单文末附结果记录规范）。

### 4.4 防漂移规则

- 讨论不追求当场收敛，但**每轮结束必须落盘**（归档动作 4.3），不留只存在于对话中的结论。
- 与两方向无关的内容不归档入本项目目录。
- 修改既有笔记时保持最小改动，不重写已有共识部分。

### 4.5 文档维护规则（2026-08-18 增补，源自两次排序事故与两次状态滞后事故）

1. **时间序列文档只追加**：日志、实录、台账类按时间排序的文档，新记录一律追加到**文档末尾**（或锚定"上一节末尾"插入），**禁止在文件头之后前插**；节级插入必须以完整节（含标题）为操作单元，避免吞掉标题产生悬空正文。（事故：工作推进日志、装配实录均因前插形成倒序堆叠）
2. **编辑后自检**：对带序号/日期标题的文档，任何插入/移动后核对标题序单调（`grep -n "^# \|^### " <file>` 一行即可）。
3. **多处登记同批更新**：同一状态若登记于多处（规划 §3 里程碑表、§8 快照、各方向 README 进度、日志），状态变更须**同批次**更新全部登记处并交叉核对，防止口径漂移。（事故：规划 §3 P2 表滞后于 §8 快照一个场次）
4. **迭代型产物的版本管理**：规则集、模板、目录、清单等会多次修订的产物，文件头只保留当前版本号，修订史记入同目录 `CHANGELOG.md`——保持成果物始终可交付。
5. **提交纪律**：重要会话结束即时本地提交（推送可延迟、网络恢复后补推）；编辑事故的修复须在提交信息或日志中记录根因，供方法复盘。

## 6. 写作约定

- 中文写作，文件内容与现有 research 文档风格一致（问题-结论表格、树状结构图）。
- 代码、框架名、命令、文件路径保留原文。
- 概念表达以清晰准确为优先：避免为省字数自造压缩术语（如"同域发现"式非通用概念）。默认读者不共享本研究的上下文概念空间，优先使用无需上下文即可理解的完整表述；研究必需的自定义概念在首次出现处用一句话定义，或链接到定义所在文档。
- 外部资料引用带 URL，便于复查。
