## 1. 实验设计

### 1.1 留出项目与零适配部署

- **fundseeker**（基金数据采集与分析系统，Python，生产在用）：在 P2 全程被刻意隔离（决策清单 §D"完全隔离、P3 冷启动留出主战场"），评审 skill（code-review，规则集 v5）的任何规则条目均未参考该项目材料——留出条件成立。
- **零适配部署**：skill v5 全资产原样拷贝至目标仓库 `.pi/skills/code-review/`，未修改任何内容；守卫扩展同步部署。收敛速度的度量起点由此定义为**零轮迭代**。
- 评估集 `cases-fs.jsonl`：三个历史缺陷锚定各自修复提交的父状态——

| 案例 | 锚点（修复前状态） | 缺陷 | 后续修复 |
|---|---|---|---|
| FS-socket | c5ee3e3 | socket 挂起无有效超时（单 float 超时不可靠触发读超时、无请求级硬截止） | 05d66d3 |
| FS-retry | 05d66d3 | HTTP 4xx 客户端错误与 5xx/超时不区分地一律重试 | b3a0342 |
| FS-cron | 517eb08 | cron 脚本无重入防护，30s 自动重试与在跑 pipeline 重叠 | c5ee3e3 |

### 1.2 隔离协议（本实验中完成 3→5 通道的演化）

被评审内容一律经 `git show <锚点>:<路径>` 读取；禁读修复提交、既有评审报告、评估材料。本实验先后暴露两条新渗漏通道，协议随之演化：

1. **修复提交主题行通道**（fs-run3 发现）：`git show <fix> --stat` 默认携带提交主题行，而主题行常直接陈述缺陷（如"add flock to prevent cron retry overlap"）——提示词自身引用的命令，其完整输出面构成答案渗漏。修正：定位一律 `git diff <fix>^ <fix> --stat`（仅文件与行数统计）。该通道在 kb-app 全部历史运行中同样存在。
2. **越界断言通道**（85 条复核发现）：隔离纪律禁止读取某材料（如设计文档目录）时，评审者仍可能对该材料内容下断言（"设计文档未登记"）——隔离的副作用。修正：禁止对被隔离材料做任何内容断言，只允许声明"未核查"。

连同 P2 期发现的三条（既往评审产物 / 工作区当前文件 / 锚点内既有评审报告），隔离协议最终形态为**五通道枚举**（收入评审工作方法总纲 §1.2 与 V1 工作包模板）。

### 1.3 对照组（同模型多次运行投票基线）

依《P2 成果与论文观点对照分析》2-2 的要求（任何多角色/知识资产增益主张应先赢过"同模型多次采样"基线）：同锚点（c5ee3e3）、同范围、无 skill、信息盲，三次并行运行（fs-ctl1/2/3）。

## 2. 结果

### 2.1 三锚点冷启动全部语义命中（含信息盲复跑）

| 运行 | 案例 × 锚点 | 结果（语义命中口径） |
|---|---|---|
| fs-run1 | FS-socket × c5ee3e3 | 命中（P1×2：单 float 超时不可靠触发读超时；主循环无硬性 deadline）——证据引用了锚点内 cron 注释的症状记录 |
| fs-run1b | 同上，**信息盲复跑** | 命中（11 条意见；未读修复提交任何信息，声明与输出核查一致）——挂起机理族完整覆盖，并前置发现 4xx 无差别重试 |
| fs-run2 | FS-retry × 05d66d3 | 命中（P1：HTTPError 继承 RequestException 落入同重试分支，机理精确且量化影响） |
| fs-run3 | FS-cron × 517eb08 | 命中（P0：脚本无重入防护，cron 30s 自动重试与在跑 pipeline 重叠——正中 flock 案例） |

- run1/run3 初期带"修复主题行经 --stat 可见"存疑注；**fs-run1b（修正协议）独立命中后存疑注解除**——命中不依赖答案渗漏。
- 这是规则集引导力**首个无答案可见风险的命中组**（源项目 kb-app 的历史命中全部带"标准答案合法可见"效度注，见评估口径卡 §3）。

### 2.2 对照组结果与 skill 增量的精确表述

85 条意见逐条代码复核（对比分析 §5，分母 = 5 份 c5ee3e3 报告经复核确认的问题主题并集 35 个）后的结论：

- **核心可靠性缺陷两组相当**：socket 挂起缺陷族对照组 3/3 独立命中，skill 组 2/2——通用工程缺陷（超时/重试/异常处理）在裸模型能力圈内，skill 近零增量；
- **skill 的增量在三处**：①非直觉类别系统性覆盖（用户输入硬上限：skill 组 2/2 vs 对照组 0/3）；②可审计的结构化产出与定级纪律（对照组 4 个 P0 复核全部偏高；skill 组唯一 P0 有真实事故背书）；③零关键错误背书（对照组 2 处，其一背书的正是被修复提交证伪的真缺陷）；
- **两轮带 skill ≈ 三轮裸模型覆盖率**（22/35，63%）——"约白送一轮"；
- **单轮评审是缺陷空间的一次采样**：单轮召回 31–46%，约半数发现为单轮独有，严重度可漂移两级，偶见"无误/缺陷"对立结论。

### 2.3 真实修复应用闭环（迁移的最后一公里）

评审发现经确认后做真实修复：编码代理（zcode）修复两项（883e8ce）→ 评审代理（pi+skill）独立复审（两条已修复 + 抓出修复引入的守卫回归一处，按处方修正 132cca3）→ 人工核实后合并主干（a6cb15f，--no-ff）。修复者当日两次低级失误分别被自身冒烟与独立复审拦截——"评审→修复→复审"三段缺一不可的现场实证。

### 2.4 泛化观察素材

- fs-run3 类型分布出现**范围缺口 ×3**（文档-实现缺口特征）——Vision-Sudoku 缺口模式之一在第三语料复现，跨项目稳定；
- 三 run 意见量 16/6/8，方差小于源项目对照期（13 vs 26）；
- 唯一经复核确认的深度发现（多季度持仓折叠，数据完整性缺陷）出自 skill 组 run1b——但样本仅 1，不足以推翻"深度发现是单轮采样运气"的判断。

## 3. 迁移成本矩阵（D1-S5 交付形态）

### 3.1 跨项目迁移（kb-app → fundseeker，实测）

| 组件 | 迁移动作 | 成本 | 说明 |
|---|---|---|---|
| code-review skill（规则集 v5 + 模板 + 指南 + 工作单） | 原样拷贝 | **零适配** | 收敛速度 = 零轮迭代即三锚点全中 |
| 守卫扩展（review-guard.ts） | 原样拷贝 | 零适配 | pi 同版本，无需重校准 |
| 评估集 | 从目标仓库缺陷史新构造（3 案例） | 约 1 工作场 | 评估集不可迁移（锚定目标项目历史），构造方法是可迁移件 |
| 评分器 score_review.py | 复用 + 目标参数 | 低 | 评分口径跨项目通用；锚点过滤参数按新案例集配置 |
| 隔离纪律 | 协议条款移植 | 低（两处修正） | 提交信息通道与越界断言通道在本实验补齐为五通道 |

结论：**可迁移的是"方法包"（规则+模板+工具+协议），不可迁移且需按项目重建的只有"考题"（评估集）**——评估集构造本身已被规约化（缺陷史挖掘 + 修复提交父态锚定，装配流程 ④）。

| 组件 | 档位 | DSH 等价形态 | 接入成本 |
|---|---|---|---|
| skill（SKILL.md + assets） | **F-通用** | `.agents/skills/code-review/` 整目录同构 | **近零**（Agent Skills 标准两框架通用） |

## 4. 结论、局限与后续

### 4.1 结论

1. **规则集引导力跨项目泛化获得首个干净正面证据**：留出项目三锚点目标缺陷全部语义命中（socket 挂起 P1×2 / 4xx 误重试 P1 / cron 重入 P0），零适配、强化隔离、信息盲复核后成立；源项目全部命中带答案可见风险，本组无此风险。
2. **收敛速度**：零轮迭代（源项目经三轮迭代达 ≥10/11，留出项目首轮即中）——支持"规则提炼的是缺陷类别的检查程序而非项目实例"的泛化假设；与 skill 边际的条件性（§2.2）共同构成工具价值的完整画像。
3. **方法级迁移成本结构**：知识资产与工具近零成本跨项目/跨框架；评估集按项目重建（约一场）；隔离协议在迁移中暴露并补齐两条通道——**迁移本身是协议完备性的最好检验**。

### 4.2 局限

- 单模型（MiniMax-M3）；三锚点均属可靠性/输入防御类缺陷，领域契约类案例在 fundseeker 上尚待补造（工具价值边界的另一半检验未完成）；
- 对照组 n=3、skill 组同基线 n=2，组间结论（尤其错误率差异）为方向性信号；
- 35 主题分母是"被至少一轮发现且复核确认"的并集，所有轮次都漏掉的问题不在分母内，真实召回只会更低。

### 4.3 后续

- fundseeker 补造领域契约类缺陷案例（cron 调度语义/数据口径一致性）再测 skill 边际（P3 遗留研究项）；
- 跨框架实迁（pi→DSH 或其他 harness）运行级验证 F-通用件"近零"估计；
- 多季度折叠缺陷已单独立项（fundseeker 仓库 docs/，2026-08-20），实现与编码留待下轮——作为评审发现转化为真实维护流程的持续样例。
