## 总体目标

产出一套从软件工程基本原理出发的 Agent 软件设计方法，具体形式（三选一或组合，待决策）：
1. 方法论框架文档（范式对比 + 设计原则 + 适用边界）
2. 中间产物规范集（需求描述、架构描述、接口规约的 LLM 友好模板）
3. 案例重分析报告（用新方法重新审视已有系统/文档）

## 阶段划分（草案）

### 阶段 0：范式对比框架确立
- 确定设计范式清单与正交的对比维度（控制流归属、确定性来源、状态管理、验证方式）
- 产出：范式对比矩阵 v1（修订 00 文档第 2 节）

### 阶段 1：子问题 A——系统构成模式归纳
- 从本仓库已有成果（context-engineering、architecture）+ 外部案例，归纳"LLM + 传统代码 + 向量库 + 知识图谱"的架构结合模式
- 每类模式标注：职责划分依据、接口形态、不确定性控制手段、失败模式
- 产出：架构模式目录（pattern catalog）

### 阶段 2：子问题 B——中间产物规范设计
- 选定一条产物链（需求 → 架构描述 → 接口规约），设计 LLM 友好的产物格式
- 用 design/kb-app 的文档链做回溯分析：哪些产物 LLM 消费良好、哪些造成障碍
- 产出：中间产物规范模板 + kb-app 案例分析报告

### 阶段 3：交叉验证（与方向一衔接）
- 用方向一的某个场景实验检验方向二的规范：按规范产出需求/架构描述，观察对专用 agent 构建效率的影响
- 产出：验证记录 + 规范修订

### 阶段 4：方法论成稿
- 汇总为最终方法论文档，归档至 research 索引

## 度量/检验方式（初拟）

- 规范的判别标准：LLM 能否仅凭产物文档完成预定任务（零口头补充）、产物间一致性可否机器检查
- 案例分析的检验：新方法能否解释已有系统中观察到的失败模式
