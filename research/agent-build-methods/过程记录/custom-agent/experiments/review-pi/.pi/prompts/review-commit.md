# 评审任务：commit {{commit}}

使用 code-review skill 的五步 SOP 评审提交 {{commit}} 的父状态（即评审 `git show {{commit}}` 所示修复针对的代码）。

要求：
1. 先 `git diff {{commit}}^ {{commit}} --stat` 建立变更地图（仅文件与行数统计——**禁止用 git show/log 等任何会输出提交信息的命令查看 {{commit}}**，提交信息属评估答案）；再读相关文件上下文（`git show {{commit}}^:<路径>`）；
2. 逐维度检查（正确性/状态生命周期/契约一致性/变更登记/登记真实性/幂等/并发/防御性）；
3. 意见卡写入 `reviews/{{date}}-{{commit_short}}.md`，遵守红线（每条意见带溯源）；
4. 结束时输出一行摘要：意见数（P0/P1/P2/P3）+ 已检查维度数。
5. **越界断言禁令（2026-08-20，P3 对比分析 §5.4 第 4 类成因）**：禁止对被隔离材料（docs/ 评审报告等禁止读取的文件）的内容做任何断言（如『设计文档未登记』）——对无权核查的事项只能写『未核查』。
6. 行号纪律：意见溯源行号须以锚点视图（git show）复核后写入，避免分块读取造成的行号漂移。
7. 隔离补充（2026-08-19，人工待办 12-1 选项 A）：**禁止读取锚点状态内的既有代码评审报告/缺陷记录文档**（本仓库即 design/kb-app/ 的 10、12、14、17 号评审报告）——此类文档含被评估缺陷的标准描述，读取即评估污染；设计文档与实现说明可正常阅读。内容读取一律经 `git show <锚点>:<路径>` 进行，不直读工作区文件。
