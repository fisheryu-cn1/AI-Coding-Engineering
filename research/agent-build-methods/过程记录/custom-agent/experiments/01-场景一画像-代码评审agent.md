## 1. 场景定义

**一句话**：面向本仓库（及同类研究型仓库）的 PR/commit，AI 先审产出结构化评审意见（分级 P0–P3 + 溯源 + 建议），供人工复审——"AI 先审 + 人后审"治理门禁的真实试验场。

**边界**：只读评审（不自动改代码）；评审依据 = 仓库规范（AGENTS.md / 设计文档 / 评审惯例）+ 通用缺陷模式；输出为评审意见卡，不直接阻塞合并（人工裁定）。

## 2. 九问正式作答

| # | 作答 | 依据/细则 |
|---|---|---|
| 1 交互 | **高（读为主）**：读 git diff、仓库文件、设计文档；写评审意见文件 | 只读写分离——写面窄（意见文件），符合"读密集"特征 |
| 2 可验证 | **强**：意见可对照"已知缺陷标注集"（见 §5）机检召回/误报；单条意见可溯源 | 反馈信号可靠 → 允许 Reflexion 式修订外循环 |
| 3 组合搜索 | 否 | 线性流程，无搜索树 |
| 4 静态分解 | **是（SOP 明确）**：读 diff → 上下文收集 → 规范对照 → 意见生成 → 分级汇总 | 倾向代码编排（LLM 节点内决策） |
| 5 时间跨度 | 分钟级（单 PR）；批量评审时小时级有状态（任务队列） | 单任务简单循环 + 批处理编排 |
| 6 错误代价 | **中**：误报浪费人审时间；漏报可被人审兜住（人在环后置） | 验证深度 P1 级（抽样复核+指标跟踪） |
| 7 团队口径 | **直接对接 D3-B**：AI 先审门禁的调参对象（阈值/分级/采纳率） | 本场景是 RQ-B3 的过程改进试验载体 |
| 8 使用者/规范 | 团队开发者；**规范载体成熟**（AGENTS.md、设计文档链、5 轮评审报告惯例） | 消费既有规范而非另造 |
| 9 分层位置 | 高自主专业位；与 Copilot/Claude Code 的通用评审互补 | AGENTS.md 为互操作公分母 |

**附加问（需求深度）**：评审规范天然是多视角的（规范符合性 / 缺陷模式 / 产物一致性）——**kb-app 模板集 v0 的 R1–R13 规则可直接子集化为评审 checklist**（如 R8 形状同断言、R11 登记真实性、R13 状态生命周期），实现"评审 agent 的行为契约 = 中间产物规范的执行者"。

## 3. 范式走查（决策树结论）

Q1 是 → Q2 是（标注集可验证）→ Q4 是（SOP）→ **代码编排形态**：pi 内核 ReAct 循环 + 扩展将流程约束为固定步骤（skill 定义 SOP）；意见生成在节点内；对单条意见可加"自评→修订"轻外循环（Reflexion 退化版）。护栏层全配（pass^k 稳定性、意见溯源锚点、人审检查点天然存在）。

**LLM 决策密度**：节点内（diff 理解、规范匹配、意见措辞）；衔接处由 skill SOP 与工具白名单约束为确定性。

## 5. 评估集（本场景的独特资产）

**标注语料 = 仓库自带的 5 轮评审报告**（07/10/12/14/17 号，含 S1–S8、P0–P3、R-1~R-13、D-1~D-5 条目，合计约 60+ 条真实缺陷 + 各自 file:line 溯源）：

- 构造法：以被评审的 diff/文档快照为输入，以评审条目为期望意见（召回目标），以"评审未报的正常点"为误报对照；
- 指标口径：意见召回率（对照标注）、误报率、**pass^k**（同输入多次评审的一致性）、平均耗时、人工采纳率（在线）；
- 增量：场景一运行中的人工复审结论持续回流标注集（Hamel 式"从生产长评测集"）。

## 6. 风险与未知

1. 评审质量基线：标注集 ~60 条偏小且集中于 kb-app 域——先做域内基线，泛化另测；
2. 误报噪音影响人审意愿：需分级阈值调参（D3-B3 的第一项实验）；
3. 只读强制的边界（意见文件写入是否算写）：契约指南错误成本判据裁定——意见写独立目录，低风险放行。

## 7. DoD（场景一 MVP）

1. 对一个真实 PR（本仓库历史 commit）产出结构化意见卡（含分级+溯源+建议）；
2. 标注集上召回率/误报率有基线数字；pass^k(k=3) 报告；
3. L1–L5 观测点落地并产出首份轨迹报告（可观测清单 §6 模板）；
4. 组件登记：组件目录新增 ≥6 条实例条目（含契约四字段与迁移参照）；
5. 装配流程 v1 全程有实录（P2 核心产出）。
