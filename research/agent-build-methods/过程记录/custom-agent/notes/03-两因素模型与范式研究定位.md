## 1. 原始思考记录（2026-08-17 备忘整理）

### 1.1 两因素模型：大模型调用的质量来源

通过大模型进行内容生成或根据输入输出工具调用指令等决策，本质是**用调用的输入去匹配大模型训练时习得的模式，并按模式形成输出**。因此输出质量依赖两个因素：

1. **因素 1**：大模型训练时是否习得了当前问题所需要的模式；
2. **因素 2**：当前输入能否准确匹配到所需模式，**并且提供模式输出所需、但大模型沉淀知识以外的信息**（外部信息）。

实际应用中，一旦选定大模型，通常默认因素 1 已大概率具备——**提示词工程、agent 设计范式、harness 工程等，实际都是以因素 2 为目的开展的**。

### 1.2 人类类比：主动澄清 vs 无内置质量门禁

类比人类协作：任务发起方向承担方提任务时，默认对方已具备基本知识能力，要做的是把背景、要求、关键标准说清楚。但人类间沟通与人-系统沟通的一大差异在于：**人类承担方因长期合作关系拥有相对完善的背景上下文，指令不清会主动发起澄清直至明确**；而大模型训练时无特定情景目标，实际应用时上下文常不完整，且限于基础设计**倾向于按概率选择可能性较大的匹配结果径直往下执行——没有内置的质量门禁**。因此任务提交给大模型后，发生"幻觉"类错误的概率远高于提交给人类执行者。

### 1.3 范式工程的核心目标与外围校验层

无论是 agent 构建的设计范式，还是基于基础框架构建面向特定场景的插件，核心目标是在**大模型基础知识限制、上下文窗口限制**两项主要限制条件下：

- 将任务拆分为**单次上下文窗口可处理范围内的子任务**；
- 确保**子任务衔接**；
- **合理构建每次调用的上下文信息**。

ReAct 范式、记忆管理、多智能体协作等都是对上述问题的（不同侧面的）解决方案。但限于当前基础能力仍有限、且实际各类工作任务的上下文信息多数缺乏完整准确的数字化载体，**输出结果不符合要求的情况不可避免**——因此还需要**在外围增加一层校验、反馈的逻辑**（外置质量门禁）。

### 1.4 本研究的主要目的（定位表述）

1. 梳理清楚当前业内常见范式的**适用范围、局限性**以及**细化的合理应用要点**；
2. 研究是否存在常见范式以外的、具有**较高通用性**或**对某些场景有较高复用价值**的其他范式；
3. 针对具体问题，如何**快速确定适用的范式或范式组合**、形成针对性设计方案；
4. 需要组合几种范式或标准方法时，如何支持**低成本、高效率的组合方法技术实现**。

## 2. 对上述设想的分析与评价（2026-08-17）

### 2.1 值得采纳的部分（已采纳为项目的工作表述）

1. **两因素模型是"核心论点"的操作化**（[D1+D2]）：方向二论点"代码退居为人/系统与 LLM 的衔接层"在此获得工程化表述——**衔接层的全部工程（提示词/范式/harness）都是因素 2 工程**。这直接为 D1 组件分层给出理论根据：上下文构建类组件（memory/skills/上下文源）服务于"模式匹配"，工具与验证类组件服务于"模式外信息供给 + 质量门禁"。已作为 D1-S2 问卷问项设计的原理表述。
2. **"外置质量门禁"统一了三个既有结论**（[D1+D3]）：τ²-bench（协调沟通是独立于推理的短板，no-user→dual-control 掉 18–25pp）、MAST FC3（验证缺位 23.5%）、self-conditioning（无门禁则错误在上下文内自我强化）分别从能力测量、失败分类、长程执行三个角度印证 1.2 节的判断；Reflexion（HumanEval 91% vs 80%）则证明外置门禁的收益。"外围校验反馈层"可作贯穿 D2-S4（evals/蜕变测试）与 D3-S3（质量闭环）的统一概念用语。
3. **"两限制 + 拆分/衔接/上下文构建"的目标函数表述**与学术梳理的两维框架**互补而非重复**：两维框架（控制流归属 × 状态管理）回答"范式之间的差异是什么"，本表述回答"范式为什么存在、都在优化什么"。建议共同构成 P1 范式决策树的动机章（已列入计划微调）。
4. **四项研究目的与现行规划高度对齐**：目的 1 = D2-S1（P1 范式决策树）；目的 3 = D1-S2（场景画像问卷，P1 P1 阶段评审）；目的 4 = D1-S3/S1（装配流程 + 组件目录，P1–P2）。定位表述可作为规划文档的"研究目的"引言。

### 2.2 需要修正或限界的部分

1. **两因素模型是启发式近似，不是机理论断**："模式匹配"是对自回归生成与 in-context learning 的隐喻化表述（其机理学界未有定论）。作为工程定位语言可用，写入对外文档时须标注为启发式模型，避免与预训练机理混淆。
2. **"选定模型即默认因素 1 具备"在关键场景不成立**：单次具备 ≠ 稳定具备（pass^k 腰斩），且能力边界随代际漂移（方向二笔记 03 已记）。修正表述：**因素 1 按"能力预算"管理（时间地平线 / pass^k 口径，属观测与评估职责，D3-S3/S5），因素 2 按工程优化职责（构建期，D1/D2）**——这一修正恰好把三方向的分工说清了：构建工程管因素 2，观测评估管因素 1 的持续验证。
3. **目的 2（范式外探索）须严格限界以防发散**：学术梳理 26 篇与工业对比其实已覆盖若干"非常见"范式（LLMCompiler 的 DAG 并行、ToT 搜索、smolagents 的 code-as-action、Reflexion 外循环、SAS↔MAS 级联路由）。因此目的 2 的执行范围限定为"**在已收集谱系内辨识空位**"（如：计划-执行-验证三段外循环的标准化、code-as-action 与工具调用的混合、级联路由作为默认控制流的条件），不新开文献调研线；发现的候选范式优先作为场景一的可选组件试验，不单独立项。
4. **人类类比的可检验推论已并入既有模板线**：类比提示"主动澄清应作为一等公民机制"——与方向二笔记 03 的澄清循环（含终止条件开放问题）合流，落入 D2-S3 模板集与场景一交互设计，无需新增研究问题。
