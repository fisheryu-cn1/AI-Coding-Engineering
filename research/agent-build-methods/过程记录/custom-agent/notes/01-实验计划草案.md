> 状态：骨架。阶段划分与产出物为初步假设，待场景选定后细化。每个阶段结束产出一个可检查的里程碑文档。

## 总体目标

形成并验证一套"场景分析 → 组件选配 → 组装落地 → 评估迭代"的专用 agent 快速构建方法，产出：
1. 方法论文档（场景分析框架 + 组件模型 + 工作流程）
2. 可复用组件库（至少覆盖 N 个场景沉淀的组件）
3. 实验报告（含度量数据：构建耗时、复用率、任务成功率）

## 阶段划分（草案）

### 阶段 0：框架能力摸底（1 个实验）
- 目标：弄清 pi / DSH 的定制机制全集与边界（能改什么、不能改什么、改动成本）
- 做法：各实现一个最小定制（如自定义工具 + 自定义 skill），记录机制文档
- 产出：`materials/` 下的框架机制摘要 + 最小示例代码归档

### 阶段 1：单场景打穿（方法原型）
- 选定 1 个场景（候选见 00 文档第 5 节），在一个框架上完整走一遍流程
- 过程中记录：场景分析问了哪些问题、组件如何切分、哪些坑
- 产出：场景模板 v1 + 方法论文档 v1

### 阶段 2：换场景验证通用性
- 用阶段 1 的方法做第 2 个（差异较大的）场景
- 度量：新组件占比 vs 复用占比、构建耗时对比
- 产出：方法论文档修订 + 组件库扩充

### 阶段 3：换框架验证迁移性
- 把一个已完成的场景迁移到另一个框架
- 度量：迁移成本、哪些组件天然可迁移（纯提示/技能类）哪些不可（框架 API 绑定类）
- 产出：框架无关层抽象 + 实验总报告

## 度量指标（初拟）

- 构建耗时（从场景描述到 agent 可用的工时）
- 组件复用率（新场景中直接复用组件数 / 总组件数）
- 任务成功率（场景评估集）
- 人工接管/干预频率
