# 方向二：从软件构建基本原理重新审视 Agent 软件设计方法

## 方向说明

对比 Agent 构建的几种常用设计范式（ReAct 反应式、plan-and-execute、workflow 编排、多 agent 协作、SDD 式规范锚定等），回到更基础的软件工程原理视角，重新审视 Agent 类软件的设计方法，聚焦"需求 → 需求描述文档 → Agent 架构设计"这一前端过程。两个子问题：

- **子问题 A（系统构成）**：如何理解 LLM 作为软件核心组件之一，与传统代码逻辑、向量库、知识图谱等组件结合形成最终系统的方式——组件职责划分、接口形态、确定性与不确定性的边界处理。
- **子问题 B（设计过程）**：在 Agent 软件的设计过程中如何有效利用 LLM 能力——为了让 LLM 能有效参与（或被有效用于构建），中间产物（需求文档、规约、架构描述）的输出规范和设计过程本身需要怎样的调整。
