> 日期：2026-08-17（P1 产出）
> 话题标签：[D2]（[D1+D2]：第 5 节字段供方向一组件目录实例化）
> 依据：`materials/软件工程原理与LLM系统.md`（六维契约差异、DbC、三方观点）、notes/02 §4、notes/03（能力边界三段）、kb-app 回溯案例（契约实践与弱断言教训）、模板集 v0（R7/R8）

## 1. 划界三判据：什么交给 LLM，什么交给确定性代码

对每一个候选决策点，依次过三问（任一判据不满足即倾向代码侧）：

| 判据 | 问题 | 代码侧信号 | LLM 侧信号 |
|---|---|---|---|
| **可验证性** | 该决策的对错能否被机器廉价判定？ | 有 schema/断言/测试可判 | 输出开放、判定需人审 |
| **错误成本** | 决策错误的代价与可回滚性？ | 权限、资金、状态一致性、不可逆操作 | 错误可被下游拦截或低成本重试 |
| **知识内蕴性** | 完成该决策所需知识在模型内还是外部？ | 需私域/实时/结构化账本数据 | 语义理解、非结构化转换、开放域常识 |

**边界三段模型**（notes/03）：①模型内蕴知识（如 UML 建模方法）——直接用；②外部知识（业务规则、用户行为、组织约定）——须人工供给；③**供给方式设计**——静态文档 / 动态澄清循环 / 参照物清单（checklist 化外部知识）。第 ③ 段最易被忽视：τ²-bench 证明"协调沟通是独立于推理的能力短板"，缺口发现→澄清问题→人工补齐的循环协议应作为一等机制设计。

**漂移警示**：边界随模型代际漂移（今天须外供的明天可能内蕴）——边界不是一次性划分，应列入观测对象（方向三 RQ-A3：能力预算的持续验证）。

## 2. 四类契约形态

LLM 组件的契约 = 传统 API 契约的四个变形面：

| 契约面 | 内容 | 表达方式 | 校验手段 | 案例 |
|---|---|---|---|---|
| **输入契约** | 上下文的构成承诺：必含信息、格式、预算、参照物 | prompt 模板 + 上下文组装规约（输入 schema、token 预算、溯源锚点） | 组装后断言（预算/必含字段/锚点存在） | kb-app FR-3.2/3.3（token 预算 8k + 溯源锚点）；16 号任务卡（file:line + Produces/Consumes） |
| **输出契约** | 结构、语义与口径 | JSON Schema + 字段语义表 + 受控词表 | schema 校验 + **形状同断言**（禁只断 code，模板集 R8） | 13 §2.2 错误三键 {code,message,suggestion}；06 §4.3 type 受控词表 |
| **行为契约** | 质量底线与禁止行为 | eval 集（标注样本+阈值）+ 蜕变关系 + 红线清单 | 离线 evals / 在线 judge / CI 门禁（promptfoo 式） | τ-bench pass^k 口径；06 §7 七条红线；kb-app DoD |
| **演化契约** | 变更时的兼容承诺 | 版本号 + 变更登记 + 回写清单 | manifest/指纹比对 + 回归门禁 | 06 §8（v1→v2 递增 summary_version）；权威转移+回写制度 |

**六维差异提醒**（vs 传统 API，引用材料 §3.1）：语义概率性、版本静默漂移、契约不可直接执行、无唯一 oracle、幻觉失败模式、组合不可加——因此每类契约都要回答"概率性满足下，校验手段的误报/漏报率如何控制"（judge 信度协议见第 4 节）。

## 3. 不确定性对策（按侵入度排序）

1. **评估集前置**：上线前定义 evals（标注样本 + 阈值 + 口径），从生产轨迹持续长出"小而毒"的评测集（Hamel 方法论）；
2. **确定性护栏**：schema 校验、guardrail（OpenInference `GUARDRAIL` span）、规则前置检查；
3. **兜底逻辑**：失败降级路径（重试/fallback 模型/默认值——09 §9 两级重试是范例）；
4. **多路校验**：独立验证器（MAST FC3 对策）、多 judge 共识 + 交换平均（位置偏差对策）、judge 版本固化；
5. **人在环**：接管点设计（Inbox 审核式 / 检查点式）；接管率作为在线质量代理信号（方向三）。

## 4. judge 信度协议（自动质量门禁的前提）

工程化清单（实证依据见方向三调研 §3.3）：rubric 化评分标准；交换-平均；多 judge 共识；与人工标注对齐的抽样校准；**judge 本身变更纳入回归门禁**（自我偏好源于低困惑度，非身份意识——换 judge 模型等于换尺子）。

## 5. 组件目录的契约字段（[D1+D2] 接口）

方向一组件目录的每个组件条目应含契约四字段（实例化本指南）：

```
输入契约：必含上下文/格式/预算/参照物
输出契约：schema/语义/受控词表
行为契约：eval 集/红线/口径（pass@1|pass^k）
演化契约：版本策略/回写义务
```

组件即契约的载体：目录登记时契约字段缺失的组件标记"契约不完整"，不得进入生产装配。

## 6. 使用边界

- 本指南管"组件边与接口"，不管"组件怎么装配"（方向一）与"产物怎么写"（模板集 v0）；
- 契约校验本身有成本——按错误成本分级（P0 全量校验 / P1 抽样 / P2 登记豁免）；
- 划界判据是启发式：最终裁定以场景实测（eval + 接管率）为准，并纳入观测回溯。
