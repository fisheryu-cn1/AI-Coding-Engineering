## 1. 需求产物模板

### 1.1 术语表（数据字典雏形）

| 字段 | 说明 | 机检点 |
|---|---|---|
| 术语 / 定义 / **颗粒度**（该术语对应的实现载体粒度，如文档级/章节级/chunk 级） / **权威源**（该术语的唯一权威文档与章节；清单类参照物须声明单源） | 案例实证：Chunk 与 Section 的颗粒度承诺错位（报告 §5-1）；主题清单两处硬编码漂移（§5-3） | R1 颗粒度一致、R2 名词单源、R3 参照物单源 |

### 1.2 场景卡（业务场景故事）

| 字段 | 说明 |
|---|---|
| 场景编号 / 触发条件 / 主对象 / 执行流程（步骤化）/ **验证点**（该场景的可判 定结果） | 案例实证：S1–S6 均含隐含验证点（如 S4 的"移动零重抽取"）；反向覆盖用 R4 矩阵核查 |

### 1.3 功能需求卡（FR）

| 字段 | 说明 |
|---|---|
| 编号 / 需求 / 优先级 / **溯源**（决策或外部依据的文档+章节）/ **实现载体颗粒度**（该 FR 落地后的最小操作单位）/ **场景反向链接**（对应场景卡编号；无场景须显式标注"配置/运维类-无场景"）/ **演化注记**（裁决变更时以括注+权威文档引用回写，不静默改写） | 案例实证：FR-1.5 引 manifest 规范、FR-3.1 的 MVP 裁决括注（权威转移模式的产物内形态）；FR-1.6/4.6 无场景未标注（§5-5） |

### 1.4 非功能需求卡（NFR）

| 字段 | 说明 |
|---|---|
| 编号 / 需求（**必须量化**：数字+口径+环境）/ **验收映射**（指向验收标准条目，无映射须登记"延后至 DoD-x 实测"） | 案例实证：NFR-4 性能数字在验收标准中缺失、直到 12 号 DoD-8 才实测（§5-4） |

### 1.5 验收标准

| 字段 | 说明 |
|---|---|
| 编号 / 可判定语句（含具体测试锚点，如具体查询词、具体操作）/ 对应 FR/NFR / **证据类型**（测试/实机/留档截图） | 案例实证：验收 3 用具体主题词可测；验收 4 "≤预算 token"可判定 |

## 6. 使用说明与边界

- **定位**：本模板集是"产物内建一致性"的最小机制，替代"依赖评审注意力"（报告 §5 关键观察）；不替代评审——产物间覆盖核查（07 模式）与代码评审仍是外置门禁的第二、三层。
- **抽象层声明（2026-08-17，custom-agent/notes/04）**：模板属**抽象层**成果物（框架层 + 领域先验层），落地须经理由 D1 装配流程执行的**具象化填充**（结合场景上下文填回被抽象的部分）；填充方法的重要性高于模板本身——使用本模板集时，"如何填"比"有什么模板"更值得记录与沉淀。
- **成本分级**：R1–R5/R7/R9/R12/R13 可机检（★），优先脚本化；R4/R6/R8/R10/R11 暂人工，模板字段设计已使其"填表即自查"。
- **弱 oracle 边界**（notes/03 §2.2）：规则集只能证伪不一致与覆盖缺口，不能证明需求完备——完整性仍靠参照物覆盖（场景卡/术语表的覆盖面）与澄清循环。
- **v1 预期修订点**：场景一试用后校验规则的可操作性与误报率；R13 的泛化（图/表系统的通用检查表）；与 D3 观测清单的对齐（R11/R12 的登记即观测数据的雏形）。
