## 5. 06-摘要构建与命名规范

1. **产物定位**：数据/内容规范——`references/<topic>/summaries/` 全部论文摘要的构建、命名、质量约定；声明"05 §2.6 为本文档的设计内浓缩版，以本文档为准"。读者为生成/审核摘要的 Agent 与研究者。
2. **关键内容**：
   - §3 命名模式 `<NN>[-<letter>]-<中文短标题>.md`：NN 与源 PDF 前缀严格一致（绑定键）、不带 `_vN`（锚点不随版本漂移）、禁非法字符与空格、主题内唯一；
   - §4 头部元数据：新文一律 YAML frontmatter（title/source_pdf/arxiv_id/arxiv_version/authors/year/venue/type/generated_at 九必填字段表）；§4.3 type 受控词表（用途×粒度两段式）；§4.5 存量 ~104 篇 blockquote 格式宽容兼容映射表；
   - §5 固定五段结构（适用场景/主要观点与方案/达到的效果/参考资源/一句话索引），顺序不可变（解析器按 `## N.` 定位）；
   - §6 锚点规范：精确到论文原生 §、多锚点 `; ` 分隔、禁"见原文"；与 KB `section_path` 双轨、章节标题匹配对齐、失败降级文档级；
   - §9 INDEX.md 规范（论文列表 `#` 列与文件名前缀一致）。
3. **上下游衔接**：上游 01（FR-1.8）、05 §2.6；下游 05 §2.6.1/§2.6.2（浓缩回写）、09 §5（M2 manifest 绑定：frontmatter 字段 + blockquote 宽容解析）、11 §3（L1/L2/L3 检索分层消费：一句话索引作 L1 ~100–200 token）、12 P1-5（策展文本构建伪 chunk）。
4. **验证机制**：§7 质量红线 7 条（审核时逐条勾选：一句话索引独立可读含数字、锚点精确、数值不外推、头部与 manifest 一致、文件名合规、五段齐全、token 落 100–200）；§11 校验清单 8 项（给生成器/审核器）；§4.4 与 `arxiv_2026-07_manifest.md` 台账五字段对齐，不一致时 `kb index` 报 `SUMMARY_MANIFEST_MISMATCH`（摘要↔台账↔源文件三方机检）；§3.3/§8 正反例。
