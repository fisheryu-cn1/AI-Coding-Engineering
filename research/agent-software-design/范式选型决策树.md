## 1. 动机：范式为什么存在（两限制与四目的）

LLM 核心软件的构建工程受**两项主要限制**约束：模型基础知识限制（因素 1）与上下文窗口限制。一切范式工程（提示词/agent 范式/harness）的实质都是在做三件事（因素 2 工程）：

1. 把任务拆分为**单次上下文窗口可处理**的子任务；
2. 保证**子任务衔接**（控制流与状态传递）；
3. 合理**构建每次调用的上下文**（匹配已习得模式 + 供给模式外信息）。

ReAct、记忆管理、多 agent、workflow 编导都是对同一问题的不同侧面解。本研究四个目的：①常见范式的适用范围/局限/应用要点；②谱系内辨识高复用非常见范式；③具体问题快速定范式或组合；④低成本组合实现。

## 2. 两维框架（含第三刻度）

| 维度 | 刻度 | 含义 |
|---|---|---|
| **控制流归属** | 模型循环 / 静态计划 / DAG 并行 / 树搜索 / 代码编排 / 消息涌现 | "下一步做什么"由谁决定 |
| **状态管理** | 上下文内 / 外部化+检查点 / 记忆流+反思 | 状态放哪、如何维护 |
| **LLM 决策密度**（kb-app 案例新增） | 节点内 / 衔接处 / 全局 | LLM 决策出现在流水线的哪一层 |

趋势锚点（工业对比 C 节）：第二代框架普遍回归"**开发者显式编排 + 模型在受限点决策**"；**状态管理成为框架分水岭**；多 agent 边界收敛为"读密集可并行、写密集慎用"。

## 3. 判别问句序列（决策树）

```
Q1 任务需要与外部环境/工具交互吗？
├─ 否 → 纯提示工程（CoT / PS+ 静态计划）。多采样+投票（best-of-N）为一切增强的对照基线。
└─ 是 → Q2 存在可验证的成败信号且允许重试吗？
    ├─ 是 → ReAct 循环 + Reflexion 式"评估→反思→重试"外循环
    │        （先答：反馈信号从哪来、是否可靠——单元测试/环境判定/人工）
    └─ 否 → Q3
    Q3 任务是组合搜索/规划型，且中间状态可自评吗？
    ├─ 是 → ToT 树搜索（预算警示：token 约 5–10 倍，需任务特化调参）
    └─ 否 → Q4
    Q4 任务可预先静态分解吗？
    ├─ 是 → 子任务独立且多工具调用？ → LLMCompiler 式 DAG 并行
    │        否则 → plan-and-execute（静态计划 + 顺序执行）
    │        流程高度确定 + 长期运行？ → 代码编排（workflow，LLM 仅节点内决策）
    └─ 否（动态环境） → 必须带 replan 的 plan-and-execute / 图编排
Q5 需要多个 agent 吗？（例外而非常态——四个前置检查）
    ① 已用"单 agent + best-of-N"作对照且确有差距？
    ② 任务/角色/终止规范已显式写清？（MAST FC1 44.2% 的拦截项）
    ③ 独立验证器就位？（FC3 23.5%）
    ④ 读密集可并行（研究/检索类）而非写密集（代码工程类）？
    全是 → 分层 MAS（角色扮演对话仅用于探索/数据生成，SOP 装配线用于确定性流程）
    有否 → SAS↔MAS 级联（简单请求 SAS、疑难升级 MAS）
Q6 任务时间跨度与状态性？
    ├─ 短且无状态 → 简单循环即可
    ├─ 长程（超模型时间地平线，小时级）→ 外部化状态 + 分段可验证检查点 + 人类检查点
    └─ 长时程连续性（一致性/多日程）→ 记忆流 + 加权检索 + 周期反思（成本警示）
```

判据来源：学术梳理 §六决策框架；SAS/MAS 数字（MAS 优势随模型增强缩至 0.8%–3.0%、prefill 贵 4–220×、级联 +12%/省 20%）见 `materials/agent范式-学术梳理.md` §4.2（精读核实版）。

## 6. 可靠性护栏层（与范式正交，必选）

1. **指标口径**：任务成功率区分 pass@1 / pass^k（生产看 pass^k）；
2. **外部化状态**：长程任务不依赖上下文滚动（self-conditioning 对策）；
3. **分段验证**：每段可判定成败；验证深度按错误成本分级（P0–P3）；
4. **人类检查点**：任务时长超出模型时间地平线（80% 口径再打 4–6 倍折扣）必须设；
5. **门禁**：harness/prompt 变更触发质量回归门禁（通用 CI 检不出，Agentic QA/HarnessFix 互证）。

## 7. 边界

- 本树解释"范式选择"，不解释"组件实现"（见 `组件划界与契约指南`）与"装配实现"（方向一组装流程）；
- 判据基于 2024–2026 证据，模型代际更替后需按 pass^k/时间地平线重新校准（能力边界漂移）；
- 弱 oracle 边界：树给出的是"适用候选"，最终以场景一的实测评估为准。
