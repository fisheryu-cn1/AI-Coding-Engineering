# GETTING-STARTED：从需求到可机器检查的规范——快速上手

> 面向第一次接触本方法的使用者。读完本页即可部署环境并开始第一个案例；原理可以后懂，先用起来。
> 研究者视角的材料（日志/报告/价值实证）与本页分离，入口见文末"深入阅读"。

## 1. 这套方法做什么

把自然语言需求逐步变成**机器可检查**的规范文档。检查四类问题，前三类机器判定，第四类显式留给人：

| 问题 | 谁判 | 怎么判 |
|---|---|---|
| 规则自相矛盾？ | 机器 | Z3 求解器报冲突并点名是哪几条规则（unsat core） |
| 需求漏了承接（登记了但模型里没有）？ | 机器 | 绑定闭包：每条需求↔模型元素的对照全解析 |
| 流程有死端/终态泄漏？ | 机器 | 状态机五性质检查 |
| 需求本身有歧义/自由度？ | **人** | 翻译时强制显式标记，裁决记录在案（不静默选择） |

一句话：**机器能判的全部交给机器，机器判不了的被迫显式，人来裁决且留痕**。

## 3. 核心概念（六个，先能用）

1. **需求登记表**（`raw/`，模板 T1）：把 NL 原文条目化，每条有唯一 ID（BR-001/FUNC-002/RULE-003…八类前缀）。原文不改，只追加澄清。
2. **概念模型**（`formal/*.puml`）：条目翻译成 PlantUML 类图+**决策注解**（`@disjoint` 互斥、`@required` 必填、`@pattern` 格式、`@decision` 裁决留痕），再确定性转换为 OWL/SHACL。
3. **翻译审计表**（`review/E30-*`，模板 T3）：人逐行核对翻译忠实度。表格分**机器区**（前五列，只读）与**人工区**（✍ 前缀三列，就地填写）——原始输出永不被覆盖。
4. **人工决策记录**（`review/E41-*`，模板 T4）：歧义与待输入事项的裁决档案，每节固定八行；**结论行空=待办，非空=已完成**，一望即知。
5. **检查链**（`method/14`）：七项机器检查+台账留痕（Run-N 只追加，含差异归因）。
6. **执行队列**（`review/G90-*`）：脚本自动从评审文件收集"待机器执行"事项——你裁决完成的瞬间，对应动作在此解锁。

review/ 目录文件名前缀：**E**=人工填写件、**V**=只读、**G**=机器生成。

### 计算引擎一览（它们是并列的，各管一段）

| 引擎 | 类型 | 回答什么问题 |
|---|---|---|
| HermiT | OWL 描述逻辑推理器 | 分类体系与断言有没有矛盾、谁蕴含谁（"是什么"的问题） |
| Z3 | SMT 求解器 | 一组数值/逻辑约束有没有解、矛盾出在哪几条（"数值与规则"的问题；**与 OWL 推理无关，是并列引擎**） |
| pySHACL | 形状校验器 | 实例数据符不符合结构约束（必填、格式） |
| fsm_check | 自研图遍历 | 状态机结构性质与场景路径 |
| 比对器（绑定闭包/模型 diff） | 自研文本结构比对 | 需求↔模型↔层间的覆盖与漂移 |

BDD 场景检查不是第六个引擎——它是**编排层**：按场景类型把断言路由给上表引擎（状态约束→HermiT、动作路径→fsm_check、数值边界→Z3）。

## 4. 微演示：三条需求走一遍核心链路（自包含，约两分钟读懂）

一组迷你需求（"设备借用"，为本页虚构）：

> **DEP-1** 设备状态：idle（空闲）/ in-use（借用中）/ returned（已归还）
> **DEP-2** 单次借用不得超过 30 天
> **DEP-3** VIP 用户单次借用 45 天（固定权益）

两条规则在文档里各自都"合理"。翻译位把**两条都忠实编码**进 Z3（规则名内嵌来源编号）：

```python
from z3 import *
s = Solver(); s.set(unsat_core=True)
d = Int('borrow_days')
s.assert_and_track(d <= 30, 'DEP-2_借用上限30天')
s.assert_and_track(d == 45, 'DEP-3_VIP固定45天')
print(s.check(), list(s.unsat_core()))
```

真实运行输出：

```
check: unsat | core: [DEP-2_借用上限30天, DEP-3_VIP固定45天]
```

机器立即报告矛盾，并**点名是哪两条规则**（unsat core 按规则名溯源）。注意：矛盾不在任何一条规则的文字里——只有两条同时为真时才冲突。这正是纯人工评审最容易漏的形态。

接下来是人的回合：裁决 DEP-2 的适用范围（它本意是"普通用户"），在决策记录里写明结论与附记，然后修正编码：

```python
s2 = Solver(); s2.set(unsat_core=True)
n, v = Int('normal_days'), Int('vip_days')
s2.assert_and_track(n <= 30, 'DEP-2v2_普通用户上限30天(裁决后加限定)')
s2.assert_and_track(v == 45, 'DEP-3_VIP固定45天')
print(s2.check(), list(s2.unsat_core()))
```

```
裁决后 check: sat | core: []
```

消解后回到自洽——且"DEP-2 曾有歧义、裁决采纳了'普通用户'限定"这件事永久记录在案（后续任何人可溯）。这就是本方法的日常循环：**机器点名冲突 → 人裁决并留痕 → 机器复核通过**。其余六项检查（本体一致性/绑定闭包/流程性质/…）同构，见 method/14。

## 5. 你的第一个案例（五步）

```bash
cp -r templates/case-template cases/mine
```

1. `raw/` 放原始需求+T1 登记表（AI 可预填，逐条人工确认）；
2. `formal/` 建概念模型 puml（AI 起草或手写，注解词表见 method/13 §3）：
   ```bash
   python tools/scripts/puml2owl.py cases/mine/formal/concept-model.puml cases/mine/formal/concept
   # 首转产物复制入 cases/mine/regression/baseline/ 作为决定性基准
   ```
3. 跑检查链（复制即用，详见 method/14"操作规程"节）：
   ```bash
   python cases/mine/formal/rules_z3.py                          # 规则（如有）
   python tools/scripts/check_model_bindings.py cases/mine       # 绑定闭包
   python tools/scripts/fsm_check.py cases/mine/formal/flow-model.puml   # 流程（如有）
   python tools/scripts/collect_review_actions.py cases/mine     # 执行队列
   ```
4. `review/` 按 T3/T4 建审计表与决策记录，人工填写（看到哪行记到哪行，保存即完成）；
5. 队列 `待执行 0 / 裁决后 0` + 绑定零 `[暂缓]` = 案例收官。

每次机器检查的输出粘进 `reports/` 台账（T5），注明触发原因；结果与上次不同必须归因。

## 6. 常见问题

- **pip 装不动**：加清华镜像（见 §2 命令注释）；
- **java 不在 PATH**：安装 Temurin 17+；check_env 会明确报这一项；
- **什么时候信机器、什么时候信自己**：七项检查绿灯≠需求正确（机器只判一致性/完整性/性质，不判需求本身好坏）；审计表与决策节是你的阵地——机器的边界在 method/11 有精确划线；
- **AI（LLM）可以用在哪**：起草登记表/翻译模型/预填审计表/回译工作台四个辅助位；**判定永不交给 LLM**（method/11 红线）；产物只进预填位与 .puml。

## 7. 术语表（操作术语，按出现频率）

| 术语 | 一句话 | 详见 |
|---|---|---|
| 条目 ID | 需求的终身唯一编号（RULE-003 式，八类前缀） | T1 |
| 决策注解 | puml 注释行承载的语义决策（@disjoint/@required/@pattern/@decision） | method/13 §3 |
| 行 ID | 审计表行的终身锚点（TA1-03 式），下游一切引用的单位 | method/16 §3 |
| 机器区/人工区 | 表格/决策节的读写分区：机器区人只读，人工区机器不动（除退回豁免） | method/16 §3/§4 |
| 决策节 | E41 里一个待裁决事项的八行档案（决策要求/机器执行/证据/状态/结论/附记/签注/沿革） | method/16 §4 |
| 附记 | 裁决的完整陈述（论证/需求修正）；结论只放一句话主句 | method/16 §4 |
| 轮次/沿革 | 决策被退回重议的历史：状态带轮次，各轮原文只追加 | method/16 §4.1 |
| 绑定清单 | 需求 ID↔模型元素定位符对照+豁免政策；三闭包检查的输入 | method/13 §7 |
| [暂缓] | 显式的"现在做不了但路径明确"，不是豁免不是遗漏 | model-bindings 实例 |
| Run-N | 台账里一次机器检查的完整留痕 | method/14 |
| 签收门 G0–G6 | 每阶段的进入下一阶段条件 | method/10 |
| 解锁 | 决策状态变已裁决→其机器执行动作自动转入待执行组 | method/16 §4 |

**理论术语**（可后懂）：Z_真/Z_伪（文档链上真决策/伪决策的集合）、分离点（Z_真 归零的最早链上位置——本方法就是把分离点前推到需求层）、分歧度（多次独立生成的语义等价类数，R4 实验）。见 README 理论根基节。
