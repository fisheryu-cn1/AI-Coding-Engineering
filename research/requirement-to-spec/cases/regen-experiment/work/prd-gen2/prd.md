# 个人消费贷款管理系统 PRD

## 1. 背景与目标

- 业务背景：某消费金融公司面向有日常消费资金需求的个人用户（用途涵盖装修、教育、旅游、医疗等），需搭建个人消费贷款管理系统，提供在线申请、自动审批、电子签约的最小可用闭环。
- 目标：
  - 为个人用户提供从贷款申请到审批签约的端到端在线办理入口；
  - 以参数化配置的评分规则实现自动审批，避免人工审批带来的主观差异与处理延迟；
  - 在合同环节透明展示费率等关键信息，支持电子签约后形成完整业务闭环。
- 成功标准：
  - 完成 Borrower / LoanOrder / CreditResult 三大实体的核心维护与端到端流转；
  - 完整跑通 M1 申请、M2 自动审批、M3 电子签约三个里程碑；
  - 前后端项目均可完成依赖安装与编译（NFR-001）；
  - 配套交付 SQL 初始化脚本（含示例数据）与 README（环境要求、启动步骤、主要页面入口）。
- 关联需求 ID：BR-001、BR-002、FUNC-001、FUNC-002、FUNC-003、NFR-001、DEL-001、DEL-002

## 4. 业务流程

### 主流程

1. 借款人分步填写申请信息（个人信息、职业信息、联系人信息、贷款需求），保存草稿（LoanOrder.status = draft）。——FUNC-001、UI-001、RULE-002
2. 借款人确认信息后提交申请，系统将 LoanOrder.status 推进至 pending，并生成待处理 CreditResult（decision = 待审核）。——FUNC-002、FLOW-001、FIELD-003
3. 系统按评分规则进行自动审批：
   - 分数 ≥ 阈值：CreditResult.decision = approved，记录 approved_amount、approved_rate、decision_reason；LoanOrder.status 推进至 active。——RULE-001、FIELD-003、FLOW-001
   - 分数 < 阈值：CreditResult.decision = rejected，记录 decision_reason；LoanOrder.status 直接推进至 closed。——RULE-001、FIELD-003、FLOW-001
4. 申请人在详情页查看完整合同信息（年化利率、服务费、逾期罚息等关键费率来自配置表）。——FUNC-003、UI-004、RULE-004
5. 合同生命周期结束后，LoanOrder.status 推进至 closed，归档完成。——FUNC-003、FLOW-001

### 异常流程

- 表单必填项缺失：提示缺失字段；保存草稿与直接提交均触发相同校验规则（草稿不等于免校验）。——RULE-002
- 贷款用途取值超出固定枚举：提示取值非法，仅允许装修 / 教育 / 旅游 / 医疗 四类。——RULE-003
- 关键字段格式错误（如身份证号、电话）：基础校验不通过时阻断保存并提示。——RULE-002
- 评分规则未配置默认值：系统在配置表读取阈值/权重，缺失则视为异常流程，需提示维护方补充配置后才能完成自动审批。——RULE-001

### 边界流程

- 删除申请：任意状态下均可执行；删除 LoanOrder 时级联删除关联的 CreditResult。——FLOW-001
- 终态处理：closed 为统一终态（无论审批通过或拒绝，完成全部流程处理后归结到 closed），不可重开。——FLOW-001
- 审批结果不可翻转：CreditResult.decision 一经形成（待审核 → approved / rejected），不得回退或修改。——FLOW-001、FIELD-003
- 状态维度拆分：单据流程状态由 LoanOrder.status 承载（四态：draft / pending / active / closed），审批结果由 CreditResult.decision 承载（三态：待审核 / approved / rejected），二者独立持久化、互不覆盖。——FLOW-001、FIELD-002、FIELD-003
- 用途字段固定枚举：仅可在 {renovation, education, travel, medical} 中取值，业务侧不可自由扩展。——RULE-003
- 费率固定展示：年化利率 3.5%、服务费率 1%、逾期罚息率 5% 为产品确认的默认值，可在配置表中调整。——RULE-004

## 5. 业务规则

| 规则 | 说明 | 关联需求 ID |
| --- | --- | --- |
| 自动审批通过条件 | 系统按收入、负债等指标计算评分；分数 ≥ 配置表维护的阈值即通过；阈值与权重由配置表维护，可参数化配置 | RULE-001 |
| 自动审批拒绝条件 | 分数 < 配置表维护的阈值即拒绝；拒绝时给出决策原因（系统记录的自动审批决策原因） | RULE-001、FLOW-002 |
| 评分模型默认值 | 配置表需提供一套合理的默认评分阈值与权重，确保开箱即用 | RULE-001 |
| 表单必填项 | amount、term_months、id_number、phone 四字段全部必填；保存草稿与直接提交均触发同样校验 | RULE-002 |
| 关键字段基础校验 | 身份证号、电话、金额、期限等关键字段具备基础格式与取值校验 | RULE-002 |
| 贷款用途枚举 | 用途字段为固定枚举，仅含装修 / 教育 / 旅游 / 医疗 4 类 | RULE-003 |
| 合同费率展示 | 合同详情页展示年化利率、服务费、逾期罚息等关键费率；费率来自配置表维护的固定值（默认：年化利率 3.5%、服务费率 1%、逾期罚息率 5%） | RULE-004 |
| 单据流程状态机（四态） | LoanOrder.status 取值 ∈ {draft, pending, active, closed}；合法迁移：draft → pending、pending → active、pending → closed、active → closed | FLOW-001 |
| 状态终态 | closed 为统一终态，不可重开；删除订单级联删除 CreditResult | FLOW-001 |
| 状态流转驱动方式 | 状态流转由自动审批结果直接驱动；MVP 主流程不引入人工操作环节；流程节点区分保留以备后续完整版本挂载处理逻辑或外部系统数据交换 | FLOW-001、FLOW-002 |
| 审批结果不可翻转 | CreditResult.decision（取值 ∈ {待审核, approved, rejected}）作为单据属性持久化，一经形成不可翻转 | FLOW-001、FIELD-003 |
| 决策原因记录 | 状态变化时由系统记录决策原因 decision_reason，作为状态变化的依据与审计字段；不再使用"人工处理意见"语义 | FLOW-002 |

## 6. 字段、数据与状态口径

| 项目 | 口径 | 来源 | 关联需求 ID |
| --- | --- | --- | --- |
| 借款人实体（Borrower） | 字段：id、name（姓名）、id_number（身份证号）、phone（电话）、income（收入）、employer（单位）、position（职位） | 实体范围 | FIELD-001 |
| 贷款订单实体（LoanOrder） | 字段：id、borrower_id（关联借款人）、amount（金额）、term_months（期限）、purpose（用途，LoanPurpose 枚举）、interest_rate（利率）、status（单据流程状态字段） | 实体范围 | FIELD-002 |
| 审批结果实体（CreditResult） | 字段：id、order_id（关联订单）、score（评分）、approved_amount（审批额度）、approved_rate（审批利率）、decision（审批决策）、decision_reason（决策原因） | 实体范围 | FIELD-003 |
| 贷款用途枚举（LoanPurpose） | 固定枚举：renovation（装修）、education（教育）、travel（旅游）、medical（医疗）；业务侧不可自由扩展 | 用途固定枚举 | RULE-003 |
| 单据流程状态（status） | 取值 ∈ {draft（草稿，起始点）, pending（待处理）, active（签约生效）, closed（完成，统一终态）}；合法迁移见 FLOW-001 / 业务规则表 | 单据流程状态机 | FLOW-001、FIELD-002 |
| 审批决策（decision） | 取值 ∈ {待审核, approved（通过）, rejected（拒绝）}；与单据流程状态字段 status 解耦，独立持久化；一经形成不可翻转 | 审批结果维度 | FLOW-001、FIELD-003 |
| 决策原因（decision_reason） | 系统记录的自动审批决策原因，作为状态变化的依据与审计字段；不再使用"人工处理意见"语义 | 状态变化审计 | FLOW-002、FIELD-003 |
| 状态维度拆分语义 | 单据流程状态（status）与审批决策（decision）属于两个独立维度：流程状态描述单据在申请-审批-签约-归档链路中的位置，审批决策描述自动审批结果，二者独立持久化、互不覆盖；同一笔订单可同时处于 active 与 decision=approved，但 status 不会等于 approved（approved 仅出现在 CreditResult.decision 中） | 状态维度拆分 | FLOW-001、FIELD-002、FIELD-003 |
| 默认费率口径 | 年化利率 3.5%、服务费率 1%、逾期罚息率 5%；配置表可调，可参数化配置 | 产品确认默认费率 | RULE-004 |
| 配置表维护范围 | 评分规则阈值与权重、贷款费率默认值均由配置表维护；缺失将导致相应流程异常 | 配置化参数 | RULE-001、RULE-004 |
