# 个人消费贷款管理系统 PRD

## 1. 背景与目标

- 业务背景：某消费金融公司面向有日常消费资金需求的个人用户（贷款用途包括装修、教育、旅游、医疗等）搭建个人消费贷款管理系统。用户在线申请贷款，填写个人信息和收入状况，系统按评分规则自动审批，通过后展示额度利率并支持在线签约。
- 目标：实现最小可用闭环——基础数据维护、业务记录提交、详情查看与简单状态处理。支撑个人贷款从申请、自动审批到电子签约的完整链路。
- 成功标准：完成 Borrower / LoanOrder / CreditResult 三实体的核心维护；实现 M1 申请、M2 自动审批、M3 电子签约；前后端均可依赖安装与编译通过；提供 SQL 脚本与 README。
- 关联需求 ID：BR-001、BR-002、FUNC-001、FUNC-002、FUNC-003

## 4. 业务流程

### 主流程
1. 申请人填写申请信息（个人信息、职业信息、联系人信息、贷款需求），可分步填写并保存草稿，草稿状态为 draft（UI-001、FLOW-001）。
2. 提交申请，草稿转为 pending（待处理）状态，生成 LoanOrder（FUNC-002、FLOW-001）。
3. 系统按评分规则对申请自动评分并决策：通过则生成 CreditResult（含 score、approved_amount、approved_rate、decision），订单进入 approved 并展示额度利率；拒绝则生成决策原因建议，订单进入 rejected（FUNC-002、RULE-001、FLOW-001）。
4. 通过后，申请人查看借款合同核心条款与费率明细并确认签署；订单进入 active（FUNC-003、RULE-004、FLOW-001）。
5. 业务操作人员基于自动审批结果对订单执行通过/驳回/完成等状态流转（复用 approved/rejected/active/closed 状态），状态变化记录处理意见；订单进入 closed 后流程完成（FLOW-001、FLOW-002）。

### 异常流程
- 提交的申请关键字段校验不通过（金额、期限、身份证、电话等）时，阻止提交并给出提示（RULE-002）。
- 自动审批拒绝时，向申请人展示决策原因与建议（RULE-001）。
- 对不合法的状态流转（如直接 pending→closed、或 rejection→pending）予以拒绝（FLOW-001）。
- 操作人员对订单的通过/驳回操作以自动审批结果为依据，不得绕过审批结果直接执行状态变更（RULE-001、FLOW-001）。

### 边界流程
- 保存草稿的申请（draft）未提交，不进入待处理状态，不入审批流程（UI-001、FLOW-001）。
- rejected 为终态，rejected 记录不可重新回流到 pending 状态（FLOW-001）。
- 删除操作可针对所有流程状态执行；删除订单时关联的 CreditResult 执行级联删除（FUNC-001、FIELD-003）。
- 列表查询支持关键字过滤，可检索到新提交记录（UI-002、UI-003）。

## 5. 业务规则

| 规则 | 说明 | 关联需求 ID |
| --- | --- | --- |
| 评分规则参数化配置 | 自动审批按收入、负债等指标评分，分数≥阈值即通过、否则拒绝；阈值/权重由配置表维护，默认给一套合理值 | RULE-001 |
| 关键字段基础校验 | 金额、期限、身份证号、电话等关键字段有基础校验，必填项有提示 | RULE-002 |
| 贷款用途固定枚举 | 贷款用途仅含装修、教育、旅游、医疗 4 类 | RULE-003 |
| 合同费率展示 | 合同展示年化利率、服务费、逾期罚息等关键费率，费率来自配置表维护的固定值 | RULE-004 |
| 状态机合法路径 | LoanOrder 状态：draft→（提交）pending→（自动审批 approved/rejected）→active→closed；draft 为起始点表示已保存未提交草稿，仅允许合法路径的状态变更 | FLOW-001 |
| 处理意见记录 | 状态变化时记录处理意见（通过/驳回/完成等）；操作人员的通过/驳回基于自动审批结果执行并复用 FLOW-001 状态 | FLOW-002 |

## 6. 字段、数据与状态口径

| 项目 | 口径 | 来源 | 关联需求 ID |
