# 需求梳理 v0.1 —— 智能化低代码数据指标分析平台（intelli-metric）

> 状态：初稿，待评审。修订记录见文末。

## 1. 背景与目标

企业数字化运营依赖大量业务指标（GMV、转化率、留存率、客单价……）。传统模式下指标开发链路长：业务提需求 → 数据工程师理解口径 → 找表找字段 → 写 SQL/任务 → 测试 → 上线 → 维护，口径分散、重复建设、知识沉淀在个人脑中。

本平台的目标：

- **低代码化**：基于数据源元数据和业务知识库，以表单化/模板化方式快速构建指标，而非手写 SQL。
- **知识驱动**：独立维护一个业务知识库（领域知识 + 通用知识），知识可被检索、被自动结构化为本体模型，并用于辅助指标构建。
- **全生命周期**：指标从构建、测试、发布服务到下架均有明确状态与管理流程。
- **智能化**：结合大模型能力，根据自然语言业务需求自动给出指标构建建议。

### 1.1 用户角色

| 角色 | 说明 | 核心诉求 |
|---|---|---|
| 指标开发者（数据分析师/业务工程师） | 平台主要使用者 | 快速构建、测试、发布指标 |
| 业务运营/管理者 | 指标消费者 | 拿到口径统一、可信的指标结果 |
| 知识管理员 | 维护知识库与本体 | 知识的录入、清洗、结构化、更新 |
| 平台管理员 | 数据源与元数据维护 | 数据源接入、元数据同步、权限管理 |
| 下游系统 | 通过 API 消费指标 | 稳定、明确的指标服务接口 |

## 3. 功能需求分解

### 3.1 数据源维护与元数据管理（基础框架）

**F-DS-01 数据源接入与维护**
- 支持关系型数据库（首期：MySQL、PostgreSQL；预留 Hive、Doris/StarRocks、ClickHouse、API 类数据源扩展点）。
- 数据源 CRUD：连接参数、连通性测试、凭据加密存储。
- 数据源状态监控（可用/不可用、最近同步时间）。

**F-MD-01 元数据采集**
- 自动采集库/表/字段级元数据：名称、类型、注释、约束、样例统计（行数、空值率、基数等可选）。
- 支持手动触发全量采集与定时增量采集。
- 采集结果入库，平台自行管理元数据副本（不依赖实时查询源库）。

**F-MD-02 元数据管理与检索**
- 元数据 CRUD（业务补充信息：业务描述、负责人、标签、敏感级别）。
- 按关键字/标签/数据源检索表与字段。
- 元数据版本管理：每次采集生成快照，可对比任意两版差异。

**F-MD-03 源结构变更检测**
- 对比相邻元数据快照，识别：表/字段新增、删除、类型变更、注释变更。
- 变更事件入事件流，供指标模块订阅（见 F-LC-04 指标下架）。

### 3.2 知识库管理（领域知识 + 通用知识）

**F-KB-01 知识条目管理**
- 知识类型（首版）：数据指标构建模板、数据清洗方法、指标加工方法、业务术语/口径说明、领域概念说明。
- 知识条目 CRUD：标题、正文（长文本/Markdown）、类型、标签、关联元数据（表/字段）、来源、版本。
- 批量导入：支持 Markdown 文件批量导入（单文件/压缩包），导入时可指定类型与标签，便于冷启动阶段灌入已有知识资产；支持导出备份。
- 全文检索 + 语义检索（向量化），支持混合检索与按类型/标签过滤。

**F-KB-02 本体模型自动提取**
- 输入：知识库中的自然语言文本（原始业务文档、口径说明等）。
- 处理：调用 LLM pipeline 抽取数据实体定义（实体名、属性、语义）与实体间逻辑关联关系（如 订单-包含→订单明细、用户-产生→行为事件）。
- 输出：本体草稿，人工审核确认后入库；支持增量补充与冲突提示。
- 本体模型 CRUD 与可视化（实体-关系图）。

**F-KB-03 本体与元数据对齐**
- 本体实体与物理表/字段建立映射（自动建议 + 人工确认）。
- 该映射是指标构建建议的关键中间层：业务语言 → 本体实体 → 物理数据。

### 3.3 指标生命周期管理（核心）

**F-LC-01 指标定义与构建**
- 指标分类：原子指标（度量+聚合方式）、派生指标（原子指标+维度+过滤+时间窗口）、复合指标（多指标运算）。
- 低代码构建界面：选择源表/字段、聚合方式（SUM/COUNT/AVG/COUNT DISTINCT/MAX/MIN…）、过滤条件、维度、时间粒度、口径说明；表单驱动，无需手写 SQL（高级模式可编辑表达式）。
- 指标元信息：中文名、英文名（唯一标识）、业务口径、负责人、所属业务域、标签。
- 指标定义存储为结构化 DSL（JSON/YAML），与具体引擎解耦。

**F-LC-02 指标构建模板管理**
- 模板 CRUD 与版本管理：模板 = 参数化的指标定义骨架 + 适用场景说明 + 验收规则模板。
- 模板可从知识库知识条目转化，也可由成功指标沉淀而来。
- 基于模板实例化指标：填参即生成指标定义草稿。

**F-LC-03 指标测试**
- 计算测试：对指标定义生成查询，在源数据上试算，返回样例结果与耗时；支持指定时间范围、维度切片。
- 有效性评估（验收规则）：
  - 基础校验：空值率、取值范围、非负性、枚举合法性；
  - 一致性校验：与已有同类指标/历史值对比（波动率阈值）；
  - 业务规则校验：来自知识库/模板中定义的验收规则（如"退款率 ∈ [0,1]"）；
  - 评估报告输出，测试通过是发布的前置条件。

**F-LC-04 指标服务（发布）**
- 发布后指标进入服务状态，对外提供：
  - 实时查询接口：REST API，按指标名 + 维度 + 时间范围查询，带缓存；
  - 批处理接口：批量指标计算任务，结果输出到表/文件/消息（首版至少支持结果表导出）。
- 服务发布配置：发布时为指标配置可调用的 API 调用方（外部消费者账户），调用方凭访问 token 调用，token 支持颁发/吊销/过期管理（详见 `02-权限设计.md` 第 7 节）。
- 版本管理与服务路由：口径变更生成指标新版本，需重新测试后发布；已发布的多版本并存，API 默认路由到最新发布版本，也支持调用方显式指定版本（便于调用方平滑迁移）；旧版本可单独退役。
- 服务管理：发布/暂停、调用记录。
- 运行期管理（服务监控、调用日志与审计、监控看板及其权限控制）详见 `03-指标服务与监控.md`。

**F-LC-05 指标下架**
- 人工下架：操作指令 + 原因记录。
- 自动触发：源数据结构变更（F-MD-03 事件）影响到指标依赖的表/字段时，自动标记"待评估/自动降级"，通知负责人，确认后下架或修复。
- 下架指标保留定义与历史数据，可查询、可重新上架。

**F-LC-06 指标状态机**

```
草稿 → 测试中 → 已发布 →（暂停）→ 已下架
         │失败      │口径变更
         └──→ 草稿   └──→ 新版本（重新走测试）
```

**F-LC-07 变更影响分析与异常处置**
- 依赖关系图谱：平台维护 数据源 → 表/字段 → 指标 的依赖关系（构建指标时自动建立），是所有影响分析的基础。
- 数据源配置变更预检：修改数据源连接配置前，系统给出依赖该数据源的已发布指标清单，供操作人评估；确认修改后，受影响指标标记为"待评估"。
- 数据结构变更联动：F-MD-03 的变更事件经依赖图谱定位受影响指标，标记"受影响"并生成处置待办、通知指标负责人。
- 处置工作流（待办驱动）：受影响指标进入负责人的处置待办列表，可选处置动作：修复定义（回到草稿修改）、暂停服务、下架；处置后需重新试算/测试验证方可恢复发布。处置过程留痕（审计）。
- 数据源删除保护：存在依赖指标（未下架）的数据源不可直接删除，须先处置依赖指标。
- 异常呈现：受影响指标在指标列表、指标详情、监控看板中均有显著状态标记，并可查看具体原因（哪个数据源/表/字段发生了什么变化）。

### 3.4 智能辅助（LLM 能力）

**F-AI-01 指标构建建议**
- 输入：自然语言业务需求（如"我想看各省近 30 天新客的复购率"）。
- 处理：需求解析 → 基于本体模型与知识库检索（RAG）匹配相关实体、已有指标、构建模板与加工方法 → LLM 生成建议。
- 输出结构化建议：
  - 建议的源数据（表/字段，附选择理由）；
  - 源数据加工方法（清洗、关联、口径处理）；
  - 指标业务含义解释（口径说明草稿）；
  - 指标验收规则建议。
- 建议可一键转为指标定义草稿，进入 F-LC-01 流程。

**F-AI-02 本体提取**（见 F-KB-02，同一 LLM pipeline 支撑）

### 3.5 平台管理（横切）

- 系统初始化与超级管理员：空实例首次启动时通过初始化向导/命令创建首个超级管理员；超级管理员拥有全部功能权限并负责创建第一批用户；系统始终保留至少一名超级管理员。详见 `02-权限设计.md` 第 6 节。
- 用户管理：创建、停用/启用、重置密码、角色分配（`user:create` 权限点扩展为用户管理）。
- API 调用方管理：外部消费者账户的创建/停用、token 颁发/吊销/过期、按指标授权调用范围。详见 `02-权限设计.md` 第 7 节。
- 权限模型：三层模型——全局功能权限（RBAC）、数据源/指标的资源级授权（owner/manager、reader、none）、授权主体抽象（为组织架构继承预留）。完整设计见 `02-权限设计.md`。
- 站内通知与待办：变更影响、处置待办、审核请求等平台内事件以站内通知触达负责人（邮件/IM 通知通道列入 backlog）。
- 审计日志：指标、知识、权限、数据源配置与服务调用的关键操作留痕（见 `03-指标服务与监控.md`）。
- 系统配置：LLM 接入配置（模型、密钥、参数）、向量库配置、调度配置。

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 可扩展性 | 数据源类型、聚合引擎、LLM 提供商均以插件/适配器方式接入 |
| 引擎解耦 | 指标定义 DSL 与计算引擎解耦，首版用 SQL 下推到源库计算 |
| 性能 | 元数据/知识检索 P95 < 500ms；指标实时查询依赖源库性能，需缓存层 |
| 安全 | 数据源凭据加密存储；LLM 密钥不落前端；操作审计 |
| 可观测 | 采集任务、计算任务、API 调用均有日志与基础指标 |
| 部署 | 单机 docker-compose 起步，组件可替换（如向量库） |

## 5. 范围边界（首版不做）

- 不做完整的 BI 可视化（图表/看板），指标结果以 API/表格输出为主。
- 不做多租户级别的资源隔离与企业 SSO（预留接口）。
- 不做流式（Flink 级）实时指标，"实时"指查询时即时计算/读缓存。
- 不替代数据仓库本身的 ETL 调度。

## 6. 术语表

| 术语 | 定义 |
|---|---|
| 指标（Metric） | 有明确业务口径的可计算度量，分为原子/派生/复合 |
| 维度（Dimension） | 指标的观察角度，如地区、渠道、时间 |
| 元数据 | 数据源的库表字段结构及业务补充信息 |
| 知识条目 | 知识库中一条独立维护的知识单元 |
| 本体模型 | 从知识中抽取的数据实体定义及实体间逻辑关系的结构化模型 |
| 指标 DSL | 指标定义的结构化描述（JSON/YAML），引擎无关 |
| 验收规则 | 判断指标计算结果是否有效的校验规则集合 |
| API 调用方（Consumer） | 调用指标服务的外部消费者账户，凭 token 访问被授权的指标 |
| 依赖图谱 | 数据源 → 表/字段 → 指标 的依赖关系，用于变更影响分析 |

## 7. 待确认问题（Open Questions）

1. 首批接入的数据源是否就是 MySQL/PostgreSQL？是否有 API/文件类数据源需求？
2. 指标计算是否允许在平台侧建物化结果表（需要平台自有存储），还是只下推源库？
3. LLM 使用公网 API（OpenAI 兼容）还是私有化模型？数据出域合规要求？
