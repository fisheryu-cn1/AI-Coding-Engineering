# 需求梳理 —— 指标服务与运行监控 v0.1

> 状态：初稿，待评审。本文细化 `01-需求总览与功能分解.md` 的 F-LC-04，并与 `02-权限设计.md` 配套。编号 F-SV-*（服务运行）与 F-MON-*（监控）。

## 1. 范围

指标发布后的运行期管理：服务状态监控、调用日志与审计、运行监控看板，以及上述能力的权限控制。指标服务的查询/批处理接口本身见 F-LC-04，本文不重复。

## 2. 服务运行监控（F-MON-01）

**监控维度：**

| 维度 | 指标项 | 说明 |
|---|---|---|
| 依赖健康 | 关联数据源连通性状态 | 指标所依赖数据源当前可用/不可用；不可用时该指标自动标记为"服务降级" |
| 性能 | 实时类指标服务延迟（P50/P95/P99）、单指标计算耗时分布 | 按指标、按时间窗聚合 |
| 可用性 | 请求成功率、错误分类统计（源库异常/参数非法/超时/权限拒绝） | 按指标、按时间窗聚合 |
| 用量 | 时间区间内访问量、QPS、按调用方（用户/下游系统）分布 | 支持按指标/调用方/时间窗筛选 |

**规则：**

- **R-MON-1 数据源状态联动**：数据源连通性检测失败时，依赖该数据源的已发布指标在监控中标记为"不可用（依赖异常）"，状态回传指标详情页；恢复后自动解除。
- **R-MON-2 监控数据存储**：监控聚合数据存平台库（时序表，按分钟/小时粒度聚合，保留期可配置，默认原始日志 90 天、聚合数据 13 个月）；预留替换为专业 TSDB/Prometheus 的接口，本期不引入额外组件。

## 3. 调用日志与审计（F-MON-02）

**F-MON-02-01 调用日志**：每次指标服务调用记录：

- 时间、调用方（用户/下游系统标识）、指标标识与版本、请求参数（维度、时间范围）、耗时、状态（成功/失败及错误类型）、结果行数、来源 IP。
- 批处理任务另记：任务 ID、输入参数、输出位置、起止时间、数据量。

**F-MON-02-02 审计记录**：除调用日志外，管理类操作留痕（与平台审计统一）：指标发布/暂停/下架、权限变更、数据源配置变更。审计记录只增不改。

**F-MON-02-03 日志查询**：支持按指标、调用方、时间窗、状态组合检索；支持导出。

## 4. 运行监控看板（F-MON-03）

**两级看板：**

1. **平台总览看板**：服务中指标数、整体成功率与延迟趋势、访问量 Top 指标、异常指标清单（依赖异常/成功率低于阈值/延迟超阈值）、数据源健康一览。
2. **单指标详情看板**：该指标的延迟分布、成功率、访问量趋势、按调用方分布、近期调用日志、关联数据源状态、版本与变更历史。

**告警（本期预留，不做通知通道）**：阈值规则模型先行（成功率、延迟、依赖异常），看板内做视觉告警；邮件/IM 通知通道列入 backlog。

## 5. 服务发布与版本路由（F-SV-01）

配合 `01-需求总览与功能分解.md` F-LC-04 的版本管理，细化运行态行为：

- **F-SV-01-01 版本路由**：指标 API 默认路由到"最新发布版本"；调用方可显式指定版本号调用。版本退役后，指定该版本的调用返回明确的错误码（`VERSION_RETIRED`），默认路由不受影响。
- **F-SV-01-02 设计变更后的服务刷新**：修改指标设计产生新草稿 → 测试通过 → 发布为新版本。发布动作即时切换默认路由（无需重启、无服务中断）；切换留痕并通知该指标的调用方负责人（站内通知）。
- **F-SV-01-03 调用方迁移支持**：指标详情页展示各版本当前调用量分布，帮助 manager 判断旧版本何时可安全退役；版本退役前检查"近 7 天无调用"。

## 6. 异常发现到处置的闭环流程（F-SV-02）

监控发现问题的标准处理路径（与 F-LC-07 衔接）：

1. **识别**：数据源连通性探测失败 / 元数据变更事件 / 成功率或延迟越过阈值 → 定位受影响指标集合（依赖图谱）。
2. **呈现**：受影响指标打状态标记（不可用/待评估/性能异常），进入平台总览看板异常清单；指标详情页展示具体原因（哪个数据源/表/字段、发生了什么变化、影响哪些版本）。
3. **通知**：向指标 manager 生成处置待办（站内通知）；数据源 owner 同时可见影响范围（仅状态，不含业务参数）。
4. **处置**：manager 在待办中执行动作——修复定义（回草稿）、暂停服务、下架；紧急情况下可一键"暂停全部受影响指标"。
5. **恢复验证**：处置后触发重新试算 + 验收规则评估，通过方可重新发布；整个处置过程（时间线、操作人、动作、验证结果）留痕，可从监控事件回溯。

## 7. 权限控制（与 02-权限设计 配套）

**功能权限：**

| 权限点 | 说明 |
|---|---|
| monitor:view | 查看监控看板（数据范围按下表裁剪） |
| audit:view | 查看审计记录与调用日志明细 |

**数据可见范围：**

| 用户身份 | 可见范围 |
|---|---|
| 系统管理员 | 全量：平台总览看板、任意指标详情、全量日志与审计 |
| 指标 manager | 其管理的指标：详情看板、调用日志、状态信息 |
| 指标 reader | 其可读的指标：运行状态与聚合用量（成功/失败、访问量），**不含**调用方明细与请求参数 |
| 数据源 owner | 依赖其数据源的已发布指标：可用性状态与聚合错误统计（不含请求参数与结果数据），用于影响评估 |
| 无 monitor:view 权限 | 不可见任何监控页面；audit:view 单独控制日志审计入口 |

**规则 R-MON-SEC-1**：监控数据的可见性裁剪在服务侧完成（查询接口即按主体过滤），前端不做兜底隐藏。
**规则 R-MON-SEC-2**：API 调用方（consumer）只见自身调用结果；其调用量数据对指标 manager 可见（按调用方分布），token 与密钥类信息不出现在任何监控/日志输出中。

## 8. 非功能要求

- 监控采集对指标查询主链路的开销 < 5%（异步落库/缓冲批量写入）。
- 看板查询 P95 < 1s（基于聚合表，不扫原始日志）。
- 日志含调用参数但不含结果数据本体，避免敏感数据经日志二次暴露。
