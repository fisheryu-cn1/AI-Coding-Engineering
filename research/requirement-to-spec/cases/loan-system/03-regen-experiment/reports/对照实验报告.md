# 对照实验报告：上游评审修复对下游 PRD 质量的传导效应

> 日期：2026-08-28。实验设计：用户提出；执行角色按设计分工——**pi**（修复登记表+按 4p12s-prd skill 重新生成 PRD，扮演交付方代理人）与 **GLM**（两轮评审，扮演方法执行方）。
> 实验命题：上游需求经本方法评审修复后，下游 PRD 质量是否提升、修复能否传导、传导边界在哪——"分离点前推"主张的首个受控数据点。

## 0. 实验流程（五阶段，全部实跑）

```
阶段1 pi 修复登记表   输入=原件+六项修改指令（源自 PRD 评审发现+loan-system 已有裁决）
阶段2 GLM 复审        逐项落实校验：六项全落实/ID 闭包 21 条无增删/操作员 0 残留 → 通过
阶段3 pi 重生成 PRD   4p12s-prd skill 独立模式（skill 原文注入），STEP_RESULT 自报 passed
阶段4 GLM 评审新 PRD  check_doc_closure 同法检查（过程中发现并修复检查器 A2 盲区）
阶段5 对比（本报告）
```

产物：`raw/requirements-register-fixed.md`、`raw/prd-regen.md`、prompts/ 两份 pi 调用原文、reports/run-regen-prd-check.txt。

## 1. 修复传导矩阵（原 PRD 六项发现 → 新 PRD）

| 原发现 | 新 PRD 状态 | 传导判定 |
|---|---|---|
| #1 RULE-003 验收断点（致命） | "M1 用途枚举"验收行存在且可测（"其他值不可通过校验"） | ✅ **传导** |
| #2 验收行无 ID 列 | 仍无（skill 模板 §9 即无此列） | ❌ **模板层缺陷，不可经上游传导** |
| #3 rejection 拼写漂移 | 消失（D 检查 0） | ✅ 传导（上游拼写统一指令生效） |
| #4 BR-001 弱承接 | 仍 1 次（目标类正常形态，非缺陷） | 持平 |
| #5 状态体系混淆（两维度混写） | **完整拆分传导且增强**：四态+decision 三值解耦/统一终态/不可翻转，且自发生成"数据口径一致性"风险项（§7 行 149） | ✅✅ **超预期传导** |
| #6 操作员语义（矛盾侧） | 消解：无人工环节+decision_reason 系统记录（"不使用人工处理意见语义"） | ✅ 传导 |

**语义层结论：6/6 修复传导**（含 1 项超预期——上游拆分不仅传导，还激发下游自发的口径一致性防线）。费率默认值（3.5%/1%/5%）、必填清单、草稿同触校验等裁决输入全部正确进入验收标准。

## 2. 新引入问题（全部为拓扑层 ID 断链）

- **形近 ID 变体 5 个**：`FULC-001/002/003`（FUNC 之误）、`FOW-001/002`（FLOW 之误），共 7 处引用——验收行的内容存在但 ID 断链（C 断点 FUNC-001~003 的真相即此）；FIELD-001/002 为部分真实缺失（验收行有维护内容但未挂 ID）；
- **验收行仍无 ID 列**：skill 模板决定，与上游无关。

## 3. 实验结论

1. **语义修复完整传导，拓扑保真不能靠 LLM**：上游把 Z_真 消解（裁决落登记表：状态拆分/操作员消解/费率/必填）后，下游生成文档的语义质量显著提升且歧义残留为零——支持分离点前推主张。但 LLM 再生成引入了新的 ID 词汇漂移（FULC/FOW），且 4p12s 的"源需求 ID 已覆盖"质量门禁（LLM 自检）没有拦住——**同源验证天花板在真实数据上的又一实证**；拓扑完整性的兜底只能来自确定性检查器。
2. **传导的三层边界**：语义层（✅ 可传导）/ 拓扑层（再生成的随机损耗，需检查器捕获）/ 模板层（skill 结构决定，上游不可传导，需改 skill 本身）。
3. **方法自身在实验中进化**：pi 的形近变体逃过了 check_doc_closure 原 A 检查（非法前缀不匹配合法 ID 正则）——新增 **A2 形近变体检测**（宽松疑似 ID 形态+编辑距离≤2），原 PRD 回归无误报。评审工具被使用、暴露盲区、修复——与回填实验同一模式。

## 4. 局限与下一步

- 单次生成/单案例：LLM 随机性下"FULC 式漂移的出现率"需 N 次采样才能定量——恰为 R4 Z_真 曲线设计的用武之地（本实验可视为 R4 的单点预演：同一上游、N 次独立生成、语义等价类+ID 完整性双指标）；
- pi 修复质量依赖修改指令的完备（本实验指令源自已有裁决——若无裁决库，修复指令本身需要人工裁决环节，即方法的 S4/S5 循环）；
- skill 模板修复（验收行 ID 化）是另一条独立改进线，属 4p12s 基线侧，不影响本方法结论。

## 5. 证据索引

## 6. 增补实验：UML 联合输入的锚定效应（2026-08-28，用户追加设计）

**变体**：pi 生成 PRD 时，输入 = fixed 登记表 + 评审阶段生成的两件 UML（prd-review 案例的 concept-model.puml / flow-model.puml，PlantUML 文本，prompt 声明为"语义与结构参照、ID 以登记表为准"）。产物 `raw/prd-regen2-uml.md`；检查输出 `reports/run-regen2-check.txt`。

### 6.1 三方对比

| 指标 | 原 PRD | regen（无 UML） | **regen2（+UML）** |
|---|---|---|---|
| A/A2 私造与形近变体 | 0 | **5 变体（FULC×3/FOW×2，7 处断链）** | **0** |
| C 验收断点 | 1（RULE-003，致命） | 5 | **0** |
| D 词表漂移 | 1（rejection） | 0 | 0 |
| B 弱承接 | 1（BR-001） | 1 | **0** |
| E 验收行无 ID 列 | 触发 | 触发 | 触发（skill 模板层，三档恒定） |
| 语义六项传导 | 基线缺陷态 | 6/6 | 6/6，且**状态维度拆分升级为显式验收标准**（"订单状态不会出现 approved/rejected 取值"） |
| 技术细节泄露 | — | — | 0（无 OWL/PlantUML 术语进入正文） |

### 6.2 结论

1. **UML 联合输入对拓扑层有显著正效应**：A2 变体、C 断点、B 弱承接全部清零——除模板层 E 项外**机器检查全绿**。机理假设：UML 文本提供了正确 ID 的上下文示范与实体-状态的显式结构锚，抑制了 LLM 的词汇漂移（H1 验证）。
2. **语义层增益**：维度拆分从"被传导"升级为"被断言"——新 PRD 把"订单状态不会出现 approved/rejected 取值"写成可测验收标准，强于登记表原文的表述。
3. **输入冲突的消解行为（意外观察）**：评审 UML 是按 PRD 原文忠实翻译的六态版，与 fixed 登记表的四态语义冲突——pi 选择了登记表口径并**在自述中显式披露**（"UML 中的 6 态/操作员迁移未进入 PRD"）。该消解依赖 skill 的主输入定位与 prompt 的"以登记表为准"指令，不能视为 LLM 的可靠默认行为——多源输入的冲突治理应成为管线显式环节。
4. **方法论意义——形式化的锚定效应**：评审/构造阶段的形式化产物不仅服务确定性检查，还能反哺下游生成质量（拓扑+语义双正效应）——**形式化不是纯成本，是可复用资产**。这为方法管线增加了正向循环证据，也提示 R4 实验应增加"有无形式化锚"作为分组变量。

局限同 §4：单次生成；"锚定效应"的稳定性需 N 次采样定量（且需排除"恰好这次没漂移"的偶然——FULC 漂移在 regen 单次中的出现本身就属随机事件）。

## 7. 管线决策记录：UML-OWL 检查的最佳环节 = requirement 阶段（2026-08-28，用户提问驱动）

**决策**：UML-OWL 重型形式化检查（S3 翻译+S4 七项）置于**登记表定稿后、PRD 生成前**；PRD 层只做轻量文本检查（check_doc_closure 五项）；已验证 UML 作为 PRD 生成的联合输入（锚定效应，§6）。

**论据**（均为本实验系列证据）：
1. 源头修复 6/6 传导（§1）——requirement 层消解的 Z_真 自动流向全部下游；PRD 层修复需回传+级联重生成；
2. 锚定效应时序（§6）——UML 锚必须在 PRD 生成**之前**存在且已验证，事后比对无从锚定：预防优于检测；
3. 归因干净——登记表层检出=需求自身问题；PRD 层检出混入生成损失（FULC/rejection 类），两类信号应分层捕获（本实验阶段 1-2 vs 阶段 4 的分组即演示）；
4. 翻译面匹配——OWL/Z3/FSM 可检语义（FIELD/RULE/FLOW）在登记表已结构化完整，PRD 新增内容大多不在形式化可检域，两层重检为冗余。

**反方与回应**：①"业务签 PRD"——语义传导 6/6+损失全在拓扑层（文本检查覆盖），更强保证用 UML 联合输入非重检；②"只有 PRD 可用"——prd-review Run-2 场景属输入约束的不得已，非最优设计（且其结论反证 PRD 层形式化检查产出有限）。

**衍生纪律**：多源输入（登记表+UML）冲突治理为生成环节显式要求（§6.2-3 教训）；method/10 阶段排序修订时引用本节。
