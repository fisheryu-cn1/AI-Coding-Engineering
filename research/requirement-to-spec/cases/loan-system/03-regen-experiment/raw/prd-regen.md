# 个人消费贷款管理系统 PRD

## 1. 背景与目标

- **业务背景**：某消费金融公司面向有日常消费资金需求的个人用户（装修、教育、旅游、医疗等场景），需要搭建一套个人消费贷款管理系统，提供在线贷款申请、自动审批与电子签约的最小可用闭环。
- **目标**：交付一个面向个人用户的贷款管理系统，覆盖基础数据维护、业务记录提交、详情查看与简单状态处理三个最小可用闭环模块（M1 申请、M2 自动审批、M3 电子签约）。
- **成功标准**：
  - 完成 Borrower / LoanOrder / CreditResult 三个实体的核心维护能力。
  - 实现 M1 申请、M2 自动审批、M3 电子签约的功能闭环。
  - 前端与后端项目均可完成依赖安装（`npm install`）与编译（`npm run build`）。
  - 提供数据库初始化 SQL 脚本（含少量示例数据）与 README 说明文档。
- **关联需求 ID**：BR-001、BR-002。

## 4. 业务流程

### 主流程

1. 个人用户在 M1 申请模块分步填写个人信息、职业信息、联系人信息与贷款需求（金额、期限、用途），可保存草稿（UI-001）。
2. 用户在 M1 完成填写并提交申请，系统按 RULE-002 触发必填项与基础校验。
3. 提交成功后，LoanOrder 进入 `pending`（待处理）状态，并在 M2 自动审批列表中可被查询到（UI-003）。
4. 系统按 RULE-001 的评分规则计算分数：分数≥阈值 → 自动审批通过（CreditResult.decision = approved）；分数<阈值 → 自动审批拒绝（CreditResult.decision = rejected）。
5. 审批通过时 LoanOrder 流转至 `active`（签约生效），M3 合同详情页展示完整信息（UI-004）与关键费率（年化利率 3.5%、服务费率 1%、逾期罚息率 5%）。
6. 合同完成相应处理后，LoanOrder 流转至 `closed`（完成）终态。

### 异常流程

1. 表单必填项缺失或字段值不合法时，系统按 RULE-002 给出提示，阻止提交；草稿保存同样触发校验（草稿≠免校验）。
2. 评分结果低于阈值时，CreditResult.decision = rejected，LoanOrder 直接流转至 `closed`（审批拒绝路径），不进入 `active`。
3. 评分规则配置表中的阈值或权重缺失/非法时，自动审批无法产出合法 CreditResult，系统应给出明确错误提示并不写入错误决策。
4. 用例字段未命中装修/教育/旅游/医疗 4 类时，提交校验不通过（RULE-003）。

### 边界流程

1. **草稿续填**：LoanOrder 处于 `draft` 时可被任意修改、再次保存或提交；其他状态下不可再编辑申请内容。
2. **状态机合法性**：仅允许 `draft → pending`、`pending → active`、`pending → closed`、`active → closed` 四条路径，`closed` 为统一终态，不可重开（FOW-001）。
3. **审批结果不可翻转**：CreditResult.decision 与 decision_reason 形成后不可修改，作为单据审计字段（FOW-001、FOW-002）。
4. **删除级联**：删除 LoanOrder 时级联删除其 CreditResult（FOW-001）；删除可针对所有状态。
5. **默认值兜底**：评分规则配置表与费率配置表需提供产品确认的默认合理值（评分阈值与权重；年化利率 3.5%、服务费率 1%、逾期罚息率 5%）。
6. **关键字检索**：M1 列表关键字查询可按姓名、身份证号、电话等可识别字段过滤（UI-002）。

## 5. 业务规则

| 表单必填项校验 | 必填字段：金额 amount、期限 term_months、身份证 id_number、电话 phone；表单必填项有提示；关键字段有基础校验 | RULE-002 |
| 草稿同样触发表单校验 | 保存草稿与直接提交均触发表单校验规则，草稿≠免校验 | RULE-002 |
