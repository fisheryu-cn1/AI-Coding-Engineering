## 2. 三段比对结果

### 2.1 PRD → 设计（diff_models，含语义甄别）

- **枚举两次改名**：OrderStatus→LoanStatus、CreditDecision→Decision——名字漂移，字面量六态/两值语义保留（需人工确认，机器 diff 报名不报值域——本例人工抽查一致）；
- **LoanPurpose 枚举丢失**：PRD 的四值用途枚举在设计中变为 string（pi 含糊清单第 1 条如实报告）——**RULE-003 断链在设计层的机械确认**；
- 关联标签全换（places→"拥有"）——建模表述漂移，语义保留；
- 服务层/配置/日志 8 个新类——设计阶段合法新增（受约束选择，多数有 design.md 依据）。

### 2.2 设计 → 代码

- **CreditService 消失**：设计的独立审批服务在代码中并入 LoanOrderService.submit 的 autoApprove()——**结构重组、语义保留**（审批逻辑与状态驱动还在，但设计的服务边界未传导）；
- **ApprovalConfig 字段全换且收窄**：设计的 threshold/weights/metrics（泛化可配置指标数组）→代码 passThreshold/incomeWeight/debtRatioLimit（**两指标硬编码字段**）——设计承诺的参数化能力（RULE-001"指标参数化"）被收窄为实现固定两指标——真实的能力弱化传导；
- **RateConfig 蛇形→驼峰**（annual_rate→annualRate）——无语义损失的命名风格漂移（合法适配）；
- 前端 10 个新类/HttpClient/Store/中间件——实现层合法新增。

### 2.3 状态机贯穿（语义抽查）

**六态在三层完整贯穿**：PRD（draft/pending/approved/rejected/active/closed）→设计（同六态同迁移）→代码（同六态，迁移带守卫函数与 API 路由标注）。且代码层暴露一个设计未言明的语义细节：**submit 原子执行 draft→pending→{approved,rejected}**——pending 在代码中是瞬态中间态而非设计的可停留状态，并伴随 pi 发现的"autoApprove 抛错留脏 pending"风险——状态机结构一致但**驻留语义**发生了实现层变异。

## 3. 四预测的终态裁决

| 预测 | 裁决 | 证据 |
|---|---|---|
| RULE-003 用途枚举链 | **比"全链丢失"更精确的三段形态**：PRD 四值枚举 → 设计 string（无枚举）→ 代码 **TS 类型层枚举回归（四值中文）+运行时 API 校验缺失** | design.md `purpose: string`（pi 含糊清单#1）；代码 types.ts `purpose: LoanPurpose`（装修/教育/旅游/医疗）+ validate 中间件无枚举校验 + 列表按字面子串匹配。**实现者自加的类型约束反向补了设计的缺口**——但仅编译期有效，外部 API 调用仍可提交任意值 |
| 操作员矛盾 | 断点呈现于 PRD→设计段：PRD 六处操作员语义，设计/代码均无操作员环节（自动审批直接驱动） | diff ①无操作员相关方法；与 D-A 裁决（采纳设计侧）的跨文档矛盾判断一致——机械呈现替代人工读码 |
| 六态贯穿 | **贯穿**（结构层），但 pending 驻留语义实现变异 | §2.3 |
| 方法对照（"LLM 方法设计"首数据点） | 设计 42 方法提取顺畅（@logic 可标注）；与代码 80 方法名级 diff 有效但**噪声需归因分层**（合法适配/重组/弱化三类都有实例） | CreditService 重组/ApprovalConfig 收窄/驼峰改名——三分法归因在本实验全程可用 |

## 4. 评估结论

1. **三段比对可行且有实质发现力**：结构维度（类/枚举/关联/方法名）的机械 diff + 少量人工语义甄别，在一个下午内产出了 4 项终态裁决+2 项新发现（pending 驻留变异、ApprovalConfig 收窄）——**文档链检验延伸到代码层成立**，且成本可控（pi 提取+diff_models+人工抽查的分工有效）。
2. **方法维度首试结论**：LLM 从设计文档提取方法与逻辑描述（42 方法+@logic）质量足以支撑比对；但方法级 diff 的原始输出噪声高（本例 38 项方法差异中合法适配占多数），**三分法归因是从噪声到结论的必要环节**——印证上轮判断："先验证、再使用"，方法设计直接当代码生成锚之前必须过归因。
3. **"提取被迫表态"是稳定的副产品机制**：pi 两次提取各产出一份"无法决定的点"清单（设计 11+代码 8）——这是 LLM 提取场景下翻译审计预填的天然素材（等价于 E30 机器预填列），值得机制化进管线（提取模板固定含"含糊点清单"节）。
4. **本实验对原交付的终评**：该交付的语义保真高于静态评估时期的认知（六态贯穿、审批语义完整、类型层反向补缺），核心缺陷 RULE-003 的真实形态是"类型层存在+运行时缺失"而非全链蒸发——**代码比对修正了此前基于文档链的推断**，这正是本实验方法价值的直接展示。

## 5. 局限
