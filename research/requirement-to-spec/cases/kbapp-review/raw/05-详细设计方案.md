## 2. 数据模型详细设计

### 2.1 SQLite 注册库 DDL

```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;

CREATE TABLE IF NOT EXISTS files (
  doc_id         TEXT PRIMARY KEY,           -- 稳定 ID：<corpus>:<relpath 归一>（SHA-256 亦可）
  path           TEXT NOT NULL UNIQUE,        -- 磁盘绝对路径
  sha256         TEXT NOT NULL,
  mtime          INTEGER NOT NULL,
  topic          TEXT,                        -- 主题域（分类结果）
  doc_type       TEXT,                        -- paper/report/note/webpage/diagrams/design
  corpus         TEXT NOT NULL,               -- references|research|design|inbox|external
  extract_status TEXT NOT NULL DEFAULT 'pending', -- pending|ok|flat|no_text|failed
  status         TEXT NOT NULL DEFAULT 'new', -- new|indexed|tombstone
  arxiv_id       TEXT,
  version        TEXT,
  authors        TEXT,                        -- JSON 数组字符串
  published      TEXT,
  pages          INTEGER,                       -- 页数（FR-1.5）
  title          TEXT,
  summary_source TEXT NOT NULL DEFAULT 'none', -- none|curated|auto
  summary_path   TEXT,                         -- 指向 curated summary 文件（若有）
  summary_stale  INTEGER NOT NULL DEFAULT 0,   -- 1=curated summary 过期（PDF 变更待重生成）
  updated_at     TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_files_topic ON files(topic);
CREATE INDEX IF NOT EXISTS idx_files_status ON files(status);
CREATE INDEX IF NOT EXISTS idx_files_sha256 ON files(sha256);

CREATE TABLE IF NOT EXISTS tasks (
  id          TEXT PRIMARY KEY,               -- ULID/时间戳+随机
  kind        TEXT NOT NULL,                  -- parse|classify|summarize|extract|index|collect|tombstone
  payload     TEXT NOT NULL,                  -- JSON：入参（doc_id / paths / scope）
  status      TEXT NOT NULL DEFAULT 'pending',-- pending|running|done|failed
  attempts    INTEGER NOT NULL DEFAULT 0,
  max_attempts INTEGER NOT NULL DEFAULT 3,
  run_after   TEXT,                             -- 退避重试的最早可执行时间（ISO）
  error       TEXT,
  created_at  TEXT NOT NULL,
  started_at  TEXT,
  finished_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_tasks_status ON tasks(status, created_at);

CREATE TABLE IF NOT EXISTS inbox (
  id             TEXT PRIMARY KEY,
  source         TEXT NOT NULL,               -- arxiv|web
  url            TEXT,
  title          TEXT NOT NULL,
  arxiv_id       TEXT,
  sha256         TEXT,
  relevance_score REAL,                       -- 0.0–1.0
  verdict        TEXT NOT NULL DEFAULT 'pending', -- pending|watchlist|accepted|rejected
  scoring_module TEXT NOT NULL DEFAULT 'default',
  scoring_version TEXT,
  scoring_notes  TEXT,                        -- 自由文本，如 "no_abstract=true;cross_topic_bonus=true"
  suggested_topic TEXT,
  created_at     TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_inbox_verdict ON inbox(verdict, relevance_score DESC);
CREATE UNIQUE INDEX IF NOT EXISTS idx_inbox_arxiv ON inbox(arxiv_id) WHERE arxiv_id IS NOT NULL;

CREATE TABLE IF NOT EXISTS collect_log (
  id          TEXT PRIMARY KEY,
  source      TEXT NOT NULL,
  query       TEXT,
  title       TEXT,
  arxiv_id    TEXT,
  sha256      TEXT,
  score       REAL,
  disposition TEXT NOT NULL,                  -- accepted|watchlist|rejected|duplicate
  run_id      TEXT NOT NULL,
  created_at  TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_collect_run ON collect_log(run_id);

CREATE TABLE IF NOT EXISTS config_audit (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  ts         TEXT NOT NULL,
  key        TEXT NOT NULL,
  old_value  TEXT,
  new_value  TEXT,
  source     TEXT NOT NULL                    -- cli|file_edit|auto（auto 为 M1 扩展）
);
CREATE INDEX IF NOT EXISTS idx_config_audit_key ON config_audit(key, ts);

CREATE TABLE IF NOT EXISTS llm_usage (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  ts            TEXT NOT NULL,
  model         TEXT NOT NULL,
  purpose       TEXT NOT NULL,                -- classify|summarize|extract|arbitrate|embed
  input_tokens  INTEGER NOT NULL DEFAULT 0,
  output_tokens INTEGER NOT NULL DEFAULT 0,
  cost          REAL,
  doc_id        TEXT
);
CREATE INDEX IF NOT EXISTS idx_llm_usage_ts ON llm_usage(ts);
```

> **M1 落地补充**（实现详见 `code/kb-app/docs/data-model.md`）：新增 `schema_version` 单行元表（M1 仅记录版本号，M3 起演化为迁移器）；另建 4 条本清单外索引——`idx_files_arxiv_id`、`idx_tasks_kind`、`idx_collect_arxiv`、`idx_llm_usage_doc`（均为反查/统计用途，口径：SQLite 侧为 WHERE/反查列建索引但不盲目全列建索引）；`config_audit.source` 取值扩展为 `cli|file_edit|auto`。

> **M2 新增**（09 §2/§8）：`topics` 表（主题清单 + 质心预留）与 `id_counters` 计数器表（doc_id 全局顺序编号）：
>
> ```sql

>   name        TEXT PRIMARY KEY,
>   description TEXT,
>   centroid    BLOB,                  -- M3: bge-m3 质心（float32 序列化）；M2 恒 NULL
>   doc_count   INTEGER NOT NULL DEFAULT 0,
>   created_at  TEXT NOT NULL,
>   updated_at  TEXT NOT NULL

> CREATE TABLE IF NOT EXISTS id_counters (
>   name  TEXT PRIMARY KEY,

>
> doc_id 采用全局顺序编号 `D%04d`（09 §2），替代本节 DDL 注释中的"`<corpus>:<relpath 归一>`（SHA-256 亦可）"开放表述；M2 起 `SCHEMA_VERSION=2`。

全文索引（FTS5，trigram，中英兼顾）：

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS fts_chunks USING fts5(
  chunk_id UNINDEXED,
  doc_id   UNINDEXED,
  section_path,
  title,
  text,
  tokenize='trigram'
);
```

要点：
- `files.doc_id` 用 `<corpus>:<relpath>` 归一，重命名/移动时仅改 `path` 不改 `doc_id`，保证引用稳定（FR-4.4）。
- `tasks` 是 WAL 式流水线核心：扫描器只入队，执行器取任务执行；崩溃后重启续跑 `pending/running` 超时任务。
- 拒绝名单不单建表，由 `inbox.verdict='rejected'` + `collect_log.disposition='rejected'` 推导；单篇 SHA-256 永久跳过见 `dedup.py`。

### 2.2 图 Schema（LadybugDB DDL，经 GraphStore 翻译）

以下为 **LadybugDB 单一后端**（15 D15-10）的 DDL，由 `GraphStore` 适配层（§3.1）从后端无关 Schema（`kbapp/graph/schema.py`）翻译生成。

```cypher
-- 节点（四类，15 §3.2 / D15-2）
CREATE NODE TABLE Document(
  doc_id STRING PRIMARY KEY, title STRING, path STRING, sha256 STRING,
  doc_type STRING, corpus STRING, arxiv_id STRING, version STRING,
  authors STRING, published STRING,
  summary_l1 STRING, summary_l2 STRING, summary_path STRING,
  valid_from STRING, valid_to STRING
);
CREATE NODE TABLE Section(
  section_id STRING PRIMARY KEY, doc_id STRING, section_path STRING,
  level INT64, title STRING, summary STRING, page_range STRING, seq INT64
);
CREATE NODE TABLE Entity(
  entity_id STRING PRIMARY KEY, name STRING, type STRING,
  aliases STRING, description STRING
);
CREATE NODE TABLE Topic(
  name STRING PRIMARY KEY, description STRING
);

-- 边（四类，15 §3.2 / D15-2）
CREATE REL TABLE CONTAINS_SECTION(FROM Document TO Section, seq INT64);
CREATE REL TABLE MENTIONS(FROM Section TO Entity, weight INT64);
CREATE REL TABLE ABOUT_TOPIC(FROM Document TO Topic, confidence DOUBLE);
CREATE REL TABLE RELATES_TO(FROM Entity TO Entity, kind STRING, weight DOUBLE, evidence_section_id STRING);
```

设计要点（MVP 收敛，15 §3.2 / D15-2）：
- **砍除**：Chunk 节点 + CONTAINS_CHUNK + MENTIONS_ENTITY + CITES + SUPERSEDES + SAME_AS；不落 `Section→Topic`（主题归类文档级，Section 主题经父 Document→ABOUT_TOPIC 反查推导）。
- **软删除只到 Document 级**：仅 `Document` 带 `valid_from/valid_to`（STRING ISO 时间戳）；删除即置 `valid_to` 墓碑（不物理删边），`Section` 经父 `Document` 级联过滤；`Entity/Topic` 为共享节点不置墓碑。
- **无属性二级索引**：热路径走主键定位 + 关系遍历（Entity 按 `entity_id = type:norm(name)` 主键定位，无需名称二级索引）。
- `RELATES_TO.kind` 受控词表：`extends|contradicts|applies|evaluates|improves-on|part-of|instance-of|uses|compares`。

### 2.3 LanceDB 表 Schema（Arrow）

```python
import pyarrow as pa

CHUNKS_SCHEMA = pa.schema([
    ("chunk_id", pa.string()),            # 主键，= 图库 Chunk.chunk_id
    ("doc_id", pa.string()),
    ("section_id", pa.string()),
    ("section_path", pa.string()),
    ("vector", pa.list_(pa.float32(), 1024)),   # bge-m3 维度 1024
])
```

- 向量列固定 1024 维 float32；`chunk_id` 为去重键。
- 正文不存 LanceDB：检索命中返回 `chunk_id`，展示时经 `chunk_id → text_ref` 取原文（与图库一致，保持向量库轻量）。
- 写入：`add(mode="overwrite")` 是**整表覆盖**，会清空其他文档向量，不可用。改用 **`merge_insert("chunk_id").when_matched_update_all().when_not_matched_insert_all()`** 按 `chunk_id` 幂等 upsert（批量 N=256）。
- 维护：`kb maintenance` 调 `cleanup_old_versions(older_than=...)`；可选 compaction。

### 2.6 Curated Summary（预生成高质量摘要）语料源与复用

`references/<topic>/summaries/` 已存有 ~104 篇**人工/Agent 策展的高质量论文摘要**，每篇固定结构：

- 头部：原论文标题、完整 PDF 文件名、作者/年份/出版、摘要类型、生成日期；
- `## 1 适用场景`（何时读这篇）→ `## 2 主要观点与方案` → `## 3 达到的效果`（度量表）→ `## 4 参考项目/资源` → `## 5 一句话索引（给 Agent 用）`，各带论文原生 §锚点；
- 每主题另有 `INDEX.md`（论文列表 + 一句话定位 + 与 GraphIt-KB 的相关性）。

**定位**：这是"分层供给 / 少即是多 / MECW 预算"的**现成实现**——把 P3 本要自动生成的"文档级摘要"替换为更高质量的策展摘要，作为**全文索引之上的高信号附加层，而非替代层**（全文 + 向量索引始终保留，对应"文本底座不可关闭"原则）。

**三处收益**：

| 维度 | 收益 |
|---|---|
| 建库开销 | 命中 curated summary 的文档跳过 P3 文档级摘要的 LLM 生成（references 69 篇 PDF 的大头），复用已有产物 |
| 检索开销 | `一句话索引`（~100–200 token）作 L1、`适用场景 + 主要观点` 作 L2、`达到的效果` 表作 compare/topic-global 高信号，Agent 用更少 token 判断相关性 |
| 质量 | 策展摘要 ≥ 自动四段式（含"适用场景"这一检索最关键信号 + 精确 §锚点）；锚点支持下钻原文 |

**集成机制**：

1. **manifest 绑定**：解析 `summaries/*.md` 头部（原论文标题 + 完整 PDF 文件名 + arxiv），建立 `summary → source PDF` 映射；`INDEX.md` 作主题级 manifest。`files.summary_source ∈ {none, curated, auto}` + `summary_path` 落库。
2. **指纹/新鲜度绑定**：curated summary 绑定对应 PDF 的 sha256；`kb index scan` 检测 PDF 变更（新版本）时将 summary 标 `stale`，回退自动摘要并提示人工重生成（复用 FR-4.1；版本链 SUPERSEDES 边已按 15 §3.2 砍除）。
3. **锚点双轨对齐**：curated summary 用论文原生 §编号，KB 下钻走自身解析的 `section_path`，二者经**章节标题匹配**对齐（arXiv 论文 §标题通常一致）；对齐失败时锚点降级为"文档级可下钻提示"。
4. **格式解析**：摘要头部与五段结构的构建规范见 §2.6.1、文件命名规范见 §2.6.2；当前存量摘要用约定式（blockquote 头部 + 固定 `##` 标题），解析器按已知标题容忍匹配，后续新摘要建议迁 YAML frontmatter 以利稳健解析（旧文用宽容解析器兼容）。

#### 2.6.1 摘要构建规范（格式与质量）

**目标**：确保所有 `summaries/*.md` 结构一致、字段齐全、可被机器稳定解析，质量达标（可直接作 L1/L2 检索信号）。

**头部字段（论文类摘要必填）**：

| 字段 | 说明 | 示例 |
|---|---|---|
| 原论文标题 | 英文原始标题 | Don't Blame the LLM: How Agent Harness… |
| 完整 PDF 文件名 | **绑定键**，含 `_vN` | `10-Ben_Sghaier-Agent_Harness_Evolution_v2.pdf` |
| arXiv ID（含版本） | 去重主键（去版本号），版本单列 | arXiv:2607.03691v2 |
| 作者 / 年份 / 出版 | 与 manifest 台账一致 | Ben Sghaier et al. / 2026 / ACM TOSEM |
| 摘要类型 | 受控词表（如 `Agent 设计参考 + 内容索引`） | 内容索引 + 设计参考 |
| 生成日期 | ISO 日期 | 2026-08-12 |

**固定五段结构（全部必填，顺序固定）**：

1. `## 1. 适用场景` — 可操作的"何时读这篇"（≥1 条），非内容复述。
2. `## 2. 主要观点与方案` — 结构化观点，每条带论文原生 §锚点。
3. `## 3. 达到的效果` — 表格三列：`度量 | 结果（数值） | 锚点`，数值须来自原文。
4. `## 4. 参考项目 / 资源` — arXiv 链接（论文类必填）、代码、数据集、基线。
5. `## 5. 一句话索引（给 Agent 用）` — ~100–200 token，独立可读，含结论 + 关键证据/数字。

**质量要求**：

- 一句话索引必须**独立可读**（脱离全文也能判断相关性），含结论 + 关键数字（如"35 release × 50 task，无显著提升 + token 翻倍"）。
- 锚点精确到论文原生 §（如 `§4 RQ0 Findings`），不得写"见原文"这类无定位表述。
- "达到的效果"数值必须来自原文，不得外推；无法量化的观点放 §2，不放 §3。
- 头部字段与 `arxiv_2026-07_manifest.md` 台账对齐（Title / Authors / Version / arXiv ID / SHA-256），保证 KB 可交叉校验。

**生成与维护**：摘要由 Agent 生成 + 人工审核后入 `summaries/`；源 PDF 版本变更（v1→v2）时更新头部"完整 PDF 文件名"与 arXiv version，并重生成受版本影响的 §3 效果表（数字可能变化），其余段落仅在必要时更新。

#### 2.6.2 摘要文件命名规范

**模式**：`<NN>[-<letter>]-<中文短标题>.md`

| 段 | 规则 |
|---|---|
| `<NN>` | 2 位补零序号（>99 自然扩 3 位）；**与源 PDF 的 `NN-` 前缀严格一致**（summary→PDF 绑定键） |
| `[-<letter>]` | 可选字母后缀（a/b/c），当同一 `NN` 号对应多篇（如 `05a`/`05b`）时使用，与源 PDF 的 letter 后缀一致 |
| `<中文短标题>` | 8–20 字中文主词，概括论文核心；多词用 `-`/`_` 分隔 |

**约束（检索相关性）**：

1. **序号即绑定**：`NN[-letter]` 前缀与源 PDF 一致 → 一键定位原文，且是主题内阅读顺序（对应 `INDEX.md` 的"推荐先读"）。
2. **中文短标题是检索信号**：文件名进入 `kb_search` 的 FTS5 trigram + 向量检索字段；中文主词比 `01-Agent-Harness-Evolution.pdf` 这类英文/PascalCase 名更利于中文召回。
3. **不带版本号**：`_vN` 属于源 PDF 文件名、不属于摘要名——摘要名保持稳定，检索结果锚点不随版本漂移（版本变更由头部"完整 PDF 文件名"字段 + sha256 绑定 + `stale` 标记处理）。
4. **不含非法/歧义字符**：禁 `/` `\` `:` `*` `?` `"` `<` `>` `|` 及空格。
5. **主题内唯一**：同一主题目录内 `NN[-letter]` 不重复。

**正例 / 反例**：

- ✅ `10-Agent_Harness演化与质量回归.md`（NN 与 PDF 一致、中文主词、无版本号）
- ✅ `05a-LLM作为数据库管理员.md`（letter 后缀与 PDF `05a-` 一致）
- ❌ `10-Ben_Sghaier-Agent_Harness_Evolution_v2.md`（带版本号 → 版本漂移破坏锚点）
- ❌ `Agent Harness 演化.md`（无序号 → 无法绑定源 PDF、无阅读顺序）

### 3.1 GraphStore 适配层（D2 落地，最关键解耦点）

```python
from typing import Literal, Protocol

class GraphStore(Protocol):
    """图库访问统一接口。单一实现：LadybugStore（15 D15-10，无降级后端）。"""

    def open(self, path: str, mode: Literal["rw", "ro"]) -> None: ...
    def close(self) -> None: ...

    def upsert_nodes(self, label: str, rows: list[dict]) -> None:
        """按主键 upsert 节点。rows 的 key 须含主键。"""

    def upsert_edges(self, rel: str, rows: list[dict]) -> None:
        """rows 每项含 src/dst 主键值 + 边属性。"""

    def query(self, cypher: str, params: dict | None = None) -> list[dict]:
        """只接受标准 Cypher（MATCH/WHERE/RETURN/ORDER/LIMIT），禁后端特有扩展。"""

    def shortest_path(self, src: tuple[str, str], dst: tuple[str, str],
                      max_hops: int = 3) -> list[dict]:
        """两节点最短路径（供 Web 图谱页"查找路径"）。返回 [{"nodes":[…],"rels":[…],"length":n}]。"""
```

实现约定：
- **Schema 中立**：schema 定义存一份后端无关的数据结构（节点/边/属性/主键），由 `kbapp/graph/schema.py` 单一事实来源，Store 翻译为自身 DDL（Ladybug `CREATE NODE TABLE`）。
- **查询口径**：只写标准 Cypher 子集，不碰 LadybugDB 内置 FTS/HNSW 向量——单一后端下换库保险靠图数据可全量重建 + 本适配层（换库只重写一个 Store）。
- **单一后端**：仅 LadybugStore（15 D15-10）；契约测试集以同一套 schema DDL + 固定查询在 LadybugDB 单后端跑通（15 §3.3）。
- **工厂**：

## 4. 处理流水线详细流程

任务由 `tasks` 表驱动；每个阶段函数签名一致：`stage(doc_id, ctx) -> StageResult`，幂等（以 doc_id/chunk_id 为键 upsert），失败抛异常由执行器记 `failed` 可重放。

### 4.0 执行器（runner）

> **M2 落地形态（09 §10）**：`kb index run` 前台同步、**串行**、单写锁；一文一任务（`kind='parse'`），任务内顺序执行 parse→chunk→classify；Ctrl-C 重置当前任务回 pending。多 runner 并发不在 M2 范围。

```python
def run_task(task: Task):
    mark(task, "running")
    try:
        result = STAGES[task.kind](**json.loads(task.payload))
        mark(task, "done")
    except RetryableError as e:
        task.attempts += 1
        if task.attempts < task.max_attempts:
            mark(task, "pending", error=str(e),
                 run_after=now() + backoff(task.attempts))   # 指数退避 30s→1m→5m…
        else:
            mark(task, "failed", error=str(e))
```

### 4.6 墓碑清理（删除/修改路径）

删除/修改文档时，索引层（向量/FTS）不做软删除，按 `doc_id` 物理清理（可由原文重建，NFR-5；对应 §2.2 设计要点）：

```python
def stage_tombstone(doc_id, reason: Literal["delete", "modify"]):
    graph.upsert_nodes("Document", [{doc_id, valid_to: now()}])   # Document 级软删除
    lancedb.delete(f"doc_id = '{doc_id}'")                        # 清旧向量
    fts.delete_by_doc(doc_id)                                     # 清旧全文
    update_files(doc_id, status="tombstone" if reason == "delete" else "new")
    if reason == "modify":                                        # 修改：清理后重跑完整流水线
        enqueue_pipeline(doc_id)                                  # parse→classify→summarize→extract→index
```

触发点：`kb index scan` 检测到删除 → 入队 `tombstone` 任务；检测到修改 → 先 `tombstone` 再入队完整流水线（03 §6.1"修改 → 旧节点置墓碑 → 入队完整流水线"；内容变更后 sha256 必变、P1 缓存必 miss，不能只跑 `index` 阶段，否则会以旧章节树/旧摘要重建索引）。重复执行 `lancedb.delete`/`fts.delete_by_doc` 幂等无副作用。

## 5. 检索引擎详细设计

### 5.1 三路检索 + RRF 融合

```python
def search(query, mode, topic, limit):
    if mode in ("hybrid", "graph"): q = query_understanding(query)   # 可选 LLM：改写+提实体
    vector_hits  = vector_search(q)          # LanceDB top-k
    graph_hits   = graph_search(q)           # MVP：主题/章节结构导航；P1 实体图谱建成后升级为实体子图遍历
    fts_hits     = fts_search(q)             # FTS5 trigram
    fused = rrf(vector_hits, graph_hits, fts_hits)   # RRF
    merged = dedup_by_section(fused)         # 同 Section 多 Chunk 归并
    return top(merged, limit)
```

**RRF**：`score(d) = Σ_path 1/(k + rank_path(d))`，`k=60`（config 可调）。三路权重默认均等，后续可扩展为加权（NFR-8 检索器可扩展点）。

**全文路 trigram 规则**（03 §5.1）：建索引 `tokenize='trigram'`；查询侧 ≤3 中文字符原样匹配，长查询按 trigram 拆分后 AND 组合。

### 5.2 上下文组装（FR-3.2，MECW 预算）

```python
def assemble_context(task, budget=8000, topics=None):
    hits = hybrid_search(task, mode="hybrid", topic=topics)
    blocks = [
        "## 知识库上下文（预算 %d tokens）" % budget,
        "### 结构化要点（来自图谱）",      # 顶层概念 + 锚点
        "### 相关资料摘要（按相关性降序）", # L1/L2 内联（50–100 token/条）
        "### 可下钻条目",                  # L3/L4 原文仅列工具调用方式
    ]
    return render(blocks, budget)  # 超预算先砍"间接相关"层；首尾锚定关键约束
```

---

> **分层与 Curated Summary**：命中 curated summary 时，L1 用"一句话索引"（~100–200 token），L2 用"适用场景 + 主要观点"，L3 为"达到的效果"表（compare/topic-global 高信号）；无 curated summary 的文档回退自动四段式。原文（L4）仍经锚点下钻，全文/向量索引不受影响。

> **MECW 计数**：token 计数用与目标模型一致的 tokenizer（默认 tiktoken `o200k_base`，可配）；预算按 MECW 而非标称窗口，组装后用同一 tokenizer 复算实际用量并写回 `used`（§6），保证"实际 ~6200"可复现。

> **计数口径（13 §8 回写）**：M3/M4 用 **4 字符/token 近似**（`assembler._CHARS_PER_TOKEN`），真实 tokenizer 复算留 P1。

## 7. 并发与一致性

### 7.1 写锁（03 §6.4）

```python
# core/lock.py
def acquire_write_lock(data_dir) -> Lock | None:
    p = Path(data_dir) / ".write.lock"
    try:
        fd = os.open(p, os.O_CREAT | os.O_EXCL | os.O_WRONLY)   # 原子 O_EXCL
        os.write(fd, f"{os.getpid()}".encode()); return Lock(p, fd)
    except FileExistsError:
        pid = _read_pid(p)                    # 打开锁文件取 fd 读 PID
        if _alive(pid):                       # os.kill(pid, 0) / psutil.pid_exists
            raise LockHeld(pid)               # 报持锁 PID；--wait 则轮询阻塞
        os.unlink(p)                          # 死锁：崩溃残留，回收后重试
        return acquire_write_lock(data_dir)
```

- 写命令（`index run`/`reindex`/`collect`）取锁；`inbox accept` **不取图库写锁**（只写 SQLite + 入队任务，实际索引由随后 `index run` 完成——03 §6.4 的刻意折衷，Web Inbox 高频审核不与只读进程互斥）。检索命令（`search`/`show`/`read`）与 MCP/Web 只读模式不取锁、可与一个写进程共存。
- Web UI 钉死为只读：其写操作统一落 SQLite 意图/任务表，由持锁执行器异步落图（03 §6.4）。
- 锁文件含 PID；获取失败时检测进程存活，死锁文件自动回收（另设 mtime 超时兜底）。

### 7.2 任务状态机

```
pending → running → done
         ↘ failed（attempts < max 则退避回 pending）
```

崩溃恢复：启动时把 `running` 且 `started_at` 超时（如 30min）的任务重置为 `pending`。写入幂等（doc_id/chunk_id 键 upsert）保证重放安全，达最终一致（03 §6.2）。

## 9. 错误处理与可观测性

**错误分级**：

| 级别 | 处理 |
|---|---|
| 单文件解析失败 | 记 `extract_status=failed`，任务 done（不阻塞流水线），列入 `kb status` 失败清单 |
| 单阶段可重试失败 | `RetryableError`，退避重试，超限 `failed` |
| 写锁冲突 | `LOCK_HELD`，报持锁 PID，`--wait` 可选 |
| Embedding 未就绪 | `EMBED_NOT_READY`，提示 `kb init` 下载模型 |
| 插件加载失败 | 降级 default，写报告，不阻塞 |

**CLI 退出码约定**（M1 落地时补充，实现见 `code/kb-app/src/kbapp/cli/config.py`）：

| 退出码 | 语义 |
|---|---|
| 0 | 成功 |
| 1 | 校验失败（配置键不存在、类型不匹配等用户输入错误） |
| 2 | 写锁冲突 / 其他 IO 错误 |

**报告**：
- `reports/run_<id>.md`：处理清单、成功/失败、token 消耗、耗时（NFR-7）。
- `reports/collect_<date>.md`：新增/去重/watchlist/淘汰 + 每篇评分模块与版本号（FR-6.7）。
- `reports/monthly_<date>.md`：新增统计、阅读路线、图谱缺口分析、依赖漂移清单。

**依赖漂移**：`kb status` 输出 `deps`（关键组件版本 + 距最新发布版次）；月度报告列需评估升级的组件（02 风险表对策）。

## 11. 关键实现约定（防踩坑清单）

1. **LadybugDB 包名是 `ladybug`**（非 `ladybugdb`），`uv.lock` 精确钉版本。
2. **MCP SDK 钉 `mcp>=1.29,<2`**；不混用 PrefectHQ `fastmcp`。
3. **图库只用标准 Cypher 子集**；向量在 LanceDB，图内置 FTS/HNSW 一律不用。
4. **LanceDB 硬单写者**：所有写走锁；定期 `cleanup_old_versions`。
5. **原文只读**：`references/`/`research/` 永不写入；产物全在数据目录。
6. **bge-m3 本地推理**：首次 `kb init` 引导下载（~2GB）；`embedding.backend=api` 兜底。
7. **改判防震荡**：主题质心不实时重算，冻结至下次批量重建。
8. **accept 与 NFR-3**：`inbox accept` 向 `references/` 移入新文件属"只新增、不改既有 canonical 文件"，符合 NFR-3"原文不可变"的意图。
9. **LadybugDB 无属性二级索引**：非主键热路径走主键定位 + 关系遍历，或落到 LanceDB/SQLite。
