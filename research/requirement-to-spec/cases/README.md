# cases/：试点案例工作区

> R1 起。案例选择标准：

1. **中等复杂度**：可在一周内人工走完 S0–S6（约 20–50 条需求条目量级）；
2. **双案例异构**：案例 A 流程重（多角色审批流/状态迁移多，主打 soundness 检查）、案例 B 规则重（数值约束/互斥规则密集，主打 SAT 矛盾检查）——覆盖三件套两侧；
3. **含隐性引用**：需求原文自然出现"jpeg 格式""二级审批"类外部共识引用（Z_伪 样本）与至少若干真自由度（Z_真 样本，用于 R4 曲线的非平凡性）；
4. **可验证**：存在领域专家（用户本人可扮演）能提供预期场景与裁决。

每个案例目录结构：`raw/`（原始需求）→ `terms/` → `items/` → `formal/`（owl/z3/pnml 及翻译审计表）→ `scenarios/` → `reports/` → `metrics/`。
