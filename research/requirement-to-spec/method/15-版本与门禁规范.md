# 15-版本与门禁规范（最小草案）

> 版本 v0.1（2026-08-27，R0 草案）。门禁的工程化（pre-commit/CI）按计划归 R5；本草案固化已实践验证的版本纪律与门禁判定集，使 R1–R4 期间规则不漂移。

## 1. 版本纪律（已实践，规则化）

1. **git 是唯一版本事实源**：禁止文件名级版本（`-v2`/`-done` 类分裂副本）；禁止快照另存（done 教训——git 历史即沿革）。
2. **三个层级的版本载体**（16 号 §2 裁定）：
   - 文件级 → git 提交历史；
   - 表格行级 → 行 ID（TA1-03，终身不复用）；
   - 决策级 → 决策节内轮次+沿革（退回重议留原文）。
3. **只追加不删改**的文件：检查台账（Run 证据）、决策沿革、登记表澄清结论。错误结果也是证据（Run-2 v1 污染缺陷留痕先例）；台账错误只能以修订标注（r1 围栏归位先例：证据行字符零改动）。
4. 提交粒度：一次语义变更一次提交（模型重构+联动+重跑为一个提交），commit message 记触发原因与实证。

## 2. 决定性基线与 DRIFT 处置（已实践）

1. 转换器（puml2owl）对同一 .puml 必须产出字节级等价产物——sha256 基线存 `regression/baseline/`；
2. 每次 .puml/转换器变更后跑 `check_determinism.py`：
   - `DETERMINISTIC` → 通过；
   - `DRIFT` → 停下归因：内容实质不同（triples 变化）→ 查因，**禁止直接覆盖基准**；仅序列化噪声 → 重建基准并在台账记明；
3. 基准重建是显式动作：须在台账新 Run 记录"基准重定"+原因（首验抓枚举子类化语义漂移的先例）。

## 3. 门禁判定集（R5 前的 advisory 形态）

当前七项检查（method/14）全部 **advisory**（人工触发、结果留台账）；R5 转 **enforced**（pre-commit 自动拦截）。转换条件与顺序：

| 优先级 | 检查 | enforced 成熟度理由 |
|---|---|---|
| 1 | 决定性回归 | 已自动化，秒级 |
| 2 | 绑定闭包 | 已自动化；判定基准锚定规范文本 |
| 3 | Z3 规则 | 已自动化（ALL_PASS 断言） |
| 4 | FSM 性质 | 已自动化 |
| 5 | HermiT | 已自动化（JVM 启动 ~1s 可接受） |
| 6 | SHACL 实例闭包 | 半自动（断言样本人工供给——R3 BDD 独立生成后升） |
| 7 | 翻译审计 | 纯人工——**永不进 pre-commit**；其 enforced 形态=G3 签收门流程化 |

## 4. 状态标注规则

1. 每项检查/每份规范标注 `advisory`/`enforced` 状态（台账头部速览+method/14 总览）；
2. 无门禁环境（advisory 态）下的防腐烂替代：台账完整性=可复跑性（method/14 一条链重跑命令是验收标准）；
3. 状态迁移（advisory→enforced）须在 R5 报告逐项记录迁移依据（运行时长/误报率/修复闭环时延）。
