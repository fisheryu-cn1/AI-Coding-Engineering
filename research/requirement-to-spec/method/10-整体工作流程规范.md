# 10-整体工作流程规范（S0–S6 七阶段流水线）

> 版本 v1（2026-08-27，R0 定稿）。来源：立项框架（README v0）+ loan-system 案例全链实练结晶（S3–S6 已实练验证；S0–S2 部分实练——输入为结构化登记而非开放式 NL，严格版待第二案例，见各阶段"实练状态"标注）。
> 配套：method/11（人机分工）、12（受控语言）、13（翻译与审计）、14（检查规程）、16（评审界面）。模板见 templates/T1–T6。

## 1. 流程总览

```
S0 原始需求接收 → S1 解析与登记 → S2 术语与受控语言定稿 → S3 形式化翻译
  → S4 确定性检查循环 → S5 分歧度签收 → S6 版本化与门禁
```

核心不变量（全程）：**每个需求条目有唯一 ID 且终身不复用；每个 Z_真 决策要么消解（有裁决记录）要么显式化（有 Z-x 节或 [暂缓] 标记）；机器判定永不依赖 LLM**。

## 2. 各阶段定义

### S0 原始需求接收

- 输入：开放式 NL 需求（含隐性外部引用，如"jpeg 格式""二级审批"）。
- 产出：`raw/` 原文存档+来源登记（谁/何时/何种媒介；视觉证据按图片登记表）。
- 执行者：人工。
- **签收门 G0**：原文不可变（后续只追加澄清记录，不改原文）；来源可溯。
- 实练状态：✅（loan-system raw/requirements-register.md，含澄清问答 Q-001~003 登记）。

### S1 需求解析与条目登记

- 输入：S0 原文。
- 产出：需求登记表（T1：BR/FUNC/RULE/FLOW/FIELD/UI/NFR/DEL 八类，每条含 ID/类型/来源位置/原文摘录/结构化表述/优先级/状态）+ 澄清问题清单（Q-x，含是否阻断标记）。
- 执行者：AI 起草 → 人工逐条确认（AI 只进预填位）。
- **签收门 G1**：①每条目有 ID+类型+来源位置（反向闭包的机器检查前提）；②歧义/缺口全部落 Q-x 而非静默选择；③"当前状态"只有已接受/已拒绝/待澄清三值。
- 实练状态：⚠️ 部分——登记表格式已实练（继承自结构化输入），**开放式 NL 的解析与歧义标记未严格实练**（第二案例验证）。
- 实证锚点：原交付"RULE-003 全链丢失"缺陷的成因链起点即登记层——本阶段的条目化是后续一切闭包检查的地基。

### S2 术语表与受控语言定稿

- 输入：S1 登记表。
- 产出：术语表（T2：统一语言，术语/定义/同义词/来源）+ 受控语句条目（EARS 子集改写，见 method/12）。
- 执行者：人工定稿，AI 辅助建议。
- **签收门 G2**：①术语封闭引用——受控条目中的领域名词必须来自术语表（未收录即登记为待定术语）；②每条目单一句式可机检（触发词模板）；③ S1 的 Q-x 已消解或升级为 Z-x（决策显式化）。
- 实练状态：❌ 未实练（loan-system 跳过——结构化输入已含受控表述）。规范为设计版，第二案例实测后修订。
- 理论锚点：S2 边界是 R4 Z_真 曲线的第一个测量点（术语表定稿后的下游独立生成）。

### S3 形式化翻译

- 输入：S2 受控条目+术语表。
- 产出：①概念模型 PlantUML+决策注解（method/13 词表）；②流程线状态图（fsm_check 消费）；③数值/逻辑规则集（Z3，z3tag 命名内嵌文档来源）；④翻译审计表（T3，E30 七列格式）；⑤绑定清单（需求 ID ↔ 模型元素定位符）。
- 执行者：AI 起草（LLM 只进 .puml/预填列）→ 人工审计翻译件本身（翻译审计点前移原则）。
- **签收门 G3**：①审计表覆盖闭包——范围内每条实体/规则/流程类条目 ≥1 行对照（豁免须在绑定清单政策表逐条登记理由）；②弱化/待澄清全部显式并各指向决策节；③绑定清单三闭包（覆盖/解析/反向）机器 PASS。
- 实练状态：✅（loan-system E30 v3、model-bindings 12 行、translation-audit 五轮迭代）。
- 实证锚点：RULE-003 在翻译层强制落点（枚举语法迫使翻译位表态）——"分离点前推"的机制化首证。

### S4 确定性检查循环

- 输入：S3 全部产物。
- 产出：检查台账（T5，只追加）+ 人工决策记录（T4，E41 八行语法）+ 执行队列（G90）。
- 执行者：机器判定（七项检查，method/14）→ AI 回译 justification → 人工裁决（含退回重议，16 号 §4.1）。
- **签收门 G4**：①七项检查全绿（HermiT/Z3/决定性/SHACL/翻译审计/绑定闭包/FSM 性质）；②E41 无空结论的待办节（或已 [暂缓] 显式）；③台账每次运行留痕（触发原因+差异归因）。
- 实练状态：✅（Run-1~11；绑定闭包抓 FUNC-002 联动遗漏、unsat core 点名文档来源、负控四命中等实证）。
- 缺口：BDD 双通道独立性未满足（同源生成）——R3 用独立模型生成 Then 断言解决。

### S5 分歧度签收

- 输入：S4 全绿产物。
- 产出：签收记录（T6 §2）。
- 执行者：R4 之前人工多轮评审替代；R4 之后=N 次独立生成×语义等价类计数。
- **签收门 G5（分歧度阈值位）**：①待决项显式率 100%（所有残留 Z_真 均有 Z-x 节+[暂缓] 或待决标记，无静默决策）；②语义等价类数 ≤ 阈值（阈值 R4 实测定标；定标前以①为替代判据）；③显式待决项随交付（消费者可见）。
- 实练状态：⚠️ 替代判据①已事实满足（loan-system Z1–Z4 全显式）；等价类计量未实练（R4 域）。

### S6 版本化与门禁

- 输入：S5 签收产物。
- 产出：决定性基线（sha256）+ 门禁配置。
- 执行者：机器（check_determinism；R5 后 pre-commit）。
- **签收门 G6**：①决定性回归 DETERMINISTIC；②全部检查 advisory/enforced 状态已标注（当前 advisory，R5 转 enforced）；③台账完整可复跑（method/14 一条链重跑命令）。
- 实练状态：✅（基线 sha256+DRIFT 首验归因+Run-10 注释零模型效应实证）。

## 3. 阶段回退规则

- G3 未过（审计发现翻译缺陷）→ 回 S3 重译该条目（不是改原文）；
- G4 检查 FAIL → 三层归因（NL→UML 错/UML→OWL 抖动/规格真矛盾，method/13 §1）后定点修复；
- 人工裁决被退回（16 号 §4.1）→ 该决策节重议，模型回滚至上一全绿 Run；
- **禁止跨阶段改写**：S3 之后发现 S1/S2 缺陷时，走变更流程（新 Q-x/Z-x+影响行标注），不直接改登记表历史行。

## 4. 与研究阶段的对应

R0=本规范定稿；R1=每阶段实练反馈修订（S0–S2 严格版为第二案例主目标）；R2=G1/G3 的机检脚本化扩展；R3=S1/S3/S4 的 AI 位替换实测；R4=G5 阈值定标；R5=G6 enforcement。
