# 19-审核方法总装 v1（最佳实践固定版）

> 版本 v1（2026-08-29）。本文档把第 30–33 场实验（loan-system 案例群四轮+kb-app 三层）迭代收敛出的最佳审核方法**固定为可执行配置**：一条总装视图 + 标准作业流 + 工具包清单 + 红线。它是单入口总纲——各环节的详细规程在 method/10–18 与 templates/，本文不重复，只负责组装与指向。使用者入口：[GETTING-STARTED.md](../GETTING-STARTED.md)（面向新使用者）；本文面向方法执行者。

## 1. 总装视图：三线八位三层

```
                 ┌────────── 文档链层（需求→PRD→设计） ──────────┐   代码层
 模型线:  需求条目 → UML(类图/状态机/注解词表) → OWL/SHACL → [HermiT | Z3 | pySHACL | fsm_check]
 场景线:  需求场景/验收标准 → BDD(两维标注) → 分路编排 → [HermiT ABox | fsm 路径 | Z3 边界 | 验收域]
 接口线:  设计 API 契约 ↔ 代码路由(OpenAPI 反向生成) → 比对 → [extract_routes | check_api_alignment*] → E50/DA 裁决
 元层:    需求ID ↔ 模型元素绑定闭包 ↔ 层间 diff(公共骨架) ↔ 文档闭包(五项)
 检查位:  ①文档五项 ②本体一致 ③规则求解 ④实例闭包 ⑤翻译审计 ⑥绑定闭包 ⑦状态机性质 ⑧API 对齐（+BDD 场景分路）
```

两线交叉互证（实例符合性/状态行为/蕴含正确性——错误来源不同，一致即强证据）+互补六盲区（空泛一致唯场景线可查；覆盖缺口与层间漂移唯模型线可查；否定式唯场景线可查等——详见 method/18 §4）。接口线⑧独占路由信息维（资源命名/HTTP 方法/CRUD 覆盖——模型线四维与场景线均不携带，05 轮实证其 17 项发现全部为 UML 通道不可见），且是唯一反向全自动锚（代码→规格 byte-identical）。引擎一览（HermiT=OWL 描述逻辑推理；Z3=SMT 数值求解——两者并列各管一段；pySHACL=形状校验；fsm_check=图遍历；比对器=文本结构）见 GETTING-STARTED §3 表。*check_api_alignment 为 R2 规则化位（exact→路径段对齐→编辑距离，A2 从 ID 空间推广到路径空间），当前比对 LLM 辅助+E50 人工裁决。

## 2. 标准作业流（按案例生命周期三种节奏）

### 2.1 首次建模（低频，全流程）

S0 原文存档 → S1 解析登记（T1，AI 预填人确认）→ S2 术语与受控语言（T2，枚举标注封闭性）→ S3 形式化翻译（忠实原则；两线各自生成；公共骨架对齐下游层）→ S4 检查循环（文档侧七项+BDD 分路；`run_checks.py --heavy` 一条命令）→ S5 签收（待决项显式率 100%+队列清零）→ S6 基线固化（决定性 sha256）→ 代码产出后首跑检查⑧（API 对齐：反向生成+比对+E50 建表）。签收门定义见 method/10。

### 2.2 常规变更（高频，轻链）

代码/文档变更后：AST 单通道提取（method/17 §4.2 工具）→ `run_checks.py <case_dir>`（转换验证/状态机/规则/绑定闭包/队列五件轻检查，秒级）→ **代码变更时加检查⑧轻链**：`extract_routes.cjs` 重跑（秒级）→ 比对差异行与 E50 已裁决行对账（新增偏差才需人工）→ 输出留台账。已知盲区按确定性规则逐步覆盖。

### 2.3 里程碑审计（低频，全通道）

双通道提取对账（AST+LLM 盲跑，method/17 §4.1）→ 层间三分法归因 → 分歧查源码裁决 → **API 全对齐复查**（比对表全行重判+行为级可疑点复查——伪成功/语义变异等运行时行为层发现直接进 DA 节）→ 人工 BDD 边界/异常场景补充（oracle 独立性谱系：同源<异模型<人工）→ 报告入案例 reports/。

## 3. 工具包清单（tools/scripts/，全部确定性零 LLM）

| 工具 | 作用 | 用法 |
|---|---|---|
| `run_checks.py` | **统一检查入口**（常规轻链五件，--heavy 加 HermiT） | `python run_checks.py <case_dir> [--heavy]` |
| `puml2xmi.py` | PlantUML 类图子集解析器（基础件） | 被 puml2owl 复用 |
| `puml2owl.py` | UML→OWL/SHACL 确定性转换 | `puml2owl.py <in.puml> <out前缀>` |
| `fsm_check.py` | 状态机五性质（含 no_escape 显式禁回） | `fsm_check.py <flow.puml>` |
| `check_model_bindings.py` | 绑定闭包（覆盖/解析/反向；--id-regex 适配 FR 体系） | `check_model_bindings.py <case> [--id-regex …]` |
| `check_doc_closure.py` | 文档五项（私造/覆盖/验收映射/词表漂移/验收行 ID+形近变体 A2） | 见 method/14 |
| `diff_models.py` | 两张同骨架 puml 五维 diff（含方法名） | `diff_models.py <上.puml> <下.puml>` |
| `collect_review_actions.py` | 执行队列聚合（退回解锁机制） | `collect_review_actions.py <case>` |
| `ast_extract_py.py` | **Python AST 提取**（标准库零依赖） | `ast_extract_py.py <src.py|目录> [-o out] [-r]` |
| `ast_extract_ts.cjs` | **TS AST 提取**（typescript@5，P2S_TYPESCRIPT 注入路径） | `node ast_extract_ts.cjs <根目录> <out.puml>` |
| `extract_routes.cjs` | **Express 路由→OpenAPI 3.0.3 反向生成**（纯正则零依赖；*收编中：首版在 cases/loan-system/05-openapi-anchor/gen/，多工程自测后入本目录*） | `node extract_routes.cjs <backend-src> -o openapi.yaml` |
| `check_env.py` | 环境自检+全组件冒烟 | `check_env.py --smoke` |

环境：`requirements.txt` 四包+Java≥17；就绪验证 `check_env.py --smoke` 应 ALL_PASS。工具红线：判定不依赖 LLM；提取产物的语义摘要（@logic）属 LLM 语义岗，不进任何判定。

## 4. 质量红线（汇总，出处各规范）

1. LLM 只在翻译/建议/回译/语义摘要位，一切判定走确定性引擎或人（method/11）；
2. 修改必须引用 justification+类型标注；禁止削信号式修复（method/11 §3）；
3. 翻译审计点前移——人审翻译件本身，不只审检查结果（method/13）；
4. 表格分隔符一律 ASCII，禁 Unicode 制表符（method/16 §3）；
5. 层间对照须公共骨架对齐；差异须三分法归因（method/17）；
6. 台账只追加不删改；错误结果也是证据（method/14/T5）；
7. 分发件自包含（plan/02 §8）。

## 5. 覆盖边界声明（不自欺）

方法覆盖四维（实体结构/状态转换/数值逻辑约束/元层对照）；**不覆盖**前置后置条件（@pre/@post 词表候选）与算法逻辑（属代码验证域）——完整边界见 method/13 §8。LLM 环节的方法分层：确定性外壳可提取可检查，概率内核无方法契约，检查位=I/O Schema+验收场景。

## 6. 版本与实证锚

v1 固定自第 30–33 场：loan-system 案例群（cases/loan-system/01~04 四轮）+kb-app 三层（cases/kbapp-review）+先例检索（notes/双通道方法先例检索与历史归因.md）。已知待验证项如实列出：BDD 严格独立（异模型）待 R3；Z_真 曲线待 R4；语义修复传导为单次生成证据；Java AST 前端未实测。
