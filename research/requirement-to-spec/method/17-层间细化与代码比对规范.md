# 17-层间细化与代码比对规范

> 版本 v1（2026-08-29 定稿，kb-app 三层检验+loan-system 代码比对两轮实练转正；此前为 method/README 候选行）。
> 覆盖：相邻两层文档（需求→PRD→概要设计→详细设计）之间与设计→代码之间的一致性检验。单层自身检验见 method/13/14。

## 1. 公共骨架原则（前提）

层间对照的下游形式化模型**必须包含上游模型的同源元素**（骨架对齐、增量叠加），否则元素级比对不可执行。比对工具：`diff_models.py`（五维：类/属性/枚举/关联/方法名；"仅上层有"=保真性检查点，"仅下层有"=溯源性检查点）。

## 2. 细化三分法（差异归因）

下游相对上游的信息增量分三类，验收标准各异：

| 类别 | 定义 | 验收 |
|---|---|---|
| ① 纯推导 | 上游蕴含，下游仅换表达 | 不歪曲原意 |
| ② 受约束选择 | 上游框定范围，下游在范围内选定 | 不出范围+选择有依据（决策记录） |
| ③ 自由新增 | 上游无痕迹，下游注入 | 决策溯源存在（或显式标待决策） |

细化合理 ⟺ 保真（零丢失变形）+ 蕴含一致（防伪推导——把③标成①）+ 溯源完备 三判据零违反。第四类"细化不完整"（如墓碑-重建语义缺口）：既非传导也非新增，是细化没做完——层间对照的主要猎物之一。

单点判定的局限与出路：蕴含判断在自然语言层不可判定，②③边界靠人——统计判据（同一上游 N 次独立设计，复现稳定=推导性强、高方差=选择性强）为 R4 层间版。

## 3. 双向对照纪律

验收清单的层间比对**双向**：多出的条目查溯源，缺失的条目查上游是否也缺（**缺口也会传导**——NFR-4 案例：需求验收层缺性能条目被两层"忠实"继承到实现门口）。

## 4. 设计→代码比对（2026-08-29 首例转正）

### 4.1 提取配置（分层决策，双通道首跑实证）

| 场景 | 配置 |
|---|---|
| 常规同步 | **AST 单通道**（确定性，见 §4.2）+ 已知盲区逐条规则化 |
| 低频审计（首次建模/大重构/里程碑） | **双通道对账**：AST + LLM 各自完整提取，且 **LLM 盲跑**（不给骨架，保独立性——防锚定效应反向风险） |
| 语义增量（@logic 摘要/领域分组/异常洞察） | LLM 常驻（与结构选择正交，AST 永远给不了） |

依据：AST=静默漏无内部审计者（内联 union 案例实证）；LLM=抄录可靠但选择性省略/漏列；对账互审是唯一能发现双方盲区的机制，且首跑实证对账边际成本低（核心集零分歧）。

### 4.2 AST 提取工具链（三门主力语言）

| 语言 | 工具 | 风险注记 |
|---|---|---|
| Python | `tools/scripts/ast_extract_py.py`（标准库 ast，零依赖） | 无 |
| TypeScript/Node | `tools/scripts/ast_extract_ts.cjs`（typescript@5 Compiler API） | **须锁 5.x**——7.x 原生重构版 API 断代（实测）；typescript@5 路径可经环境变量 `P2S_TYPESCRIPT` 注入 |
| Java | javaparser / Spoon / IDE 逆向 | 工具最成熟 |

已知盲区规则化清单（每发现一条补一条确定性规则）：内联联合类型→命名枚举提升（正则可做，LLM 该提升行为可机械化）。

### 4.3 对账归因

diff 原始输出按三分法+建模选择差异归因（AST 按文件归组 vs LLM 按语义命名=选择差异非错误；LLM 选择性省略=抄录偏差非编造；枚举分歧→**查源码判定**——两通道各忠于不同抽象层的可能）。
