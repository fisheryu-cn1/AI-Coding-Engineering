# 13-形式化翻译与审计规范（v0.2）

> 状态：R0 定稿（v0.1 草案经 loan-system 实练修订）。覆盖 S3 阶段：受控需求条目（S2 产出）→ PlantUML 类图/状态机 → OWL/SHACL。
> 执行件：`tools/scripts/puml2owl.py`（映射器）+ 决策注解词表（本规范 §3）。
> v0.2 变更：§4 审计表对齐 E30 实践（七列+行 ID+机器区/人工区分区，取代 v0.1 五列格式）；补审计操作步骤与判废标准；新增 §7 流程线与绑定清单。

## 1. 两段式翻译架构

```
NL → [LLM 翻译] → PlantUML + 决策注解 → [人审图形+注解] → [puml2owl 确定性转换] → OWL + SHACL
```

- **LLM 的职责边界**：NL→UML 翻译 + 决策注解建议；**不得**直接产出 OWL/RDF（保持"OWL 是需求的确定函数"，否则检查器失败无法三层归因：NL→UML 错/UML→OWL 抖动/规格真矛盾）。
- **转换确定性**：同一份 .puml 输入必须产出字节级等价的 OWL（回归测试项）。

## 2. PlantUML 类图子集（翻译输出语法面）

- `class X { 属性... }` / `abstract class` / `interface`、`enum X { ... }`（单行/多行）
- 关联 `A "m" --> "n" B : label`（箭头变体统一按无向关联处理）
- 泛化 `A <|-- B` 与 `B --|> A`
- 单行注释 `' @anno: value` 形式的决策注解

## 3. 决策注解词表 v0.1（LLM 建议→人审→代码执行）

PlantUML 表达不了的语义决策通过注解进入转换。**每条注解都是决策显式化（Z_真 → 显式记录）**：

| 注解 | 语义 | 映射到 |
|---|---|---|
| `' @disjoint: C1, C2[, ...] | 类间互斥（如状态字面量类） | owl:AllDisjointClasses |
| `' @required: Class.prop[, Class.prop...] | 属性必填（是否填写了内容） | SHACL sh:minCount 1（2026-08-27 Z4 执行新增） |
| `' @pattern: Class.prop = 正则 | 属性格式校验 | SHACL sh:pattern（同上） |
| `' @cardinality: P exactly N | 关联精确基数 | Restriction(exactly) |
| `' @functional: P | 属性函数性 | FunctionalProperty |
| `' @key: Class.prop | 身份属性 | HasKey |
| `' @reflexive/-irreflexive: P | 自反/反自反 | 子性质公理组（最小版可挂起标记） |
| `' @rangeUnion: P = C1, C2 | 值域联合 | union range |

规则：
1. **只允许出现词表内注解**——词表外语义需求必须回落到 S2 需求条目（条目粒度不够则提新词表提案）；
2. 注解由 LLM 按需求文本建议、人工在翻译审计中逐条确认——确认后的注解是**已消解的 Z_真 记录**，随图入 Git；
3. 词表版本化：扩词表=改本表+改 puml2owl 对应处理逻辑，同 PR 提交。

## 4. 翻译审计对照表（v0.2：七列格式，实练对齐版）

每行一个被形式化的条目，**前五列机器区（翻译位生成，评审者只读）后三列人工区**（16 号 §3；首例 E30）：

`| ID | 条目ID | NL 原文(摘录) | 模型元素/落点 | 机器预填 | ✍评审结论 | ✍执行标记 | ✍签注 |`

- 行 ID：`<表码><轮次>-<序号>`（TA1-03），终身不复用——下游（决策节/队列/绑定清单）的锚点；
- 评审结论合法值：`忠实` / `弱化(<原因>)` / `待澄清(<问题>)` / `确认` / `驳回(<原因>)` / `修正(<内容>)` / `补充(<内容>)`（后两值=评审产出需求精化，须联动执行标记）；
- 覆盖率判据：范围内每个含实体/规则/流程语义的需求条目 ≥1 行对照（豁免在绑定清单政策表逐条登记）；
- 弱化判定：NL 中可观察行为被译为纯结构元素而无对应注解/条目/规则承接，记"弱化"并回 S2 或立决策节；
- 预填质量：机器区说明文字上下文自足、不自造词（16 号 §3 预填文字质量要求）。

### 4.1 审计操作步骤（人的动线）

1. 开案例 `review/V00-INDEX.md` → 看"本次待办"；
2. 逐行读机器区五列（原文↔落点对照），需要证据时按 INDEX 链接只读材料（图形/台账）；
3. 人工区三列就地填写（结论/标记/签注）；"待澄清"即按 16 号 §4 在决策记录立节；
4. 保存即完成——git diff 即评审记录。

### 4.2 判废标准（何时本轮翻译作废重译）

- 审计发现 ≥3 行"弱化"且成因同类（系统性翻译偏差）→ 整轮重译而非逐行补丁；
- 落点与需求条目错位（张冠李戴级）→ 该条目行作废，新行新 ID 重开（旧行不删，标记作废原因）；
- 机器区被人工误改（分区被破坏）→ 以 git 恢复机器区，人工区内容按行 ID 合并回填。

## 5. BDD 双检衔接（S4 接口）

- 场景二分标注：状态约束类 Then → OWL 蕴含检验（ABox 断言+HermiT）；动作效果类 Then → 流程模型线（SCXML/Petri，另行供给）；
- 双通道独立生成原则：BDD 库与 OWL 必须来自对需求的**独立翻译**（防 tautology）；
- 公理覆盖率反向提示：未触达公理清单自动生成，驱动补场景。

## 6. 转换质量红线

1. 同输入必同输出（字节级回归）；
2. LLM 产物仅允许进 .puml 文件与对照表预填列，禁止直改 .owl/.shacl/.ttl;
3. 注解词表外语义一律不进模型（宁可标待决也不静默丢弃或即兴表达）；
4. 每次 PLANTUML/puml2owl 版本变更重跑回归样例集。

## 7. 流程线与绑定清单（v0.2 新增，实练补全）

- **流程线翻译件**：状态机用 PlantUML 状态图子集（`[*]/状态/迁移/终态`），结构性质五项由 `fsm_check.py` 判定（可达/共可达/终态封闭/无死锁/显式禁回）；显式禁回清单 `no_escape_from=[...]` 在图内配置。范围声明：FSM 性质子集，并发分支出现时升级 WF-net soundness 工具链。
- **绑定清单**（formal/model-bindings.md）：需求 ID ↔ 模型元素定位符对照 + 豁免政策表（逐条带理由）+ `[暂缓]` 显式机制。三闭包（覆盖/解析/反向）由 `check_model_bindings.py` 判定——**缺失类缺陷的唯一确定性防线**（回填实验 A 结论：结构检查器捕误用不捕缺失）。定位符语法：`class:/enum:/attr:/assoc:/disjoint:/decision:/z3tag:/trans:`。
- **规则集**：Z3 编码，z3tag 命名必须内嵌文档来源（`O1_登记侧_…`/`Z2_…_人工输入日期`）——unsat core 的可读性=跨文档矛盾的定位力。

## 8. 检查覆盖面边界（2026-08-28 立，用户追问驱动）

本管线检查四个维度：**实体结构**（类图→OWL→推理/形状校验）、**状态转换**（状态机结构性质+BDD 动作路径）、**数值与逻辑约束**（Z3：规则自洽/蕴含/组合效应）、**元层对照**（绑定闭包/模型 diff/翻译审计）。

方法（类操作）的覆盖以"行为三分路由"实现：生命周期行为→状态机（迁移与操作无损互转，Run-13 实证）；数值判定逻辑→Z3 规则集；方法签名→diff_models 方法维度（名级）。**不覆盖**：前置/后置条件（词表扩展 @pre/@post 候选，OCL 式约束可转 Z3/SHACL——后续方向）；算法/伪代码逻辑正确性（属代码验证域，超出文档层定位，兜底=翻译审计人工+验收测试）。LLM 环节方法分层：确定性外壳（触发/落库/签名）入类图可查；概率内核无方法契约，检查位=I/O Schema+验收场景（与红线同构）。
