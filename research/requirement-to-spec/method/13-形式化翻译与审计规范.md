# 13-形式化翻译与审计规范（草案 v0.1）

> 状态：R0 草案，待 R1 案例试点后修订。
> 本规范覆盖 S3 阶段：受控需求条目（S2 产出）→ PlantUML 类图/状态机 → OWL/SHACL。
> 执行件：`tools/scripts/puml2owl.py`（映射器）+ 决策注解词表（本规范 §3）。

## 1. 两段式翻译架构

```
NL → [LLM 翻译] → PlantUML + 决策注解 → [人审图形+注解] → [puml2owl 确定性转换] → OWL + SHACL
```

- **LLM 的职责边界**：NL→UML 翻译 + 决策注解建议；**不得**直接产出 OWL/RDF（保持"OWL 是需求的确定函数"，否则检查器失败无法三层归因：NL→UML 错/UML→OWL 抖动/规格真矛盾）。
- **转换确定性**：同一份 .puml 输入必须产出字节级等价的 OWL（回归测试项）。

## 2. PlantUML 类图子集（翻译输出语法面）

- `class X { 属性... }` / `abstract class` / `interface`、`enum X { ... }`（单行/多行）
- 关联 `A "m" --> "n" B : label`（箭头变体统一按无向关联处理）
- 泛化 `A <|-- B` 与 `B --|> A`
- 单行注释 `' @anno: value` 形式的决策注解

## 3. 决策注解词表 v0.1（LLM 建议→人审→代码执行）

PlantUML 表达不了的语义决策通过注解进入转换。**每条注解都是决策显式化（Z_真 → 显式记录）**：

| 注解 | 语义 | 映射到 |
|---|---|---|
| `' @disjoint: C1, C2[, ...] | 类间互斥（如状态字面量类） | owl:AllDisjointClasses |
| `' @cardinality: P exactly N | 关联精确基数 | Restriction(exactly) |
| `' @functional: P | 属性函数性 | FunctionalProperty |
| `' @key: Class.prop | 身份属性 | HasKey |
| `' @reflexive/-irreflexive: P | 自反/反自反 | 子性质公理组（最小版可挂起标记） |
| `' @rangeUnion: P = C1, C2 | 值域联合 | union range |

规则：
1. **只允许出现词表内注解**——词表外语义需求必须回落到 S2 需求条目（条目粒度不够则提新词表提案）；
2. 注解由 LLM 按需求文本建议、人工在翻译审计中逐条确认——确认后的注解是**已消解的 Z_真 记录**，随图入 Git；
3. 词表版本化：扩词表=改本表+改 puml2owl 对应处理逻辑，同 PR 提交。

## 4. 翻译审计对照表

格式（模板见 templates）：每行一个被形式化的 S2 条目——
`| 条目ID | NL 原文（摘录） | UML 元素（类/属性/关联） | 采用注解 | 审计结论（忠实/弱化/待澄清） |`

- **覆盖率判据**：范围内每个含实体/规则/流程语义的需求条目 ≥1 行对照；
- **弱化的判定**：NL 中可观察行为被译为纯结构元素而无对应注解/条目承接，记"弱化"并回 S2；
- 审计单位是人（领域专家），LLM 可预填对照表但结论列须人工复核。

## 5. BDD 双检衔接（S4 接口）

- 场景二分标注：状态约束类 Then → OWL 蕴含检验（ABox 断言+HermiT）；动作效果类 Then → 流程模型线（SCXML/Petri，另行供给）；
- 双通道独立生成原则：BDD 库与 OWL 必须来自对需求的**独立翻译**（防 tautology）；
- 公理覆盖率反向提示：未触达公理清单自动生成，驱动补场景。

## 6. 转换质量红线

1. 同输入必同输出（字节级回归）；
2. LLM 产物仅允许进 .puml 文件与对照表预填列，禁止直改 .owl/.shacl/.ttl;
3. 注解词表外语义一律不进模型（宁可标待决也不静默丢弃或即兴表达）；
4. 每次 PLANTUML/puml2owl 版本变更重跑回归样例集。
