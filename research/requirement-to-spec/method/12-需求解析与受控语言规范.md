# 12-需求解析与受控语言规范

> 版本 v1（2026-08-27，R0 定稿）。**实练状态声明：S1 解析与 S2 受控语言的严格版未实练**（loan-system 输入为结构化登记）——本规范是设计版，第二案例（开放式 NL 输入）实测后修订；修订点预留见 §6。

## 1. 受控语言选型定案：EARS 子集（否决 SBVR-SE）

| 维度 | EARS（选定） | SBVR-SE（否决，MVP） |
|---|---|---|
| 学习成本 | 五种触发词模板，一页纸 | 词汇+规则双层（概念/命名/事实类型/规则），上手周级 |
| 表达面 | 系统需求单句式（恰好覆盖本项目条目粒度） | 全业务词汇域（合规/法务级场景更强） |
| LLM 翻译友好度 | 模式化强→生成面收窄，译文可机检（触发词即语法） | 结构自由度高→译文一致性难机检 |
| 与 S3 衔接 | 结构（类图）/行为（状态机）/规则（Z3）三线分治直接对位 | 需先做 SBVR→UML 映射层（多一层翻译墙） |
| 工具生态 | 可徒手（正则可检） | 需专门工具链 |

**定案：EARS 子集**。重议条件：第二案例（规则重）中若出现 EARS 表达不了的互斥/数值组合语义（超过 §2 子集），则定向扩子集而非换 SBVR——受控语言的价值在窄而确定，不在全。

## 2. EARS 子集（本项目合法句式）

五种触发词模板（URT = 可选系统名 + 触发条件 + 系统响应）：

| 句式 | 模板 | 典型承载 |
|---|---|---|
| U **When** C, R | 条件触发 | RULE-001（评分≥阈值→通过） |
| U **If** C, then R | 分支 | 分支规则 |
| U **While** S, R | 状态期持续 | 状态内约束 |
| U **Where** F, R | 特征筛选 | 字段级校验（RULE-002） |
| U **After** E, R | 事件后续 | 流转后动作（FLOW-002 意见记录） |

子集约束：
1. 一条目一句式（复合条件用 and/or 连接词显式括号，不嵌套句子）；
2. 触发条件与响应中的领域名词必须来自术语表（封闭引用）；
3. 数值直接量进 Z3 词法（比较符+单位），不在 NL 层解释；
4. 否定只出现在条件位（If not C），响应位禁止否定式（避免"不应失败"类不可判定响应）。

## 3. 术语表约定（统一语言）

模板 T2，字段：`术语 | 定义（一句话，自足） | 同义词/禁用别名 | 首次来源（需求 ID）`。规则：

1. **封闭引用**：S2 之后的全部产出物（受控条目/翻译件/审计表/决策节）中的领域名词只能取自术语表；新名词出现即登记（待定术语标 `?`）；
2. **一义一名**：同义词列入表中但产出物只用主名；禁用别名显式列出（如"单据/订单"统一为 LoanOrder 后中文统一"订单"）；
3. 术语表定稿是 R4 曲线第一个测量边界（S2 后的独立生成以术语表为共享锚——同锚不同文才是可计数的分歧）。

## 4. 歧义与缺口标记法（S1）

1. **Q-x 澄清问题**：登记表澄清节，字段=问题/关联需求 ID/影响/是否阻断 G3/询问方式；已消解的 Q 转为登记结论行（证据留痕）；
2. **阻断分级**：阻断 G3（无法翻译）vs 非阻断（可译但语义自由——这类是 Z_真 候选，升级为 Z-x）；
3. **结构性冲突标记**：两侧语义都合理但相反（如操作员矛盾）→ 不选边，双记录+立 D-x；
4. 视觉证据（图片/截图输入）单独登记表：image_id/区域/观察/提取的条目 ID/置信度/未解决问题。

## 5. 条目分类与 ID 规范（S1 登记表）

八类前缀（BR/FUNC/RULE/FLOW/FIELD/UI/NFR/DEL-三位序号），ID 终身不复用；每条必填：类型/来源位置/原文摘录/结构化表述/优先级/当前状态（仅 已接受/已拒绝/待澄清 三值）。**结构化表述是 S3 翻译的输入**——它本身已是半受控语言，S2 的 EARS 改写在其上进行。

## 6. 预留修订点（第二案例实测项）

- 开放式 NL→条目化的拆分粒度（一句多条/一条多义的处理）；
- EARS 五句式对规则重案例的覆盖是否充分；
- 术语表规模与封闭引用检查的脚本化（R2 候选：术语闭包脚本——与绑定闭包同构）；
- 隐性外部引用（"jpeg 格式"类 Z_伪）在术语表的登记方式（外部标准引用条目）。
