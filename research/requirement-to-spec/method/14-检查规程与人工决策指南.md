# 检查规程与人工决策指南（loan-system）

> 目的：让任何人（包括未来的你自己）脱离本次会话上下文，仍能**重跑全部机器检查、理解每项输出、在正确位置记录人工决策**。
> 检查项总览：

| # | 检查 | 工具 | 判定"通过"标准 | 自动化程度 |
|---|---|---|---|---|
| 1 | 本体一致性 | HermiT（经 owlready2） | 输出 `consistent=True` 且无 unsatisfiable class | 全自动 |
| 2 | 规则一致性+场景触达 | Z3 | 规则集 `sat` 且 core 为空；每个场景"可满足=True"且判定方向符合预期；两次同场景结果一致 | 全自动 |
| 3 | 转换决定性 | check_determinism.py | 输出 `DETERMINISTIC`（sha256 一致） | 全自动 |
| 4 | 实例闭包校验 | pySHACL | `Conforms: True`（或违规被确认为预期） | 半自动（断言样本人工供给） |
| 5 | 翻译审计 | 人 | 对照表结论列无空置；"待澄清"≤1 且有裁决记录 | **纯人工** |
| 6 | 需求↔模型绑定闭包 | check_model_bindings.py + formal/model-bindings.md | 覆盖/解析/反向三闭包零 FINDING；DEFERRED 行必须带 `[暂缓]` 与承接路径 | 全自动 |
| 7 | 流程线结构性质 | fsm_check.py + formal/flow-model.puml | P1–P4 PASS 且 no_escape_from 显式禁回清单逐条 PASS（MVP 为 FSM 性质子集，并行流程出现后升级 WF-net soundness 工具链） | 全自动 |

> **检查项 6/7 的由来（2026-08-27 回填实验结论，勿删）**：结构三件套只能捕"误用"不能捕"缺失"——
> 实验证明枚举静默丢失时 HermiT/pySHACL 双层均判通过（缺省世界=一致）；跨文档语义矛盾若双侧被同时
> 忠实编码则 Z3 unsat core 即时命名来源。因此缺失类缺陷以绑定闭包兜底（第 6 项），流转合法性由状态机
> 性质检查承载（第 7 项），二者均为确定性判定、零 LLM 参与。

### 证据落账规则（每次运行后做什么）

1. 打开 `reports/check-run-log.md`；
2. 复制本节"检查 N"的全部终端输出（含命令行），粘贴为台账新小节：
   ```markdown
   ## Run-N <日期> <检查名>（触发原因：<常规回归|需求变更|注解词表扩展…>）
   ```
3. 若结果与上次不同（无论变好变坏），在新小节末尾加一行 `> Δ 与 Run-M 的差异:` + 一句话归因；
4. 台账只追加不删改——错误结果也是证据（先例：Run-2 v1 的 48 分污染缺陷留痕）。

### 判废规则（何时本轮作废重来）

- 检查 1 出现 unsatisfiable class 或 inconsistent → 最近一次 .puml 修改引入矛盾，回滚或修复后重跑；
- 检查 2 core 非空 → 编码进 Z3 的两条规则真矛盾（这是业务发现而非工具故障，走 D-A 决策流程消解）；
- 检查 3 连续 DRIFT 且内容实质不同 → puml2owl 被改动过——恢复转换器版本或显式重建基准（需在台账记明"基准重定"原因）；
- 机器全绿但你对翻译件不满意 → 正常迭代（改图→全链重跑→重填审计行），机器检查的意义就是把这类迭代的风险压到零。
