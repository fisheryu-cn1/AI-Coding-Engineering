## 1. 系列衔接（收束篇的双重任务）

- EP07 结尾落点原文："这些用血换来的上下文经验，能不能不随会话结束而消失，变成仓库里可维护的资产传下去。"EP08 正面回答：skill 就是这种资产的雏形，而且已经有了注册表市场、复用链和明确的维护模式。
- **回扣第1篇**（本篇的核心结构任务）：第1篇结论=AGENTS.md 全局注入不涨成功率（p=0.87）、成本+20~23%；本篇的 skill 是同一问题的另一端=按需加载（loaded on demand）的结构化上下文包。第1篇问"该不该写"，本篇问"写出来之后它过什么日子"。收束句：上下文从一次性燃料变成有生老病死的资产。注意回扣时用括注重述第1篇方法一句话（跨期引用固定形态），不喊"第1期"——但作为收束篇，"还记得第 1 篇那个可能白写的 AGENTS.md 吗"式的回环是规划定案，允许出现一次期号（第2期 U 形曲线同理），写法上仍以内容描述为主。
- 与 EP02 容量纪律的呼应：skill 的"按需加载"正是容量纪律的产品化形态——不是把知识常驻窗口，要用时再进。
- 与 EP03-07 四条路线的总收拢：运行时管理（预取/门控/压缩/自治）治的是"一次会话内"；资产化治的是"跨会话、跨人"。两层合起来才是完整的上下文纪律。

## 2. 论文→建议映射（advice-first）

**主建议：把 skill 当依赖管理——复制进来那一刻不是终点；项目特定绑定（环境/工具/路径）主动本地化，行为契约（交互/监控/恢复）创建时一次写好；上游更新基本不会跟，别指望。**

- 操作点 1（复制即 fork）：70.3% 复用对相似度≥0.99、53% 复制后再未修改、上游更新 40.2% 从未同步——收下 skill 当天就该做本地化（元数据/环境/路径），别留"以后再说"。
- 操作点 2（行为契约一次写好）：与用户交互、进度监控、失败恢复三件几乎不被下游修改——创建时的质量会一直随 skill 旅行，写糙了没人替你修。
- 操作点 3（维护投项目特定绑定）：修改集中在前两类（重排操作规格/适配知识与资源）——维护精力放绑定层，别反复重写通用知识（那是注册表该收敛的）。
- 操作点 4（失效即执行）：过期 README 人能看出来绕过去，过期 SKILL.md 会被智能体直接执行——维护优先级高于普通文档。

## 5. 去AI味自查（本文高发点）

- 收束篇最容易犯：全系列总结写成排比清单。控制：回扣第1篇用一处具体回环（"白写的AGENTS.md"→"写出来的文件过什么日子"），四条路线各带一个内容描述，不铺陈。
- "生老病死/血换的"类拟人：血换→按检查单换直陈（"花代价换来的"也偏口语，用"积累的"）；生老病死最多出现在草稿区标题一次或不用。
- 数字口径两处高危：①Construction 28.3%/22.1%（库内摘要22.1%/14.5%是错的，勿引用摘要）；②内容六主题与六类修改的频次都是分层/编码样本口径（180/444），不是全集统计，表格与正文注明。
- "一次性复制"是论文直陈（one-time copy），可用；不另造"复制即弃"类新词。
- 固定栏目措辞对齐 EP03-07；破折号每段≤1；无阅读指令语；无"你"称呼（草稿区外）；数字无空格；无 strong；跨期引用括注形态；个人经验段只留位。
- 对话素材：本期对话无新调研素材，不预写候选观点段。但用户有 references/ 多层摘要索引的实践（EP03 对话讨论过种子作用），结尾候选素材可提示用户自己写（不代写）。
