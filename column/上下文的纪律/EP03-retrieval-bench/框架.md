## 2. 论文→建议映射（advice-first）

文章落点（延续 EP02 的"实用建议为落点"）——**一条主建议 + 三个操作点**：

- **主建议：把检索层当被测组件，别当默认管道。**"找上下文"是未解决的能力，不是已解决只差拼装（规划备忘原话）。
- 操作点 1（多路互补）：语义嵌入与结构信号互不替代，工程上多路融合是零训练的便宜做法（RRF：MRR 0.2296→0.2713，trace2code R@20 升到 0.8795）。
- 操作点 2（按任务选通道）：报错找根因（trace 类）结构信号强于语义（RepoMap R@20 0.8366 vs Qwen3-4B 0.5050）；语义嵌入在"实现找测试"类占优。
- 操作点 3（初始上下文值得投入）：种子实验显示 oracle 初始上下文 +0.31 File F1，random 也有 +0.02（提示扰动效应，控制后检索种子仍有效且更省 token）——为 EP04 预取埋线。

## 5. 去AI味自查（本文高发点）

- "不是语义相似，而是下一步需要"——概念本身是对比，**用具体例子呈现**（review comment 指A缺B / 报错栈指测试根因在实现），不落"不是X而是Y"口号句式。
- 比喻额度已用于系列比喻（结尾一句"缺页测量"），正文零比喻。
- 标题候选不用"体检/透视/照妖镜"类花哨词——"体检"一词在正文小节可用一次吗？不，规划里的"诊断学"概念改为直陈："把找文件单独拿出来测"。
- 四个表格信息密度高，每个表前后用一句话点出"读什么"，不逐格复述。
- 数字排版无空格；无 strong；副题本篇新写。
