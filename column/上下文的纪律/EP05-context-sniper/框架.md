## 2. 论文→建议映射（advice-first）

**主建议：token 成本大头不在补丁生成而在翻找过程；对"读文件/跑命令"的输出在进窗口前做保守过滤（保留路径行号、原件可恢复），比事后压缩整个 prompt 更治本。**

- 操作点 1（门控位置前移）：现有做法多在"prompt 已经很长"之后压缩；ContextSniper 在 read/bash 输出产生的时刻过滤，不让噪声进窗口。三层相关工作（压缩/输出过滤/仓库记忆）各改一环，本文合成一个上下文访问层。
- 操作点 2（保守原则）：宁可少删不多删——删掉有用证据的代价大于多花 token；被截断的输出打 sniped 标记+附恢复提示，原件存记忆层，agent 可要求展开。
- 操作点 3（可追溯性）：保留证据必须带源（路径+行区域+产生它的命令），与均匀摘要压缩的本质区别——摘要会弄糊出处和行号。
- 操作点 4（诚实边界）：门控有适用条件——任务太短摊不开检索开销（+9.6%~+17.3%）、首轮检索没命中关键文件时会引发更多搜索（seaborn +152.3%）；45/50 省是分布不是保证。

- 同步两阶段：hook 即时（搜索/读/编辑/命令时记录，编辑走门控工具面时校验路径+应用替换+派发该文件记忆刷新）+任务边界（新用户提示到达时对账工作树diff，防止stale memory）

- 门控三类：FileRead→请求区域+本地定义+邻居；CommandOutput→命令+退出状态+断言消息+栈轨迹+失败路径+简洁成功信号；其他→状态信号（变更文件/触碰符号/仓库状态）；保守原则："removing evidence can be worse than spending extra tokens"
- 三条相关工作线：prompt压缩（LLMLingua/LongLLMLingua/RECOMP/COMPACT/SelectiveContext/AutoCompressor——作用于已选进prompt的文本）；agent工具输出过滤（RTK 60-90%/Headroom 60-95%/Bearing——最接近但无同步代码记忆）；仓库记忆/定位（RepoGraph/KGCompass/Codebase-Memory——不控进窗）
- 部署：Claude Code 走 MCP（search_code 为首选替代 grep+探索性读取，配对 edit_file 校验路径+应用替换+刷新记忆）；OpenClaw 走 plugin+runtime hooks；代码 gitcode.com/lukchiwang/ContextSniper（评估harness）+AntTrail引擎 gitcode.com/datagallery/AntTrail

## 5. 去AI味自查（本文高发点）

- "狙击"是论文自用隐喻（ContextSniper），介绍名字由来可以，正文行文不扩散使用"狙击手/瞄准"类动词；sniping 首现拆解：机制（保留任务相关、删低价值区段、组装成紧凑证据包）先行，名字后给。
- "门控"首现拆解：在输出进入上下文窗口之前决定放行什么的检查位（gate=闸门/关卡，通行说法，不算自创译名）。
- 核心对比句"不是均匀压缩，而是可追溯的保留"——按检查单⑤⑤避免"不是X而是Y"口号化：用具体机制差异写（压缩对整段文本均匀下手；门控按输出类型选择性放行，保留路径行号，原件入记忆层可恢复）。
- 副题数字口径：−51.5%/−38.9% 是实测主结果可用；修复率必须写"基本不变/−2pp"不可写"不掉"（检查单15：上限/效果口径）。副题候选："token省四成，修复率基本不变"。
- 固定栏目措辞对齐 EP03/04 定稿：简要结论、名词速查、本期论文、蓝灰虚线框、图注"图 N｜…（原论文Figure X）"。
- 开场陈述现象作事实（"读-试-错-再读"循环），无"读者/你"称呼、无泛化场景；小标题长而明确。
- 破折号每段≤1；无阅读指令语；无自创译名；拟人动词不用（省token不写"喂"）；格言短句展开。
- 跨期引用固定形态："（参考本系列第二篇荐读论文，关于……的讨论）"。
- 个人经验段只留位；对话素材：本期对话无新调研素材，不预写候选观点段。
