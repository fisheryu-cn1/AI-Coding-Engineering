# column — 公众号专栏工作区

公众号专栏写作的统一工作区：**计划、草稿、成果物**三类内容集中在此，与 `research/`（研究过程）分离。引用的论文原文与精读摘要在 [`../references/`](../references/)，写作时从那里取材，不在本目录重复存放。

## 目录结构

```
column/
├── README.md            # 本文件：约定与索引
├── 发布台账.md           # 每篇文章的状态与发布记录
├── plans/               # 计划层：跨系列的选题规划、编排策略
│   └── 专栏系列规划备忘_2026-08-31.md   # 三系列选篇/顺序/主线/节奏（当前总纲）
└── 上下文的纪律/          # 系列层：一个系列一个目录（目录名=系列名）
    └── EP01-AGENTS-md/  # 篇层：一篇一个目录，EP{两位编号}-{短名}
        ├── article.html      # 成果物：公众号 HTML（内联样式，可直接粘贴）
        ├── 草稿-人工补充.md   # 草稿层：人工补写内容的收集处
        └── images/           # 正文图片（发布时上传公众号素材库）
```

## 约定

- **篇目录命名**：`EP{NN}-{英文短名}`，与 `plans/` 规划备忘中的期号一一对应；系列内按写作顺序编号，发布顺序=编号顺序。
- **成果物**：固定为 `article.html`；修订不另建文件（历史由 git 承担），发布后如有内容勘误直接改 HTML 并在发布台账记一行。
- **草稿**：凡尚未合入 HTML 的素材（人工补充段落、待选标题、配图替换方案）记为 `草稿-*.md` 放在同篇目录；合入后删除或清空对应小节。
- **图片**：一律放篇目录 `images/`，HTML 内用相对路径引用；发布时上传素材库并替换 `src`（步骤见 article.html 顶部注释块）。
- **状态流**：`草稿 → 待人工补充 → 成品 → 已发布`，状态记入发布台账，不写在文件名里。
