## 1. 编排策略类型学（专栏顺序为什么不必按时间）

| 策略 | 做法 | 适用条件 | 本备忘采用者 |
|---|---|---|---|
| A. 时间正叙（编年） | 从源头经典讲到近期前沿 | 读者偏研究向、需要领域演化史框架 | （本备忘均不采用，理由：第 1 期往往是最老、最熟、传播力最弱的论文，专栏首期立不住） |
| B. 钩子回溯 | 近期反直觉论文开场抛出问题 → 回溯经典解释根因 → 推进前沿 | 存在一篇"与读者日常相关 + 结论反直觉"的近期论文 | 系列一 |
| C. 观点对立（辩论式） | 两篇结论相反的论文对撞开场，全系列任务是解释矛盾，各篇是矛盾的一个侧面 | 领域存在真实、可核实的分歧（非 strawman） | 系列二 |
| D. 谱系/生命周期（生态位） | 按概念谱系（轻/重/桥接学派）或软件生命周期（需求→设计→实现→演化）组织生态位，每篇占一位；时间可以 zig-zag | 论文分散在不同阶段/立场，单线叙事串不起来 | 系列三 |

选择依据三条：①读者画像（实践者→B/C，研究者→A/D）；②系列是否存在真实对立（有→C 最强）；③是否有可贯穿的"记忆装置"（比喻、谱系、公式），连载需要记忆点。

### 2.2 排序理由（为什么不按时间正叙）

- 时间正叙会把 Lost in the Middle（2023）放第 1 期：人人可入但无新闻性，专栏冷启动风险高。
- 钩子回溯让第 1 期直接命中读者日常（AGENTS.md/CLAUDE.md/SKILL.md 都是当下实践），第 2 期再回 2023 年讲"这个结果早有物理预兆"，反而把老论文讲出新闻感。
- 第 4–7 期不是按发表时间（ACQUIRE 07-13、ContextSniper 07-02、ARC 07-27、ACM 07-26 交错），而是按**资源管理的时序逻辑**排：事前预取 → 事中门控 → 事后压缩找回 → 自治管理。这一顺序本身就是论述内容（见 2.3）。
- 若专栏受众偏研究向，期 1/期 2 可互换回正叙，其余不动。

### 2.3 论述主线（三幕 + 一个贯穿比喻）

- **第一幕（期 1-2）破除两个迷信**：①窗口迷信——"窗口越大越好"被 U 形曲线证伪；②上下文迷信——"多给上下文总是好"被 AGENTS.md 临床试验证伪（且机制查清：指令确实被遵循——uv 工具 1.6 vs 0.01 次/实例，无效的是内容本身：overview 无用、与既有文档冗余；删光仓库文档后 LLM 生成文件才 +2.7%，说明它生成的是冗余）。
- **第二幕（期 3）建立诊断学**：把"找上下文"从端到端分数里拆出来单测（四种工作流任务 + 弃权任务 + token 预算指标 BCY），结论：检索是未解决的能力，不是已解决只差拼装。
- **第三幕（期 4-7）四条工程路线**：预取（ACQUIRE）→ 门控（ContextSniper）→ 可寻址压缩（ARC）→ 自治（ACM）。
- **收束（期 8）**：上下文从运行时资源变成仓库里的可维护资产，回扣期 1 的"什么值得写"。

**贯穿比喻（系列记忆装置）**：四条路线恰好重演操作系统内存管理演化史——手工分配（AGENTS.md）→ 缺页测量（Retrieval Bench）→ 预取（ACQUIRE）→ 按需调页（ContextSniper）→ 虚拟内存换页（ARC）→ 进程自治管理（ACM）。**上下文就是编码智能体的内存。** 每期结尾用这个比喻串一句。

### 2.4 系列主要观点

1. **上下文是稀缺资源，不是免费容器**。成本三重：token 费用、延迟、注意力稀释（位置偏差/干扰）。"给"≠"有用"。
2. **"找上下文"本身是未解决的能力**——闭源 agent 三成轨迹碰不到关键文件；语义检索与结构检索互不替代。
3. **演化方向确定**：从 prompt 手工管理 → harness 外部监控 → 模型内化的自治能力。出路不是更大的窗口，而是会管窗口的模型。
4. **方法论主张**：上下文策略必须做临床试验级评测（对照、消融、成本会计、泄漏控制）——期 1、期 3 两篇是范式样板，这让系列区别于纯技术推介。

### 2.5 写作节奏

- 期 1、期 2 是"问题对"（现象 + 根因），建议同周双发或间隔 ≤4 天，先把矛盾立住。
- 期 3 承上启下（从"破"转"立"），不可断更。
- 期 4–7 每周一期，四条路线结构对称，可预告"路线连载"。
- 期 8 收尾拔高 + 回环（"还记得第 1 期那个白写的 AGENTS.md 吗"）。
- 每期固定栏目：一句话 TL;DR → 为什么此刻值得读 → 论文怎么做 → 关键数字（注明出处表）→ 局限与适用边界 → 下期钩子。

## 3. 系列二《分数之外：编码智能体评测的危机与重构》（7 篇，戏剧性最强）

### 3.1 论文清单与推荐顺序

**编排策略：C 观点对立。** 核心 exploiting 事实：**METR 同一家机构在 2025 年发表了两篇方向相反的论文**（一篇说能力每 7 个月翻倍，一篇说真实开发者用 AI 反而慢 19%）。用这对自对撞开场，全系列解释矛盾。

### 3.2 排序理由

- 时间正叙（SWE-bench 2023 → …）会把最出名的论文放第 1 期，但"介绍 SWE-bench"没有悬念；把它放第 3 期，它就成了"被审问的证人"——前两期立完矛盾，第 3 期开始追问"实验室端的强是怎么测出来的"。
- 期 1/期 2 必须紧邻：对撞是整个系列的引擎，拆开就泄压。
- 期 4→5 是"拆基准→换标尺"的连续动作；期 6→7 是"换方差来源→换任务形态"，两组各成小单元。
- 若想再强化对立，可把期 5 提到期 2 之后（"正方内部也有口径之争"），但会牺牲 4/5 的连续性，不推荐。

### 3.3 论述主线（对撞式三幕）

- **第一幕（期 1-2）矛盾成立**：同机构、同年度、方向相反。都是严肃实证，都不是 strawman——矛盾只能出在"测的东西不同"。
- **第二幕（期 3-5）拆解实验室端**：定义赛道的基准是什么（SWE-bench）→ 它被污染（Illusion）→ 换标尺重测（单步 vs 任务级，Diminishing Returns）。
- **第三幕（期 6-7）拆解方差与形态**：分数差异多少来自 harness（Ben Sghaier）→ 任务形态离真实工作还有多远（ICAE-Bench，边问边建只拿 38.2%）。
- **收束**：把所有评测排在一条"理想化 ↔ 真实"光谱上（RCT 在真实端，SWE-bench 在理想端），分数随理想化程度单调上涨——期 1 与期 2 的矛盾被光谱解释，不是谁错了。

### 3.4 系列主要观点

1. **能力不是标量，是函数**：能力 = 模型 × harness × 任务分布 × 时间地平线 ×（使用它的人）。单一榜单数字时代结束。
2. **榜单分数与真实生产力的落差是测量问题，可解释、可定位**（光谱框架），不是玄学也不是立场之争。
3. **污染是标杆式基准的固有风险**，Illusion 的三个探测模板（文件路径识别/函数复现/前缀补全）可被读者直接复用。
4. **"收益递减"之争是口径之争**：单步准确率双曲增长（80% 后急剧拉升）、任务成功率是其复合函数；scaling 是否值得，取决于经济价值挂靠在哪个口径上。
5. **harness 应成为评测的报告单位**：报告 agent 分数必须同时报告 harness 版本与配置（呼应期 6）。

### 3.5 写作节奏

- 期 1+2 同周双发（对撞必须一次立住），期 3 紧随（趁热追问）。
- 期 4、5 连读单元；期 6、7 连读单元；两单元之间可空一周。
- 末期配一张"理想化↔真实光谱"收束图（全系列唯一信息图，成本可控、传播性强）。
- 本系 3 篇超一年（SWE-bench 2023-10、Illusion 2025-06、RCT 2025-07），但按现版口径最后三期（2026-03/07/07）满足"近 6 个月"底线；写第 1、2 期时要主动交代论文时间，把"旧文新读"讲成刻意的回溯结构。

### 3.6 可替换论文

- Agent Frameworks 代码任务实证（AgentParadigms/18，2511.00872，2025-11）：可插在期 5-6 之间作"框架层方差"补充期。
- TAU-bench / TAU²-bench（AgentParadigms/23、24）：若想扩到工具型/双控任务可加，但会稀释"编码"焦点，不推荐。

- 纯时间正叙（Clover→Chen→SDD→Faria→Intent→PICKLES→Event-B→Oliveira）会把最强钩子（SDD 愿景）埋在第 3 位，且丢失生命周期这条脊梁。
- 生命周期顺序给专业读者一个天然记忆装置（每期可加"阶段徽章"：需求/设计/实现/演化），并让全系列收在库内最新论文（2026-08）上——首尾都是"现在"。
- Clover 放期 2 而非实现期位（与期 7 并列），是为了制造"愿景-先声"的对仗：工业界讲成新故事的东西，学术 2023 年就有蓝图。若嫌 2023 太老，可删 Clover 把系列收到 7 篇，期 7 独占实现期。

### 4.3 论述主线（三幕）

- **第一幕（期 1-2）愿景与先声**：SDD 把"代码成为派生工件"讲成 AI 时代的新命题（三级严格度 + 失败模式命名：过度规格化/规格腐烂/虚假信心）；Clover 证明闭环可验证生成 2023 年已有完整蓝图。张力：**愿景不新，新的是 LLM 让人力成本结构变了**。
- **第二幕（期 3-6）需求期与设计期的四个生态位**：矛盾检查（SAT）与意图对齐（可追溯）在需求侧；BDD/形式模型生成（PICKLES）与精化策略自动化（Event-B Agent）在设计侧。暗线是"规格语言之争"：NL 轻学派 vs 形式重学派，在桥接派（意图对齐/PICKLES）中被消解——**从 NL 侧自动生成形式侧，而不是逼人选边**。
- **第三幕（期 7-8）实现期与演化期**：注解自动生成（Faria）让"验证写法"不再全靠专家；行为等价检测（Oliveira）把规格用作重构护栏。收束：**形式规格的新角色——不是文档，是 agent 的 oracle：让 AI 写下承诺，再让机器检查承诺**。

### 4.4 系列主要观点

1. 形式方法几十年不普及的主因是人力成本，而 LLM 补的恰好是这一环——每个生命周期锚点都有 2026 年论文占位，这不是巧合是拐点。
2. 规格语言之争正被"可追溯桥接"路线消解（NL 侧生成形式侧），选边站的时代过去了。
3. 规格的角色从"人读的文档"变为"机器检查的 oracle"，这是 agent 时代软件工程最实质的变化之一。
4. 诚实边界：SDD 论文自己命名了失败模式（过度规格化/规格腐烂/虚假信心），专栏应如实呈现，避免写成愿景通稿。
