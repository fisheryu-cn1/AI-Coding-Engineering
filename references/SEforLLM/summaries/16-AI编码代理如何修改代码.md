# 论文摘要：AI编码代理如何修改代码（UNLV）

## 1. 适用场景

- 当你要为 AI 编码代理提交的 PR 设计**评审/triage 启发式**（如用 commit 数与 files touched 而非 LOC 作 Agentic PR 范围的早期指标、对 deletion-heavy 或宽范围 Agentic PR 加强审查）时，读这篇——它给出各结构度量的效应量排序。
- 当你需要 **Agentic vs Human PR 的大规模实证基线数字**（Cliff's δ 效应量、四路 description–diff 相似度描述统计）用于自己的 mining 研究对照或引用时，读 §3 与 Table 1/2。
- 当你要论证"agent 生成的 PR 描述与代码编辑一致，可支撑 release note 生成 / changelog 构造 / reviewer 路由等下游任务"，或想构建**描述–diff 对齐异常低的自动预警**时，读 §3 RQ2 与 §4。
- 当你关心**不同 agent（Copilot / OpenAI Codex / Claude Code / Cursor / Devin）产出的异质性**（紧凑单焦点 vs 宽范围编辑）时，读 §3 RQ1 的按 agent 分层观察。

> 锚点：Abstract; §1 Introduction; §2 Method; §3 RQ1; §3 RQ2; §4 Implications

## 2. 主要观点与方案

- **研究问题与数据**：首个 PR 级大规模实证，回答 RQ1（Agentic PR 的 additions/deletions/files touched/commit 数与 Human PR 相比如何）与 RQ2（PR 描述与代码编辑的对齐在两组间有何差异）。基于 MSR 2026 Mining Challenge 版 AIDev 数据集（2025-11-01 检索：932,791 个 Agentic PR + 6,618 个 Human PR，跨 116,211 仓库）；因 Human PR 缺 commit 级信息，用 GitHub REST API 重建其 commit 与 patch；过滤只留 merged 且全部 commit 有非空 unified diff 的 PR，得分析集 **24,014 个 Agentic PR（440,295 commits）vs 5,081 个 Human PR（23,242 commits）**。files touched 按跨 commit 去重的唯一文件路径计，重命名算单文件修改（§1; §2 Step 1–3）。
- **方法**：结构度量不满足正态性 → Mann–Whitney U 检验 + Cliff's δ（标准阈值解释效应大小）。RQ2 从两个维度测描述–diff 对齐：lexical（TF–IDF cosine、Okapi BM25）与 semantic（CodeBERT、GraphCodeBERT embedding cosine）；diff 预先剥离文件头/hunk 头/行前缀只留增删行；BM25 无界、对 tokenization 敏感，仅作相对 lexical 信号而非校准的相似度（§2 Step 4）。
- **RQ1 结论——差异在"结构"而非"规模"**：最大实际差异是 commit 数（δ=0.5429，Large）；files touched（δ=0.4487）与 deletions（δ=0.4462）为 Medium；additions（δ=0.2836）与总行变更（δ=0.3158）仅 Small——即新增代码总量两组接近，真正区分二者的是变更如何跨 commit 与文件组织分布。Human PR 中位数更高、上尾更长（更宽、更分散的修改），Agentic PR 更小更局部；Agentic 内部不均匀：Claude Code 与 OpenAI Codex 变异性较大，Devin、Cursor、Copilot 高度紧凑局部（§3 RQ1; Table 1; Figure 2–3）。
- **RQ2 结论——Agentic 描述一致性略优**：lexical 分数两组都聚在近零（表面词汇重叠很小），semantic 分数紧峰于 0.9–1.0（措辞虽异、语义均捕获 patch 含义）；Agentic PR 在全部四个指标上中心趋势略高于 Human PR——agent 生成的描述与其编辑内容的对齐至少与人相当、部分指标略好（§3 RQ2; Table 2; Figure 4–5）。
- **启示**：评审流程与 triage 可用 commit 数、files touched 作 Agentic PR 范围的早期指标而非仅看 LOC；deletion-heavy 或宽范围 Agentic PR 值得更严审查；agent 行为不均匀，研究下游结果（评审负担、延迟、缺陷率）时应建模 agent 身份与任务上下文；高语义对齐支撑依赖准确摘要的下游任务，可对对齐异常低的 PR 自动提示人工介入（§4）。
- **效度威胁**：结果依赖 AIDev 完整性与 Human PR commit 重建（GitHub rate limit、删库、历史重写、超大 diff 截断）；结构度量不捕获意图/正确性；结论外推限于数据集覆盖的开源 GitHub 项目与其中的 agent 版本（§6）。
