# 论文摘要：CodeGraph 教材（代码图谱基础概念与系统综述）

> **原论文标题**：CodeGraph: A Foundational Textbook / Survey on Code Graphs（教材/讲义）

> 作者 / 年份 / 出版：综合编著（含 CodeGraph 团队及关联工作），2024–2025 期间版本，教材/讲义

> 生成日期：2026-08-12

## 1. 适用场景

- 在 Agent / RAG / 代码理解系统设计前，需要**建立"代码图谱"的概念基线**时（什么是 AST / CFG / PDG / CPG / 调用图 / 仓库图、它们各自能回答什么问题、不能回答什么问题）。
- 给非程序分析背景的工程师讲解"为什么 LLM 应当消费结构化代码表示而不是纯文本"时的**配套阅读材料**。
- 作为 API 文档知识图谱、详细设计图谱、Wiki/图数据库混合架构的**概念对照表**——明确每种图谱适合承载哪类语义。
- 设计或评审"代码 → 图 → LLM"中间层时的**术语与边界参考**。
- Agent 安全/审计领域（CPG、Agent-BOM、Code-T-Text-Code）入门时所需的**背景章节**。

> 锚点：教材各章（典型结构：Ch.1 引言 / Ch.2 程序表示 / Ch.3 静态分析 / Ch.4 图数据库 / Ch.5 代码图谱应用 / Ch.6 与 LLM 的结合）。

## 2. 主要观点与方案

### 2.1 核心命题

- **代码是一等公民的结构化数据**：源代码天然可用图（节点 = 语法元素/语句/函数/类，边 = 语法/控制/数据依赖/调用/继承）建模；任何对代码的"理解"都建立在某种图之上。
- **不同图承载不同问题**：AST 承载语法、CFG 承载控制、PDG 承载依赖、调用图承载跨函数、CPG 融合多类关系、仓库图承载跨文件。每种图都有"擅长的查询"和"代价"。
- **图查询是程序分析的执行模型**：漏洞、依赖、影响分析都可统一表达为图遍历，这与"代码即图"是同构的。
- **LLM 不应直接消费整张图**：图需要切片、投影、编码后才能进入上下文；并要权衡 token、精度、可解释性。

### 2.2 主要内容骨架（教材式组织）

- **基础表示**：AST、CFG、PDG 的定义、构造、典型用途。
- **图数据库实现**：属性图、Neo4j/Gremlin 风格遍历、批量导入、索引、缓存策略。
- **代码属性图（CPG）**：AST+CFG+PDG 融合，是"代码-漏洞"分析的代表性综合图。
- **仓库级图谱**：跨文件的调用、import、继承、类成员关系，与 SWE-bench 任务对接。
- **图与 LLM 的结合**：图编码、GraphQA、CodeGraph、RepoGraph 等的范式。
- **审计与安全**：CPG 漏洞遍历、Agent-BOM 风格的属性图审计。
- **演化与重工程**：Code–Text–Code 风格的"代码-文本-代码"中间层。
- **可视化与多模态**：仓库图作为图像供 MLLM 消费的可行性边界。

> 锚点：教材各章节；本仓 `references/CodeGraph/论文解读摘要.md` 对四种表示的相互关系梳理。
