# 论文摘要：Code Property Graph（用代码属性图建模与发现漏洞）

> **原论文标题**：Modeling and Discovering Vulnerabilities with Code Property Graphs
> **完整 PDF 文件名**：`Modeling and Discovering Vulnerabilities with Code Property Graphs.pdf`
> 作者 / 年份 / 出版：Fabian Yamaguchi, Nico Golde, Daniel Arp, Konrad Rieck；University of Göttingen / Qualcomm Research Germany；2014；IEEE S&P（Oakland）
> 摘要类型：Agent 设计参考 + 内容索引
> 生成日期：2026-08-12

## 1. 适用场景

- 设计或评审 **LLM 代码审计 / 安全扫描 Agent** 时：决定要喂给 LLM 哪些结构化程序分析事实（AST、CFG、PDG 切片、CPG 子图）。
- 构建 **代码知识图谱 / API 文档图谱** 时：参考 CPG 把"语法-控制-数据"三轴融合到一个属性图的设计。
- 在 **千万行级代码库** 上做静态漏洞扫描：参考 Neo4j + Gremlin 的导入与查询开销数据。
- 把"漏洞模式"作为模板沉淀为可复用的图查询；为 LLM 自动生成审计规则提供基础。
- **AI 生成代码** 的事后审计：先用 CPG 提取候选可疑点，再交给 LLM 解释。

> 锚点：摘要；§1 Introduction；§VI Evaluation。

## 2. 主要观点与方案

### 2.1 核心论点

- **单一表示都不够**：AST 没有控制流/数据流，CFG 没有数据依赖，PDG 难做语法模式匹配；常见漏洞需要同时利用三者。
- **Code Property Graph（CPG）**：在"语句/谓词"节点上对齐 AST、CFG、PDG，融合为单一属性图。
- **漏洞即图遍历**：常见漏洞可被表达为 Neo4j / Gremlin 图查询，效率上可与数据库查询相提并论。
- **图查询的"高召回 → 精化"模式**：先以宽松遍历召回候选，再引入控制/数据约束降误报。

### 2.2 方法

- **图模型**：属性图（key-value 属性 / 多边 / 有向），节点类型涵盖 ENTRY/EXIT/FUNC/DECL/CALL/PRED/ARG/STMT 等。
- **遍历模板**：作者为 4 类漏洞设计具体遍历——缓冲区溢出、内存泄漏、内存映射、零字节分配。
- **评估对象**：Linux kernel 3.10-rc1（约 130 万行 C 代码）。
- **回顾性验证**：对 2012 年 Linux 内核的 88 个 CVE 分类后，10 类可由 CPG 遍历建模，且都需 AST+CFG+PDG 联合使用。
- **发现性验证**：4 条遍历在 Linux kernel 中发现 **18 个此前未知的漏洞**，获分配 CVE-2013-4511/4512/4513/4514/4515/4516/6378/6380/6381/6382 等并修复。

## 5. 一句话索引（给 Agent 用）

> 想做代码级 LLM 审计/扫描时，**别只用 AST 或只让 LLM 读代码**：CPG 已经证明把语法、控制、数据依赖三轴融合成属性图后，**简单 Gremlin 遍历就足以在 Linux kernel 上挖出 18 个新 CVE**——这是"图查询比 LLM 更适合结构化审计"的最强经验证据。
