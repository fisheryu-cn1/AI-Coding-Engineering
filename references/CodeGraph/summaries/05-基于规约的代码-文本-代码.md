# 论文摘要：Code–Text–Code（用规约驱动的 LLM 软件演化）

> **原论文标题**：Specification-Based Code–Text–Code Reengineering for LLM-Mediated Software Evolution
> **完整 PDF 文件名**：`Specification-Based Code–Text–Code.pdf`
> 作者 / 年份 / 出版：Oleg Grynets, Vasyl Lyashkevych, Arsen Dolichnyi, Roman Piznak, Taras Zelenyy, Volodymyr Morozov；EPAM Systems；约 2025–2026；IEEE 会议论文
> 摘要类型：Agent 设计参考 + 内容索引
> 生成日期：2026-08-12

## 1. 适用场景

- 用 LLM 做**跨语言代码迁移**（Java ↔ C# ↔ Python ↔ C++ ↔ …）或 **SQL 方言迁移**（BigQuery、PL/SQL、PL/pgSQL、Snowflake、T-SQL 等）时，需要控制语义漂移、提升可追溯性。
- 设计 **LLM 软件演化流水线**：把"Code → Text → Code"作为可验证中间层，配合 AST、图、本体、文档、RAG 形成证据环。
- 需要**多源证据融合**（AST 元数据、依赖图、向量检索、图检索、文档重排）来支持语义保持时。
- 在数据库驱动的应用上做端到端迁移，配合 DBMS 反馈做执行级校验。
- 当直接 prompt 改写失败率高、且需要 loss estimation 评估迁移质量时。

> 锚点：摘要；§I Introduction；§III Reengineering Model；§V Pipeline Architecture。

## 2. 主要观点与方案

### 2.1 核心论点

- **直接 code-to-code 易产生语义漂移**：保留源语言习惯用法、引入未声明行为、丢失业务语义、破坏异常处理、缺乏可追溯。
- **应把 LLM 辅助演化视为"跨多表示层的再工程"**，而不是翻译。
- **核心是 Code → Text → Code**：先把源代码转成不依赖具体语法的中性文本规约（Sn），再据此生成目标代码。
- **中性规约 ≠ 注释 / 摘要**：必须显式捕获目的、输入输出、步骤、条件、数据访问、副作用、错误处理、依赖、假设。
- **知识表示层** 整合 AST 元数据、图依赖结构、OWL/RDF 本体、技术/业务文档、架构视图。
- **流水线**：事实上下文提取 → Code2Text → 源-规约校验 → Text2Code → 目标代码校验；对 SQL 加入方言感知解析和 DBMS 执行反馈。

### 2.2 方法

- **基本变换式**：`C0 → IC → Sn → C1`（源代码 → 事实上下文 → 中性规约 → 目标代码）。
- **扩展式（业务驱动演化）**：`C0 → TD0 → BD0 → BD1 → TD1 → C1`，让业务用户只改业务文档，倒推回代码。
- **知识表示层**：AST→JSON 元数据；图（节点=文件/模块/函数/表/视图/服务，边=read/write/call/import/depend/invoke）；OWL 类与 SKOS 概念；向量库；图库；架构视图。
- **混合检索**：向量检索（语义）+ 图检索（结构）+ 元数据过滤 + 重排序 + 校验。
- **损失估计**：用结构保持、反向兼容性、接口稳定性、图相似度 4 个维度估计变换损失。
- **SQL 迁移扩展**：方言感知 AST/CST 解析（SQLGlot / TreeSitter / ANTLR）、LLM 解析反馈、DBMS 反馈执行、chunks 组装、目标方言校验。

## 3. 达到的效果

| 度量 | 结果 | 锚点 |
|---|---|---|
| 数据集 | 9 种语言各 1,000 脚本 + 多种 SQL 方言实例 | §VII.A |
| 中间表示对比 | 自然语言 IR（中性文本）效果最好；伪代码 / 图 IR / 编译器 IR 表现次之 | §VII.B |
| 检索 | 向量检索准确率更高、图检索速度更快；最佳嵌入模型 `nomic-ai/CodeRankEmbed` | §VII.C |

| SQL 迁移 | BigQuery/PL-SQL/PL-pgSQL/Snowflake/T-SQL 等均有反馈回路 | §V.F，图 5 |

## 5. 一句话索引（给 Agent 用）

> LLM 软件演化若要可控、可追溯、损失可量化，就**别直接 code-to-code**：在源代码与目标代码之间插入**中性文本规约（Sn）作为受控中间层**，并以 AST 元数据 / 依赖图 / 文档 / RAG 作为证据环，再用结构保持 + 接口稳定性 + 图相似度 4 个指标估损失——这是"用规约代替黑箱生成"的最完整框架。
