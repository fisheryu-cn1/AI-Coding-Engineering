# 论文摘要：从注册表到仓库——AI Agent Skills 的写、改、维

> **原论文标题**：From Registry to Repository: How AI Agent Skills Are Written, Adapted, and Maintained

## 1. 适用场景

- 设计**coding agent 的 skills / context bundles**（SKILL.md + 可选资产）时，需要有"内容结构、覆盖范围、维护模式"的实证基线。
- 想给 centralized skill registry（如 skills.sh）与 personal-use skill（仓库本地维护的 SKILL.md）建 SWEBOK-based 知识图谱时——本文提供对照数据。
- 评估 AI 供应链安全 / 演化风险时——skills 与传统 npm 包一样是依赖，但又可编辑、可现场复制、含可执行脚本。
- 制定 skill 标准化（Anthropic skill 规范 17 项 provisions）的合规性评估 / tooling 时。
- 当你想研究"领域内代码 + 自然语言可执行 spec"这一新 artifact 类别的 conservative 适应 / 演化模式时。

> 锚点：Abstract；§I Introduction；§II Related Work。

## 2. 主要观点与方案

### 2.1 核心主张（"skill 是软件工程 artifact，要工程化地看"）

- 现有 skill 研究多把它当成"agent capability layer"看功能 / 安全 / 性能；本文把它当作 "engineered artefact"——作者 / 复用 / 定制 / 维护 各环节系统研究。
- 数据规模：skills.sh 中央仓 18,463 个 skill；个人使用仓 5,876 个 GitHub 仓库出 23,199 个 skill；恢复 3,709 个 reuse link。
- SWEBOK v4（18 知识域 + Non-SE）作为知识图谱，得到 29,450 个 SE skill 的分类。
- 三 RQ：
  - RQ1 skills 覆盖哪些 SE 知识域；
  - RQ2 怎么写、内容结构如何；
  - RQ3 如何被定制 / 演化维护。

### 2.2 方法学（§III Methodology）

- **数据收集**（§III-A）：query skills.sh（截止 2026-03-04，安装数 ≥ 20）共 19,830 个 indexed，retrieve 到 18,463；GitHub API 按 `filename:SKILL.md` + 排重 forks/archives/低 star，得 110,090 → 去 aggregator（关键词过滤）→ Tukey fence（> 18）→ 5,876 repos / 23,199 skills。
- **Reuse-linkage 构造**：YAML `name:` 字段匹配候选 + 内容最长公共子串比 sim(A,B) = 2·LCS(A,B)/(|A|+|B|)；阈值 ≥0.1；边界桶 [0.1, 0.3) 由两名作者人工 audit，得到 90% 一致、93% 真人 reuse 真实；阈值 0.1 以下 30 条全部独立手工核验。
- **SWEBOK KA 分类**：Qwen3.6-27b + Gemma-4-31b-it（k = 0.61 → 升级 → 0.79），再加 285 条 gold，Qwen κ = 0.82；用其跑全集，得到最终分类。
- **RQ2 内容主题分析**（§III-C）：分层抽样 180 个 SKILL.md（每 KA 10 个），段落为分析单位，open coding → axial coding → 6 大 themes。
- **RQ3 修改主题分析**（§III-D）：把定制（linked pairs 中 621 对非 verbatim）与演化（5,978 个 unlinked skill 的 SKILL.md commit history，按 churn 分 4 quartile）分别抽样共 444 条作为 coding corpus。

### 2.3 主要结果速读

- **RQ1 SWEBOK 分布**：Software Construction 主导（centralized 22.1%、personal 14.5%），之后为 SE Operations / Testing / Config Management（差异化），其余 14 KA 是 long tail；约 28.5% / 29.8% 是 Non-SE（speech synthesis 等）。centralized 偏通用设计 + 安全；personal 偏配置管理 + 测试 + 维护 + quality。
- **RQ2 内容 6 themes**：① scoping/orchestration ② execution lifecycle ③ output quality ④ governing agent conduct ⑤ grounding domain knowledge ⑥ user/agent coordination。
- **RQ3 修改 6 themes**：a) metadata 配置 b) reworking operational specifications c) recalibrating behavioural constraints d) adapting knowledge and resources e) compatibility maintenance f) polishing presentation；主要目标是 **b + d**；behavioural constraints（c）几乎不动。

## 5. 一句话索引（给 Agent 用）

> 当你把"SKILL.md" / "AGENTS.md" 当作 AI Agent 的可复用依赖工程品来看时，**优先关注三件事**：①70% 的复用是近 verbatim copy、53% 之后从未修改——本地一定要记得复制时主动本地化；②定制化主要改 operational specifications + adapting knowledge/resources，behavioural constraints 几乎不动，所以"安全 / 行为契约"应在初次注入就稳定固化好；③Software Construction 主导、长尾严重、非-SE skill 占 29%——registry / tooling 应帮助 consolidation of drifting skill contents，而不是放任维护者反复重写一遍原仓库里的知识。
