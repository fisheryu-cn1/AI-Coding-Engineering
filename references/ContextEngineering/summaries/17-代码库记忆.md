# 论文摘要：Codebase-Memory（仓库级长期记忆）

> **原论文标题**：Codebase-Memory: A Repository-Level Code Understanding System with Persistent Memory
> **完整 PDF 文件名**：`17-Vogel-Codebase_Memory.pdf`
> 作者 / 年份：Christian Vogel et al.，2024–2025
> 摘要类型：Agent 设计参考 + 上下文工程方案
> 生成日期：2026-08-12

## 1. 适用场景

- 设计 **跨会话、跨任务** 的仓库级 Agent 时，需要把"对仓库的理解"持久化为可重用的记忆。
- 实现 **MCP（Model Context Protocol）后端** 时，本文给出把代码图 + 社区划分暴露为工具的具体做法。
- 需要在 **66 种语言** 上做 AST 抽取 + 跨语言实体对齐时，本工作提供了可参考的工程实践。
- 想用 **Louvain 社区检测** 把仓库功能模块化为"语义块"喂给 LLM 时，本文给出做法与边界。
- 给 Agent 加 **跨会话连续性 / 项目记忆层** 时，本文的 SQLite + JSON 双层存储是有用的参考。

> 锚点：Abstract；§1 Introduction；§3 Architecture；§4 Memory Layer。

## 2. 主要观点与方案

### 2.1 核心问题

- 现有 RAG / SWE-agent 多为 **单次任务** 的检索：进入会话 → 检索 → 输出 → 丢弃上下文。
- 真实 Agent 落地需要 **跨会话、跨任务的仓库理解**——同一团队反复问同一仓库时，不应每次从零开始解析。
- 需要一种 **仓库级长期记忆**，能跨语言、跨文件、跨会话地保存结构化知识。

### 2.2 系统架构

- **解析层**：基于 **Tree-sitter** 解析 66 种语言的 AST。
- **存储层**：
  - **SQLite** 存实体元数据（函数/类/变量/文件）及其结构化关系。
  - **JSON checkpoint** 存高阶摘要、跨会话状态、嵌入缓存。
- **检索/推理层**：
  - 实体级查询（"哪些函数调用了 X"）。
  - 关系级查询（"X 类被哪些模块使用"）。
  - 摘要级查询（"这个模块做什么"）。

### 2.3 MCP 暴露层（关键贡献）

- 通过 **Model Context Protocol** 把记忆层以"工具"形式暴露给 Agent：
  - `query_entity(name)`：返回实体的定义、位置、依赖。
  - `query_relationships(name)`：返回实体的入边/出边。
  - `summarize_module(path)`：返回模块的语义摘要。
  - `find_callers(name)`：返回所有调用者。
- 这样 LLM Agent 可像调用其他工具一样调用仓库记忆，**避免把整个图塞进 prompt**。

### 2.4 社区划分

- 用 **Louvain 社区检测算法** 在仓库级代码图上做模块化聚类，输出"语义社区"作为更高一级的组织单位。
- Agent 可以按社区（模块）请求上下文，而不是按文件/类——提高 token 利用率。

### 2.5 跨语言能力

- Tree-sitter 支持 66 种语言；不同语言的 AST 统一映射到内部实体模型（带 language tag）。
- 跨语言实体对齐：通过 **符号名 + 语义嵌入** 联合匹配，可在多语言 monorepo 中把同名/同义实体聚合起来。

### 2.6 评测（§6）

- 任务：**跨会话仓库问答** 与 **跨任务代码检索**。
- 关键对照：
  1. 无记忆（每次从零解析）。
  2. 纯向量检索（RAG baseline）。
  3. Codebase-Memory（MCP + 社区划分 + 跨会话记忆）。
- 指标：任务准确率、token 消耗、响应时延、跨会话一致性。

## 3. 达到的效果

| 度量 / 现象 | 数值 / 结论 | 锚点 |
|---|---|---|
| 支持语言数 | 66（基于 Tree-sitter） | §3 |
| 存储后端 | SQLite（实体 + 关系） + JSON checkpoint（摘要 + 状态） | §4 |
| 社区检测算法 | Louvain | §4 |
| MCP 工具集 | 至少包含 query_entity / query_relationships / summarize_module / find_callers | §4 |
| 跨会话一致性 | 比无记忆 / 单次 RAG 显著提升 | §6 |
| Token 效率 | 通过按社区/实体查询，把上下文压到 LLM 可承受范围 | §6 |
| 跨语言实体对齐 | 支持 monorepo 中按符号 + 嵌入聚合同名实体 | §4 |

## 5. 一句话索引（给 Agent 用）

> 给跨会话、跨任务的 Agent 设计 **仓库级长期记忆** 时，参考 Codebase-Memory 的架构：**Tree-sitter 多语言 AST + SQLite 实体关系 + JSON 摘要 + Louvain 社区检测 + MCP 工具暴露**，把仓库理解作为可调用的工具，而不是每次都塞进 prompt——这是给 Agent 做"项目大脑"的事实模板。
