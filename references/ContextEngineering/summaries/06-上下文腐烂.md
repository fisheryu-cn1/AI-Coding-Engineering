# 论文摘要：Context Rot（上下文腐烂：输入 token 增长如何影响 LLM 性能）

> **原论文标题**：Context Rot: How Increasing Input Tokens Impacts LLM Performance
> **完整 PDF 文件名**：`06-Hong-Context_Rot.html`（Chroma 官方网页版技术报告）
> 作者 / 年份 / 出版：Kelly Hong, Anton Troynikov, Jeff Huber（Chroma），2025（July 14），Chroma Technical Report
> 摘要类型：Agent 设计参考 + 内容索引
> 生成日期：2026-08-12

## 1. 适用场景

- **RAG / 文档问答 Agent 的上下文工程**：解释为什么"塞更长上下文"并不提升效果——甚至简单检索类任务也会因上下文腐烂（Context Rot）失效。
- **设计 distractors / 干扰项过滤策略**时：作为"为什么 distractor 数量和位置都会显著降低 NIAH 类任务表现"的实证依据。
- **评估模型长上下文鲁棒性**时：本文给出 controlled 实验设计模板（固定任务难度 + 变化输入长度）。
- **做 haystack 内容选型**时：发现"shuffled haystack > 逻辑连贯 haystack"反直觉结论，可指导语料重排 / chunking 策略。
- **设计 Repeated-Words / verbatim 复述类任务**时参考：定位准确性随 unique word 位置与输入长度共同变化。

> 锚点：Introduction；Needle in a Haystack Extension；LongMemEval；Repeated Words；Conclusion。

## 2. 主要观点与方案

### 2.1 核心问题与定位

- 业界普遍假设"LLM 在长上下文内行为均匀"；本文通过 controlled 实验 **驳斥这一假设**。
- 评测 18 个 LLM：Claude Opus 4 / Sonnet 4 / Sonnet 3.7 / Sonnet 3.5 / Haiku 3.5；OpenAI o3 / GPT-4.1 / mini / nano / GPT-4o / GPT-4 Turbo / GPT-3.5 Turbo；Gemini 2.5 Pro / 2.5 Flash / 2.0 Flash；Qwen3-235B-A22B / 32B / 8B。
- **关键方法学**：固定任务复杂度，只变化输入长度（isolate input length as the only variable）—— 弥补了 NIAH / Graphwalks / Latent List 等"长度↑ = 复杂度↑"的方法学缺陷。

### 2.2 四类控制实验（NIAH 扩展）

1. **Needle-Question Similarity**：基于 5 种 embedding model（text-embedding-3-small/large、jina-embeddings-v3、voyage-3-large、all-MiniLM-L6-v2）取平均 cosine similarity，分 8 个 needle 档位（PG essay: 0.445–0.775，arXiv: 0.521–0.829）。**结论：低相似度 needle-question 对随输入长度↑ 衰减更快。**
2. **Impact of Distractors**：4 个手写 distractor，3 种配置（Baseline / Single / Multiple）。**结论：单个 distractor 即显著降级；4 个叠加更糟；不同 distractor 影响非均匀（Distractor 3 对 arXiv+PG-needle 组合最致命）。**
3. **Needle-Haystack Similarity**：用 PG essays / arXiv 两种 haystack，5 模型取 top-5 chunk cosine 均值。**结论：needle-haystack 相似度的影响非均匀（PG haystack 显著；arXiv haystack 接近无差）。**
4. **Haystack Structure**：Original（保留逻辑流）vs Shuffled（句序随机）。**反直觉结论：shuffled 一致性比 structured 表现更好**——可能反映 attention 受结构流影响。

### 2.3 LongMemEval（真实 chat QA 场景）

- 用 306 条 prompt（平均 113k tokens），对比 Focused（~300 tokens，含答案相关内容）vs Full（113k 含无关上下文）。
- 题型：knowledge update / temporal reasoning / multi-session。
- 评分：GPT-4.1 作为 LLM judge（与人类判断对齐 > 99%）。
- **结论**：所有模型在 Full 上都显著低于 Focused；**Claude Opus 4 / Sonnet 4 因 abstention 策略表现低于旧 Claude**；非 thinking 模式下 knowledge-update > multi-session > temporal-reasoning；启用 thinking 后顺序变为 knowledge-update > temporal-reasoning > multi-session。

### 2.4 Repeated Words（自回归输出长度扩展测试）

- 任务：复述 N 次重复词 + 在某 index 插入一个 unique word；1090 个 (length, index) 组合；长度从 25 到 10,000。
- 7 种词对（apple/apples、golden/Golden、orange/run、orange/San Francisco、San Francisco/sf、Golden Gate Bridge/Park）。
- 评分：normalized Levenshtein distance + 位置正确性 + word count diff。
- 关键观察：
  - **位置准确性在 unique word 处于序列前部时最高**（随长度↑ 更明显）；
  - 多模型在 2500+ 词出现 refusal（"copyright" / "I can't" 之类）；
  - GPT-4.1 nano 把 "San Francisco" 输出成 "san Francisco"；Gemini 2.5 Pro 出现随机字串（`orange--g./2021/01/20/orange-county-california-sheriff-deputies...`）；
  - Qwen3-8B 在 5000 词时退化为"Okay, I'm going to take a break…"循环胡话；
  - GPT-4 turbo 在 500 词处出现局部性能峰；之后 undergenerates。

### 2.5 关键模型行为差异

- **Claude 系**：最保守，多用 abstention；Opus 4 唯一在 Repeated Words 任务有 2.89% 拒绝率。
- **GPT 系**：highest hallucination rate，distractors 下生成 confident but incorrect 答案；GPT-4.1 拒绝率 2.55%。
- **Gemini 系**：2.5 Pro 变异性最大，多个词对出现 random outputs（500–750 词起）。
- **Qwen 系**：8B 出现循环胡话；thinking mode 提升 focus / full 表现但仍存在 gap。

## 5. 一句话索引（给 Agent 用）

> **别再用"模型支持 N tokens = 它能均匀用好 N tokens"来设计长上下文 Agent**——Chroma 的 Context Rot 报告用 18 个模型在 NIAH / LongMemEval / Repeated Words 上证明：低 needle-question 相似度、distractor 数量、shuffled haystack、unique word 位置等多个因素都会非均匀地随输入长度放大性能下降；Agent 上下文工程必须主动管理"信息出现的位置 / 相似度 / 干扰项密度"而不是简单追加。
