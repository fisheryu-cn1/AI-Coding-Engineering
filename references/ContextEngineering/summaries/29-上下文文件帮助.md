# 论文摘要：上下文文件（AGENTS.md / CLAUDE.md）到底帮不帮助编码 Agent？

> **原论文标题**：Do Context Files Help Coding Agents? A Two-Agent Ablation Study on Real Repositories
> **完整 PDF 文件名**：`29-Khatri-Do_Context_Files_Help_v1.pdf`
> 作者 / 年份 / 出版：Prakhar Khatri（Independent Researcher），2026，arXiv:2607.27250v1
> 摘要类型：Agent 设计参考 + 内容索引
> 生成日期：2026-08-12

## 1. 适用场景

- 在评估 / 部署编码 Agent 时，回答一个"看似简单"的问题：**AGENTS.md / CLAUDE.md 这类静态上下文文件，到底对正确性有没有可测量影响？**
- 当工业实践与学术研究结论冲突时（Lulla et al. 2026 在 Codex 上称有效率提升 vs Gloaguen et al. 2026 在 Claude 上称无完成率效果），本论文用同一份 protocol 给两方都做。
- 想用**等效性检验（TOST） + 置换检验 + power 分析**刻画 bounded null 时（而非传统 NHST）。
- 想分离"channel of delivery"（system prompt vs on-demand retrieval） vs "content of context" 这两个独立变量时。
- 作为 AGENTS.md / CLAUDE.md 实践 / 工具设计的决策参考：边际收益、agent-specific 难度差异、failure-mode 类型。

> 锚点：Abstract；§1 Introduction；§2 Related Work；§3 Method 概览。

## 2. 主要观点与方案

### 2.1 核心主张（"对正确性没可测量影响"）

- AGENTS.md 是当前 coding agent 部署的标准上下文层，业界花了大量精力写规范；但实证证据矛盾。
- 作者用受控 ablation：同一任务、同一评估、同一 host 上运行三种注入策略（NONE / ALWAYS ON / SELECTIVE），并把 3 repeats 平均到 task 级以避开 floor/ceiling trap。
- 结论是一个 **bounded null**：
  - **Claude（15 tasks × 3 strategies × 3 repeats）：无显著策略效应；TOST 配对差异 ≤ 10pp、omnibus permutation p = 1.00；pass-rate 53.3% (NONE) / 55.6% (ALWAYS ON) / 55.6% (SELECTIVE)**。
  - **Codex（17 tasks）：无显著策略效应；TOST 配对差异 ≤ 15pp、omnibus permutation p = 0.66；pass-rate 58.8% / 56.9% / 52.9%**。

### 2.2 三种策略（§3.3；Figure 1）

- **NONE**：移除仓库根 AGENTS.md，零上下文，仅靠代码。
- **ALWAYS ON**：每一轮把完整 AGENTS.md 注入 system prompt（同时从 workspace 移除，避免二次读取）。
- **SELECTIVE**：在工作空间放 topic-organized wiki（e.g., `wiki/architecture.md`、`wiki/error-handling.md`）；system prompt 给一行 hint 让 agent 按需 `Read`。
- 注意 caveat：opshin 的 SELECTIVE corpus 等于 AGENTS.md，其他（pdm / firebase）却是 ~10×~18× 词的 auto-generated wiki；等于 SELECTIVE 在这两仓既换 channel 又扩了 corpus，但这只会"加强 null"。

### 2.3 任务/评估/统计（§3.2-3.6）

- **3 个真仓库**（pdm / firebase-admin-python / opshin），filter 条件：Python、单一 root AGENTS.md、足够质量、不超大规模。
- **17/15 真实 merged PR tasks**：PR description 当 prompt、base commit 当起点、PR 自带 tests 当 gold eval（agent 看不见）。egress-locked + PATH shim 防止 git push 偷答案。
- **统计**：omnibus permutation（label permute 1–2 万次）+ paired Wilcoxon + Holm-Bonferroni；TOST 任务聚类 bootstrap 10k；Monte Carlo 模拟 binary outcome 找 MDE（>30pp）。
- **样本**：288 完整 cells，3 个 Claude run crash/timeout 从 correctness 排除。

### 2.4 Failure-mode / 机制证据（§4.2-4.4）

- 失败发生在 **implementation skill**（feature 设计、pattern 选择、wiring），不是因为缺仓库知识。
- 操控实验：real AGENTS.md 不能把"接近成功"翻成"成功"（两个 agent 都一样）。
- Borderline 难度具 **agent-specific**：Spearman ρ = 0.75（同一任务对一个 agent 是 floor、对另一个是 ceiling）——为单 agent 研究互相矛盾提供了候选解释。
- 唯一可重复的"小"效应：Claude × opshin SELECTIVE 减少 cache-creation tokens（pure delivery mechanics 效应，无 correctness 收益）。

> 锚点：§4 Results（4.1 Correctness 4.2 Efficiency 4.3 Borderline band 4.4 Failure analysis）；Tables 1-3；Figures 2-4。

## 5. 一句话索引（给 Agent 用）

> 别再相信"加个 AGENTS.md 就能让模型更准"——把 injection strategy 当独立变量（NONE / ALWAYS ON / SELECTIVE）在 15 个 Claude + 17 个 Codex 任务、288 个 gold-test 评估 run 里做 audit，结论是一个 bounded null：Claude ≤ ±10pp、Codex ≤ ±15pp，且 border-line 难度呈 agent-specific（ρ = 0.75）、失败原因在 implementation skill 而非知识缺口——3 策略都不会复活 near-miss。下次花力气写 AGENTS.md 之前，先确认你的任务确实不是 floor / ceiling，然后再看 cache token 能否拿到一点 footprint 红利。
