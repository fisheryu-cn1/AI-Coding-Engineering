## 2. 主要观点与方案

### 2.1 核心论断（§1.4）

- "The bottleneck to effective agentic software development is not **model capability** but **knowledge architecture**."
- 区分 3 类 **knowledge consumer**：autonomous AI agent / newly onboarded engineer / cross-team contributor，**面对相同的结构性 deficit**——Institutional Impedance Mismatch。

### 2.2 关键概念

- **Institutional Impedance Mismatch**：knowledge consumer 既有知识 vs 组织专属知识 之间的结构失配。Deployment 侧称 **last-mile problem of agentic software development**。
- **Context Window Economy**（§3）：用信息论 + cognitive load 理论建模 LLM 上下文预算稀缺性，引入 3 类约束（token budget / attention decay / latency cost）。
- **Context Rot**（§3.5）：引用 Chroma 2025 报告（见摘要 06），当 context window 累积 correction / 失败 trail 时，**有效推理容量系统性衰减**。
- **Institutional Knowledge Tax**：因 mismatch 引起的 senior engineer 时间税（与新人 onboarding 同构）。
- **Knowledge Activation**：从"retrieve documents for interpretation"转向"deliver action-ready specifications"——**编码 what to do / which tools / what constraints / where to go next**。

### 2.3 三种现状不足（§1.3）

- **RAG**：把知识当 undifferentiated text fragment，按语义相似度注入；适合 QA，不适合 multi-step agent workflow。
- **Prompt / Custom Instructions**：静态；不易 version / compose；context budget 超过后被迫 ad hoc 优先级。
- **Tool-use / MCP**（[3]）：定义"工具存在 + 怎么调"，不规定"什么时候用 + 为什么这个工具 + 治理约束"。
- **Task decomposition**（CoT / ReAct / Toolformer / Reflexion）：假设知识 already 具备或可 retrieve，不解决知识架构。

### 2.4 关键经验冲突

- Liu et al. 2026（AGENTS.md）：runtime ↓ 28%，token ↓ 16%。
- Gloaguen et al. 2025：naive context files（含 LLM-generated）**降低** task success、↑ 20%+ inference cost。
- 大规模实证（2,303 文件跨 1,925 repo）：文件治理 / 安全约束仅 **14.5%** 案例声明。
- 结论："context helps **efficiency** but hurts **quality** when unstructured"——即本文要补的 gap。

### 2.5 知识激活流水线（§4 Knowledge Activation Pipeline）

- 三阶段：**codification → compression → injection**。
- 与 RAG 对比：Knowledge Activation 不是"找相关文档"，而是"以可执行规范送达 action-ready 知识"。
- **Knowledge Density** 作为优化目标（§4.4）：引用 ICLR 2023（小样本可匹配大数据）——**"context window size matters less than what occupies it"**。
- 与 Nonaka-Takeuchi **SECI 模型** 映射：Socialization→Externalization→Combination→Internalization。

### 2.6 Atomic Knowledge Unit（AKU）/ Skill Schema（§5）

- **7-component schema**：
  1. **Intent**（目标 / 触发条件）
  2. **Procedure**（操作步骤）
  3. **Tools**（可调工具）
  4. **Metadata**（version / owner / tags）
  5. **Governance**（合规模块 — 内禀属性）
  6. **Continuations**（下一步 / handoff）
  7. **Validators**（deterministic 治理脚本）
- 关键设计原则：每个 AKU **声明与其他 AKU 的关系**，构成 **composable knowledge graph**，agent 在 runtime 遍历。
- **Validators**（§5.5）：deterministic governance scripts，**governance-as-code**。
- 例：Deploy Microservice Skill（§5.6）展示完整 schema。

### 2.7 Agent Knowledge Architecture / 三层（§6.2）

- **AKU Registry**：版本化、可发现。
- **Knowledge Topology**：AKU 间关系图。
- **Activation Policy**：触发 / 权限 / 上下文注入策略。
- **AI-Generated Golden Paths**（§6.5）：从静态 template 转向 runtime 由 agent 动态组合 workflow。
- **Paved Lanes**（§6.4）：Pre-Composed Skill Chains。
- **Skill Discovery**（§6.6）：检索 / 推荐机制。

### 2.8 治理梯度（§7）

- Governance 是 AKU 的 **intrinsic property**（不是外挂）。
- **Organizational Metadata Pairing**：把 governance / compliance 标签与业务 metadata 配对。
- **Governance Gradient**：从 advisory → warn → block 的连续谱。
- **Building Enterprise Trust**（§7.4）：审计日志、版本回滚、shadow run。

### 2.9 Yahoo 企业部署（§8 Case Study）

- 87 个 modular agent-consumable skills。
- 67 位工程师匿名问卷（统计显著）。
- 主要 finding：
  - 4 个 perceived-experience driver 全部 large–very large effect size；
  - **每位工程师平均节省 2.6 hours/week**；
  - **Net Promoter Score = +35**；
  - 跨 business unit / tenure strata 无显著差异（公平性）。
- 引用：2025 ICSE-SEIP 484 Microsoft 开发者研究 — 实际编码时间仅 11% of workweek。
- Operational learnings（§8.7）：skill 过时、命名冲突、role-based gating、隐式依赖。
- Threats to validity（§8.8）：单组织 / 自报告问卷 / 短期观察。

### 2.10 长期维护（§9.5 Knowledge Commons）

- 借鉴知识共享理论 [31, 80]，把 Skill 库当作 **community-maintained commons**。
- 治理 = 探索 / 利用平衡（§9.4）。
