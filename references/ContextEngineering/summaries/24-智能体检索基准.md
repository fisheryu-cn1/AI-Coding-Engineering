# 论文摘要：Agent Retrieval Bench（编码 Agent 的"找上下文"基准）

> **原论文标题**：Agent Retrieval Bench: Evaluating Repository Context Retrieval for Coding Agents
> **完整 PDF 文件名**：`24-Qin-Agent_Retrieval_Bench_v1.pdf`
> 作者 / 年份 / 出版：Bowen Qin（NUS）、Yi Xie（Peking University），2026，arXiv:2607.24882v1
> 摘要类型：Agent 设计参考 + 内容索引（基准 / 评测）
> 生成日期：2026-08-12

## 1. 适用场景

- **做编码 Agent 评测/选型时作为"上游"基准**：评估 retrieval 层而不是 patch 产出层——找对文件 = 让后续 patch 有正确上下文。
- **做相关综述/比较时参考**：与传统代码搜索（CodeSearchNet、CodeXGLUE）、repo-level completion（RepoBench）、端到端 patch 评测（SWE-bench / SWE-agent / Agentless / LocAgent）以及新近探索基准（CORE-Bench / SWE-Explore）形成对照。
- **做 ABSTENTION / NO-GOLD 选择时参考**：评估 retrieval 在"应返回哪些文件"和"应识别为本地无法解决"两件事上的能力。
- 当现有静态检索器在评估前后需要**泄漏控制（leakage control）**、**构造透明**、**与上下文预算耦合**指标时。
- 当需要**联合评估**静态 retrieval + interactive agent 轨迹。

> 锚点：Abstract；§1 Introduction（Figure 1）；§2 Related Work（Table 1 定位表）。

## 2. 主要观点与方案

### 2.1 核心主张（"agentic retrieval ≠ semantic retrieval"）

- 现有 benchmark 把相关性定义为"query 与文件的语义相似度"，但 coding agent 真正需要的是 **下一步有用的那个 file**，可能是 review-comment 的额外上下文、failure trace 的 root-cause 文件、anchored edit 的 ripple 文件，甚至"应跳过本地直接 abstain"。
- 端到端评测（SWE-bench）把 retrieval 失败 / reasoning 失败 / editing 失败 / validation 失败混在一起，无法诊断 agent 是不是因为没找到文件而败。
- Agent Retrieval Bench 把 retrieval 拆成独立层评估：file-level ranking、token-budget BCY、selective abstention、轨迹成本与受控 seed 干预。

### 2.2 任务结构（§4 + §3 metrics）

- **code2test**：PR intent → 已存在 test 文件（实现换文件可能暴露，目标测试不一定）。
- **comment2context**：review comment + 已给 file → 额外 must-context files（"the reviewed file 不算 gold"）。
- **trace2code**：reproduced failure excerpt → root-cause source（visible test 是 evidence 不是 main gold）。
- **edit2ripple**：anchored edit → 其他受影响文件（用 changed-file 证据 + 同 symbol / 同路径 / 同组件三种 ripple relation）。
- **selective**：50 条 maintainer-evidence-backed natural no-gold（外部依赖 / 用户错误）+ 32 条 counterfactual wrong-repository。
- **指标体系**：Recall@5/10/20、MRR、**Budgeted Context Yield (BCY@B)**（token budget packing 下 gold 文件被装进 prompt 的 fraction）、PES@20（Potential Exploration Savings）、2×2 互补矩阵（both / retriever-only / agent-only / miss）、Span-level Line F1（287-sample 子集）。

### 2.3 构造与控制（§5, §6）

- 来自 25 个 GitHub 仓库、6 种语言（13 Python / 3 Go / 3 Rust / 3 TS / 2 Java / 1 JS），共 **427 samples**（345 positive + 50 natural no-gold + 32 counterfactual）；corpus manifest 含 308 base-commit 快照、392K 文件、7.9M chunks。
- 每个 sample 在 base-commit 上评估，防止 fixed-code 泄漏；**query sanitization** 同时移除 patches、fix hashes、确切 gold path、autogenerated review artifacts。
- 双语 lock：fatal leakage 诊断 4 类（exact gold-path / raw patch diff / fix-commit hash / autogenerated review）**全 0**，schema / corpus invalid rows = 0。

### 2.4 相关性类型学（taxonomy，§8.3）

- D = semantic-direct、S = structural-indirect、W = workflow-conventional、C = causal-indirect；287 代码样本 94.8% 有 ≥2 个关系；primary projection 仅做诊断性切片，不进入主分。

## 5. 一句话索引（给 Agent 用）

> 别只 report MRR / Recall@k 评估编码 Agent 的检索：Agent Retrieval Bench 用 4 个工作流驱动的 retrieval 任务（code2test / comment2context / trace2code / edit2ripple）+ 50 条自然 no-gold + 32 条 counterfactual 错仓库，给出 file-level + token-budget BCY + 轨迹 PES + 闭门工具干预；最强单一检索 Qwen3-4B / Qwen3-8B / RepoMap 各胜一方，RRF(Qwen3-8B + RepoMap) 才稳赢，证据提示"语义 + 结构互不替代"。
