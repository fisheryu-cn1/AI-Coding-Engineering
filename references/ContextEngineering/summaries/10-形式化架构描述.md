## 1. 适用场景

- **设计 Coding Agent 的代码库导航辅助**时：把模块边界 / 符号签名 / 约束 / 数据流显式编码为"形式化架构描述符"。
- **选型 agent context 文件格式**（Markdown / JSON / YAML / S-expression）时：本文给出 reader-side 准确度等价 + writer-side 失败模式差异的对比。
- **做代码定位任务（code localization）评测**时：参考本文 paired within-task + Wilcoxon 检验方法。
- **自动生成架构描述**时：把"auto-generated descriptor（零人工修改）vs curated（人工精修）"作为成本-效果基线。
- **设计多 Agent 子树切分 / 治理管线**时：参考 S-expression 天然支持递归 descent parser < 100 行。

## 2. 主要观点与方案

### 2.1 核心问题：Navigation Paradox

- 现实 codebase 中，AI coding agent 把大量 tool call 浪费在 undirected exploration（grep / glob / read module）上。
- 即便 context window 扩大，瓶颈从"retrieval capacity" 转为 **"navigational salience"**。
- LoCoBench-Agent（[5]）指出 **12-turn efficiency threshold**——超过后急剧 diminishing returns；SWE-agent（[6]）显示 iterative search 反而比不 search 更差。
- 现有方案的两类：① **Human-configured context files**（CLAUDE.md / AGENTS.md / Cursor Rules）—— 60K+ projects 采纳，但 Gloaguen et al. 2026 显示 **task success 无显著提升 + inference cost ↑ 20%**；② **Automated code representations**（Aider tree-sitter / CodexGraph / RepoGraph）—— 仅抓语法结构，缺 design intent / 架构约束。
- 形式化 ADLs（AADL / Acme / xADL）从未为 AI agent 设计过。

### 2.2 方案：intent.lisp（S-expression 架构描述符）

- **格式**（§2.1）：nested S-expression 树，结构为
  - **pillars**（top-level 责任域）
  - **components**（pillar 内模块）
  - **symbols**（函数签名 / 类型 / 常量）
- 包含字段：design-constraints, purpose, role, invariants, data-flow, symbols。
- 生命周期：① Generation（AST scan + LLM translate natural language intent）→ ② Consumption（agent 把它当 navigation entry point）→ ③ Co-evolution（与 code 同步、版本控制）。
- 关键定位：S-expression 价值**不在于 LLM 更爱读它**（reader-side 无显著差异），而在于 4 个**writer-side / 治理侧**属性。

### 2.3 S-expression 的 4 个关键属性

- **Syntactic enforcement of hierarchy**：唯一允许的结构是 nested lists，containment 由括号决定——**结构性保证**而非约定。
- **Compression density**：表 1 显示 5 个生产项目（646K 总行）压缩比 5:1（小项目 dense L3）~ 64:1（大型 compiler 单文件），**weighted average 34:1**；比 JSON 短 22%。
- **Graceful error degradation**（§3.2 / Table 3）：JSON 失败 atomic，1 个 brace 错即整文件 0% 恢复；YAML **silent corruption 50%**；S-expr 检测 100% 结构完整性错误，错误前内容**保持结构完整**。
- **Formal parseability enables tooling**：< 100 行 recursive descent parser 即可；JSON 有 Structured Outputs / Schema-constrained generation 优势但 API-level 生态差异存在。

### 2.4 4 个互补实验

#### Reader-Side：Code Localization（§3.1 / Table 2）

- 24 tasks × 4 conditions on `jarvis` (Rust, ~22K lines) with Claude Sonnet 4.6, temperature=0, max 20 steps.
- **Result 1**：architecture context reduces navigation by **33–44%**。Blind 5.2 steps vs S-expr 3.4 / JSON 3.4 / Markdown 2.9 steps。Wilcoxon Blind vs S-expr **p = 0.009, d = 0.92**；Blind vs Markdown **p = 0.005, d = 1.43**。5 tasks 因 descriptor staleness 全部失败。
- **Result 2**：no significant format difference detected（pairwise p > 0.07）。独立 comprehension 实验 20 questions × 4 formats → identical 95% accuracy。
- 注意：stronger model 缩小 blind baseline 的 marginal benefit（早期较弱 model 跑出 d = 1.70，Sonnet 4.6 d = 0.92）；descriptor 价值在 100K+ 行 codebase 上应更大（threats to validity）。

#### Writer-Side：生成可靠性 + 错误恢复（§3.2 / Tables 3）

- Design：8 NL descriptions × 4 formats × 3 repetitions = 96 runs + 3 error types × 96 injections.
- **Result 3**：JSON 100% / S-expr 95.8% / YAML 91.7% parse validity.
- **Result 4**：failure modes differ critically——详见 Table 3（silent corruption 50% for YAML, 100% for MD; 21% for JSON; S-expr 50% silent corruption but 100% structural completeness detection）.

#### Artifact vs Process Value（§3.3 / Table 4）

- Design：15 tasks on `jarvis-forge` (Rust, 43K lines)，developer **从未 refactor code** 匹配任何 descriptor。3 conditions：Blind / AutoGen (~170-line auto-generated) / Curated (698-line hand-refined).
- **Result 5**：**AutoGen 100% vs Blind 80%**（Wilcoxon **p = 0.002, d = 1.04**）——零人工修改、零 code 重构条件下 descriptor artifact **本身**就有 navigation value；**refutes "self-clarification" hypothesis**。
- **Result 6**：Curated 87% / 2.9 steps / 5.2 censored mean vs AutoGen 100% / 3.9 / 3.9 → 长度未必更好（token budget 竞争 ~52K vs ~20K）。

#### Observational Field Study（§3.4）

- 4 个 active projects，MissionD logs：7,012 sessions / 484,937 messages（Nov 2025 – Apr 2026）。
- 2026-04-03 在 2 个 project 引入 intent.lisp。
- **Finding 1**：per-session explore/edit ratio IQR **从 2.24 降到 1.08（52% reduction in behavioral variance）**——descriptor 限定 worst-case agent behavior。
- **Finding 2**：引入后 "read intent.lisp" sessions vs "did not" 无 per-session advantage（1.65 vs 1.65）—— **developer self-clarification effect**（formalize 行为本身可能改善 prompts）。但配合 Experiment E 的 AutoGen 结果，说明 artifact value 独立成立。

### 2.5 关键论断

- "Context engineering debate should not focus on **'what format does the LLM prefer'**"（reader-side 无显著差异）。
- 更有生产意义的问题："**what format avoids catastrophic failure when LLMs both write and read it**"。
- 生产 codebase（100K–470K lines）中，**34:1 压缩比**让"constant-cost architectural access regardless of codebase size" 成为可能。

## 5. 一句话索引（给 Agent 用）

> **为大型 codebase 提供形式化架构描述符（intent.lisp / S-expression）能直接削减 33–44% 导航步骤（d=0.92, p=0.009）并把 agent 行为方差降低 52%**——reader-side 格式无显著差异（JSON/YAML/MD/S-expr 95% 同分），但 writer-side 差异巨大：S-expr 检测 100% 结构完整性错误、YAML silent corruption 50%、Markdown 100%；自动生成（170 行、零人工、零重构）即可达到 100% 准确率，证明 descriptor artifact 本身有 navigation value，与"developer self-clarification" 无关。
