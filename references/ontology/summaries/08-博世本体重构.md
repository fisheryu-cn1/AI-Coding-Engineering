## 1. 适用场景

- 在 **工业 4.0 / IoT 制造数据** 上落地 KG（焊接、汽车、Equinor 等场景）。
- 解决 **"知识导向领域本体 vs 数据导向 KG schema"** 之间的鸿沟——把前者 reshape 到后者。
- 提供 **Welding-ML KG** 五层架构（Machine / Data / KG / Application / Ontology）作为工业 KG 落地的参考蓝图。
- 评估 **blank node / 查询复杂度 / 存储** 等工程指标的改善空间。

> 锚点：Motivation；Challenge；Ontology Reshaping Enhanced KG Generation；Evaluation at Bosch；Outlook。

## 2. 主要观点与方案

### 2.1 核心张力（trade-off）

- 知识导向：领域本体要反映一般领域知识，不要被数据集特殊性污染。
- 数据导向：KG schema 必须贴合原始数据，否则产生大量 blank node。

### 2.2 解决方案（Ontology Reshaping）

- 把领域本体投影为 labelled multi-graph → 按用户启发式/效率/简洁性选子集节点与边 → 用最优连接准则把子图连起来。
- 用 reshape 后的本体作为 KG schema，再 ETL 到关系表/JSON/SQL/XML。

### 2.3 五层架构

- Machine Layer：生产线上焊机数据。
- Data Layer：Data Transformation（json/SQL/XML → relational）。
- KG Layer：Welding-ML KG（生产 + ML 分析）。
- Application Layer：ML Analysis 等。
- Ontology Layer：Ontology Reshaping module。

### 2.4 Bosch 评估（离线）

- 数据：4.315 million records / 1000 焊接操作 / ~100 辆车。
- 多种异构源（传感器历史、焊机配置、生产规格、质量估计）。

### 2.5 关键改进（vs 无 reshape 的 baseline）

- KG 生成时间 **7–8× 更快**。
- 实体数 **降到 1/2–1/6**。
- 存储空间 **降到 2/3**。
- blank node **归零**，查询更短更简洁。
