## 1. 适用场景

- 在 **金融情报机构（FIU）+ 监管合规** 场景下，把反洗钱任务形式化为可解释的规则推理。
- 把 **Datalog± / Warded Datalog±** 这类逻辑型 KRR 语言落地到金融领域 KG。
- 设计 **逻辑型 KG**：EDB（事实）+ IDB（规则） + 派生 extensional。
- 在 **STR（Suspicious Transaction Reports）+ 企业数据 + KYC** 异构源上做决策支持。

> 锚点：Abstract；§1 Introduction；§2 A Rule-based Vision on AML；§3 Real-world case；§4 Challenges。

## 2. 主要观点与方案

### 2.1 核心论点

- 全球洗钱规模 1.7–4.5 trillion USD（IMF 估计）；AI Fintech 投资涨 50%+；ML 仍集中在 compliance）。
- 现有 AI 方案不满足 FIU 四大质量需求：
  - ① 复杂推理（异构实体网络）；
  - ② 全可解释（满足法律跟进、避免不公正）；
  - ③ 平衡归纳与领域经验；
  - ④ 可扩展到极高吞吐。

### 2.2 决策任务形式化

- Task 1：Suspicion assessment（判定可疑）。
- Task 2：Suspicious offence determination（判定潜在上游犯罪）。
- 衍生任务：Suspiciousness scoring、Suspicion classification、Risk-driven optimization、Reconstruction。

### 2.3 规则型 KG（VADALOG / Warded Datalog±）

- KG = EDB + IDB（推理规则）+ 派生 extensional。
- 选用 **VADALOG**（基于 Warded Datalog±），特征：full Datalog + full recursion；可表达 SPARQL/OWL 2 QL entailment；PTIME 数据复杂度；支持 aggregation、分层 negation、概率推理、嵌入 ML 模型。
- 规则形式：∀x̄∀ȳ (φ(x̄,ȳ) → ∃z̄ ψ(x̄,z̄))。

### 2.4 真实案例（意大利 FIU 脱敏）

- 把 AML 知识建模为 KG（交易 / 企业 / STR / 媒体 / 法律跟进反馈）。
- IDB 既表达法规（RegTech），也编码洗钱模式（循环电汇、金字塔控股结构）。

### 2.5 关键挑战

- 数据治理、合规检查、分析、seen/unseen 洗钱模式识别、不确定性、伦理决策。

> 锚点：§2 A Rule-based Vision；§2.2 Towards Rule-based KG for AML；§3 Real-world case；§4 Challenges。
