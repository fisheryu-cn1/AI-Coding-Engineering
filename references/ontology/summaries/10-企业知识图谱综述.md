## 1. 适用场景

- 设计 **下一代企业信息系统（EIS）** 时，把 KG 放进架构层次，作为"raw data storage → 上层应用"的中间语义层。
- 评估企业数据集成范式（XML Schema 集成 / Data Warehouse / Data Lake / MDM / PIM-PCS / Enterprise Search） vs EKG。
- 选型 **RDF** 作为企业 KG 数据模型 + 9 维评估框架（数据模型、集成策略、概念/操作、异构数据、内外部数据、源数、集成类型、领域覆盖、语义表示）。
- 把 EKG 与 Data Lake、MDM、Enterprise Search 等结合使用的思路。

> 锚点：Abstract；§1 Introduction；§2 Motivation；§3 Enterprise Knowledge Graphs；§4 Assessment framework；§5 Clustering evaluation。

## 2. 主要观点与方案

### 2.1 核心论点

- Linked Enterprise Data（LED）仍是抽象想法，需要"起点 / 结晶点"——EKG 作为它的具体化身。
- EKG = 企业内部概念的语义网络（concepts / properties / individuals / links）。
- 形式定义：EKG = ⟨σ, A, R⟩，其中 σ = 签名，A = 公理集合（本体），R = 限制（基于本体的限制）。
- EDIS = ⟨EKG, S, M⟩：本体+实例 + 数据源 + 映射。

### 2.2 与七大数据集成范式对比（Table 1）

- P1 XML Schema Integration（DOM trees, LAV, operational, …）
- P2 Data Warehouses（relational, GAV, operational, …）
- P3 Data Lakes（various, LAV, operational, …）
- P4 MDM（UML, GAV, conceptual, …）
- P5 PIM/PCS（trees, GAV, operational, …）
- P6 Enterprise Search（document, …）
- P7 EKG（RDF, LAV, both, very high semantic representation）

### 2.3 企业架构定位（Figure 1）

- 自下而上：Text / Media / 半结构化 / RDB / RDF → Semantic Data Lake → Ontological Coherence Layer（多个本体：组织、安全、供应链） → EKG → API（GUI/REST/XML-JSON/SPARQL/APIs） → Enterprise Applications（ERP/MDM/ESB/Web Apps）。
- 治理 / 成熟度分析 / 质量 / 安全 / 来源（provenance）作为正交维度贯穿全栈。

### 2.4 评估框架与方法

- 9 维评估 + 聚类分析 → 揭示哪些 EIS 共享哪些 EKG 特征。
- 结论：现有方法都不能完整实现 EKG，是下一代 EIS 的核心挑战。

> 锚点：§2 Motivation；§3 EKG formal definition；§4 Assessment framework；§5 Clustering。
