## 1. 适用场景

- 在 **跨学科工业团队**（焊工/工艺/数据科学/管理）中，用 KG 作为 ML 实践的"通用语言"。
- 解决 **ML 解决方案不透明、文档不规范、复用困难** 三大工业痛点（C1/C2/C3）。
- 设计 **可执行 KG（Executable KG）**——把 ML 知识编码到 KG，再翻译成模块化可执行脚本。
- 评估 **R1–R6**（Transparency / Usability / Executability / Coverage / Reusability & Modularity / Scalability）需求框架。

> 锚点：摘要；§1 Introduction；§2 Use Case；§3 Related Work；§4 Framework；§5 System；§6 Evaluation。

## 2. 主要观点与方案

### 2.1 工业 ML 三痛点

- C1：对非 ML 专家不透明（domain expert 不理解 ML 方法/结果 → 信任问题）。
- C2：缺乏标准化描述（依赖个人写作风格 → 难回顾、难审计）。
- C3：方案 ad hoc（针对特定应用 → 难以迁移到相似数据/相似问题）。

### 2.2 解决方案（Executable KG）

- 把 ML 解决方案编码到 KG；KG 可翻译成模块化可执行脚本。
- 五层系统：① Semantic artefacts（schema）→ ② Semantic modules（半自动构建）→ ③ KG data layer（存储）→ ④ Application layer（visual / statistical / ML analytics）→ ⑤ Non-KG data layer。

### 2.3 三类 ML 活动

- Visual analytics（line/scatter/bar/heatmap）。
- Statistical analytics（mean/median/std/sliding window/outlier）。
- ML analytics（feature engineering + deep learning，分类/回归）。

### 2.4 Bosch 焊接监控用例

- Resistance Spot Welding (RSW)：百万级车辆/年；传统方法需拆焊件测焊点直径（极贵）。
- 数据来源跨 4 个工厂 × 3 个客户；同类焊接工艺（hot-staking、超声波焊接）。

### 2.5 评估手段

- 用户研究（验证透明度、复用性）。
- 可扩展性评估（自动生成的脚本在大规模数据上的运行时间）。

> 锚点：§2 Use Case；§4 Framework；§5 System；§6 Evaluation。
