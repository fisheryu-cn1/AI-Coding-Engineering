# 论文摘要：收益递减的错觉——LLM 长程执行的测量与 self-conditioning 效应

## 1. 适用场景

- 设计或诊断**长程任务 agent 架构**（上下文管理/滑窗、任务分段、外部化状态、是否保留历史轨迹）时——本文给出"自己的错误历史会诱发继续犯错"的因果证据与可行缓解。
- 评估"单步准确率只涨了几个点"的模型升级/继续 scaling 是否值得时——用复合公式把单步增益换算成可完成任务长度的变化。
- 决定给 agent 配多少 **thinking/推理预算、串行 vs 并行测试时算力**时——thinking 是修复 self-conditioning 与拉长单轮执行的最有效手段，并行多数投票替代不了。
- 构建**可控合成评测**（去污染、可程序化再生、解耦 planning/knowledge/execution）时借鉴其 key-value dictionary 任务设计。
- 需要解释"模型会做复杂推理题却在加长版简单任务上失败"这类矛盾现象、或撰写 scaling 经济学论证时。

> 锚点：ABSTRACT; §1 INTRODUCTION; §2 FORMULATION; §3 EXPERIMENTS; §5 CONCLUSION。

## 2. 主要观点与方案

### 2.1 研究问题与动机（§1 INTRODUCTION）

- 背景：scaling law 在单步指标（如 test loss）上收益递减，引发"继续投入算力是否值得"之争；而 METR 等观测显示长任务能力在指数增长。同时 LLM 在"简单但长"的任务上失败，常被解读为"不会推理"（Mirzadeh et al.）或 thinking 只是"思考的错觉"（Shojaee et al.）（§1）。
- 核心主张：把 planning（决定做哪些步骤）、knowledge（步骤所需信息）、**execution（执行既定步骤）**解耦后单独测量——假设"即使 planning 与知识完美，LLM 在长程执行中仍会出错"，并解释短任务基准为何给出"进步放缓"的错觉（§1、§2）。

### 2.2 形式化：指标与复合公式（§2 FORMULATION）

- 关键定义（§2 Key Terms）：Planning / Execution / Knowledge / reasoning task / agentic task；评测指标（§2 Evaluation Metrics）：**Step Accuracy**（单步状态更新正确率）、**Turn Accuracy**（单轮正确率）、**Turn Complexity K**（每轮步骤数）、**Task Accuracy**（全程无错完成率）、**Horizon Length H_s**（平均任务准确率跌破阈值 s 的步数，取 s=0.5，与 Kwa et al. 2025 的 50% 口径对齐）。
- **命题 1（§2.1 DIMINISHING RETURNS IN STEP ACCURACY COMPOUND OVER A LONG HORIZON）**：假设各步独立、准确率恒为 p 且无自我纠正，则 H_s(p) = ln(s)/ln(p)——地平线长度随单步准确率**双曲增长**，在 80% 单步准确率之后急剧拉升（图 2）；p→1 时 H_0.5 ≈ ln2/(1−p)，对 ∆p 的增益随 p 二次放大（附录 J 推导）。推论：METR"每 7 个月翻番"的指数地平线增长只需**递减的单步准确率改进**即可维持——"收益递减"是短任务基准的测量错觉；若经济价值来自可完成任务长度，scaling 仍可能划算。
- **受控任务设计（§2.2 ISOLATING EXECUTION BY DECOUPLING PLANNING AND KNOWLEDGE）**：把长程任务抽象为"retrieve-then-compose"步骤链，实现为 **key-value dictionary addition**：上下文内给出固定字典（五个字母常用英文词 → [−99,99] 整数），每轮提供 K 个 key（即"计划"），模型查值并维护累加和；计划以 key 形式显式给出、知识在上下文中给出，从而剥离 planning 与参数化知识；任务长度 = 轮数 × K，两轴可控；少样本示例约束输出格式（附录 G 全部 prompt 与超参：固定 100 个 key、50,000 步 rollouts、Qwen3/Gemma3 各 100 条、前沿模型 20–50 条；温度 0.6/0.7、CoT 限 10k/thinking 限 32k 输出 token；4×A100 + OpenRouter）。

### 2.3 实验发现（§3 EXPERIMENTS）

- **执行本身就是挑战（§3.1 EFFECT OF INCREASING THE NUMBER OF TURNS，Result 1）**：K=1、直接作答（无 thinking），Qwen3 [4,8,14,32]B 与 Gemma3 [4,12,27]B 除 4B 外首步准确率近满分，但任务准确率随轮数骤降——最好的 Qwen3-32B 也在 **15 轮内跌破 50%**。
- **规模效益不递减（§3.1 Result 2）**：任务不缺知识（首步近满分）也不更难，但越大模型能执行的轮数显著更多、地平线更长，未见收益递减；输出级并行聚合（majority voting）模拟不出规模收益（附录 D）。格式错误占比约 0.1、非主要失败源（附录 H）；温度设 0 趋势不变（附录 G/图 14）。
- **self-conditioning 效应（§3.2 WHY DOES TURN ACCURACY DEGRADE? THE SELF-CONDITIONING EFFECT）**：轮准确率随轮数下降，两种假说对撞——长上下文退化 vs 自我条件化。反事实实验：向历史注入 0/25/50/75/100% 错误率的伪造输出。**Result 3**：两种效应都存在——0% 错误历史下 turn 100 准确率仍低于初始（长上下文退化），且随注入错误率上升单调恶化（self-conditioning）；机制解释：模型训练目标即"给上下文最可能的续写"，会像 in-context learning 一样把自己的错误历史也"学"进去（§3.2）。
- **规模消不掉 self-conditioning（Result 4）**：200B+ 前沿非思考模型（Kimi-K2、DeepSeek-V3、Qwen3-235B-Instruct-2507）在 0% 错误历史下基本修复 100 轮内长上下文退化，但随历史错误率上升仍一致退化；CoT 模型用程序化生成含错轨迹测试，self-conditioning 依旧（附录 I）。
- **thinking 修复 self-conditioning（Result 5）**：Qwen3 thinking 模型（RL 训练）turn 100 准确率对历史错误率**不敏感**；可能原因：RL 使模型面向任务成功而非续写上下文、thinking 轨迹不入历史使其独立思考当前轮。替代缓解：滑动窗口式的**上下文工程**（只留最近 N 轮）显著改善（附录 C.2）；提示自我验证**不能**完全修复——CoT 模型因 token 暴涨提前耗尽上下文、thinking 模型"过度思考"且验证步本身出错（附录 C.1）。
- **单轮可执行长度基准（§3.3 WHAT IS THE LENGTH OF TASKS MODELS CAN COMPLETE IN A SINGLE TURN?）**：二分搜索求准确率 ≥80% 的最大 K。**Result 6**：无 CoT/thinking 时，Qwen3-32B、Gemma3-27B 及前沿非思考模型 DeepSeek-V3 (670B)、Kimi K2 (1026B) 单轮连 ~6 步都执行不了，DeepSeek-V3 连 4 步都难，其 thinking 版 R1 可执行 >100 步——先推理后行动（ReAct）对 agent 是刚需；并行多数投票收益边际（附录 D）。**Result 7**：前沿 thinking 模型单轮执行——GPT-5 thinking（代号 Horizon）**2176 步**，远超 Claude-4 Sonnet 432、Grok 4 384、Gemini 2.5 Pro 120；Qwen3-Next（Gated DeltaNet + attention 混合架构）胜过更大的纯 attention 模型，提示架构对长程执行的影响。任务可程序化再生、无污染。

### 2.4 相关工作（§4 RELATED WORK）

- 定位于四条线：任务长度增加（GSM-Infinite 等，常归因推理失败）、长上下文评测（RULER、GSM-Infinite——关注输入长度而非输出长度，本文证明二者不同）、自我纠正/exposure bias（Ranzato et al. 2015 的 RL 直觉）、scaling 与 RL（单步测量 → 长 horizon 经验 scaling law 的需求）、工具使用（把执行转移给可靠程序，但推理本身仍需模型执行）。

### 2.5 局限、真实任务佐证与结论（§5 CONCLUSION；附录 A、B、E、F）

- **self-conditioning 在真实 agent 中也显著（附录 A）**：人工分析 AgentErrorBench 标注轨迹，估计约 **20% 的 GAIA、48% 的 ALFWorld、33% 的 WebShop 失败**类似 self-conditioning（inefficient_plan / progress_misjudge / causal_misattribution 类）。
- **局限性（§5 Limitations）**：合成任务是必要非充分条件——不含真实 agentic 任务的大动作空间与可变步骤、不存在"多条正确计划"问题（用错 key 即错）、Task Accuracy 不计自我纠正；单轮求和理论上属 TC^0 可被常数深度并行计算、非"未来_proof"，故用 TC^1 的 2×2 矩阵连乘变体复验：无串行测试时算力时模型连 2 个矩阵都乘不了，加 thinking 显著改善（附录 B）。
- **错误解构（附录 F）**：单独的检索、单独的加法在长程上近满分，带状态维护的 prefix-sum 任务仍缓慢退化——瓶颈不在原子操作而在**状态维护与"边查边更"的组合**。
- **轮数 vs 轮复杂度（附录 E）**：固定总步骤数下不同家族最优 K 不同（Qwen3-32B 偏好高 K、Gemma3-12B 在中等 K 最差），无普适规律；轮数增多伴随 token 用量上升（overthinking 迹象）。
- **结论与展望（§5）**：短任务基准制造"进步放缓"的错觉；**模型规模拉长可执行轮数、串行测试时算力拉长单轮可执行长度**，二者共同决定 horizon length；未来方向：研究 horizon 的经验 scaling law、内生串行任务、自我纠正、以及生成式模拟环境中的长程可靠性。

## 5. 一句话索引（给 Agent 用）

> 做长程任务 agent 必读：单步准确率的微小提升会**双曲级放大为可完成任务长度**（H_s=ln s/ln p，80% 后陡增），"收益递减"是短任务基准的错觉；长程失败源于**执行（状态维护）而非推理缺失**——首步近满分的模型 15 轮内即跌破 50% 任务准确率；发现 **self-conditioning：自己的错误历史诱发继续犯错，扩大规模（含 200B+ 前沿模型）消不掉，thinking/RL 与滑窗上下文工程可修复**；单轮执行 GPT-5 thinking 达 **2176 步**（Claude-4 Sonnet 432、Grok 4 384、Gemini 2.5 Pro 120），无 CoT 的 DeepSeek-V3 连 4 步都难；真实基准约 20–48% 失败与此相似——须外部化状态、分段验证、控制错误历史并给足 thinking 预算。
