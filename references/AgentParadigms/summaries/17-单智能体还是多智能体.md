# 论文摘要：单智能体还是多智能体？——SAS↔MAS 实证对照与级联混合范式

## 1. 适用场景

- 在新项目上决定"默认走单 agent（SAS）还是多 agent（MAS）、MAS 只留给哪类请求"时读这篇：它提供 15 数据集 × 7 类任务 × 9 框架的系统对照与选型依据。
- 设计"简单请求 SAS 直答、疑难请求升级 MAS"的 Agent Routing / Agent Cascade 混合架构，需要难度评分器设计与成本公式时。
- 需要归因 MAS 失败根因（节点/边/路径三类缺陷）并用置信度打分定位"该升级哪个 agent"时。
- 为 MAS 方案做 token 成本预算、或需要实证数据说服团队不要盲目上 MAS 时（prefill 4–220× 的实测开销）。
- 复现 MetaGPT / ChatDev / SelfCol / MATH-DEBATE 等框架，需要数据集、指标、生成配置与 prompt 细节时（附录 B/F 全公开）。

> 锚点：Abstract; §1 Introduction; §3 Multi-agent or Single-agent Systems?; §4 Towards Cost-Effective Agentic Deployments。

## 2. 主要观点与方案

### 2.1 研究问题与动机（§1 Introduction; §2 Background and Related Work）

- MAS 曾在软件工程、数学推理、科学发现等领域报告准确率优势，但定义角色与协调逻辑的工程成本高、运行时 token 与延迟开销大、失败难诊断；同时 OpenAI-o3、Gemini-2.5-Pro 等前沿模型在长上下文、记忆与工具使用上的快速进步，正在消解当初催生 MAS 的单智能体局限（§1）。
- 由此提出两个问题：日益强大的 SAS 与 MAS 相比表现如何？如何在输出质量与部署成本之间做工程权衡（§1）。
- §2 梳理多智能体应用（MetaGPT、ChatDev、multiagent debate 等）与 agentic 系统优化工作（Agent Workflow Memory、StateFlow、Cognify、Ayo、LLM-as-judge 失败归因等），指出既有优化未回答"SAS vs MAS 该用哪个"。

### 2.2 问题形式化（§3.1 Problem Formulation）

- 将 agentic 执行流建模为有向图 G=(V,E)：节点为 LLM agent 或外部工具（V=Vllm+Vtool），有向边 ei,j=(vi,vj,wi,j) 表示消息依赖，自环 ei,i 可表示 self-reflection；**SAS 即 |Vllm|=1，MAS 即 |Vllm|>1**。
- 部署目标：最大化任务评估 f(G(r))（二元成败或连续分）并最小化累计成本 C(r)=Σ|wi,j|×(cout(i)+cin(j))，即按输入（prefill）/输出（decode）token 单价计的全消息成本。

### 2.3 大规模实证与三大发现（§3.2 Study of MAS and SAS Performance）

- 实验设置：7 类任务——代码生成（MetaGPT/ChatDev/SelfCol × HumanEval/MBPP/DS-1000/BigCodeBench）、软件工程（ChatDev/MetaGPT/HyperAgent × SWE-bench/MAST）、数学推理（MATH-DEBATE × GSM8K/MATH-500/AIME）、旅行规划（TDAG × ItineraryBench）、金融分析（FinRobot × 3 数据集）、RAG 问答（DocRetrieval × HoVer）、科学实验（Curie），共 15 数据集、9 框架；模型含 Gemini-2.0-Flash（默认）、Gemini-1.5-Flash、Gemini-2.5-Pro、GPT-4o、GPT-3.5-Turbo、Llama-3.1-8B/70B，沿用各框架原论文生成配置（Table 1; Appendix B.1）。
- 发现一（优势消退）：原框架论文用 ChatGPT 报告 MAS 相对 SAS 提升 9%–16%，换 Gemini-2.0-Flash 复现后提升仅 0.8%–3.0%，且该趋势跨任务、跨框架一致（Table 2）。
- 发现二（效率差距）：7 个数据集上 MAS 的 prefill token 为 SAS 的 4–220×（AIME 达 220.22×），即使假设完美上下文复用，decode token 仍需 2–12×——对话/辩论/反思式消息生成是范式内生的（Table 3）。
- 发现三（过度思考）：简单任务上 MAS 甚至低于 SAS（overthinking，§1 观察 iii；§4.2 亦引用）。

### 2.4 数据点级归因：三类缺陷（§3.3 Why MAS Is Losing Its Edge?）

- 方法：对每个样本比较 MAS/SAS 输出对错，分 Both Pass / Both Fail / MAS Win / SAS Win 四象限。三个观察：约 80% 样本是"平局"；SAS Win 不可忽视；换更强模型（Gemini-1.5-Flash→2.0-Flash）只增加 Both Pass 而 MAS Win 基本不变，OpenAI 与 Gemini 模型上趋势一致（Figure 2; Appendix C Tables 6–12 给 6 个模型的全量表）。
- **Node-Level Defect**：性能被"负责最难子任务的关键 agent"瓶颈——任务分解作用有限：简单题 SAS 也能解、难题 MAS 也失败；例外是最难的 AIME，MAS 仍稳定胜出，说明其在极端困难任务上的价值。
- **Edge-Level Defect**：高入度节点（如 debate 的 summarizer、RAG 的 synthesizer）被上游信息淹没而 overthinking 出错；SelfCol 案例中 analyzer 列出 9 个 edge case，迫使 coder 过度防御地 strip() 掉区分性信号（尾随空格）导致失败，简化 prompt 后同模型可做对（Appendix E.2）。
- **Path-Level Defect**：中间输出被摘要/过滤时关键信息丢失且不可恢复（早轮正确解经 summarizer 后丢失），与 SAS 可全量访问自身历史形成对比；与既有"决定性错误"研究不同，这类传播错误需要全局知识才能定位（Appendix E.3 案例：多数票从正确答案滑向错误答案）。
- 小结（§3.3 Summary: Think twice before adopting MAS deployment）：MAS 并非 one-size-fits-all、常呈成本无效；但仍有隐私、并行性、民主化等场景价值。

### 2.5 置信度引导的关键路径增强（§4.1 Augmenting MAS Critical Path）

- 洞察：全面换最强模型过于昂贵；应选择性升级瓶颈 agent。但公共 API 框架对 KV cache/微调控制有限，且逐条验证中间消息复杂度随深度指数增长，故需要轻量探测机制。
- 方法：每个 agent 以 1–10 自报置信度 ci（拼接到回复尾部，正则抽取），结合最终输出质量 Qr 累计重要性得分 Ii = Qr·ci + (s−ci)(1−Qr)（s 为置信上限，跨轮累加，Appendix B.2），据此定位该升级的关键 agent（如 Gemini-1.5-Flash → Gemini-2.0-Flash）。
- 验证：AIME 上三 solver 混编（Llama 系/GPT 系/Gemini 系）。升级场景：基线 (Llama3.1-8b, GPT-3.5, Gemini-1.5-Flash) 最终 15.0%，得分把 Solver 3 标为最关键（262 vs Solver 2 的 223），仅升级它（Gemini-1.5→2.0）得 23.3%，是三种单次升级中的最优；降级场景同理能选出代价最小的降级对象（Table 5; Figure 4a）。

### 2.6 SAS-MAS 混合部署（§4.2 Integrating SAS-MAS Paradigms）

- **Agent Routing**：LLM rater（Gemini-2.0-Flash，temperature=0.3，max_tokens=300）给请求打 1–10 难度分，按用户阈值分流——高于阈值走 MAS、低于走 SAS；总成本 = C_Rater + p·C_MAS + (1−p)·C_SAS，rater 开销可忽略（system prompt 可缓存、输出为常数级少量 token）。在 GSM8K+AIME 混合集上比 MAS 基线以 50% 成本换 +2% 准确率；未微调专用评分模型，结果可视作下界（Figure 4b/4c; Appendix B.3）。
- 附录 B.3 补充：二元分类变体（直接判 SAS/MAS）与阈值版仅 37/1319 分歧；换 GPT-4o 作 rater 最大分差 2，跨 rater 一致。
- **Agent Cascade**：先由 SAS 产出初始输出，可低成本验证（exact match、pass@1）则直接返回，不达标再升级 MAS；成本 = (1−p)·C_MAS + C_SAS，因 C_SAS ≪ C_MAS（Table 3），失败尝试的开销可忽略、成功尝试则省下整段 MAS。7 个数据集上准确率一致优于 SAS 与 MAS、最高 +12%，成本较逐请求跑 MAS 最多降 20%（Table 4; Abstract）。
- 前提（Appendix B.4）：级联仅在输出可被准确廉价评估时成立；若需人工或 LLM-as-a-Judge 评估，成本模型要额外加评估项。

### 2.7 消融与人工标注（Appendix C Full Evaluation Result; Appendix D Ablation Study）

- 连续分数任务（TDAG 旅行规划、HoVer、FinRobot）给出 SAS/MAS 逐题分布图（Figures 5–7）。
- MAST 30 题人工标注：Gemini-2.5-Pro SAS 解 24/30，对 ChatDev 15 胜 1 负、对 MetaGPT 13 胜 0 负（Tables 13–14）。
- 消融：Math Debate 中增加 solver 数量多数不涨点（单 agent 亦可比）→ 佐证 Node Defect；弱模型下 Summarize 差于 Concatenate（摘要丢关键信息）→ Path Defect；debate/反思轮数在 AIME 涨点、在 GSM8K 反降 → Edge Defect；把上游消息截断到约 25% 即接近全量效果（Figure 8–10）；T=0/0.4/0.8 结论一致。

### 2.8 结论、局限与未来工作（§5 Conclusion; Limitation; Broader Impact）

- 结论：MAS 擅长复杂任务、SAS 在简单任务上同样有效且更高效；三类缺陷归因 + 置信度引导关键路径 + SAS-MAS 混合路由/级联，准确率最高 +12%、成本节省最高 88.1%。
- Limitation：实验集中在通用模型（非微调模型）构建的 agentic 系统，且聚焦任务求解型（最流行的）系统，其余留作未来工作。
- Broader Impact：挑战"MAS 准确率必胜"的流行假设，呼吁 MAS 研究把部署效率而非单纯准确率纳入核心关切。
