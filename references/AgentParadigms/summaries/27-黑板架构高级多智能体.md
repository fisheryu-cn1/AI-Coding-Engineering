# 论文摘要：Exploring Advanced LLM MAS Based on Blackboard Architecture——黑板架构驱动的自组织多智能体系统（bMAS/LbMAS）

## 1. 适用场景

- 评估"**共享黑板（全局结构化状态对象）能否替代消息传递式 MAS**"时读这篇：首个把 1980s 黑板架构引入 LLM 多智能体系统的工作（通用框架 bMAS + 首个实现 LbMAS），agent 只经黑板通信、LLM 控制单元按黑板当前内容逐轮选 agent——是"黑板路线 vs 消息传递路线"的直接实证材料。
- 设计**无需预定义 workflow / 协作机制的自组织 MAS** 时直接参考：三组件（控制单元 + 公共/私有黑板 + agent 组）、五种常驻角色（planner/decider/critic/conflict-resolver/cleaner）、查询驱动的专家生成、decider 出解 + 累积相似度多数投票兜底的双出口（§3; Algorithm 1）。
- 论证"**共享黑板可替代 agent 私有 memory 模块并压低 prompt 总长**"时引用其 §3.2：消息全存黑板即可保一致性，使 MAS 在 token 约束下能进行更多轮讨论；以及 §4.3 Table 3 的 token 成本证据。
- 对比"**先搜 workflow 再解题**"的自治 MAS（GPTSwarm/AFlow/MaAS）的额外代价时：MATH 上 LbMAS 总 token 4,721,489 为第二低、性能 72.60 最高，而 AFlow/MaAS 需 16.7M/13.0M 且依赖领域训练数据（§4.3; Table 3）。
- 对本研究（`research/agent-software-design/materials/harness与冯诺依曼架构类别关系.md` 的"黑板架构替代路线"一节）：黑板=外置共享结构化状态，是"文档传递式协同"（跨阶段靠文档）的近亲——本文提供黑板路线在知识/推理/数学六基准上的可用性与成本证据（平均 81.68 最佳），可与消息传递式 MAS（ChatEval/EoT/MultiPersona/GPTSwarm/AFlow/MaAS）直接对照；其"私有空间做辩论/自省"与"cleaner 删除冗余消息"是控制黑板膨胀（token 成本）的机制参照（§3.2; §4.3; §4.5）。

## 2. 主要观点与方案

### 2.1 动机与研究问题（§1 Introduction）

- 既有 LLM MAS 多为固定架构 + 预定义角色与协作机制，需人工构造、缺通用性；动态/自治 MAS（DyLAN、GPTSwarm、AgentPrune、ADAS、AFlow、MaAS）需监督训练步 + 搜索空间无法覆盖所有协作架构（§1; §2 Related Work）。
- 提议将黑板架构（Hayes-Roth 1985; Nii 1986）引入 LLM MAS：bMAS 通用框架三组件——**控制单元、黑板、多角色 agent 组**；控制单元按黑板当前消息选本轮参与的 agent，被选 agent 以整块黑板为 prompt 调用其 LLM 并把输出写回黑板，循环至黑板达成最终解（Abstract; §1; §3; Algorithm 1）。
- 两项贡献（§1 末）：(1) bMAS 一般框架——agent 经黑板自主通信与贡献；(2) 首个实现 LbMAS——不同于其它自治 MAS，可按黑板内容**即时调整协作机制**，面向"没有良定义结构/workflow"的复杂动态问题求解，无需监督训练步。

### 2.2 黑板架构谱系（§2 Blackboard System）

- 经典 BA 三组件：knowledge sources（异质独立模块，只感知黑板状态、彼此不知存在）、blackboard（全局数据库：输入/部分解/候选/终解）、control（运行时决定下一个执行的 KS）；KS 间交互仅经黑板变更发生（§2）。
- BA 本为复杂、病态结构问题设计（整合异质知识源的探索式编程）——正是引入当今 LLM MAS 的理由；agent+BA 组合在 LLM 之前已有研究（Ettabaa et al. 2006; Szymanski et al. 2018; Dong et al. 2005），但当年的 KS 与 LLM agent 本质不同（§2）。

### 2.3 bMAS 框架与 LbMAS 实现（§3; §3.1; §3.2; Figure 1; Algorithm 1）

- **黑板双层结构**：公共空间（全员可见的对话与知识）+ 私有空间（特定 agent 的辩论/自省）（§3）。
- **Agent 生成**（§3.1）：agent 生成器 AG 按查询 q 与专家生成指令 I 随机产出 n 个专家提示 (Ei, Di)（身份 + 专长描述）；基座 LLM 从集合 {Llama-3.1-70B-Instruct, Qwen-2.5-72B-Instruct} 随机抽取——依据"MAS 用不同 LLM 优于单一 LLM，模型多样性补偿个体局限"。
- **常驻 agent**（§3.2 Agent group）：decider（判断黑板消息是否足以出解、给解并停循环）、planner（规划/分解复杂查询）、critic（指出黑板消息错误——可能来自幻觉——并迫使相关 agent 重思）、conflict-resolver（检测矛盾、点名冲突 agent 在私有空间讨论后各写新消息回公共空间）、cleaner（检测并**直接删除**无用/冗余消息——内容管理既促进有效通信又降 token）。
- **黑板即通信与记忆**（§3.2 Blackboard）：与 MetaGPT 把共享内存池用作知识存储辅助不同，LbMAS 中 agent **仅通过黑板通信、无任何直接接触**；由此**移除 agent 常规 memory 模块**——消息全存黑板即可保证各消息一致性，同时缩短所有 agent 的 prompt 总长。
- **控制单元**（§3.2）：本身是 LLM，按 (q, B, {D1..Dn}) 选下一轮 agent（式 2）；达最大轮数或 decider 出解即停。
- **双出口**（§3.2 末）：decider 直接给解；或循环结束后全员基于黑板内容各出一答、按累计相似度 V(ai)=Σ_{j≠i} sim(ai,aj) 取 argmax（软多数投票兜底）。

### 2.4 实验设置（§4.1）

- 六基准：MMLU（每类随机 20 题、共 1140）、ARC-Challenge、GPQA-Diamond、BBH-date understand、MATH（HuggingFaceH4/MATH-500 的 500 题子集）、GSM8K。
- 基线：CoT、Major-Vote（Li et al. 2024）；静态 MAS：ChatEval、Exchange-of-Thought、MultiPersona；自治 MAS：GPTSwarm、AFlow、MaAS。
- 公平性协议：所有对比 MAS 采用与 LbMAS 相同的随机 LLM 选择方式；temperature 0.7；黑板循环上限 4 轮；API 访问（§4.1）。

### 2.5 主要发现（§4.2–§4.4）

- **主结果**（Table 1）：LbMAS 平均 81.68 全场最佳，超 CoT 平均 +4.33%、静态方法 +5.02%；单基准 MMLU 85.35、GPQA-D 54.04、MATH 72.8 最优，BBH 90.00 并列最优，ARC 93.43 次于自家 Majorvote 变体 93.51，GSM8K 94.46 低于 CoT(Llama) 94.84（变体 94.61 次优）。LbMAS-Majorvote 平均 81.65，与 decider 方式几乎相同——decider 与全员在 MMLU/GPQA/MATH 上的共识比例分别为 89.8%/52.5%/29.4%（§4.2）。
- **单基座对照**（Table 2）：全 Qwen 时 LbMAS 反超 CoT（MATH 78.6 vs 76.4、GSM8K 96.05 vs 94.46）；全 Llama 时落后（58.4 vs 62.2、92.57 vs 94.84）——弱基座模型会拖累 MAS 整体表现（§4.2）。
- **独家解题数**（Figure 2）：LbMAS 在 MMLU/GPQA/MATH 上"仅自己解出"的题数最高，其余方法（含 Vanilla）亦各有独家解出的题（§4.2）。
- **成本**（§4.3; Table 3, MATH）：LbMAS 总 token 4,721,489（第二低；最低 MP 2,171,890 但仅 65.80 分）、性能 72.60（最高）；对比：Chateval 5,451,820/70.20、GPTSwarm 5,449,425/67.25、MaAS 13,012,658/70.77、AFlow 16,697,032/69.25、EoT 8,328,772/60.40。自治 MAS 的两步策略（先搜 workflow）额外烧训练 token 且需领域训练数据，无数据即失效；LbMAS 按黑板消息即时选/执行 agent 直至共识（§4.3）。
- **案例**（§4.4; Figure 3）：易题一轮即停、难题多轮讨论；cleaner 删除冗余消息（案例 a）、conflict-resolver 识别冲突并组织讨论（案例 c），角色机制有效运转。

### 2.6 框架研究（§4.5; Tables 4–5）

- **轮数分析**（Table 4）：Max Round=4 时平均执行轮数 MMLU 2.88 / GPQA 3.29 / MATH 3.04（正文 §4.5 写作 2.88/3.05/3.29，与表格不一致，疑为笔误，建议以表为准）；易题（MMLU）轮数少、难题（GPQA/MATH）需更多轮；MMLU/GPQA 最优在 4 轮（85.17/54.04），MATH 在 8 轮（74.80）。据此设主实验上限 4 轮。
- **消融**（Table 5）：(a) 去掉控制单元（agent 自行决定是否响应黑板）：性能仅微扰（MMLU 85.17→85.52、GPQA 54.04→53.53、MATH 72.60→72.80）但 token 暴涨 2.9–4.5 倍（MMLU 5,074,931→18,829,644、GPQA 2,984,204→13,325,826、MATH 4,721,489→13,858,631）——LLM agent 有一定自主性，控制单元的价值在成本控制与精准选人；(b) cleaner 由"删除"改"标记"冗余消息：三集性能全降（85.17→84.38、54.04→53.53、72.60→71.00）——黑板内容管理必要。

### 2.7 机制解释与局限（§5 Discussion; Limitations）

- 三大优势（§5）：动态选 agent（跨域解题无需改 prompt 或优化协作机制的高度泛化框架）；agent 生成与交互双高度自主；高可扩展（agent 组无约束、随需增删）；黑板作为交互介质可承载公共/私有、扁平/层级等多种交互形态。
- 为什么有效（§5）：(1) 黑板共享内存池使 agent 间信息交换更全面；(2) 按黑板当前内容动态选 agent 保证所选 agent 适配既有消息、避免不必要的 agent 执行；且不同于"先搜最优 workflow 再执行"的自治 MAS，无需监督训练步及其额外数据与 token。
- 局限（Limitations）：预定义 agent 类型少（未含代码写作、工具使用）；基准覆盖有限；agent 生成模块简单（应引入 MASRouter 类的 prompt/基座联合优化）；对黑板本身的探索不充分——**共享内存池 vs agent 私有 memory 模块的对照实验**仍是待做工作。
