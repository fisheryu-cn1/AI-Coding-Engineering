# 论文摘要：More Agents Is All You Need——采样投票的规模化收益

## 1. 适用场景

- 为任何多 agent / 复杂 prompt 方案确立**对照基线**时读这篇：sampling-and-voting（Agent Forest，本质即 best-of-N + 多数投票）无需角色分工、通信拓扑与人工提示设计，任何 MAS 增益主张都应先赢过它（论文中它单独使用即在多数任务上超过 CoT/ZS-CoT/SPP/Debate/Reflection 单独使用）。
- 决定**采样次数 N 与推理预算**（性能 vs token 成本线性权衡）时，参考其难度三维模型与增益曲线判断"再加采样还有没有收益"。
- 判断"**多 agent 收益在什么条件下出现/消失**"时：固有关联难度先升后降、推理步数越多收益越大、正确答案先验概率越低绝对性能越差——据此设计任务分解或分层采样。
- 做**小模型 + 大集成 vs 换大模型**的成本决策时：Llama2-13B 集成 40 次在 GSM8K 上 0.59，反超单次 Llama2-70B 的 0.54。
- 澄清"多 agent"术语边界（本文指同构多采样集成，非角色协作式 MAS），避免文献误引时。
- 设计**步级采样（Step-wise AF）或分层异构模型管线（Hierarchical AF）**时直接复用其两个衍生方法。

> 锚点：§1 Introduction; §3 Method; §4 Experimental Setup; §5 Experimental Results; §6 Understanding the Performance Gains。

## 2. 主要观点与方案

### 2.1 研究问题与动机（§1 Introduction）

- 观察：LLM-Debate、CoT-SC 等工作的附带数据显示"agent 数量增加"本身似能提升性能，但无人系统研究过该现象是否普遍成立；本文提出问题"Does this phenomenon generally exist?"并做**首个针对 raw agent 规模化性质（scaling property）的系统研究**。
- 核心发现：仅靠 sampling-and-voting，LLM 性能随实例化 agent 数（ensemble size）提升；暴力集成小模型可达到甚至超过大模型（Fig 1：GSM8K 上 ensemble 达 15 时 Llama2-13B ≈ Llama2-70B，达 15/20 时 Llama2-70B/GPT-3.5-Turbo ≈ 各自更强对手）；该方法与既有复杂方法**正交**，可叠加增强；增益幅度与任务难度、模型强弱相关。
- 三项贡献：规模化现象确证、与既有方法的兼容性验证、难度维度分析 + 优化策略（§1 末 Contributions）。

### 2.2 相关工作定位（§2 Related Work）

- LLM self-ensemble（CoT-SC 及扩展）：仅限推理任务、只考察与 CoT 兼容；本文覆盖推理 + 生成任务、兼容面更广。Blended（Lu et al., 2024）面向聊天场景、靠人工标注评估；本文关注规模化趋势本身。
- 异构 LLM ensemble（LLM-Blender、知识融合、路由等）：依赖监督学习与标注数据、泛化受限；本文**无监督、零额外训练**。
- 多 agent 协作框架（Debate、AutoGen、MetaGPT 等）：关注交互结构而非"数量-性能"关系；本文与其正交并可叠加。

### 2.3 方法：Agent Forest（§3 Method）

- 两阶段（Algorithm 1，致敬 Random Forest）：**Sampling**——将查询 x（可叠加提示工程或多 agent 协作框架 fM）独立执行 N 次得到样本集 S={s1..sN}；**Voting**——对每个样本累加与其余样本的相似度 V(si)=Σ_{j≠i} sim(si,sj)，取累计相似度最高者为最终答案（等价于软多数投票）。
- 相似度度量按任务类型选择：开放式生成（代码）用 **BLEU**（sacreBLEU），封闭式（选择题）用**选项出现频次**；数学任务用数学等价比较抽取 `\boxed{X}`（§3; §A.2–§A.4）。

### 2.4 实验设置（§4 Experimental Setup）

- **任务**：算术推理 GSM8K、MATH；一般推理 MMLU、Chess（棋局状态追踪）；代码生成 HumanEval（BLEU 投票）。Table 1 与 CoT-SC/Complexity-CoT/Debate/Blended 逐维对比，显示本文覆盖"多 LLM × 多任务类型 × 多方法集成"最全。
- **模型**：Llama2-Chat 13B/70B、GPT-3.5-Turbo（主实验 gpt-3.5-turbo-0613）；GPT-4（gpt-4-0613）仅作单次对照。
- **被增强方法**：提示工程（CoT、Zero-Shot CoT、SPP）与多 agent 协作（LLM-Debate、Reflection/Reflexion）。
- **协议**：每配置 10 次独立运行取平均；ensemble size 上探到 40（与 Debate 组合时因其通信开销限到 10）；§6 案例研究用 gpt-3.5-turbo-1106 + JSON 模式（§4; §A.1）。

### 2.5 主要发现（§5 Experimental Results）

- **泛化性（§5.1，Table 2/Fig 3）**：所有任务 × 所有模型均随 ensemble size 单调提升。绝对增益：GSM8K +12%~+24%、MATH +6%~+10%、Chess +1%~+4%、MMLU +5%~+11%、HumanEval +4%~+9%。典型数字：GSM8K 上 Llama2-13B 0.35→0.59、Llama2-70B 0.54→0.74、GPT-3.5-Turbo 0.73→0.85（GPT-4 单次 0.88）；HumanEval 上 GPT-3.5-Turbo 0.67→0.73（逼近 GPT-4 单次 0.88）。
- **兼容性（§5.2，Table 3）**：+Ours 对各方法再提升：GSM8K +10%~+21%、MATH +1%~+15%、Chess +1%~+13%、MMLU +1%~+11%、HumanEval +2%~+7%。例外：Debate + Llama2-13B/70B 在 HumanEval 上增益为 0（0→0），归因于辩论中引用他 agent 答案的噪声破坏代码逻辑连贯性。
- **单独使用有效性（§5.3，Table 4）**：按 Table 3 计算五任务平均排名，Ours 总体 2.5 为最高（GPT-3.5 上 2.6、70B 上 2.6、13B 上 2.2），优于 CoT 3.6、ZS-CoT 2.7、SPP 4.4、Debate 4.4、Reflection 3.3；除 Llama2 两模型的 Chess 外，单独使用即超过其余方法单独使用。
- **鲁棒性（§5.4，Fig 4）**：GPT-3.5-Turbo、20 次平均，改变 temperature T 与 nucleus probability p，规模化增益一致存在。
- **Token 成本（§5.5，Table 5）**：单 agent token 开销与其他方法同量级（GSM8K：Ours 235±54 vs CoT 261±63、ZS-CoT 228±56、SPP 341±85、Reflection 214±45），总开销随 agent 数线性增长，本质是"用 token 预算换性能"。

### 2.6 机制分析：难度三维与两个衍生方法（§6 Understanding the Performance Gains）

- 相对增益 η=(P_m−P_s)/P_s 随难度上升（Table 6）：GSM8K（易）上 Llama2-13B/70B/GPT-3.5 分别 +69%/+37%/+16%，MATH（难）上 +200%/+120%/+34%——**任务越难、模型越弱，收益越大**。
- 用可控合成任务（求使 Σa_i·b_i 落入区间 Δk 的区间，ai、bi 取自 [−I,I]）把难度解耦为三个正交维度（§6.1）并逐一隔离实验（GPT-3.5-Turbo，40 次采样 vs 单次，10 轮平均）：
  - **固有关联难度 I（§6.2，Property 1）**：增益先升后降——I 从 10 增到 100/200 时增益最显著，I=400 时回落（超出模型推理能力后边际收益递减）。
  - **推理步数 S（§6.3，Property 2.1/2.2）**：增益随步数单调增大（{I=10,K=2} 时 +4%~+18% vs {I=100,K=4} 时 +16%~+48%）；逐步分析显示 AF 能缓解误差逐步累积。**衍生方法 Step-wise Agent Forest**：先分解任务为步，逐轮用 AF 确定每步结果再更新任务；S=8、K=4、I=100→400 时比 Agent Forest 再多 +15%~+42% 且随难度上升。
  - **正确答案先验概率 1/K（§6.4，Property 3）**：绝对性能随先验概率升高而升高。**衍生方法 Hierarchical Agent Forest**：把低先验概率任务分解为高先验概率子任务分层求解；K=32 任务上同构组合（GPT-3.5 先解 K=8 再解 K=32）从 21% 提升到 31%，异构组合（GPT-3.5 出中间答案 + GPT-4 解终答）从 GPT-4 单独的 35% 提升到 47%，且易子任务用便宜模型可省成本。
- 统计显著性（§B.2，Table 7）：对 ensemble size ∈ {1,10,20,30,40} 做 one-way ANOVA（10 次运行），全部 p<0.05。

### 2.7 结论、局限与未来工作（§7 Conclusions and Future Work）

- 结论：确认"more agents is all you need"的规模化规律、其正交性与难度依赖性，并给出两个增效变体。
- 局限与未来工作：同一输入重复采样导致成本随 N 线性膨胀，采样阶段降本是首要开放问题；引 Kapoor et al.（2024）指出当前基准窄化地只看精度、催生昂贵 agent，且缺乏充分 holdout 集与标准化评估，均待解决。适用边界：依赖可投票/可比对的答案（客观题、数学等价、代码 BLEU 共识），完全开放式无参照生成不适用。

## 5. 一句话索引（给 Agent 用）

> 评估多智能体方案前先跑这个基线：腾讯 Agent Forest（TMLR 2024）证明只做"多采样 + 多数投票"（无角色分工与通信）LLM 性能即随 agent 数稳定上升，ensemble=40 时 GSM8K +12~24%（Llama2-13B 0.35→0.59 反超 70B 单次 0.54）、MMLU +5~11%、HumanEval +4~9%，且与 CoT/Debate/Reflection 等正交可再叠加 +1~21%；收益随任务变难、模型变弱而放大（MATH 上弱模型相对增益最高 200%），受固有关联难度（先升后降）、推理步数（单调升）、正确答案先验概率（正比）三维调控，衍生 Step-wise（再 +15~42%）与 Hierarchical（异构 35%→47%）两个变体；代价是 token 随 N 线性增长，仅适用于可投票/可比对答案的任务。
